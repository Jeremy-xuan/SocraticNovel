## 本讲要回答的核心疑问

> **虚拟内存让每个程序都以为自己有一大片地址空间。可物理内存是有限的——当所有程序真正要用的页加起来超过了物理内存，操作系统必须把一些页挪走，才能腾出位置给现在要用的页。问题是：挪走谁？**

**先把题目讲清楚**：这不是"内存满了怎么办"的泛泛问题，而是一个**必须在信息不足的情况下当场做决定**的问题。操作系统要在缺页发生的那一瞬间选出一个牺牲页（victim page），而它对未来的访问毫无知识。

不要让学生猜"桌上""架子"各指什么——先讲清物件与动作对应什么（桌子＝物理内存、书架＝后备存储、稿子＝页），再进入技术问题。

## 教学地图（选择动作，不按顺序过关）

### 值得学生推导的关键关口

**一、缺页之后要发生哪几件事？** 这是本讲最该让学生自己走一遍的流程。起点由教师给：访问一个页表项里"存在位为 0"的页，硬件会陷入内核。之后就值得问：

- "内核现在知道这条指令要访问哪个虚拟地址吗？"——知道，出错的那条指令和地址是可以拿到的（通常由硬件提供或从上下文恢复）。**这一条可以直接给**，不必让学生猜。
- "它要去的那个页，现在在哪？"——在后备存储（swap space，交换空间）里。
- "要把它读进来，得先有个空帧。如果没有空帧呢？"——这就是本讲的中心：**必须选一个页挪走**。
- "被挪走的那页，直接丢回后备存储就完了吗？"——🔴 这里值得停一下。如果那页被改写过，直接丢就丢了修改。所以要先看它的**脏位（dirty bit / modified bit）**：脏的页要先写回后备存储，干净的页可以直接覆盖。

走到这里，学生就能自己说出**存在位**和**脏位**各解决什么问题：前者回答"它在不在内存"（决定要不要缺页），后者回答"它能不能直接丢"（决定要不要先写回）。这两个位不是一回事，是本讲第一个要分开的东西。

**二、"最久没用过的先扔"是个好规则吗？** 学生通常能凭生活经验说出 LRU（Least Recently Used，最近最少使用）的思路。这时可以往下推一层：

"这个规则要成立，你得先知道什么？"——你得知道**每一页上一次被访问是什么时候**。追问："每访问一次内存，你都要去更新一次这个记录。这个记录存在哪？谁来维护？代价是多少？"

学生大概率会意识到：**精确 LRU 要在每次访存时都动手脚**，而访存是程序里最频繁的动作。这个取舍的结论就是本讲第二条主线：**精确的 LRU 太贵，现实中用 Clock 这类近似实现。**

**三、如果连"最久没用"都做不到，为什么还要讲最优策略？** 这是学生容易滑过去的一点。OPT（最优替换策略）用**未来**的信息来选牺牲页——它不可能实现（操作系统没有未来访问序列），但它给出一个**下界**：任何真实策略的缺页次数都不会比 OPT 更少。所以它的用途是**当标尺**：拿来量"我离理想还差多远"。这个"理论最优只用作基准"的用法，是计算机系统里的常见套路，值得点明。

### 关键点之后的讲解主线

以下几个片段彼此衔接，但不要求同一轮全讲完；学生的提问也可能改变顺序。

- **片段一 · 一次缺页的完整流程**：硬件发现存在位为 0 → 陷入内核 → 页错误处理程序（page-fault handler）找到该页在后备存储中的位置 → 有自由帧就直接读入；没有自由帧则按替换策略选一个牺牲页，脏页先写回 → 把目标页读入该帧 → 更新页表项（存在位置 1、记下帧号）→ **返回并重新执行刚才那条指令**。最后这一步容易漏：不是"继续往下跑"，而是"把出错的那条指令再做一遍"。
- **片段二 · 策略的层次**：OPT 用未来 → 不可实现，只作标尺；LRU 用过去近似未来 → 方向对，但精确实现太贵；Clock（第二次机会算法）→ 用**使用位（use bit / reference bit）**近似"最近有没有被用过"。也可以顺带讲 FIFO，说明"看起来最简单的规则未必安全"。
- **片段三 · 换页的代价来自哪里**：缺页的代价主要在**后备存储的访问**（磁盘或 SSD），它比访问物理内存慢好几个数量级（具体倍数随介质差别很大，标「待核」，不给单一数字）。所以性能对缺页率非常敏感——缺页率的小幅上升就可能带来明显的整体变慢。
- **片段四 · 抖动（thrashing）**：当进程真正在用的页集合（工作集，working set）大于它能拿到的物理内存时，每一轮访问都要换入换出，系统几乎把所有时间花在搬页上。更糟的是：CPU 利用率看起来很低，操作系统可能因此**再引入更多进程**，于是内存更紧、换页更凶——恶性循环。

把这些串起来，本讲回答的是：**虚拟内存的"随意使用"是有条件的**——当工作集超出物理内存时，虚拟内存不会失效，但会从"看起来免费"变成系统性能的主要瓶颈。

### 真正值得再停下来的地方

- 学生把"换出"当成"删除"：🔴 这是本讲最该纠正的一个直觉。换出的页**仍然完整地待在后备存储里**，需要时会再取回来。回答这个问题时可以说清：它的内容没有丢，丢的只是"此刻在物理内存里"这个状态。可以补一句我们必须诚实说明的边界：后备存储本身也可能被填满，那是另一个层面的资源问题。
- 学生把"页错误"当成"程序出错了"：页错误是**正常的、可恢复的**机制，是虚拟内存得以工作的日常事件；程序访问了没有权限的地方是另一回事（那才是通常说的段错误一类异常）。两者都会"陷入内核"，但性质与后续处理完全不同。
- 学生把存在位和脏位混成"一个状态位"：用提问检验——"这页在内存里，但没被改过，该做什么？"（可以直接丢掉，不必写回）。"这页不在内存里，该做什么？"（去后备存储取）。两个问题答案不同，说明是两个位。
- 学生问"是不是总是把最久没用的页换出去"：说明真实系统常用的是**近似**，并且替换只是众多策略之一；不要把 Clock 说的"扫一圈、给第二次机会"背成"精确 LRU 的实现"。
- 学生看到 Clock 算法觉得"这不精确，是不是有 bug"：这不是 bug，是**设计上的取舍**——用一点点准确度换取每次访存都不必维护精确顺序。可以顺带问："如果允许你每访存一次都更新一次记录，你打算怎么存这个顺序？"让他自己看到复杂度。

### 检验理解的一个新情境

给一个简短的页访问序列（例如页号序列 A B C A B D），告诉他物理内存只能放三页，然后问两件事：

1. 如果**知道未来**，按 OPT 该在出问题时换掉谁？让他把理由说出来（不是背结论）。
2. 如果按 Clock 走，指针会扫到哪里、哪些页的"使用位"会被清掉？让他自己走一遍。

学生能解释"为什么 OPT 换掉的那页和 Clock 换掉的那页可能不同"，就说明他分清了**理论标尺**与**近似实现**。教师可以先讲解再检验，也可在学生已掌握时直接继续下一讲。不必要求他复述预设句子。

## 本讲核心事实（知识锚 · 不许说错）

- **换出／换入（swap out / swap in）**：物理内存不足时，把页移到**后备存储**（swap space，交换空间）；需要时再取回。换出**不是删除**。
- **存在位（present bit）**：页表项里标明该页当前是否在物理内存中。为 0 时访问它会触发**页错误（page fault）**。
- **脏位（dirty bit / modified bit）**：标明该页自被读入以来是否被改写过。脏页换出前**必须写回**后备存储；干净的页可以直接被覆盖。
- **页错误处理流程**：陷入内核 → 定位该页在后备存储中的位置 → 有空闲帧则读入，无空闲帧则按替换策略选牺牲页（脏页先写回）→ 读入目标页、更新页表项 → **重新执行**引发缺页的那条指令。
- **OPT（最优替换策略）**：替换未来最久不会被访问的页。它需要未来信息，**不可实现，只能作为缺页次数的下界／标尺**。
- **LRU**：替换最久未被使用的页，用过去近似未来。精确实现需要在每次访存时维护访问顺序，代价很高。
- **Clock（第二次机会）算法**：把页排成环形，每页带一个**使用位**；指针扫过时使用位为 1 则清零并跳过（给它第二次机会），为 0 则选它作牺牲页。它是 LRU 的**近似**，不是精确 LRU。
- **抖动（thrashing）**：工作集大于可用物理内存时，系统把大量时间花在换入换出上，几乎不做有效工作；CPU 利用率低还可能诱使操作系统引入更多进程，使情况恶化。
- 缺页代价主要来自后备存储访问，**比访问物理内存慢若干数量级**；具体倍数随介质（磁盘／SSD）差别很大，本教材不给单一数字（**待核**）。
- ⚠️ **待核**：FIFO 在某些访问序列下会出现"物理帧增加、缺页反而变多"的反常现象（通常称为 Belady 异常）。该现象的一般性说法是标准结论，但**具体反例序列见 OSTEP ch22，本教材不复制、不编造数字**。

## 类比的边界（可能误导时讲清）

**编辑部隐喻在哪不成立？**
- 她走到书架前取一份稿子，和机器去后备存储取一页，**不是同一种代价**。人的动作时长不能用来推断磁盘访问的开销；本讲的性能结论必须基于存储层级的事实，不能基于这段演示。
- 人可以说"我记得哪份最久没碰"，**机器不能**。机器只有**位**（使用位、脏位）这种极其有限的记录。把"凭印象挑"当成 LRU 的实现，正好会掩盖本讲最关键的那层取舍。
- 书架上的东西可以被人**同时看着、同时取**；真实系统的换页与处理器执行是**相互干扰**的——换页本身就是系统变慢的原因。人做演示时不会感觉到"越搬越慢"，机器会。
- **书架的容量是有限的**，这一点反而应该保留：后备存储不是无限的，说"不会丢，它在架子上"时不要顺口暗示"架子永远放得下"。
