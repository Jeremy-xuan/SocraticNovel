## 本讲讨论的模型

问题是：**多个程序都需要 CPU 时，操作系统怎样让它们各有执行机会，同时保持对机器的控制？**

先用一个简化模型：一颗核心、一个执行位置，某一刻只分给一个程序。不讨论核心内部的流水线、多执行单元或 SMT。这里的“同时运行”指用户观察到多个程序都在推进，不是断言真实 CPU 每周期只能执行一条指令。

## 可借用的日常情境

潮汐观测站外阳光带只有一片，多项下潜作业都需要在这片光线下推进。轮流处理可以帮助学生先看见**共享一个有限工作位置**。映射到技术问题时，应明说：阳光带在此只对应简化模型中的 CPU 执行机会，待处理作业对应需要 CPU 的程序，轮流处理对应时间共享。

这个情境的边界同样重要：观测站记录员会主动轮换，CPU 不会；作业记录是被动的，运行中的程序会继续执行指令；作业记录放在台面上也不等于此刻正在执行它。日常情境只提供入口，后面的机制以程序、进程、CPU 和内核来说明。

## 概念之间的因果关系

### 1. 时间共享与进程

操作系统可以让进程依次使用 CPU：A 运行一段，停止 A，运行 B，之后再给 A 机会。这是 CPU 时间共享，也是“多个程序看起来都在运行”的来源之一；共享有开销，不能说每个进程真的始终独占 CPU。

**程序文件**是一组尚未执行的指令和静态数据。**进程**是程序的一次执行及其状态：除了代码与数据所在的地址空间，还包括寄存器、下一条指令的位置，以及与执行有关的其他资源。入门模型中，进程可处于正在执行、已就绪等待 CPU、或因输入输出等事件而阻塞的状态。“进程是正在运行的程序”是简短定义，不表示进程每一刻都占用 CPU。

### 2. 切换时为什么要保存状态

若 A 被切走后还要继续，必须保留足以接续执行的状态，例如程序计数器与寄存器的值。操作系统决定从 A 换到 B 时，保存 A 的相关状态，再恢复 B 先前保存的状态，B 才能接着执行。这是**上下文切换**。保存和恢复执行状态不等于重新复制或装载程序文件；若状态丢失，只能说不能正确接续，不能断言它会自动从程序开头重跑。

一次定时器中断给操作系统一个决定机会，**不等于一定发生上下文切换**。是否换进程属于调度决定；本讲只需理解切换的机制，具体调度策略留在后续课程。

### 3. 快速运行与重新取得控制权

**受限直接执行**让用户程序直接在 CPU 上执行普通指令，避免每条指令都由操作系统转手，因而运行得快。若只依赖程序自愿发起系统调用或让出 CPU，一个持续计算且不主动让位的程序就可能长期占着核心。

在抢占式模型中，硬件定时器定期产生中断，使 CPU 进入内核的处理代码；内核于是有机会决定让原进程继续，还是切换到另一个进程。定时器的特别之处是**定期提供抢占机会**，并非唯一无需程序自愿就能进入内核的途径：异常和设备中断也可能做到这一点。系统调用和自愿让位则由程序主动发起。

### 4. 快速运行与权限边界

CPU 有受限制的**用户态**和有特权的**内核态**。普通程序在用户态不能执行设置定时器等特权操作；需要操作系统服务时，它通过系统调用这一受控入口进入内核，由内核处理，再返回用户态。

不要把所有隔离都归给模式位。普通读内存指令本身不是特权指令；程序能访问哪些地址，还受地址翻译与硬件内存保护约束。本讲只划清这两类保护的区别，地址翻译在后面的内存单元展开。

## 一段把机制连起来的例子

以下是一种**可能**的执行顺序；它假设内核在定时器中断后选择让 B 运行，且 B 的读文件操作需要等待：

1. 浏览器 A 正在计算，音乐播放器 B 已就绪。
2. 定时器中断使内核重新得到 CPU；内核选择切换，保存 A 的执行状态，恢复 B 的状态。
3. B 执行并发起读文件的系统调用。若数据尚未就绪，B 阻塞；内核可以让已就绪的 A 再运行。
4. 读取完成后，设备事件让 B 重新就绪。**就绪不等于立刻执行**；什么时候再运行 B，取决于后续调度决定。

图示时保持这个顺序：`A 执行 → 定时器中断 → 内核保存 A、恢复 B → B 执行 → B 发起读文件系统调用 → B 阻塞 → A 可继续`。这段例子同时呈现时间共享、进程状态、上下文切换和进入内核的不同路径，不要求学生逐步猜出每个硬件事实。

## 容易混淆的边界

| 容易混在一起的两件事 | 应当分开的原因 |
|---|---|
| 指令已在内存／缓存中 vs 正获得 CPU | 前者涉及指令和数据如何被取得；后者涉及哪一个进程此刻得到执行机会。 |
| 程序文件 vs 进程 | 文件本身不会因“放着”而推进；进程有正在变化的执行状态，也可能暂时等待。 |
| 定时器中断 vs 上下文切换 | 中断让内核重新介入；内核可以决定换进程，也可以不换。 |
| 系统调用 vs 定时器中断 | 前者由程序请求，后者按硬件定时机制发生；异常和设备中断也不要求程序自愿。 |
| 用户态限制 vs 内存隔离 | 特权指令限制与地址翻译、内存保护是相关但不同的机制。 |
| 简化的一颗核心 vs 现代 CPU 内部并行 | 本讲只讨论操作系统分配执行机会，不把简化模型当作微架构事实。 |

## 可用来观察理解的新情境

- A 被切走后再次运行：它靠什么从原来的位置继续？“代码还在内存里”为什么不足以回答？
- A 一直计算、不调用内核服务：内核凭什么仍有定期重新介入的机会？
- B 发起读文件请求并等待：这一步如何进入内核，B 此时为何可以不占 CPU？
- 程序尝试设置定时器，或尝试读取不属于自己的地址：这两种限制是否由同一个机制解释？

这些情境供教师选择、改写或跳过；是否掌握以 `knowledge_points.md` 的实际证据为准，不以本页的题目是否全部问过为准。
