## 本讲要回答的核心疑问

> **谁能保证程序访问不到别人的内存？**

**先把题目讲清楚**：这里的"保证"不是"操作系统会检查一下"这种软性说法，而是**每一次内存访问都会被检查**，越界会当场被拦下。学生若问"那它凭什么拦得住一个故意写坏地址的程序"，答案正是本讲的主线：**翻译和检查发生在硬件里**，程序绕不过去。

## 教学地图（选择动作，不按顺序过关）

### 值得学生推导的关键关口

**这中间是谁在做事？** 第一个关口。写两个框——"我记的第 3 层" / "它实际在哪"——**中间留空**，问学生："这中间是谁在做事？"如果学生说"操作系统"，追问一句："那**每一次**访存都要操作系统来做，行不行？"让他自己算出代价：每次读一个变量都先陷入内核（第 1 讲的用户态／内核态切换），**慢到不可接受**。于是结论只能落在硬件上。

**这张规则是谁写的？** 第二个关口，用来把"谁翻译"和"谁定规则"分开。把层位对照规则那张纸举起来——"这张是我写的，但每次查找不是我做的。"对应到系统：**操作系统设定规则**（这个进程能用哪段物理内存、边界在哪），**硬件执行翻译与检查**（每次访存时按寄存器里的值算和比）。**两者缺一不可**：只有硬件没有规则，它不知道该拦谁；只有规则没有硬件，每次访问都要软件介入。这一段是本讲最值得学生记住的对照，**值得让他自己把两个动词各说一遍**（"谁设" / "谁做"）。

**空位明明够，为什么放不下？** 第三个关口。把整份作业记录往层位格里塞，塞不进——因为**基址 + 界限（base and bounds）**要求整个地址空间**连续**放在物理内存里，必须按"整块"分配。地址空间里栈和堆之间那片**没人用的空闲区，也一并被占住了**。这就是**内部碎片（internal fragmentation）**：浪费发生在**分配单元的内部**。让学生把这个词和"空位够但放不下"对上号。

### 关键点之后的讲解主线

- **片段一 · 基址与界限各自解决什么**：每个进程有一对寄存器。**基址（base）**给出这段地址空间在物理内存里的起始位置，于是 `物理地址 = 虚拟地址 + base`——它解决的是**重定位**：同一段程序可以被放到物理内存的任何地方，程序自己不用改。**界限（limit）**给出这段空间的长度，硬件检查"虚拟地址是否越界"，越界就触发异常、交给操作系统处理——它解决的是**隔离**。（**约定差异**：有些材料把第二个寄存器写成"上界"而不是"长度"。两种写法表达的是同一件事，读别的材料时**先看清它用的是哪一种**。）
- **片段二 · 为什么翻译必须在硬件里**：翻译发生在**每一次访存**上，如果让操作系统软件来做，每次访存都要陷入内核，代价高到不可接受。所以硬件里有一块专门做这件事的部件，通常叫 **MMU（memory management unit，内存管理单元）**。操作系统的工作是在**创建进程、切换进程**时把 base 与 limit 的值写进硬件寄存器，并决定哪个进程用哪块物理内存。
- **片段三 · 分段怎么缓解内部碎片**：把地址空间按**逻辑段**切开——典型是代码、栈、堆三段，**每段各有一对 base / limit**。段内没用到的那部分**不必分配**，于是栈和堆之间那片空闲不再被白白占住，内部碎片缓解了。硬件怎么知道这次访问属于哪一段？**常见做法是用地址的高位来选段**（显式方式）；也有**隐式**方式——由这个地址是怎么产生的（栈指针、程序计数器、还是普通访存）来判断。**具体实现依架构，本讲不展开。**
- **片段四 · 那外部碎片呢**：分段解决了"段内浪费"，却带来新问题：**每个段仍要求连续**的物理内存，而**段的大小不一**。于是可能出现——空闲内存**总量够**，却**凑不出一块足够大的连续区域**放一个段。这叫**外部碎片（external fragmentation）**：浪费发生在**分配单元之间**。两条出路：**紧凑（compaction）**——把所有段挪到一起腾出大块，代价是要搬移数据，而且通常得先让用到这些内存的进程停下；或者用更聪明的空闲空间分配策略（首次适配／最佳适配／最差适配一类，**属 OSTEP ch17，不在本课主线，学生追问时再展开**）。
- **片段五 · 这一讲的收束**：基址界限把"重定位"和"隔离"两件事用两个寄存器办成了，代价是**要求连续**；分段把连续的要求缩小到"每段连续"，代价是**段之间的空隙凑不起来**。**这条"解决一个问题、带出一个新问题"的线索会一直延续到第 7 讲**——分页就是冲着外部碎片来的。

**角色内的讲法仅供示意**：她把层位对照规则那张纸举起来——"这张是我写的，但每次查找不是我做的。"这段说完可以停，不必马上讲页表。

### 真正值得再停下来的地方

- 学生把"硬件执行翻译"理解成"硬件很聪明地决定映射到哪"：纠正——硬件只是**按寄存器里的值做加法和比较**，它不判断、不选择。决定映射关系的是操作系统写进去的值。
- 学生以为操作系统在每次访存时都参与：明确它只在**创建／切换进程时设值**，之后每次访问用的是寄存器里的值。
- 学生把内部碎片与外部碎片混为一谈：给一句可检查的判据——**浪费在分配单元内部 → 内部碎片；空闲总量够但凑不出连续的一块 → 外部碎片**。
- 学生问"界限寄存器挡住的是地址，还是挡不住什么"：提醒它管的是**地址范围**；"用户态不能执行特权指令"（第 1 讲）管的是**操作类型**，两者是两套机制。
- 学生问"紧凑能不能随便做"：说明它要搬数据、要让相关进程停下，**代价很高**，所以现实里更愿意换一种内存管理方式（第 7 讲）。

### 检验理解的一个新情境

给一个具体设定：某进程的 `base = 0x4000`、`limit = 0x2000`。让学生判断：虚拟地址 `0x1000` 会被翻译成什么？虚拟地址 `0x3000` 会怎样？——能说出前者是 `0x5000`、后者越界触发异常（交给操作系统处理），即达到判据。（**数值是示例，用来检验规则，不是任何真实系统的配置。**）

## 本讲核心事实（知识锚 · 不许说错）

- **基址 + 界限（base and bounds）**：`物理地址 = 虚拟地址 + base`。**base 解决重定位**（程序可以被放到物理内存的任何位置）；**limit 解决隔离**（越界访问被拦下，交给操作系统处理）。第二个寄存器也有写成"上界"的约定，**与"长度"表达的是同一件事**。
- **硬件执行翻译与检查**（每次访存，通常在 MMU 里完成）；**操作系统设定规则**（创建／切换进程时写入 base 与 limit，并决定物理内存的分配）。翻译必须在硬件里，因为软件方案要求每次访存都陷入内核。
- **内部碎片**：基址界限要求整个地址空间**连续**，必须整块分配，于是栈与堆之间未被使用的空闲区也被占住——浪费在**分配单元内部**。
- **分段（segmentation）**：按逻辑段（代码／栈／堆）分别给一对 base / limit，段内未用到的部分不必分配 → 缓解内部碎片。但每段仍要求连续，段大小不一 → **外部碎片**（空闲总量够，却凑不出足够大的连续区域）。
- 应对外部碎片：**紧凑（compaction）**（要搬移数据、通常要暂停相关进程，代价高）或更复杂的空闲空间分配策略（**OSTEP ch17，不在本课主线**）。

## 类比的边界（可能误导时讲清）

**海洋隐喻在哪不成立？**
- "洋流执行搬运"：硬件**不查找、也不判断**，它只是按寄存器的值做加法与比较。**中间没有任何人在做决定**——这个隐喻最容易让人以为存在一个"负责翻译的人"。
- "层位规则那张纸是我写的"：规则**不是每次访问时被读的**——它在进程创建／切换时被写进硬件寄存器，之后每次访问用的是寄存器里的值。规则是"设定一次、执行很多次"。
- "空位明明够，为什么放不下"：这是**分配单元内部**的浪费，不是层位格物理上塞不下。隐喻里"整份作业记录"对应的其实是"整个地址空间需要一段连续的物理内存"——层位格的容量类比不了"连续性"这个要求。
