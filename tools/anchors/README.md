# tools/anchors —— 「文档只写锚点，行号集中进旁挂表」的机核

> 解决的是一个**已经真实发生过多次**的问题：取证/实现报告里**散写源码行号**，
> 源码一被改动，那些行号就**悄悄失准**——没有报错、没有提示，读的人照着改就改错地方。

---

## 〇 · 一句话

**把行号从正文里赶出去。** 正文只写锚点 `〔A01〕`，行号、「引的是哪个版本（sha256 前 16 位）」
全部集中进**每份文档一份的旁挂文件** `<文档名>.anchors.md`；本工具逐条核对，
**对不上就报 ERROR 并让退出码非 0**——从"静默失准"改成"响亮报错"。

---

## 一 · 一条命令（从仓库根执行）

```bash
# ① 机核一份文档（--list 逐条打出判定、解析到的文件、实际行号与命中行原文）
node tools/anchors/check-anchors.mjs clients/live2d-host/README.md --list

# ② 机核一个目录（递归找 .md；有旁挂锚点表的核，没有的 SKIP）
node tools/anchors/check-anchors.mjs clients/

# ③ 只量现状（不需要锚点表）：数出正文里散写了多少处行号
node tools/anchors/check-anchors.mjs . --scan

# ④ 工具自测（临时目录造最小仓库，逐类注入错误）
node tools/anchors/selftest.mjs
```

**退出码**：`0` ＝ 全部成立；`1` ＝ 有 ERROR；`2` ＝ 用法/目标错。可直接进 CI。

`--root <仓库根>` 可显式指定仓库根；**不传时默认＝本工具往上两级**（`tools/anchors` → 仓库根）。
锚点表里的相对路径按 **① 仓库根 → ② 文档所在目录 → ③ 从文档目录逐级向上到仓库根** 的顺序解析，命中即用。

---

## 二 · 旁挂锚点表格式（三张表，标题逐字）

文件名固定为 `<文档名>.anchors.md`，与文档同目录。`⏎` 表示换行（多行锚点用）；
片段内**不得含 `|` 或反引号**。行可写区间（`1553-1557`），机核只按**起始行**核对，区间用于人读。

```markdown
## 版本表

| V | 文件 | sha256 前 16 位 |
|---|---|---|
| V1 | clients/classroom-ui/lib/client.js | 6d387ce2f2ca4980 |

## 锚点表

| 锚点 | 说明 | 版本 | 行 | 片段 |
|---|---|---|---|---|
| A01 | applyPhase() 开头 | V1 | 2241 | `applyPhase(state) {` |

## 行号散写豁免

| 文件 | 行 | 理由 |
|---|---|---|
| some.md | 511 | 代码块里的示例，不是引用 |
```

第三张表**可选**（缺了不报错）。它的用途是登记"看着像行号、其实不是引用"的行；
登记的豁免若已无对应散写行号，会报 WARN 提醒删掉（防止豁免越积越多）。

## 三 · 判据（任一不成立即 ERROR）

| # | 判据 | 报的 kind |
|---|---|---|
| ① | 版本表指向的文件存在，且**当前 sha256 前 16 位 ＝ 表里记的值** | `version-drift` / `source-missing` |
| ② | 锚点片段在该文件里**恰好命中一次**（0 次＝失效；>1 次＝不唯一，定位不到行） | `snippet-not-unique` |
| ③ | 命中行号 ＝ 表里写的起始行号 | `line-drift` |
| ④ | 同一行号不得被两个锚点占用（一行一锚） | `line-collision` |
| ⑤ | 正文里每个 `〔Axx〕` 都能在锚点表里找到（**悬空引用**） | `dangling-ref` |
| ⑥ | 锚点表里每一行都至少被正文引用一次（**孤儿锚点**） | `orphan-anchor` |
| ⑦ | 锚点 id 不得重复 | `anchor-id-duplicate` |
| ⑧ | 版本表里每条版本至少被一条锚点用到（**孤儿版本**） | `orphan-version` |
| ⑨ | 正文里**不得散写行号**，除非在豁免表里登记 | `scattered-line-number` |

另有两条 FATAL 级：锚点表**缺 `## 版本表` / `## 锚点表` 标题**报 `missing-heading`——
**不允许"测了个空壳还全绿"**。

## 四 · 本目录文件

| 文件 | 用途 |
|---|---|
| `check-anchors.mjs` | 机核本体（纯 Node，无第三方依赖）。也可被 `import` 当库用：导出 `parseAnchorTable` / `collectRefs` / `scanScatteredLineNumbers` / `resolveSourcePath` / `checkDoc` 等纯函数 |
| `selftest.mjs` | 自测：临时目录造最小仓库，**逐类注入一种错误**并断言报出对应 kind，最后证明干净输入退出码 0 |
| `fix_anchors.py` | 漂移后的重算工具：只改**版本表哈希**与**锚点表行号**两个数字列，不动说明列、不动锚点 id、不删锚点。多行锚点用 `⏎` 表示换行，**与机核同一口径**（两侧必须一致，否则多行锚点会被静默跳过） |

**报红时的修法**：

```bash
# ① 看红在哪几条
node tools/anchors/check-anchors.mjs <文档> --list
# ② 重算哈希与行号（先 --dry 看要改什么，再写回）
python3 tools/anchors/fix_anchors.py <文档>.anchors.md --dry
python3 tools/anchors/fix_anchors.py <文档>.anchors.md
# ③ 若报 snippet-not-unique（片段 0 次或 >1 次）→ 必须人工处理：
#    那段代码已不在原位，要重新选一条能唯一定位的片段（--set A05=<新片段>）
```

🔴 **不允许为了让机核变绿而删锚点或放宽判据。** 报红是**如实反映**源码已漂，
修法是"重新取行号/重选片段"，不是"把这条判据拿掉"。

## 五 · 局限（诚实边界 —— 本工具**不做**什么）

1. **不自动改写行号。** 版本对不上就报 ERROR，让人重取行号——静默自愈＝下一次静默漂移。
2. **不判断"片段语义对不对"。** 只判断"这段文字在不在这一行"。**语义漂移机核看不见**
   （例如片段文字仍在原行、但函数体已被改）。这是本工具最大的盲区。
3. **不解析非 md 文档。** HTML/JSON/YAML 里散写的行号不在扫描范围（工具只读 `.md`）。
4. **不支持跨文档引用。** A 文档引用 B 文档的锚点在设计上就不支持（不是漏测）。
5. **版本哈希是「整文件」粒度。** 文件任何一处改动都会让**所有**引用它的锚点报 `version-drift`
   → 会有**假红**。这是刻意的取舍：**选"绝不漏"，不选"少打扰"**。
6. **锚点表自己也会漂。** 它记的是"取数那一刻"的哈希与行号；源文件一改它就过期——
   区别只在于**机核会当场报 ERROR**，而不是像散写行号那样悄悄失准。
7. **只把 CRLF 归一成 LF**，不处理裸 CR；未做目录级批量性能压测。

## 六 · 扫描范围

| 模式 | 范围 |
|---|---|
| `check-anchors.mjs <文档>` | 该文档正文 ＋ 它的旁挂锚点表 ＋ 锚点表指向的源文件（**只核锚点表里登记过的文件**，不遍历全仓） |
| `check-anchors.mjs <目录>` | 递归收集 `.md`（**跳过 `node_modules/` 与点开头目录**；跳过 `*.anchors.md` 自身）；有旁挂锚点表的核，没有的打印 `SKIP` 且**不计入** |
| `--scan` | 只数正文里的散写行号，**不做**悬空/孤儿/版本核对 → **`--scan` 绿 ≠ 文档已合格** |

**迁移策略是增量的**：只要求**新写/修改的文档**必须合规，存量文档分批迁，
不追求一次性全仓合规。
