## 本讲要回答的核心疑问

> **`fork` 之后，为什么会有两个"我"？**

**先把题目讲清楚**："两个我"指的是**两个进程**——它们执行同一段程序，各自持有自己的执行状态。不是在说"一个进程分裂出两条线程"，也不是"同一份稿子被摊成两半"。学生若问"那它们共享内存吗"，先给出事实：fork 之后两个进程在**语义上各有独立的地址空间副本**（实现上常用写时复制延迟真正的复制，见下文片段一），再继续。

## 教学地图（选择动作，不按顺序过关）

### 值得学生推导的关键关口

**为什么父子都从 `fork` 那一行往下走？** 这是本讲第一个关口。学生若说出"fork 把当前的执行状态复制了一份"，直接确认并补上：被复制的内容包含程序计数器和寄存器，所以子进程的"下一条指令"与父进程是同一处；两者的区别体现在**返回值**上——父进程拿到子进程的 PID，子进程拿到 0，失败时是 −1。不要让学生猜"谁先跑"：两者的执行顺序不确定，这是可以直接给出的事实。

**`exec` 为什么不是"再创建一个进程"？** 第二个关口。可以问："要跑另一个程序，为什么不是再 fork 一次，而是把当前这个换掉？"这里**不要求**学生答出"因为要保留 PID 和已经设置好的环境"——那是设计事实，教师直接讲。**学生若已说出"fork 是复制、exec 是替换"，确认命名后立刻推进**，不要求他背 exec 家族有哪几个变体。

### 关键点之后的讲解主线

- **片段一 · 复制了什么**：`fork` 之后，两个进程各有自己的一套地址空间（代码、数据、堆、栈）与自己的寄存器、程序计数器。它们不是同一个进程的两个视角。**实现层面**，现代系统常用**写时复制（copy-on-write）**：先让两边的页表指向同一批物理页并标记只读，谁写谁触发一次复制。这个细节不是本讲必须推出来的；学生问到时讲，并说明它只是实现优化，**不改变 fork 的语义**（具体实现依系统，待核）。
- **片段二 · `exec` 换掉的是什么**：`exec` 用新程序的代码与数据替换当前进程的地址空间，重建堆与栈，从新程序的入口开始执行。**成功时 `exec` 不返回**——因为"返回"要执行的那段代码已经被换掉了；失败时返回 −1，原程序继续跑。进程的 PID 不变：**换了内容，保留了编号**。
- **片段三 · `wait` 与退出状态**：父进程用 `wait`（或 `waitpid`）等待子进程结束，并取回它的退出状态。子进程已经结束、父进程还没取走状态时，内核仍要保留一小份记录——这个状态下的进程叫**僵尸进程（zombie）**。僵尸不是 bug，而是"父进程还没来取件"的必然结果；父进程取走后，记录才被释放。**具体保留哪些字段依系统（待核）**，本讲只需知道"至少要留得下退出状态"。
- **片段四 · 那个窗口为什么重要**：`fork` 与 `exec` 之间的窗口，是**子进程还能被改动、而父进程不受影响**的时刻。shell 的重定向就住在这个窗口里：`ls > out.txt` 要先把子进程的标准输出接到文件上，**再** exec。必须在 exec 之前做，因为 exec 之后当前映像已经不存在，做设置的代码也就没了。管道（`ls | wc`）用的是同一个窗口——只是接的是管道的写端。

**角色内的讲法仅供示意**：她把两份稿纸并排，其中一份"换掉内容、保留编号"，问"编号没变，东西变了，这算什么？"——答案是 exec。这段说完可以停，不必马上讲文件描述符，也不必问"那父进程怎么知道子进程结束了"。

### 真正值得再停下来的地方

- 学生把 `fork` 理解成"从某一行开始分叉出两条线程"：区分进程与线程——本讲的两个进程各有自己的地址空间副本，线程共享地址空间（第 9 讲细讲）。
- 学生以为子进程一定先跑、或父进程一定先跑：直接说执行顺序不确定，取决于调度器。
- 学生把"子进程结束"等同于"进程完全消失"：僵尸进程就是反例。若他接着问"那父进程先结束呢"，说明子进程会被别的进程接管（传统上是 PID 1；现代系统还有 subreaper 之类的机制，**依系统，待核**），这与僵尸是两种不同情形。
- 学生以为 `exec` 会创建新进程：明确 exec 不创建进程，它替换当前进程的程序映像。

### 检验理解的一个新情境

让学生解释 `ls > out.txt` 这条命令在 shell 里大概发生了什么：fork 出子进程 → 在子进程里把标准输出接到文件 → exec `ls`。可以只要求说出"重定向必须在 exec 之前完成"，以及为什么。若学生能指出"如果在 exec 之后再做，就没有可执行的代码来做这件事了"，即达到判据。

## 本讲核心事实（知识锚 · 不许说错）

- `fork()` 创建一个**新进程**，它是调用进程（近乎）的副本；父子都从 fork 的返回处继续，区别在返回值：父得子进程 PID，子得 0，失败得 −1。
- `fork` 是**复制**（得到新进程、新 PID），`exec` 是**替换**（不新建进程，换掉当前进程的代码与数据）。两者是两件事，可以单独用，也可以接在一起用。
- `exec` 成功**不返回**；失败返回 −1。
- `wait` / `waitpid` 让父进程等待子进程结束并取回**退出状态**；父进程未取走前，子进程处于**僵尸（zombie）**状态，内核保留最小记录。
- `fork` 与 `exec` 之间的窗口，允许在**只影响子进程**的前提下改动它的执行环境（文件描述符重定向、管道、权限等）——这正是 shell 实现重定向与管道的位置。

## 类比的边界（可能误导时讲清）

**编辑部隐喻在哪不成立？**
- 人抄一份稿子要花时间、可能抄错；`fork` 在**语义上**给出精确的副本。实现上用写时复制时，"复制"甚至不是立刻发生的——**不能用"抄写"的动作耗时去推断 fork 的开销**。
- 稿纸是静态的，进程有执行状态。两份稿纸并排放着，表示不出"两个进程都在从同一行往下执行"。
- "编号不变、内容变了"这个演示在 exec 上恰好成立，但**PID 不变不等于进程身份的全部**——地址空间、打开的文件、堆栈都已经换了。
