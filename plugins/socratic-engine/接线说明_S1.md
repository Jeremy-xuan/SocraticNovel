## 0. 一句话

新增 `lib/postclass.mjs`，监听宿主的 **`agent/turn-stopping`**（turn 自然停止边界上的 awaited 通知），把该回合的**确定性事实**（回合号／时间／相位／学生原话／工具名与成败）**原子追加**到教室 `runtime/session_log.md`。
`index.mjs` 需要新增 **1–2 个 import ＋ 1 段调用**。

**本版只写 `session_log.md` 一个文件**；其余 7 个 runtime 文件（diary / learner_profile / mistake_log / progress / review_queue / session_archive / wechat_group）留 `updaters` 接口，**不实现**。

## 2. `index.mjs` 要新增的调用（逐字）

### 方案 A（推荐，只接 S1）：在 `const phase = createPhaseStore(...)` 之后插入

**原行（第 54 行，逐字）**：

```js
  const phase = createPhaseStore(config.defaultPhase ?? 'boot')
```

**改为（原行 → 新行）**：

```js
  const phase = createPhaseStore(config.defaultPhase ?? 'boot')

  // ---- 1.5) 课后自动更新教室 runtime/（B2「它记得你」宿主侧） ----
  registerPostClass(ctx, {
    runtimeDir: config.runtimeDir ?? join(config.classroomDir, 'runtime'),
    getPhase: () => phase.phase,
    log,
  })
```

> 位置必须在「`config.classroomDir` 硬门槛」之后（现状第 37–52 行的早退分支），否则 `config.classroomDir` 可能为空。

### 方案 B（与 S2 的教室自动发现协同）

S2 的 `registerDiscovery` 通过 `onDiscovered` 回调刷新一个 `current = { dir, manifest }` 快照，**教室目录可能在同一进程内变化**。因此把 `runtimeDir` 传成**取值函数**（S1 已支持，按回合求值）：

```js
  registerPostClass(ctx, {
    runtimeDir: () => (current ? join(current.dir, 'runtime') : null),
    getPhase: () => phase.phase,
    log,
  })
```

> 函数返回 `null` / 空串时的行为＝**不写＋记录原因**（日志：`runtimeDir 缺省（教室尚未确定），跳过课后更新`），**不抛崩会话**。

### 不要改的行

- `apply` **不必**改成 `async`（S1 只注册监听器，不做加载期 IO）。
- `inject` **不必**加新服务名（只用 `ctx.on`）。
- `cordis.patch.yml`（插件自带那份）**不必**改（不新增 config 声明，配置由 profile 的 patch 层给）。

## 3. 需要传入的配置项

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `runtimeDir` | `string \| (() => string \| null)` | `join(config.classroomDir, 'runtime')`（方案 A 里显式给出） | 教室 `runtime/` 目录。**字符串或取值函数**；缺省/求值为空 → 不写＋记日志 |
| `getPhase` | `() => string \| null` | 无（省略相位段） | 取当前相位，用于记录（骨架里是 `() => phase.phase`） |
| `enabled` | `boolean` | `true` | `false` ＝ 不注册监听器 |
| `updaters` | `object[]` | `[SESSION_LOG_UPDATER]` | 更新器清单，`{file, render(facts, env)}`。**其余 7 个 runtime 文件就挂在这里** |
| `mode` | `number` | `0o600` | 写入权限位。教室现有 runtime 文件即 `-rw-------` |
| `now` / `formatTime` / `atomicWrite` / `log` | — | — | 可测性/可观测性注入；生产接线**只需 `runtimeDir` ＋ `getPhase` ＋ `log`** |

**插件配置写在 profile 的 patch 层**（例：`$DSH_HOME/profiles/socratic-headless/cordis.patch.yml`）：

```yaml
- id: socratic-engine
  name: socratic-engine
  config:
    classroomDir: /tmp/snx-postclass-probe/classroom
    # runtimeDir: /tmp/snx-postclass-probe/classroom/runtime   # 可选；缺省＝classroomDir/runtime
```

## 4. 写入格式（与真实教室 `runtime/session_log.md` 一致）

追加一条的**确切形态**（`<!-- … -->` 是幂等去重标记，渲染后不可见）：

```
<!-- socratic-engine:session=<sessionId> turn=<turn> -->
### 第 <turn> 回合 · <YYYY-MM-DD HH:mm> · 相位 <phase>
- 学生：<学生原话（多行折叠为单行，逐字不改写）>
- 工具：<工具名>（成功|失败|未完成） ／ <工具名>（…）
```

- 首条追加时**移除教室自带的 `（尚无。…）` 占位行**（该行原文即「第 1 讲结束后在此追加第一条」）。
- **无学生消息也无工具调用的回合不写**（「空回合」）。
- 工具**只有 `tool/call` 没有 `tool/result`** 时记 **`未完成`**（不得谎报成功）。

## 6. 待确认清单（S1）

1. **`runtimeDir` 的默认来源**：本接线说明取 `join(config.classroomDir, 'runtime')`。
   - 问题：S2 的教室自动发现落地后，教室目录可能**在一个进程内变化**；方案 B 已支持函数形式，但**默认值该由谁算**？
   - 倾向：**由 index.mjs 算**（`postclass.mjs` 保持「只认显式路径」，不内建教室发现逻辑，与「与教室自动发现解耦」的任务边界一致）。
2. **目标文件缺失时是否该新建**：当前实现＝**不写＋记日志**（理由：追加格式的权威来自教室现有文件，凭空造头部＝发明格式）。
   - 选项：A 保持现状（倾向）；B 缺失时用内置最小头部新建。
3. **写入权限位**：当前沿用 `0o600`（与教室现有文件一致）。
   - 待确认：教室文件是否要可分享/被其它工具读（→ `0o644`）？
4. **`session_log.md` 的压缩规则未实现**：文件头部写明「超过 10 条时把最早 5 条压成一段移入 `session_archive.md`」。
   - 本版**不做**——压缩涉及「概括教学事实」，落在「不许生成式改写」红线边缘。**是否允许用确定性规则（如纯搬运＋标号）做压缩，需拍板。**
5. **是否需要 LLM 生成式摘要**：本版**明确不做**（项目红线）。若日后要做，必须与「确定性事实追加」分离成两个 updater，并在文件里标注生成物来源。
6. **其余 7 个 runtime 文件**：接口已留（`updaters: [{file, render}]`），**未实现**。
   - 已知难点：`mistake_log.md`（错误类型）、`review_queue.md`（复习队列）、`learner_profile.md`（学习画像）都需要**判断**，不是纯事实搬运 → 需要先拍板「哪些字段允许确定性提取、哪些必须人工/LLM 介入」。
7. **多教室并发写同一 `runtime/`**：`withFileLock`（`<file>.lock` 兄弟文件）已用于跨进程串行化读-改-写。
   - 待确认：是否需要**清理孤儿锁**的运维动作？（宿主原文：孤儿锁不自动删除，属 operator action。）
8. **前向兼容**：master 已出现 `packages/session/session-turn-outline`（逐回合提纲）。升级到 master 时应评估**改用该包**而非继续自己过滤 `snapshotEvents()`。
