## 2. `index.mjs` 要新增的调用（逐字）

### 2.1 把 `apply` 改成 `async`

第 27 行，由

```js
export function apply(ctx, /** @type {{enabled?: boolean, classroomDir?: string, defaultPhase?: string}} */ config = {}) {
```

改为

```js
export async function apply(ctx, /** @type {{enabled?: boolean, classroomDir?: string, defaultPhase?: string, classroomSearchDepth?: number}} */ config = {}) {
```

> 理由：发现是异步的（要探测文件系统）。cordis 支持 `apply` 返回 Promise，加载器会等它。

### 2.2 替换第 37–52 行的「硬门槛 + 同步加载」

**现状（第 37–52 行，逐字）**：

```js
  // ---- 1) manifest 加载 ----
  if (!config.classroomDir) {
    log(`未配置 classroomDir，插件空转（skill 模式兜底生效中）`)
    return
  }
  let manifest
  try {
    manifest = loadManifest(config.classroomDir)
  } catch (cause) {
    if (cause instanceof ManifestError) {
      log(`manifest 校验失败，插件空转：${cause.message}`)
      return
    }
    throw cause
  }
  log(`教室已装载：${manifest.classroom.id}（${manifest.blocks.length} 块）`)
```

**替换为（逐字，可直接粘贴）**：

```js
  // ---- 1) manifest 加载：显式指定优先，其次工作区自动发现 ----
  // 发现结果由 lib/discovery.mjs 给出；多个候选时不静默选一个（带排序键与理由）。
  /** @type {{dir: string, manifest: object} | null} */
  let current = null
  const loadInto = (dir) => {
    const loaded = loadManifest(dir)
    current = { dir, manifest: loaded }
    log(`教室已装载：${loaded.classroom.id}（${loaded.blocks.length} 块，来自 ${dir}）`)
    return loaded
  }

  const discovery = registerDiscovery(ctx, {
    defineTool,                                   // 宿主已 import 的 defineTool
    initialDir: config.classroomDir,              // 有配置就作为最高优先级的「显式指定」
    maxDepth: config.classroomSearchDepth,        // 缺省 3（见 §3）
    onDiscovered: async (result) => {
      if (result.status === 'none') {
        log(`未发现任何教室：${result.reason}`)
        return
      }
      try {
        loadInto(result.selected.path)
      } catch (cause) {
        if (cause instanceof ManifestError) {
          log(`发现的教室 manifest 校验失败：${cause.message}（路径 ${result.selected.path}）`)
          return
        }
        throw cause
      }
    },
  })

  const initial = await discovery.run()
  if (initial.status === 'none') {
    log(`0 候选：${initial.reason}；插件空转（skill 模式兜底生效中）`)
    return
  }
  if (initial.status === 'ambiguous') {
    log(`🔴 发现 ${initial.candidates.length} 个候选，已选 ${initial.selected.path}；理由：${initial.reason}`)
    log(`其余候选（未被选用，可用 config.classroomDir 显式切换）：${initial.candidates.filter((c) => !c.selected).map((c) => c.path).join(' | ')}`)
  }
  if (current === null) {
    log('发现的候选 manifest 校验失败，插件空转')
    return
  }
```

### 2.3 把后续对 `manifest` 的引用改成 `current.manifest`

`registerDiscovery` 的回调会在**每次**发现后刷新 `current`，因此所有后续读取都改为「当下快照」：

- 第 54 行 `const phase = createPhaseStore(config.defaultPhase ?? 'boot')` —— **不变**。
- 第 56–63 行的系统段注册循环：把 `for (const block of manifest.blocks)` 改为
  ```js
  for (const block of current.manifest.blocks) {
  ```
- 第 68 行起的 `agent/pre-step` 注入：把
  ```js
  const due = planTurnInjections(manifest.blocks, phase, { classroom: manifest.classroom.id })
  ```
  改为
  ```js
  const blocks = current.manifest.blocks
  const due = planTurnInjections(blocks, phase, { classroom: current.manifest.classroom.id })
  ```
  （注入回调本身**不变**。）
- 第 84 行起 `classroom_status` 的 `execute`：把
  ```js
        return {
          classroom: manifest.classroom.id,
  ```
  改为
  ```js
        return {
          classroom: current.manifest.classroom.id,
  ```

> ⚠️ **「系统段注册」是一次性的**：`ctx.systemPrompt.section()` 在启动时按当时装载的教室注册。
> 若发现结果在**运行中**变化（用户新增/删除了 `classroom.yaml`），**系统段不会自动重注册**；
> 自动重注册需要 `ctx.systemPrompt` 的注销/重建语义（本骨架未取证）。当前口径：
> **启动时定案**；运行中用 `classroom_list` 只能**看见**变化，**不能**切换注入内容。
> 若将来要做「运行时切教室」，必须先取证 `systemPrompt.section()` 能否注销。

```yaml

  name: socratic-engine
  config:
    enabled: true
    classroomDir: /abs/path/to/classroom   # 可选（语义变化：从「必填」变为「最高优先级的显式指定」）
```

| 配置项 | 类型 | 缺省 | 语义 |
|---|---|---|---|

| `classroomDir` | string | 无 | 🔴 **语义变化**：由「必填，缺省即空转」改为「**最高优先级的显式指定**」。给出时它排在所有自动发现之前；给出但无效（不存在/缺 manifest/是符号链接）时**记入 `skipped` 并回退到自动发现**，不再让插件整体空转 |
| `classroomSearchDepth` | integer | `3` | 工作区根下 deep 扫描的深度上限（避免扫进 `node_modules`） |

> 🔴 **不要**把新配置写进 `$DSH_HOME/settings.yaml`。取证 B2 已证：`settings.yaml` 是 **legacy**，

## 4. 🔴 `classroom_status` 该怎么改（由集成代理执行；S2 未动）

**目标**：让 `classroom_status` 从「只报相位/回合」升级为「报相位/回合 **＋ 当前教室与发现状态**」，同时**不改变它的既有行为**（相位/回合的语义、工具名、只读性质全部保留）。

**🔴 硬约束（已取证）**：`ctx.tools.register()` **同名重复注册会抛错**——
`tmp/dsh-installed/dsh-tools/lib/index.js:2538` 逐字：

```js
		this.tools = new NamedEntries((name) => /* @__PURE__ */ new Error(scope === void 0 ? `tool "${name}" is already registered (for a per-agent variant, register through that agent's \`agent.ctx\` instead)` : `tool "${name}" is already registered in this scope`));
```

→ **因此绝不能在 `onDiscovered` 里重新注册 `classroom_status`。**
正确做法：**注册一次，`execute` 里读可变快照 `current`**（§2.3 已把 `execute` 改成读 `current.manifest.classroom.id`）。

**建议的 `classroom_status` 增强（保持向后兼容：只增字段，不改旧字段语义）**：

```js
        output: {
          schema: {
            type: 'object',
            additionalProperties: false,
            properties: {
              classroom: { type: 'string', required: true },
              phase: { type: 'string', required: true },
              turn: { type: 'integer', required: true },
              classroomDir: { type: 'string', required: true },   // 新增：当前教室目录
              discovered: { type: 'integer', required: true },    // 新增：本次发现候选数
              selectedBy: { type: 'string', required: true },     // 新增：'explicit' | 'convention' | 'deep' | 'none'
              ambiguity: { type: 'string', required: true },      // 新增：歧义说明（无歧义时空串）
            },
          },
          render: (_args, value) => [
            { type: 'text', text: `教室 ${value.classroom}｜相位 ${value.phase}｜第 ${value.turn} 回合｜候选 ${value.discovered} 个（来源 ${value.selectedBy}）` },
          ],
        },
        execute: async () => {
          const result = discovery.last()
          const selected = result?.selected ?? null
          return {
            classroom: current.manifest.classroom.id,
            phase: phase.phase,
            turn: phase.turnCount,
            classroomDir: current.dir,
            discovered: result?.candidates.length ?? 0,
            selectedBy: selected?.source ?? 'none',
            ambiguity: result !== null && result.status === 'ambiguous' ? result.reason : '',
          }
        },
```

> 🔴 `output.schema` 用了 `additionalProperties: false` → **`execute` 的返回对象必须与 properties 完全一致，不能多字段**（多字段会被 schema 校验拒掉）。上面已对齐。

## 5. 发现规则与排序键（实现口径，供 review 用）

**优先级（发现阶段）**

| 序 | 来源 `source` | 规则 |
|---|---|---|
| ① | `explicit` | `config.classroomDir` 指定的目录，或该目录下的 `classroom.yaml` 本身 |
| ② | `convention` | `<workspaceRoot>/classrooms/*/classroom.yaml` |
| ③ | `deep` | `<workspaceRoot>` 下任意深度（`≤ classroomSearchDepth`，缺省 3）的 `classroom.yaml` |

**排序键（选中阶段，`compareCandidates` 纯函数）**

1. `source` 优先级：`explicit`(0) > `convention`(1) > `deep`(2)
2. 距工作区根**更浅**者优先（`depth` 小者优先）
3. 绝对路径**字典序**（`localeCompare(..., 'en')`，固定 locale 以免随环境变化）

**歧义处理**：多个候选时**不静默选一个**。返回 `status: 'ambiguous'` ＋ `reason`（含排序键、来源、深度、路径）
＋ `candidates[]`（每个带 `selected` 布尔）＋ 未选中的完整清单。工具返回的 `summary` 文本明说
「发现 N 个 / 已选 X / 理由 Y / 其余未选中（M 个）」，并把未选中路径逐条列出，**模型看得见全部候选**。

**健壮性**

| 情形 | 行为 |
|---|---|
| 目录里没有 `classroom.yaml` | 不算教室（`explicit` 会记入 `skipped`；`convention` 下的缺 manifest 子目录不记，那是常态噪音） |
| 符号链接（目录项 / 显式路径 / `classroom.yaml` 本身） | **一律拒绝、不跟随**，记入 `skipped`。依据取证 C3：`resolve()` 会 realpath 跟随，故必须用 `lstat()` 判 `type === 'symlink'` |
| 无读权限目录 | 跳过并记入 `skipped`（`reason` 含「目录不可读」），**不中断扫描**。🔴 深度上限那一层的不可读目录也会被记录（见 §7 的实现坑） |
| 0 候选 | 返回 `status: 'none'` ＋ 明确 `reason`，**不抛错** |
| 工作区根不存在 | 返回 `status: 'none'` ＋ `problems[]` 一条，**不抛错** |

## 7. 实现坑（S2 实测踩到，务必知情）

**🔴 「不可读目录」只在**下探**时才检查会静默漏记。**
初版实现把 `listDir()` 的 try/catch 只放在递归进入目录时，结果：`maxDepth = 1` 时，
工作区根**下一层**的 `mode 000` 目录从未被进入 → `skipped` 为空、用户完全看不到它不可读。
实测复现（`skipped []` 而目录确实 EACCES）后改为：**对每个候选目录先做一次 `classroom.yaml` 的 `lstat` 探测**
（`probeRegularFile` 三态返回 `'file' | 'missing' | 'error'`），`'error'` 即判为不可读并记录。
单测 `不可读目录被跳过并记录，不中断扫描` 锁死该行为。
