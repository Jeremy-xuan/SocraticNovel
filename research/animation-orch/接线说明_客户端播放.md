## 1. 引擎已经给出的东西（**跨端契约**）

动画就绪（或被闸门拦下 / 渲染失败）之后，引擎会在**下一回合开头**注入一条消息，
`source` 里带下面这组机器可读字段（定义在 `lib/animationstore.mjs` 的 `animationNoticeSource`）：

```jsonc
{
  "kind":   "socratic-engine",          // 与教室块注入同一个 kind（客户端已在渲染这类来源）
  "form":   "animation-notice",         // ← 靠它把"动画通报"与普通教室块区分开
  "block":  "animation-notice:L01-T01-20260924-130755",
  "taskId": "L01-T01-20260924-130755",
  "state":  "ready",                    // ready | blocked | failed
  "artifact": "animations/L01-T01-20260924-130755/L01-T01-20260924-130755.mp4", // **教室相对**路径
  "absPath": "/…/classroom/runtime/animations/L01-T01-20260924-130755/L01-T01-20260924-130755.mp4",
  "title": "时钟中断：程序怎样被换下来、又怎样接回去",
  "lesson": 1,
  "turn": 1,
  "durationSec": 15.733008
}
```

🔴 **不要解析消息正文里的中文路径**。正文是给老师模型看的，措辞会改；上表字段才是契约。

## 2. 客户端该读哪个文件

**默认情形（本项目的正常部署）：学生会话的 cwd 就是教室目录**（教室自己的 `AGENTS.md`
靠这条被宿主注入 —— 见 `实现报告_DRAW3` §4.6 的取证）。
→ 此时 `source.artifact` 就是**工作区相对路径**，直接走现成通道：

```js
// packages/api/workspace-files/src/index.ts:227 —— read(sessionId, path)，path 可为工作区相对路径
const r = await ctx.remote.workspaceFiles.read(sessionId, `runtime/${source.artifact}`)
// r 是 RemoteResult<T>；拿到字节后交给 <video> 播
```

⚠️ **若教室目录不在会话工作区**（把 `config.classroomDir` 指到工作区外时）：
`workspaceFiles.read` 只认工作区相对路径 → 这条路走不通，需要另开一个读取通道
（或把教室的 `runtime/animations/` 同步进工作区）。
🔴 **这一条我没有取证**（本轮实测里教室副本在 `/tmp`，不在工作区），
**标【待确认】**，不要当成"已经能用"。

## 3. 怎么在消息流里播

1. **挂在哪**：把 `source.form === 'animation-notice'` 的注入行**当成普通注入行渲染**
   （与教室块同一通道），但按 `state` 分支：
   - `state === 'ready'` → 在该行位置渲染一个内嵌播放器（`<video controls src=…>`），
     标题用 `source.title`，时长可用 `source.durationSec`；
   - `state === 'blocked'` / `'failed'` → **什么都不播**，只显示一行灰色说明
     （"这段动画没过质量闸门 / 没渲出来，老师会改用板书图讲这一步"）。
     🔴 被闸门判 BLOCK 的片子**渲染是成功的**，文件也在盘上——**只有 `state` 能区分它能不能播**，
     不能靠"文件存在"来决定播不播（这正是闸门存在的意义）。
2. **播的时机**：引擎把这条注入在**下一回合开头**，所以客户端"按消息流顺序渲染"就自动是
   正确时机（学生问下一句的那一刻，动画出现在他眼前）。**不需要**客户端自己做定时或轮询。
3. **一条通报 = 一个任务**：引擎保证一条消息只带一个 `taskId`，
   所以客户端不需要处理"一条消息里多个动画"的情况。
4. **幂等**：引擎侧有 `announcedAt` 门，同一任务只通报一次；
   客户端可以按 `source.taskId` 去重（刷新/重放会话日志时用得上）。

---

## 4. 老师那边同时发生了什么（客户端不必管，但要知道，免得误判）

- 老师拿到的是同一件事的**中文正文**（"你上一轮的动画已就绪，现在就放"），
  它会据此在讲解里把动画"放出来"——**"放"这个动作在客户端就是上面第 3 条**。
- 老师还可以随时调 `classroom_animation_status` 主动查（只读工具），
  返回里带同样的 `taskId / state / 路径`。这条是兜底：即使通报因为回合边界错过了，
  老师也能自己发现（**实测发生过一次**，见报告 §4.3）。

## 5. 引擎侧的落点（给客户端联调时对文件用）

```
<教室目录>/runtime/animations/
├── index.md                      ← 人读索引（一行一个任务：日期/讲次/回合/状态/标题/产物）
└── <taskId>/
    ├── scene.py                  ← 模型交来的脚本原文（逐字）
    ├── task.json                 ← 宿主写：讲次/回合/标题/announcedAt（通报幂等门）
    ├── status.json               ← 渲染器写：**状态真源**（state/renderMs/bytes/durationSec/reason/gate）
    ├── render.log                ← manim 自己的输出
    ├── runner.log                ← 渲染器进程自己的输出（崩溃原因在这里）
    ├── <taskId>.mp4              ← 产物（要播的就是它）
    └── gate/                     ← 过闸门时的产出（verdict.json / verdict.md / contact_sheet.png / frames/）
```

`taskId` 形如 `L01-T01-20260924-130755`（讲次-回合-时间戳），可直接排序。
