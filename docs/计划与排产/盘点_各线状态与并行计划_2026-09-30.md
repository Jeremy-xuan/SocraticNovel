## 二 · 为什么之前没并行 —— 三条真实约束（不是借口，是排期事实）

1. **DSH 定制线的验证是"独占资源"**：同一个工作区**只能有一个活动写句柄**，两个 `dsh web` 实例抢会话会报 `SessionAlreadyOwnedError`。
   → 之前每轮**只能有一个真会话在跑**。**但这种独占只对"同一 profile／同一工作区"成立**——**开多个隔离 profile ＋ 不同端口就能并行**（本轮已证明：`avalon` profile 与真 web profile 互不干扰）。
2. **前端样稿在等你的审美裁定**：上一轮你连续否掉两版（"非常不好看！推倒重来"），
   在**视觉方向未定**时并行做实现＝**赌错就全废**。所以那几轮是"先定稿再动手"，不是"该并行没并行"。
3. **少数工作在等用户拍板**（PR 推不推、白板落点、UCAS 身份…）。**这类不能靠并行解决，只能等你**。

**结论**：约束 ① 已经**可以绕开**（多隔离 profile），所以从本轮起确实应该并行推进；约束 ②③ 是真实存在的，不是懒。
