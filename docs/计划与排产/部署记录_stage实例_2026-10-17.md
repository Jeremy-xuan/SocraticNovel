## 二 · 🔴 一个月卡点解决了：新实例怎么「开出一堂课」

上次（09-30 → 10-01）卡在「全新实例没有工作区、没有会话 → 舞台拿不到会话钩子 → 既读不到也发不出」，试过点点按钮、手写 `workspace.json`、点 Choose workspace 都没成。

**这次成了，做法是把 `storages/workspace.json` 按正确形状写一份**：

```json
{
  "unit": { "name": "workspace", "version": 2 },
  "global": { "initialized": true, "workspaceIds": ["<uuid>"], "archivedSessionIds": [] },
  "tables": { "workspaces": { "<uuid>": {
      "path": "/srv/dsh-users/stage/workspace",
      "title": "教室舞台测试区",
      "sessionIds": [],
      "createdAt": "...", "updatedAt": "..."
  }}}
}
```

写完后重启实例，页面直接就是可用状态：

- 舞台根 `#stage-warm-root` 出现（**5 秒内**，不是之前以为的「卡住」）
- `舞台没拿到会话数据` 这句消失
- 左上角显示「小 鞠 知 花 · 在场」「教室舞台测试区」，正文区显示「（这段会话还没有内容）」，输入框可用
- 发一句话 → **真的进了会话**，纸带上出现「你：老师好，我想学操作系统第一讲。」，会话目录也生成了 `session-*.v3.jsonl.zstd`

📌 上次失败的原因（现在能说清了）：`workspace.json` 的 `unit` 之外还必须有 `tables.workspaces` 里带 `path` 的真实记录，只写 `global.workspaceIds` 不够。

修好 patch 后，暴露出**三个 0.1.5 独有的契约要求**，逐个补：

| # | 报错 | 补了什么 |
|---|---|---|
| 1 | `service "whiteboardStore" has been registered` | `lib/index.js` 加幂等守卫（已存在就跳过；只吞「已注册」这一种错误，其他照抛） |

`_anchor.md` 的选项纪律加了却不生效，顺着查下去发现更严重的事：

`loadManifest` 直接抛错 ——

```
classroom.yaml: prep（第 101 行）声明了备课清单，但本教室没有启用教学动画
（顶层缺 animation: {enabled: true}）—— 这份清单永远不会被用到，预热也起不来。
```

**因果链**：上一轮我为了绕开「服务器没有 Manim」把 `animation.enabled` 改成 `false`，但**没删 `prep:` 段**。引擎的 manifest 校验发现「声明了备课清单却没启用动画」→ 抛 `ManifestError` → **整份教室内容（47 个块、教材、纪律、讲次门）一个都没注入**。

所以之前几轮老师只是在**按 persona 自由发挥**，并不是在读教室。这也解释了为什么纪律写了没反应、老师不按教学法走。

**处置**：把 `prep:` 整段（115 行）移除（备份 `classroom.yaml.bak-before-prep-off`）。之后 `loadManifest` 返回 **47 个块**，选项渠道纪律在 `anchor.lesson_ban` 块里命中。

⚠️ **教训**：关掉某个能力时，必须同时清掉**依赖它的声明**，否则是「静默降级＋硬失败」二选一。而且引擎的这类失败在启动日志里不一定显眼——我是用独立脚本直调 `loadManifest` 才看见的。

## 二 · 🔴 脚本第一版把实例搞崩了两次，都是「覆盖式部署」

| # | 现象 | 根因 |
|---|---|---|
| 1 | 覆盖 classroom-ui 后实例崩在 typert 校验 | 脚本的 `UI_PKG` 指向**工作区**那份（`DSH定制/code/clients/classroom-ui`），而 zod 修复在**产品仓库**那份。工作区的是旧版 → 覆盖回去等于回滚了修复 |
| 2 | 覆盖教室包后实例崩在 `ManifestError: 声明了 animation 段但渲染环境不可用` | 脚本把仓库原版教室包整个 scp 上去，**把服务器上按环境裁剪过的版本（animation=false + 无 prep）冲掉了** |

→ **纪律**：**部署脚本不能假设"源＝线上"**。凡是线上被按环境改过的东西（教室包、settings、bundles），要么脚本自带裁剪/合并步骤，要么明确标注"此目录以线上为准，脚本不覆盖"。
第二版修法：传完教室包立刻跑 `tailor-classroom-for-host.sh`；`UI_PKG` 默认指向产品仓库并注明理由。

## 三 · SSH 限流的正确应对

服务器 sshd 对短时间多次连接会直接 `Connection closed by ... port 20084`。脚本最初每步一个新连接，跑到第 5 步就断。

处理：`R()`（ssh）与 `SC()`（scp）各带**3 次重试、间隔 15 秒**，并打印每次被拒的原因。改完整个流程一次跑通。
→ 纪律：**限流是真实约束，用重试应对，不要靠"换种写法绕过"**。

# 附 · 2026-10-19 第七轮（goal 轮 3–4）：白板面板打通，goal 四项收齐

## 一 · 🔴 白板面板的真因：guide 条目缺 `kind`

面板注册**一直成功**，但用户永远打不开。原因在 0.1.5 的 `GuideBody.js`：

```js
"data-sidebar-right-guide-entry": entry.kind,
onPick: (entry) => tab.actions.openTab(entry.kind, { replaceTab: true })
```

它读的是 `entry.kind`，而我们的 guide 条目只写了 `id: "classroom"` →
`data-sidebar-right-guide-entry` 拿到 `undefined`、`openTab(undefined)` 直接失败。
**注册不报错、日志看不出来**，表现为「面板永远打不开」。

修：guide 条目同时给 `id`（兼容按 id 读的版本）与 `kind: TYPE_KIND`。

## 二 · 验证证据（真服务器 0.1.5-rc.1）
