# 跨车道契约 · K0–K4（2026-10-20）

> **谁写的**：主代理（集成者）。依据 `开发文档_功能开发_2026-10-20.md` §2.3。
> **谁能改**：只有主代理能改；改完必须通知所有车道。车道发现契约不够用时，**看契约、不要等对方代码**；确实需要改就写进自己的实现报告，由主代理统一改。
> **依据的实测事实**（不是猜测）：0.2.1-rc.2 的宿主代码（读自 `DeepSeek Harness.app` 的 asar）＋ 本仓库三插件的侦察。
> **K0 是新增的**：开发文档只列了 K1–K4，但侦察发现舞台**没有任何 window 全局挂载点**，而 C2 的「独立表情驱动模块」必须拿到 React/store。这个缝不写死，C2 无法开工，故补 K0。

## K0 · 舞台浏览器端模块的挂载点契约

**生产方 → 消费方**：S 车道（`clients/classroom-stage-warm/lib/client.js`）→ X 车道（新增的独立浏览器模块）。

**事实**：舞台的浏览器半边是一个闭包（`lib/client.js` 末尾 `window.__ModuleLoader__.load({id, factory})`），`module.exports` 与 `__test` 都**不上 window**。舞台加载静态 JS 的唯一通路是 `loadOneScript()`（`client.js:708-725`，`async=false`），清单来自 `lib/index.js:196-202` 的 `listLibs()` 产出的 `manifest.l2d` 字段；`assets/l2d/` 已被 `registerStaticDir` 覆盖（`lib/index.js:368`），所以新 `.js` 丢进 `assets/l2d/` 就能取到，**不必改宿主路由**。

**契约**：舞台必须在上文所述闭包里，开出一个稳定的全局挂载点：

```js
// 舞台侧（S 车道实现）：在 PIXI 应用创建后挂、销毁时删。
window.__SOCRATIC_STAGE__ = {
  version: 1,
  // 舞台当前可用的 React（宿主下发的那一份，不要另引）
  React,
  // 只读订阅：store 快照 + 订阅函数（舞台内部就是 useSyncExternalStore 的同一份数据）
  subscribe(fn),        // 返回 unsubscribe；每次 store.set 后调用 fn()
  getSnapshot(),        // { sessionId, running, title, messages, hasChatHook, phase }
  // 舞台已解析出的「屏幕状态」与切屏函数（表情模块只读它，不自己改屏幕）
  screen(),             // 'live' | 'board'
  // 舞台 PIXI 应用实例（表情模块把自己的 ticker 挂到 app.ticker 上，随 app 销毁而销毁）
  app,                  // 可能为 null（Live2D 未就绪时）
  model(),              // 当前 PIXI.Live2D 模型实例，可能为 null
  // 表情模块注册入口：舞台在「动作层」里给表情层让位
  setExpressionDriver(driver),   // driver = { drive(emotions, dt) } 或 null
}
```

**纪律**：
1. 舞台**不 import** 任何外部包来提供这个对象（它本来也不 import，见 `lib/index.js` 头注释的「少一个模块解析点」）。
2. 表情模块**只读** `getSnapshot()`，**不改**舞台 store；只能通过 `setExpressionDriver` 交出驱动函数。
3. 驱动函数签名固定为 `drive({ active: {label, intensity} | null, dt: number }, ctx)`——`ctx` 即该对象自身，避免模块再用第二个全局。
4. 舞台销毁（`props.killed` / cleanup）时必须 `delete window.__SOCRATIC_STAGE__`，并且**先**调用 `driver.dispose?.()`。
5. 静态 JS 的加载**不要**塞进 `listLibs()` 的 phases（会被 `if (!window.PIXI) throw` 连带门控）。新增独立的 `ensureStageModule(file)`，复用 `loadOneScript`。

## K1 · 情绪标记（Emotion Marker）

**生产方 → 消费方**：E 车道（教老师怎么写 + **在 `llm/stream` 里剥离与广播**）→ S/X 车道（读情绪通道、驱动表情）。

### K1.0 🔴 先看这条：为什么不能用「藏在正文里的 HTML 注释」

初版设想是让标记留在正文里、由舞台和原生界面各自隐藏。**0.2.1 实测否掉了它**：

- 0.2.1 的原生对话框用 **micromark + mdast 自建渲染器**（`dsh-client-ui-primitives` 的 `MarkdownText`，编进 web shell bundle）。它的 mdast→React 分支逐字是
  `case "html": return e.value`——**HTML 注释被当成字符串子节点原样转义显示**，没有任何特判或剥离。
- 全站**唯一**零输出的节点是 `definition` / `footnoteDefinition`（`return null`），而 CommonMark 的 definition 只能出现在**段落开头**，做不了逐句标记。
- `〔…〕` 全角括号走 `case "text"`，同样可见。

同时查明：**没有**「助手文本持久化前 transform」的官方钩子。能改助手输出的只有两个位置：
`llm/stream` waterfall（`dsh-llm/lib/index.js:2395-2398`，包裹 chunk 流，**在落盘前**；官方 `dsh-llm-replay` 就是这么玩的）与端上的渲染层遮蔽（`inject-hide` 那条路，但遮蔽后无法复用宿主渲染器）。

**所以 K1 改成「源头剥离 + 侧通道广播」**：标记只在**流里**存在，落盘与显示的全是剥净的文本。

### K1.1 语法（老师写的形态）

```
〔emo:<label>:<intensity>〕
```

- `<label>` ∈ `calm` | `happy` | `shy` | `puzzled` | `excited`（**只这五个**，与 C1 的五种可辨认状态一一对应）。
- `<intensity>`：`0.00`–`1.00`，**必须两位小数**（`0.6` 非法、`0.60` 合法）。解析器不做浮点格式容错。
- **位置**：句末（`。`／`？`／`！`／`…` 之后）。一句**至多一个**；整条回复不必每句都带。
- 全小写；括号是全角 `〔` `〕`（U+3014 / U+3015）。
- 🔴 **只有以 `emo:` 开头的括号对才是标记**。正文里别的全角方括号（`〔注一〕`、`〔见下〕`、`〔完〕`…）
  **一律原样保留**，不许剥、不许当事件。这一条是 2026-10-20 由 E/S 两条车道分别实现后对齐出来的判据收窄：
  原先「凡括号都剥」会吃掉正文。两份实现之间有 parity 测试钉着（`plugins/socratic-engine/test/emotion-parity.test.mjs`）。

### K1.2 引擎侧：唯一剥离点（E 车道）

在引擎里包一层 `llm/stream` waterfall：

1. 拿到适配器的 chunk async iterable，**逐 chunk 过**流式解析器。
2. `type` 为文本增量（`text-delta`）的 chunk：剥掉标记，**只把剥净的文本往下传**。其它 chunk **原样透传**（一个字段都不许改）。
   🔴 **只剥 `text-delta` 不够（2026-10-20 追认）**：宿主的 `BlockAssembler` 在 block 结束时用
   `chunk.block` 里的**整段文本**覆盖累加结果，而适配器给的 `block.text` 是**未剥的原文**。
   所以 **block-end 里的文本块也必须剥**，否则落盘与原生界面仍会带标记（E 车道实测过）。
   判据：凡是「会进 `assistant/message` 的文本」，都要过同一台状态机——不要按 chunk 类型挑。
3. 每剥出一个合法标记 → 往**情绪通道**（K1.4）追加一条事件。
4. 任何异常：**放弃剥离、原样透传**并记日志。宁可原生界面脏一行，也不能让课堂断流。

> 🔴 实现前必须先核对 0.2.1 的 chunk 形状（`text-delta` 的字段名）。核对方法：在隔离 profile 里挂一个只 observer 的 `llm/stream` 监听器打一行 `JSON.stringify(Object.keys(chunk))`。

**剥净是"所有可见表面"的唯一保证**——因为下游（`assistant/message` 持久化、原生界面、`session_log.md`、`classroom_note`）拿到的都已经是剥净文本。**E 车道仍要在 `session_log` / `classroom_note` 落盘前再剥一次**（幂等、防御性）：那两处可能来自历史会话或别的写入者。

### K1.3 流式解析器（纯函数，必须单测）

```js
createEmotionStreamParser() -> {
  push(chunk) -> { text: string, events: Array<{ label, intensity }> },  // text 已剥净
  flush() -> { text: string },
}
```

规则：
1. **跨 chunk 拼接**：维护「可能是标记开头」的尾巴缓冲。看到 `〔` 但还没有 `〕` 时，这段先**不往下传**，等后续 chunk；补齐后按上面的语法判定。
2. **flush 时仍不完整**：把缓冲**原样交回**（宁可显示半截，不吞正文），**不发事件**。
3. **非法标签 / 强度越界 / 缺两位小数**：整个标记**剥掉**（不显示），**不发事件**，不报错。
4. **一句多个标记**：取第一个，其余剥掉。
5. 单测判据：对同一段文本，**任意切分方式**的 chunk 序列，输出必须与一次性喂入逐字节相同。

### K1.4 情绪通道（引擎 → 舞台）

**位置**：`<教室>/runtime/emotions.jsonl`（append-only，一行一条）。

```json
{ "v": 1, "seq": 7, "ts": "2026-10-20T23:15:00-04:00", "session": "<sessionId>", "turn": 5, "label": "shy", "intensity": 0.60 }
```

- `seq` 单调递增（进程内计数器 + 启动时读文件末行续号，不必全局唯一）。
- 写入用 `withFileLock` + 追加写（**追加**，不是整文件重写；这个文件只增不改）。
- 体积防护：超过 64 KB 时把老记录折叠成一行 `{"v":1,"collapsed":true,"upTo":<seq>}` 并重写（保持"读末尾即可"）。

**舞台侧读法**（S 车道）：宿主半边加 `GET /stage-board/emotions?after=<seq>` → `{ events: [...], nextSeq }`，从同一文件读、只回 `seq > after` 的；浏览器半边每 **250ms** 轮一次（仅当舞台可见且 `running === true` 时轮）。**不做长轮询**（实现简单、失败可见）。

- 舞台拿到事件后交给表情驱动模块（K0 的 `setExpressionDriver`）。
- 🔴 舞台仍然要带上一份 K1.3 的**防御性剥离**：万一 `llm/stream` 包装没生效（引擎未装、版本不匹配），纸带不能把 `〔emo:…〕` 显示出来。

### K1.5 其它消费方

- **纸带**：文本已被剥净，正常情况下解析器无标记可剥；防御性剥离兜底。
- **`session_log.md` / `classroom_note`**：落盘前再剥一次（K1.2 末）。
- **DSH 原生聊天界面**：由 `llm/stream` 保证——**这是本契约唯一的隐藏手段，没有第二条路**。

### K1.6 退路（若 `llm/stream` 包装不可行）

1. 若 0.2.1 的 `llm/stream` 包装无法安全改写 chunk：改用**每条回复末尾一条 link reference definition** 汇总（`[emo]: <shy 0.6>` 这种 definition 是零输出节点），把逐句情绪降级为逐条情绪。**先报主代理再动**。
2. 若连 definition 也不可信：**放弃隐藏**，标记只存在于工具调用参数里（老师每句调一次 `classroom_tone`）。代价是每回合多几次工具调用。

## K2 · 板书事件（Board Event）

**生产方 → 消费方**：E 车道（`classroom_draw` 的结果）→ S 车道（板书屏自动切屏）／P 车道（板书历史列表）。

### K2.1 引擎侧：`classroom_draw` 成功时多给三样东西

🔴 **先记一条 0.2.1 的事实**：工具结果进会话事件时，`content` 是 **`tool.output.render(args, value)` 的产物**（展示文本/块），而结构化 `value` **不进事件**；要带结构化数据，唯一出口是 `tool.output.presentationMeta(args, value)` → 落进事件的 `meta` 字段（`dsh-agent-loop/lib/index.js:690-706`）。

所以：

1. **`output.presentationMeta` 返回** `{ board: { id, lesson, turn, kind } }` —— 舞台优先读这里。
2. **`output.render` 的文本末尾单独一行**加机器可读行（兜底路径，也是给模型自己看的）：
   ```
   [board] id=<diagramId> lesson=<N> turn=<T> kind=<kind>
   ```
   `lesson` 缺失时写 `lesson=0`。
3. **`execute` 的返回值与 `output.schema`** 同步加三个字段：`diagramId`（=`.mmd` 文件名去扩展名，如 `L03-T05-20261020-231500-flowchart`）、`boardRoute`（恒 `"/stage-board/diagrams/" + diagramId`）、`board`（同 presentationMeta 的形状）。

失败时不给任何结果节点（或 `isError: true`），消费方据此**不切屏**。

### K2.2 舞台宿主半边：读图路由（S 车道）

- `GET /stage-board/diagrams/<id>` → `200 text/plain; charset=utf-8`，body 是 mermaid 源码。
- `GET /stage-board/diagrams` → `200 application/json`，`{ items: [ { id, lesson, turn, kind, title, time, file, session } ] }`，按时间倒序。
  `session` 取自索引新增的「会话」列，**可能为空串**（老记录）。解析必须**按表头名取列**，不按固定下标；
  没有「会话」列的老索引照常返回，`session` 给空串。
- 根目录严格限定：`<会话工作区>/classrooms/<教室目录>/runtime/diagrams/`。
- **拒绝规则**（逐条都要有测试）：`<id>` 必须匹配 `^[A-Za-z0-9_-]+$`；`decodeURIComponent` 之后仍必须匹配；`resolve()` 后必须仍在根目录内；`fs.realpathSync` 后必须仍在根目录内（防符号链接）。任一不满足 → `400`，**不是 500**。
- 只允许 loopback（沿用舞台现有 `isLoopback`，`lib/index.js:110-113`）。

### K2.3 舞台浏览器半边：怎么得知「刚画了一张」（S 车道）

**唯一判据**（都从 Chat 节点的 `useChat` 快照里取）。

🔴 **2026-10-21 实测更正**：0.2.1 **不下发** `kind === 'tool-result'` 的节点。真机 dump 里节点 kind 只有
`turn-process` / `user` / `tool-call`；而**工具结果折在 `tool-call` 节点的 `data.root` 里**，
`root.kind === 'tool-result'`，并带 `name` / `content` / `isError` / `meta` / `time`。
所以判据要**两种形状都认**（向后兼容宿主以后再拆开）：

```
// 形状 A（本契约最初的写法，宿主未来可能恢复）
node.kind === 'tool-result' && node.name === 'classroom_draw' && node.isError !== true
// 形状 B（0.2.1 实际形状）
node.kind === 'tool-call' && root.kind === 'tool-result'
  && root.name === 'classroom_draw' && root.isError !== true
```

命中后，`id` 按以下顺序取：
1. `node.meta.board.id`（首选）
2. 从 `node.content`（数组，元素形如 `{type:'text', text}`）拼出的文本里，用 `/\n\[board\] id=(\S+) lesson=(\d+) turn=(\d+) kind=(\S+)/` 抓
3. 两者都没有 → **不切屏**，只记一条 console.warn（不要让 UI 崩）

> 依据：0.2.1 `dsh-client-ui-chat/lib/client.js` 的 `rootResult()` 逐字给出 Chat 节点形状
> `{ kind:'tool-result', seq, time, callId, name, args, call, callTime, content, isError, meta, subCalls }`。
> 注意 `name` 来自**上一次 tool-call 节点**（`previous?.name`），所以「先有 tool-call 再有 tool-result」是必然顺序。

### K2.4 行为（S 车道）

- 命中 → 2 秒内播拉出节拍切到板书屏，渲染**这一张**（不再用 `L03`）。
- 学生发下一句话（或点手动按钮）→ 反向节拍收起。
- 正在显示板书时又来一张 → **直接替换内容，不重播拉出动画**。
- mermaid 渲染失败 → 板书屏显示「这张图渲染失败」＋**图的源码**，不白屏。
- 舞台关闭时画了图 → **不自动打开舞台**，只进历史（P 车道）。

### K2.5 面板侧（P 车道）

- 数据源**不是** `whiteboardStore`（该服务无任何写入者），而是 `runtime/diagrams/index.md`（引擎在写）。
- 走 `ctx.remote.workspaceFiles.read()` 读该文件，按表格行解析；点开时读对应 `.mmd` 全文再渲染。
- 显示顺序：时间倒序；每行带「标题 + 讲次 + 回合」。**只读，没有任何编辑入口。**

## K3 · 课堂记录（Classroom Record）

**生产方 → 消费方**：E 车道（`classroom_note` 落盘）→ X 车道（日记/群聊/世界观 agent 读）／P 车道（面板展示）。

### K3.1 单一真源：`<教室>/runtime/notes.jsonl`

**决策与理由**：真源用 **JSONL**，三份 markdown（`mistake_log.md` / `review_queue.md` / `knowledge_points.md` 的状态位）是**从 JSONL 机械重算出来的投影**。

- 否决「markdown 当真源」的理由：要「机械推导 `review_queue` 和 `progress`」，就必须解析 markdown 表格；解析 markdown 是不确定性的来源，且无法保证幂等与并发安全。
- 否决「两套都写、互不推导」的理由：两条真源必然漂移。
- 投影文件头**必须**写一行：`> 本文件由 runtime/notes.jsonl 机械生成，请勿手改。`
- 投影是**整文件重写**（原子写 + 文件锁），不是追加。人读的「不删除已解决记录」由 JSONL 保证。

### K3.2 记录字段（一行一条 JSON，UTF-8，`\n` 结尾）

```json
{
  "v": 1,
  "id": "N-20261020T231500-001",
  "ts": "2026-10-20T23:15:00-04:00",
  "session": "<宿主 sessionId>",
  "lesson": 3,
  "turn": 5,
  "type": "misconception",
  "kp": "KP-3.2",
  "quote": "学生原话（已按 K1 剥净）",
  "note": "老师一句话说明",
  "origin": "teacher",
  "resolved": false
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `v` | 是 | 恒 `1`；将来改结构就升版本，读方按版本分派 |
| `id` | 是 | `N-<yyyyMMddTHHmmss>-<三位序号>`；同一秒内多次写入靠序号区分；**全局唯一、不复用** |
| `ts` | 是 | 带时区的 ISO 8601 |
| `session` | 是 | 宿主 sessionId |
| `lesson` | 是 | 讲次整数；无讲次门时写 `0` |
| `turn` | 是 | 引擎的 `phase.turnCount` |
| `type` | 是 | `misconception`（误解）｜`blocker`（卡点）｜`evidence`（掌握证据）｜`group_question`（群里提的问题） |
| `kp` | 否（`group_question` 可为 null） | `KP-<讲>.<序>`，必须在 `knowledge_points.md` 里真实存在 |
| `quote` | 是 | 学生原话，**非空**，已剥净 K1 标记与 markdown |
| `note` | 否 | 老师一句话 |
| `origin` | 是 | `teacher` ｜ `group_agent` |
| `resolved` | 仅投影用 | **不由工具写入**；由投影时机械推导（见 K3.3），写回时忽略输入值 |

### K3.3 推导规则（确定性、可单测）

按 `(lesson, turn, id)` 字典序 = 时间序排序后：

1. **`knowledge_points.md` 的状态位**：对每个 `kp`，取**时间序最后一条** `type ∈ {misconception, blocker, evidence}` 的记录：
   - 最后一条是 `evidence` → `[x]`
   - 最后一条是 `misconception`／`blocker` → `[~]`
   - 没有记录 → 保持原文件的 `[ ]`（**不写 `[x]`**）
   - 该 `kp` 所属讲次在 `progress.md` 里是「跳过」→ 状态位**不动**（`blocker` 也不写），并在条目末尾加 `（跳过）`。**这是 J2 的红线**。
   - 🔴 **取值来源（2026-10-20 追认）**：`progress.md` 里读可选机器行 `skipped_lessons: 1,2,3`（缺失＝无跳过）。
     **J（任意讲次进入）必须用同一个键名写这一行**，不要另起一套标记。
   - 🔴 红线：**「老师讲过」不产生 `evidence` 记录**，所以永远不会因「讲过了」推断出 `[x]`。工具只在**有学生原话作证据**时被调用。
2. **`mistake_log.md`**：每条 `misconception|blocker` 一行；`resolved` = 同 `kp` 上存在更晚的 `evidence` 记录。解决的记录**保留**，只标「已解决（第 N 讲 · 第 T 回合）」。
3. **`review_queue.md`**：对每条 `misconception|blocker`，生成到期点 = `记录时讲次 + {1, 3, 7}`（只保留 ≤ 课程总讲数的）。条目在「当前讲次 ≥ 到期讲次」且 `resolved === false` 时为**到期**；`resolved === true` 时该条的后续到期点作废。同一 `kp` 多条记录只保留最早一条的到期点（避免堆积）。
4. **`progress.md`**：**只**维护已存在的机器可读行 `current_lesson: <int>` 与「本轮要讲」那一行的同步；**不改** `current_phase`（那是 `classroom_set_phase` 的职责），不动「记录」表（那是课后写回的职责）。

## K4 · 群聊 API

**生产方 → 消费方**：X 车道（存储与调度）→ P 车道（群聊 tab）。

### K4.1 通路：typert Remote 服务，**不是**自建 HTTP

**依据（实测）**：`clients/classroom-ui/lib/client.js` 里 `fetch(` / `XMLHttpRequest` / `EventSource` / `Authorization` / `token` **全部 0 处命中**；面板唯一已验证的网络通路是 `ctx.remote.<service>`（typert Remote，`lib/whiteboard-host.mjs:79-100` + `lib/typert.host.js` + `lib/index.js:29-42` 三件套）。鉴权由网关完成，插件侧**不持有任何凭据**。

所以：新增服务 `classroomGroup`，浏览器侧 `ctx.remote.classroomGroup.<method>(sessionId, ...)`。

🔴 **2026-10-21 实测补两条（P2 车道在真机上抓到，缺一条就跑不起来）**：

1. **第三方命名空间不会自己出现在浏览器侧**。`ctx.remote.<ns>` 来自 `dsh-api-remotes` 的**静态装配表**；
   第三方插件没有 client 面产物，所以**消费方必须自己 `ctx.remote.$mount(...)` 挂一份清单**。
   而且读 `remote.<ns>` 需要 `inject`，而这两个命名空间又是本插件自己挂的 —— **`inject` 会死锁**，
   只能走 `ctx.get('remote')`。
2. **宿主 Remote 方法的接收者不是裸实例**：类里用 `#` 私有方法会抛
   `Receiver must be an instance of class …`。宿主 Remote 的公开面只能用普通方法或字段。
   （同一隐患存在于 `clients/classroom-ui/lib/whiteboard-host.mjs` 的 `#rootOf` / `#readCurrentRev`；
   目前没有浏览器调用方所以没暴露，记为技术债。）

> ⚠️ 0.2.1 的 `dsh-typert-loader` 要求每个 `codec` 带 **`create()` 工厂**（不再收 `schema`）。形状照 `clients/classroom-ui/lib/typert.host.js` 现在这份（已迁好）。

### K4.2 存储真源：`<教室>/runtime/wechat_group.jsonl`

- 一行一条消息，append-only；**md 是投影**（`wechat_group.md` 由 JSONL 重新生成，文件头写「机械生成，请勿手改」）。
- 消息字段：

```json
{
  "v": 1,
  "seq": 12,
  "id": "G-20261020T231500-012",
  "ts": "2026-10-20T23:15:00-04:00",
  "role": "student",
  "speaker": "你",
  "text": "在吗",
  "clientId": "c-3f9a",
  "kind": "message"
}
```

  - `seq`：单调递增整数，**由服务端分配**，是排序与「未读」的唯一依据
  - `role`：`student` ｜ `character` ｜ `system`（开场/无法回复的说明）
  - `speaker`：显示名。`role==='character'` 时必须是 `characters/` 或 `world/` 里已定义的人物名，或一次性路人名（以 `路人·` 开头）
  - `clientId`：学生端生成的幂等键，用于「重试不重复写入」
  - `kind`：`message` ｜ `typing`（**不持久化**，见 K4.3）｜ `open`（首次开场）

### K4.3 服务方法

| 方法 | 入参（wire） | 返回 |
|---|---|---|
| `history` | `limit`（默认 50，上限 200） | `{ messages: Message[], nextSeq, unread }` |
| `send` | `text`（1–2000 字，**按 Unicode 码点计数**，空白串拒绝）、`clientId` | `{ ok: true, message, unread }` ｜ `{ ok: false, error: { code, message } }`（**不抛异常**，让学生能重试） |
| `poll` | `afterSeq`、`waitMs`（0–25000，服务端可缩短） | `{ messages, typing, nextSeq, unread, serverTime }` |
| `markRead` | `seq` | `{ unread }` |

- `typing`：`true` 表示「她正在输入」。它在 `poll` 的返回里，**不落盘**（是瞬态）。
- `error.code` ∈ `EMPTY` ｜ `TOO_LONG` ｜ `RATE_LIMITED` ｜ `AGENT_FAILED` ｜ `STORE_CORRUPT`。
- 并发：所有写走 `withFileLock` + `writeFileAtomic`（同 `postclass.mjs:326-339` 的做法）；**两个标签页同时发言不能丢消息**（AC 明确要求）。
- 读：`poll` 允许长轮询（最长 25s）；服务端实现可以退化为「立即返回」，但**返回形状必须一致**。

### K4.4 节奏与「课堂进行中不回群」（X 车道）

契约只定**状态出口**，不定实现：
- `poll` 返回的 `typing` 必须真实反映「她已被排入回复队列」。
- 「课堂进行中不回群」的判定在 X 车道：相位不是 `close` **且**最近一次回合活动在 30 分钟以内。
- 学生连发多条 → **合并成一次回复**（服务端按 `afterSeq` 去抖，不靠前端）。
