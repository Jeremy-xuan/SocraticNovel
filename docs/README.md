# docs/ —— 设计、取证、实现报告与计划

代码在 `clients/`、`plugins/`、`tools/`；这里只放**文档**。

| 目录 | 收什么 | 怎么找 |
|---|---|---|
| `架构/` | 系统怎么搭的、模块边界、契约与规格 | 只有 5 份，是骨架级的 |
| `计划与排产/` | 正在进行的计划、部署记录、状态盘点 | 数量少，会持续更新 |
| `历史报告/` | 实现报告 / 取证 / 研究 / 实测，**按主题前缀＋日期命名** | 直接按文件名搜：`实现报告_*`、`取证_*`、`研究_*`、`实测_*`、`计划_*` |

## 历史报告怎么查

文件名自带分类前缀和日期，所以**平铺放着比强行分类更好找**：

```bash
ls docs/历史报告/ | grep 实现报告_       # 所有实现报告
ls docs/历史报告/ | grep 取证_           # 所有取证
ls docs/历史报告/ | grep 2026-10-19      # 某一天做的所有事
grep -rl "Live2D" docs/历史报告/         # 按内容搜
```

## 这里的文件会过期

`历史报告/` 里的内容是**当时状态**的记录，不是当前真相。当前真相在代码和
`架构/` 那几份里。看到报告和代码不一致时，**以代码为准**，并把报告标注为过期。

## 废案

已废弃的实现不放这里，放仓库根的 `archive/`（每个目录带 README 说明被谁取代）。
