# docs/ —— 设计、取证、实现报告与计划

代码在 `plugins/`、`clients/`、`classrooms/`；这里只放**文档**。

> 🔴 **状态不在这里。** 哪些能力能用、到哪一级、差什么，只看仓库根的 [`STATUS.md`](../STATUS.md)。
> 本目录下任何文档里写的「已完成 / 半成品 / 能用了」都是**当时的记录**。

| 目录 | 收什么 | 现状 | 怎么找 |
|---|---|---|---|
| `架构/` | 系统怎么搭的、模块边界、契约与规格 | **活的**（少量，会更新） | 只有 5 份，骨架级 |
| `历史报告/` | 实现报告 / 取证 / 研究 / 实测，**按主题前缀＋日期命名** | **只读**，不再更新 | 按文件名搜：`实现报告_*`、`取证_*`、`研究_*`、`实测_*` |
| `证据图/` | 截图、原始输出、复现命令 | **只读** | 每个子目录一份 README 说明它证明了什么 |
| `计划与排产/` | 过去的计划、盘点、部署记录 | 🔴 **全部是历史快照**，不再维护 | 只在追溯「当时为什么这么排」时看 |

## 三类文档的读法

1. **架构 / 契约**（`架构/`）：动手前读，与代码冲突时以代码为准。
2. **历史报告**（`历史报告/`）：只在两种时候读——查某个结论的**依据**，或查某个坑**当初怎么踩的**。
   文件名带日期，**日期就是它的边界**；引用它的结论前先核对 `STATUS.md` 或代码。
3. **证据**（`证据图/`）：报告里引用的截图与原始输出都在这里，每个目录的 README 写「证明了什么 + 怎么复现」。
   🔴 **第三方源码与仓库快照不再入库**（2026-10-20 整顿），只留出处、commit 与重建命令。

## 历史报告怎么查

文件名自带分类前缀和日期，所以**平铺放着比强行分类更好找**：

```bash
ls docs/历史报告/ | grep 实现报告_       # 所有实现报告
ls docs/历史报告/ | grep 取证_           # 所有取证
ls docs/历史报告/ | grep 2026-10-19      # 某一天做的所有事
grep -rl "Live2D" docs/历史报告/         # 按内容搜
```

## 废案

已废弃的实现不放这里，放仓库根的 `archive/`（每个目录带 README 说明被谁取代）。
一次性实验的源码放 `research/`，结论写进 `历史报告/`。
