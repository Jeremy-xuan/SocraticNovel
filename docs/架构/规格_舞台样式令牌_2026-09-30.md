## ⑤ 「拉出」时序（`pull-out.html`）

### 5.1 参数源（逐字）

```css
/* pull-out.html:52-58 */
--T1:170ms;   /* 预备：角色侧身 */
--T2:390ms;   /* 拉出：面板出现到过冲点 */
--T3:220ms;   /* 收尾：回正落定 */
/* 「拉重物」曲线：先慢 → 中快 → 末端减速（不是 easeOut，那太"UI"） */
--EASE-PULL:cubic-bezier(.62,.02,.36,1);
--EASE-BACK:cubic-bezier(.22,.61,.36,1);
--SPEED:1;    /* 慢放用 */
```

## ⑥ px 口径清单

### 6.0 根因（先明确，否则下面两栏没法判）

四份样稿共用同一套「固定画布 + 整体缩放」结构（`avalon-warm.html:45-47`，另三份同）：

```css
#stage{position:absolute;left:50%;top:50%;width:1920px;height:1080px;
  transform:translate(-50%,-50%) scale(var(--k,1));transform-origin:center center;
  background:#0C0A08;overflow:hidden}
```
```js
/* avalon-warm.html:441-443 等 */
var k=Math.min(innerWidth/1920, innerHeight/1080);
stage.style.setProperty('--k',k);
```

**推论**：画布内所有 px 都被**同一个 `k` 等比缩放**（`k` 取两轴较小者，会留黑边/裁切）。因此——
- 在 1920×1080 内，px 值之间**互相成比例**，视觉比例正确；
- 一旦宿主不是 16:9，`k` 仍是单一标量，画布内比例**依然自洽**，但**画布与宿主视口的比例关系变了**（留白/裁切位置变）；换成非固定画布（＝内容直接铺在宿主视口里、不再整体 scale）时，纵向 px 值的「占屏高比例」会全部改变。
- 🔴 **判据**：`必须换相对量` = 该值承载**纵向构图节奏**（占屏高比例会直接改变观感的东西）；`可保留 px` = **与分辨率绑定而非与构图比例绑定**的细线/描边/圆角/小装饰（发丝线永远应该是 1px）。

### 6.3 🔴 已存在的两处「单位错配」（移植前必须处理，不是待定，是现在的实际行为）

| 位置 | 逐字 | 问题 |
|---|---|---|
| `reading-v2.html:144` | `.body{max-height:56vh;…}` | `56vh` 解析的是**真实视口高度**，而 `.body` 活在 `#stage` 内并被 `k` 缩放 → 画布内等效高度 = `0.56*h_real/k`。只有窗口恰为 1920×1080（`k=1`）时才等于注释里的 `606px`（`reading-v2.html:341`：`var N_BODY_MAX=606;   /* 56vh of 1080 */`）。**窗口一变，正文可视行数就变**，而且 `k<1` 时反而显示**更多**行。 |
| `reading-v2.html:202` | `.state-a .body,.state-ao .body{max-height:400px;margin-bottom:0}` | 固定 `400px`，**不随任何东西变**；与同一元素的基线值 `56vh` 混用两种单位系。 |
| 同上（复刻件） | `pull-out.html:100`、`features.html:67` | `.body{max-height:56vh;…}` 同错配。 |
| `reading-v2.html:179` ＋ `534-535` | `max-height:132px` 与 `Math.min(say.scrollHeight, 132)` | 输入框自增上限写死 `132px`（两处必须同步改） |

### 本规格的已知边界

1. **只覆盖这四份样稿**（`avalon-warm` / `reading-v2` / `pull-out` / `features`）。同目录另有 `index.html`、`adaptive.html`、`reading-inline.html`、`a-card.html`、`b-band.html`、`c-column.html`，**本次按要求未纳入**。
2. **`?state=` 差异是逐条从 CSS/JS 抄出的**，但 `.line.stopped/.stopped2` 在 `state-ao` 下的实际观感未经浏览器渲染核验（本任务只做静态抽取，未启动浏览器）。
3. **⑤ 的两处不一致（过冲数值 / 时序）只做如实并列**，未替使用者裁决。
4. ⑥ 两栏的归类含**判据**（见 6.0）与**边缘项标注**（`.corner`、`.punchcard`、`.console`），边缘项我给了倾向但未定案——因为「画布 vs 视口」的最终宿主形态未定。
5. 引用位置一律 `文件名:行号`，行号基准为 2026-09-30 读到的版本；**样稿一旦改动，行号会漂**（本项目已有「行号漂移」的历史教训），比对时请以逐字内容为准。
