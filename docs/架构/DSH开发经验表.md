## 开发经验

| 要点 | 内容 |
|---|---|
| 🔴 **DSH 插件开发两条铁律（2026-09-23 实证，SocraticNovel 定制线）** | ① **插件绝不能把宿主核心包**（`@deepseek-ai/dsh-tools`／`dsh-llm` 等）**装进 profile 或插件自己的 node_modules**——会出现同一包的第二个实例，Symbol 键（如 `TOOL_RUNTIME_SCHEDULER`）失配 → 工具调用崩 `Cannot read properties of undefined (reading 'prepare')`；宿主自带解析（实证：用户 web profile 的 `node_modules/@deepseek-ai/` 只有外围包）。② **本地插件包用 `file:` 安装**（`dsh plugin --profile X add file:<路径>`），`link:` 会让插件从自己路径解析、找不到宿主核心包。③ 🔴 **硬链接镜像不抗「替换式写入」（2026-09-24 实证）**：`file:` 安装后 profile 里的插件文件与工作区镜像**共享 inode**，但 `edit`/`write` 是「写新文件再替换」→ **第一次编辑就打断硬链接，profile 里停在旧版本**，于是「改代码＝实时生效」只对**从未被编辑过**的文件成立。实例：M3 第一次真实会话失败（模型调不到新工具），逐文件 inode 核对才查明。→ **跑真实会话前必须显式同步（`cp` 或重装）＋ 哈希复核**，不得依赖硬链接自动生效；**最终验收更要在独立冻结目录里装一份再跑**。详见 `开源线/DSH定制/实测报告_P1骨架与装载坑_2026-09-23.md`。 |
| 🔴 **DSH 客户端插件：装载机制与两个实测坑（2026-09-24 实证，T1 跑通）** | ① **客户端插件必须有 `dsh.bundle.patch`** 才成为 profile 的一层；**`package.json` 的 `files` 必须列 `cordis.patch.yml`**，否则 pnpm 打包不带它 → 启动报 `failed to read overlay … ENOENT`。② **浏览器半边**由宿主 Loader 条目扫 `dsh.client.platform==='web'` ＋ `exports["./client"]` 装配（行 id ＝ 包名）。③ 🔴 **产物是 `window.__ModuleLoader__.load({id, factory})` 的惰性 CJS 表，宿主不转译** → `lib/client.js` 要**手写产物**（`require("react")` ＋ `React.createElement`，**不用 JSX/CSS 模块，也不需要打包器**）。④ **双半插件是官方常态**（如官方右栏包同时有 `main` 宿主半边 ＋ `exports["./client"]` 浏览器半边）——只做浏览器半边时也要给一个**空的宿主半边**（Loader 行需要可 import 的宿主模块）。⑤ **本地包改代码后重装：`dsh plugin --profile X remove <pkg>` 再 `add file:`**——同版本 `file:` 依赖 pnpm 会说 `Already up to date` 而不刷新。⑥ **客户端读工作区文件有现成通道**：`ctx.remote.workspaceFiles.read(sessionId, path)`（path 可为**工作区相对路径**，`packages/api/workspace-files/src/index.ts:227` 逐字；返回 `RemoteResult<T>`）→ 面板类插件**不需要服务端配合**。 |
| 🔴 **DSH 客户端插件开发：第一步查「安装版内置座目录」（2026-09-24 实证，省半天）** | 安装版 `tmp/dsh-installed/dsh-cordis-client-runner/lib/client.js`（约 5175 行）里有一份**机器可读的全部扩展点目录**：每个座带 `kind`／`scope`／`registerOptions`／`ownerProps`／`keyDomain`／`declaredBy`／`occupants`／**`replaceRisk`**／**官方示例代码**，并附 `source:` 指向上游源文件行号。→ **做客户端 UI 插件前先查它，别从零翻源码**。同时已验证的三条安装版事实：① 根 frame 只有 **4 个座**（master 记的 5 个已过时）；② **右侧面板的正确入口是 `sidebar.right.pane.tab`（keyed/session，`replaceRisk="none"`），不是 `rightbar`**（后者是 `single/root` 且已被官方右栏占据）；③ **消息区没有"说话人身份"字段**，"谁在说"由 kind 决定渲染器、由 `source.kind` 决定归类——想在一个回合里显示两个角色说话，最省的做法是**第二个角色走注入通道并给独有的 `source.kind`**（客户端会自动渲染成带名字的注入行），或复用 `tool-call` kind 自画气泡（后者会盖掉官方工具树）。证据见 `开源线/DSH定制/取证_P3_客户端槽位与派发语义_2026-09-24.md`。 📌 **本行读数已过期（2026-09-28 更新）**：座目录现为 **89 个座**（`replaceRisk` 两档：`none` **48**／`shadows-shipped-ui` **41**），文件 **6644 行**，路径改为 `/Applications/DSH Desktop.app/Contents/Resources/app.asar.unpacked/node_modules/@deepseek-ai/dsh-cordis-client-runner/lib/client.js`。**62 是 09-24 的读数，引用时须写明基准日。** |
| 🔴 **DSH 客户端插件：`shell.overlay` 全屏落点的三条铁律（2026-09-28 实证，两路独立实测）** | 🔴 **① 必须写成「root 穿透 ＋ 自己的控件 opt-in」**——官方 doc 说条目 "opt back into pointer events" 听起来是 opt-in，**实际是 opt-out**：宿主 CSS 逐字规则 `.pI_x6G_overlayLayer > * { pointer-events: auto }` 已把条目默认 opt-in，而 `pointer-events` 是**继承属性** → **不写 `pointerEvents` 的全屏根节点＝整帧接管鼠标**（实测 7 个官方取样点里 6 个被挡、真点输入框后 `document.activeElement` 是 `body`）。→ 全屏根节点显式 `none`，要接收点击的子控件各自显式 `auto`。**不写就等于把整个 app 变成不可点。** 🔴 **② 全屏落点必须 `position: fixed; inset: 0`**，不能用 `width/height:100%`——层的父 `frame` 是 `overflow:hidden` 但**可程序化滚动**的容器（实测 `scrollWidth 2436 > clientWidth 1680`、`scrollLeft 11`），层自己是 `absolute; inset:0` 会跟着偏；`fixed` 恒在 0，流内写法偏 −11px 并可能被裁边。🔴 **③ 条目不是 layer 的直接子节点**，中间隔一层 `display:contents` 的 wrapper（`renderSlot` 给每个条目包的）→ **「在 layer 上写样式」的直觉不成立**，能命中你的规则在 wrapper 上。✅ 同轮验证通过的四条：铺满视口（rect == 视口 1680×1050）、在所有列之上（层 `z-index:20` vs 官方列 `auto`）、`useSessions` 拿得到会话（1744 条、activeId 非空、cwd 正确）、撤场零残留（节点 7→0，body 579→572，console.error＋pageerror 全 0）。⚠️ **`shell.overlay` 拿不到对话流**（条目实际收到的 props 只有 `useSessions`／`useSessionStatus` 等 **7 项，无 `useChat`／`useConversation`／`sessionId`**）→ 它是**全屏演出层**，**不是主舞台**；主舞台要用 `conversation.view`（session 级，多 8 项会话专属接口）。⚠️ **`order`／`label` 两个 registerOption 在该座上无可观测效果**（owner 不投影 nav 行/标题）；**多个条目共存时谁压谁未验**。🔴 **结论只对 `dsh 0.1.7-rc.2` 成立**（`dsh-client-ui-layout` sha256 前 16 位 `0aa7c7437cc30a09`）；`display:contents` 是宿主实现细节，官方座目录**未承诺**。证据：`/tmp/overlay-probe/EVIDENCE.md`（子代理，237 行，五档配置 ＋ 逐节点残留核 ＋ 祖先链查证）＋ `/tmp/overlay-probe-lead/EVIDENCE.md`（主代理）；探针源码留仓 `开源线/DSH定制/code/probes/overlay-probe/`；裁决与成熟案例见 `开源线/DSH定制/研究_UI-B1_舞台落点与成熟案例_2026-09-28.md`。 🔴 **2026-09-30 补一条（来源：Avalon 皮肤 `docs/MAINTENANCE.md` 逐字，我们此前未记录）**：**该座上任何一次 render 抛错，DSH 的 `SlotErrorBoundary` 会「永久」把整个槽变成崩溃占位** —— **逃生门和被救的对象一起死**（皮肤自己的关闭入口也在那个槽里，于是关不掉）。→ 整屏类插件**不要把「唯一的关闭出口」放在 `shell.overlay` 里**。 |
| 🔴 **DSH 隔离 profile 的装载配方：`dsh plugin add` 建出的 profile 起不了 UI（2026-09-28 实证）** | `dsh plugin --profile <新名> add file:<包>` 自动建的 profile **只有 `bundles: ["@deepseek-ai/dsh-base","<包>"]`——没有 `@deepseek-ai/dsh-web-app`** → `dsh web` **进程活着但端口不监听、日志 0 字节**（等 60 秒确认，重跑排除日志缓冲假象）。→ **正确配方：建 profile 时手工写 `package.json` 的 `dsh.profile.bundles = ["@deepseek-ai/dsh-base","@deepseek-ai/dsh-web-app","<包名>"]`**（`dsh-web-app` 从 **harness 级** `profiles/node_modules/` 解析，**名字进 bundles 就够、不需要装**；想用 `dsh plugin add` 装它会被版本兼容门拒——peerDeps 钉 `0.0.1-rc.1` vs 实装 `0.1.7-rc.2`，输出逐字 `nothing was installed`）。📌 **同轮另两条再次实证**：`dsh plugin add file:` 对已装包只说 `Already up to date` 不刷新；硬链接不抗替换式写入（改探针后**真的**撞上 profile 停在旧版本、探针挂不上）。📌 **诊断口诀：`dsh web` 启动报出十几条失败时只看 `Failed plugins` 那一条**——其余（`connection`／`file-upload`／`ui-deliverables`…）全是级联等待；本轮根因只有一条 `EADDRINUSE`。📌 **token 每次重启都变**，要从**当前进程的输出**取，不要复用旧日志（否则页面只显示 `dsh web authentication required`）。📌 **`nohup … &` 起的服务器会随 bash 调用结束被杀** → 必须用受管后台任务起。 |
| 🔴 **DSH 技能（skill）机制：靠 description 触发，且校验会静默（2026-09-24 实证）** | ① **装法＝复制目录，没有 CLI**（`dsh` 只有 `web`/`plugin` 子命令）；扫描根：项目级 `<项目根>/.dsh/skills`、`$DSH_HOME/skills`（**用户级，跨 profile**）、`~/.agents/skills` 等，**只扫两层**；`$DSH_HOME` 在本机是**桌面版 harness 目录**（`~/Library/Application Support/dsh-desktop/harness`），**不是 `~/.dsh`**。② `SKILL.md` frontmatter 必需 `name`（正则 `^[a-z0-9]+(?:-[a-z0-9]+)*$`）＋`description`；会话启动只把 **name＋description 拼成目录行**（description 截断 500 字符），**没有任何关键词机制** → **触发完全取决于 description 写得像不像用户会说的话**；模型决定用才调 `skill` 工具**重新读盘取全文**（改正文不用失效缓存）。③ 🔴 **所有加载失败都只是 `logger.warn` + 跳过，模型侧拿不到任何诊断**（分不清"没装"与"装坏了"）→ **凡发包必自带自检命令**。④ 包内其他文件不会被当技能，但会记进 `resourceBase.directory` → **"内容随包走"就靠这条**。证据：`开源线/DSH定制/实现报告_M3_skill打包_2026-09-24.md`。 |
| ⚠️ **本机 Clash TUN 会让"连不通"类测试假失败（2026-09-19 实证）** | fasthttp 基线 `go test ./...` 唯一失败 `TestDialerGetDialFuncForTLSNoProxy`（期望拨号 **TEST-NET-1 `192.0.2.1`** 失败而实际成功）——**查明是本机 Clash Verge TUN 模式**（`utun0–utun4`）接管全部出站 TCP，连不可路由地址也**秒连成功**（0.000s）；与代理环境变量**无关**（`env` 里没有 proxy 变量，显式清空后失败完全相同）。→ 规则：**本机任何"依赖某地址连不通"的测试／复现，都要先用一次独立拨号验证前提是否成立**；**这类失败不得当作被测项目的 bug** 上报或写进材料。判据：`python3 -c "socket.create_connection(('192.0.2.1',80),3)"` 若"成功"，即 TUN 在拦截。 |
| 🔴 **cordis 日志：级别门是反直觉的，写 `warn` 反而会被静默丢掉（2026-09-24 实证）** | 级别门判断逐字是 `(exporter.levels?.default ?? this.level ?? 1) < level` **才跳过** → **默认门限 1 下，只有 `info`(1) 及以下可见；`warn`(2)／`debug`(3) 会被跳过**。实例：教学插件的 `log()` 原本写成 `ctx.logger?.(名字, ...args)`（**cordis 的 `ctx.logger(name)` 只接受一个参数** → 参数被丢弃、返回的 Logger 被抛弃），**插件所有报错/警告一条都不落任何地方**，直到验收流水线把日志桥修好才发现；改用 `ctx.logger?.(名字).info(...)` 后同一路径从"收到 0 条"变成"收到 15 条"。→ 规则：**① 取 logger 必须"先取再调级别方法"，不能把参数塞给 `ctx.logger()`；② 想要"一定能被看见"就用 `info`，别想当然用 `warn`；③ 插件必须自带"报错真的能落盘"的运行时段验证（对照组装回旧形状应收不到）**。④ 📌 **日志名一旦被验收断言引用，就成了契约**——改名必须同时改验收（实例：`acceptance/lib/asserts.mjs` 硬编码了 `[socratic-engine]`）。 |
| 🔴 **`dsh plugin add` 会重算 `dsh.profile.bundles`，可能把别的插件踢出列表（2026-09-24 实证）** | 装一个插件时实测发现：**没声明 `dsh.bundle` 的插件（如 `socratic-test`）被移出了 `dsh.profile.bundles` 列表** → 它的层不再被装载。→ **规则：每次 `plugin add`／`remove` 之后，都要核一遍 profile 的 `dsh.profile.bundles` 名单**（装前、装后各看一次），发现被踢就**手工加回**；跑真实会话前尤其要核（否则会出现「工具突然不见了」这类看着像 bug 的现象）。 |
| 🔴 **隔离 `DSH_HOME` 必须用「硬判据」，不能靠 `??` 默认值（2026-09-24 实测：连跑 4 次都跑在真 harness 上）** | 本环境 **`process.env.DSH_HOME` 本来就指向真 harness**，所以脚本里写 `DSH_HOME = process.env.DSH_HOME ?? 默认值` 时，**想让 `DSH_HOME=… 前缀`生效其实是无效的** → **静默在真 harness 上加载了旧副本插件**（连着 4 次会话都是旧引擎，最后靠模块顶层打印 `import.meta.url` 才定位）。副作用：那 4 次把 **session 记录写进了真 harness 的 sessions 目录**（profile 配置与教室文件未改动）。→ **规则**：跑任何"隔离环境"的脚本，开头就**硬判**（目标路径不是预期的隔离目录就**拒绝运行**），**不许用 `??` 兜底**；并且**验证隔离真的生效**（打印实际加载的模块路径 / profile 路径）。 |
| 🔴 **`pnpm add file:` 会按 `package.json` 的 `files` 白名单裁剪「安装副本」（2026-09-24 实测）** | `dsh plugin add file:` 装出来的目录**只含 `files` 列出的文件**（实例：引擎安装副本只剩 24 个文件、`test/` 全没；客户端只剩 7 个）。→ 运行期代码 DIFF=0 不影响功能，但**「安装副本 ＝ 工作区副本」对未列入 `files` 的文件不成立**；推论：**不该进运行时的文件（声明、探针、测试）不要写进 `files`**；**核哈希时只能核 `files` 之内**。 |
| 🔴 **探针/辅助 `.mjs` 不能躺在别的插件包里（2026-09-24 实测：profile 直接起不来）** | 把一个日志桥 `.mjs` 放在 `classroom-ui/` 目录树里 → 客户端 `client-modules` 判定「**同一个包被两个 Loader 源解析**」→ 整个 profile **起不来**。→ **规则**：探针/脚本要**自带 `package.json`** 单独成目录（如 `probe/`），别寄生在别的插件包里。 |
