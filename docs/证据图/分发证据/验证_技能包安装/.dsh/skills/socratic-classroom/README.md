# 苏格拉底式教室 · 技能包

把一整套「教室」交给任何一台装了 DSH 的机器：装一次，新开对话就能上课。

包里自带一个现成的教室：**计算机系教室 · 操作系统**（14 讲，教材正文写到第 7 讲，其余在写）。
你也可以换成自己的教室 —— 只要那个目录里有 `classroom.yaml`。

---

## 装上之后的三步操作

### 第一步：把这个文件夹整个复制到「技能目录」

复制的是**整个 `socratic-classroom` 文件夹**（里面有 `SKILL.md`、`classroom/` 等），不是里面某个文件。
两个位置都行，二选一：

**A. 只给一个项目用** —— 复制到那个项目的根目录下：

```sh
mkdir -p "<你的项目>/.dsh/skills"
cp -R socratic-classroom "<你的项目>/.dsh/skills/"
```

**B. 所有项目都能用**（推荐）—— 复制到你的 DSH 主目录下：

```sh
mkdir -p "$DSH_HOME/skills"
cp -R socratic-classroom "$DSH_HOME/skills/"
```

**C. 放到 `~/.agents/skills/`**（宿主也扫这个根，优先级最低）：

```sh
mkdir -p ~/.agents/skills
cp -R socratic-classroom ~/.agents/skills/
```

> 🔴 **桌面版 DSH 的 `$DSH_HOME` 不是 `~/.dsh`**（本机实测是
> `~/Library/Application Support/dsh-desktop/harness`）。别猜路径——直接跑 `node validate`，
> 它会**把四类扫描根逐个列出来**并给出可直接复制的 `cp` 命令。

复制完不用重启，也不用装任何插件。想确认装没装上：**跑一次 `node validate` 看第 ⑤ 项**
（比"问一句有哪些技能"更可靠——问不到时你分不清是"没装"还是"装坏了"）。

### 第二步：新开一个对话，说一句话开始上课

```
用 socratic-classroom 技能，开始上操作系统课
```

（想用别的教室就说：「用 socratic-classroom 技能，教室目录是 `<路径>`」。）

### 第三步：上课，结束时说「今天到这」

上课过程中正常对话就行 —— 提问、答错、要求讲慢一点，都可以。

**结束的时候一定要说「今天到这」**（或类似的话）。这句话是课后存档的开关：它会让 AI 把进度、
课堂摘要、错题、复习计划写回教室文件。**不说的后果**：下次接着上时，它还停在上一讲。

## 想检查教室完不完整

教室自带一个自检命令（需要装 Node）：

```sh
node <技能目录>/socratic-classroom/validate
```

它会报出五件事：教室缺哪些必需文件、课程表里声明的每份材料是不是真的在磁盘上、
声明的讲次有没有超出教室讲数、教材正文还缺哪几讲，以及**本包自己现在在不在技能扫描根下**。

- 退出码 `0` = 全部通过；`1` = 查出问题（逐条打印出来）；`2` = 连检查都做不了（目录或解析器缺失）。
- **报「缺第 N 讲正文」是正常的** —— 教室正文还在写。它不是脚本报错，是内容进度。

### 第 ⑤ 项：本包在不在扫描根下（**最该先看的一项**）

技能能不能被 DSH 发现，取决于**它被放在哪里**，而不是它内容全不全。放错地方的后果是**双重静默**：
宿主既不报错、也不提示，只是**扫不到**——你在会话里看不到这个技能，也不知道为什么。

所以 `validate` 会逐个判四类扫描根，并直接打印"该放哪"的可复制命令：

```
[⑤] 发现链路（本技能包在不在扫描根下）
  本包位置：<当前所在目录>
  项目根（只认 .git）：<向上找到 .git 的那一层；找不到就是本包的父目录>
  三类扫描根逐个判：
    ✗ 不在  项目级 · .dsh/skills  [project-dsh rank=100]  →  <项目根>/.dsh/skills
    ...
  ✗ 本包**不在任何扫描根的直接子目录下** → 宿主扫不到它：候选 0 条、告警 0 条（双重静默）
    请把本包放到下面任一个位置（直接复制整包，路径可直接复制）：
      cp -a "<本包路径>" "<项目根>/.dsh/skills/socratic-classroom"
```

顺带它还会校验 `SKILL.md` 的 frontmatter：`name` 必须匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`、
`description` 必须非空，且值里不能有"裸冒号"（`description: 文本: 还有冒号` 会让 YAML 解析失败）。

> 宿主对技能加载失败的处理是**只写一条 `logger.warn` 然后跳过**，模型侧拿不到任何诊断 ——
> 所以「装没装上」这件事只能靠这个自检来问，不能靠"看日志"。

## 目录里有什么

| 路径 | 作用 |
|---|---|
| `SKILL.md` | 技能本体。DSH 在会话开始时只读它的名字和一句话说明；真正上课时才读全文 |
| `classroom/` | **教室内容**（自包含副本）。课程表、知识点、故事节点、教材正文、教师人格、世界观、纪律便条、运行记录，都在这里 |
| `validate` | 自检命令 |
| `sync-classroom.sh` | 把源教室目录同步进 `classroom/`（改教室内容后跑一次，副本才跟上） |
| `node_modules/yaml` | 自检用的 YAML 解析器，随包附带 |

### 依赖来源

`validate` 只用 Node 内置模块，外加一个 YAML 解析器 `yaml`（v2.6.1）。

它是**复制过来的，不是新装的**：来源是本仓库里教学插件 `code/plugins/socratic-engine/`
本来就声明的依赖（同一个包、同一版本），复制一份进包内，好让技能包离开本仓库也能独立运行。
`LICENSE` 随包一起复制。没有联网安装，没有改动任何文件内容。

> 为什么不用手写解析：`classroom.yaml` 的解析结果决定了自检报不报得出问题，
> 手写一个"够用"的解析器会在它不认识的结构上悄悄少报 —— 那正是自检最不该犯的错。

### 副本与源教室的关系

`classroom/` 是 `code/classrooms/cs-os/` 的**副本**。两边不会自动联动：

```sh
sh sync-classroom.sh              # 从默认源教室同步
sh sync-classroom.sh <教室目录>    # 从别的教室同步
```

**代价说清楚**：复制 = 包体积翻倍，且源教室更新后必须手动跑一次同步，否则副本会旧。
换来的好处是「一个文件夹复制过去就能用」，不依赖任何外部路径。
