## 本讲要回答的核心疑问

> **先用一个简化模型：一颗核心一次只给一个程序执行机会，暂不讨论核心内部怎样并行处理指令。音乐播放器和浏览器都有事要做时，怎样让两边都有机会继续？**

**先把题目讲清楚**："打开着"不等于"这一瞬间占用 CPU"；这是讨论操作系统如何分配执行机会的入门模型，不是在问现代 CPU 一周期能执行多少条指令。学生若追问硬件线程、流水线或超标量，承认真实机器更复杂并回答相关问题，再说清本讲简化的目的。不要让学生猜"桌上""没改完""被手按着"各指什么，也不要把"一笔"当作新的技术单位。

## 教学地图（选择动作，不按顺序过关）

### 值得学生推导的关键关口

**一个核心怎样让两个程序都有执行机会？** 在本讲的简化模型中，只有一个程序能在某一刻获得这个执行位置。如果学生还没想到轮流，可以问："浏览器先占用这个位置，音乐播放器后来怎样获得机会？"若学生已说出轮流或时间片，直接确认；若他想不出或要求说明，教师解释时分共享。不要继续用更小的同义问题让他猜“轮流”。

**受限直接执行的取舍**可在学生已有背景时讨论：让程序直接使用 CPU 很快，但如果它一直不交还控制权，其他程序怎么办？这是可推导的后果。硬件定时器、特权级和系统调用是教师要提供的机制事实，不是学生凭空猜出的谜底。

### 关键点之后的讲解主线

学生理解“轮流”之后，先讲与它直接相连的**切换如何接得上**。下面三个片段彼此衔接，但不是要求同一轮全讲完的清单；学生的提问也可能改变顺序。可用白板、代码或稿子演示；插问时先回应。不在每个细节之间追问，也不在讲完片段后自动考一遍。

- **片段一 · 切换后怎样接着跑**：程序文件是静态的；程序的一次执行连同当前状态称为进程。进程可能正在执行，也可能等待 CPU 或输入输出。切走时保存执行位置与寄存器等状态，切回来时恢复；这就是上下文切换的核心。不保存就无法正确接续，不能断言它必然“从头再跑”。
- **片段二 · 操作系统怎样重新介入**：程序可直接在 CPU 上运行以减少干预，也可能通过系统调用、异常或自愿让位进入内核；但操作系统不能只依赖程序主动配合。在抢占式模型中，硬件定时器中断让内核即使面对持续运算、不主动让位的程序，也能定期重新取得控制权。操作系统可以据此决定是否切换；中断不意味着每次都必须换进程。
- **片段三 · 程序为什么不能随意操作机器**：普通程序在用户态不能执行特权指令；需要这些操作时通过系统调用进入内核，由操作系统处理。用户态/内核态与定时器中断分别处理特权操作和重新取得控制权的问题。访问其他进程的内存还依赖地址空间与硬件内存保护，不能只用“用户态不能执行特权指令”解释。

这些机制一起解释本讲的**受限直接执行**与 CPU 虚拟化：多个进程共享 CPU，每个进程获得自己的执行机会和状态。不要把“看起来独占”说成进程真的检测不到切换。

**角色内的讲法仅供示意**：学生说“轮流用核心”后，小鞠可以先确认，再在白板上写 `A 执行 → 存 A 的状态 → 恢复 B 的状态 → B 执行`，解释“进程”和“上下文切换”。这段说完可以停顿，不必问“谁去切”或“它凭什么拿回来”，也不必马上把定时器和权限一起讲完。若学生问控制权如何回来，再进入片段二并直接给硬件事实。

### 真正值得再停下来的地方

- 学生把“指令已在内存／缓存中”当作“已经获得 CPU”：直接说明前者关系到取得指令或数据，后者关系到执行机会。若他仍混淆，可比较“存放位置”与“正在执行的状态”。
- 学生把“保存执行现场”当成“把程序文件再放进内存”：区分程序文件、进程状态与缓存。可用切换后从哪条指令继续的例子检验。
- 学生问真实 CPU 是否一次只能执行一条指令：说明本讲只是假设一个执行位置来讨论操作系统的时间共享；现代核心可能有流水线、多个执行单元或 SMT，不把简化模型说成硬件定律。
- 学生问“程序不让位怎么办”：这是讨论抢占与定时器中断的自然关口。先给出硬件事实，再讨论为何不能只依赖自愿让位。不要说“程序永远不会自己停”或“没有定时器就绝无进入内核的途径”。

不要把刚刚解释过的“没有定时器会怎样”原样作为轮末考题；要检验理解，可换一个未讨论过的情境或等学生提出疑问。

若学生已经理解某个混淆，就跳过；若他主动问更深入的机制，顺着问题展开。上述项目不是必须逐一问完的题单。

### 检验理解的一个新情境

例如：音乐播放器被切走后，浏览器执行了一会儿；音乐播放器再获得 CPU。让学生解释它为什么能从暂停处继续，以及“播放器的指令仍在内存里”是否足以保证这一点。教师可以先讲解再检验，也可在学生已掌握时直接继续下一讲。学生能解释或应用机制即可，不必复述预设句子。

## 本讲核心事实（知识锚 · 不许说错）

- 进程是**程序的一次执行及其状态**（含寄存器等执行状态）；进程也可能暂时等待 CPU 或输入输出，程序文件本身是静态的。
- 虚拟化 CPU 可通过**时分共享**：操作系统在多个进程间切换，让每个进程获得执行机会；“仿佛独占”是帮助理解的简化说法，进程仍可能观察到等待与切换。
- **受限直接执行**：程序**直接在 CPU 上运行**（这是"快"的来源），操作系统通过
  ① **用户态/内核态**（限制特权操作）与 ② **时钟中断**（在抢占式模型中定期让内核重新取得控制权，不依赖程序主动让位）来保持控制。
- **用户态不能执行特权指令**；需要特权操作时，程序**请求操作系统代做**（系统调用）。
- 其他进程的内存受到地址翻译和硬件保护；**不能只靠用户态/内核态这一对名称解释内存隔离**。
- **上下文切换** = 保存当前进程的执行状态 + 恢复下一个进程的执行状态。

## 类比的边界（可能误导时讲清）

**编辑部隐喻在哪不成立？**
- 人处理稿件的动作与 CPU 上的上下文切换不是同一种工作，不能用人的动作时长推断机器开销。
- 人会有"想起来"这种主动行为；**CPU 不会**。在这里讨论的抢占式模型中，硬件定时器帮助操作系统重新取得控制权。
- 稿子是**被动**的；持续运算、未主动请求内核服务的程序可以一直占用 CPU，因此抢占不能只靠它自觉让位。程序也可能因系统调用或等待输入输出而暂停。
