# 苏格拉底式教室

## 这是什么

一个**教室**就是一个目录，里面是：

- **内容**（markdown）：课程表、知识点清单、每讲的故事节点、每讲的教材正文、教师人格、世界观与隐喻、纪律便条；
- **`classroom.yaml`**：声明每份材料"放在上下文的什么位置、多久给一次"；
- **`runtime/`**：8 个运行记录（进度、学习者档案、课堂摘要、历史归档、复习队列、错题本、日记、群聊）。

它**不需要装任何插件**。插件版本做的是"按讲次和课堂环节自动把材料喂进上下文"；在这个技能里，那件事由**你按下面的顺序自己读**来完成。所以纪律比插件版更依赖你照做。

## 教室在哪

- **本技能自带的教室**：`<本技能目录>/classroom/`（当前是「计算机系教室 · 操作系统」，14 讲）。
  `<本技能目录>` ＝ 加载本技能时 `skill_resources` 里给出的 base directory。
- **用户也可以指定别的教室**：只要那个目录里有 `classroom.yaml`，就把下文的 `<教室>` 换成它。

🔴 **教室内部的一切相对路径都相对 `<教室>` 解析**（`story/ch01.md` ＝ `<教室>/story/ch01.md`）。
**不要**把它们解析成当前工作目录。

## 怎么上课

### 第 0 步 · 读入口（先做，别跳）

完整读一遍 `<教室>/AGENTS.md`。**它是这个教室唯一完整的操作手册**：六层加载顺序、启动顺序、课后更新清单、教材路径规则都在里面，本技能不重复它的内容。

⚠️ 宿主只会自动加载"当前工作目录链上"的 `AGENTS.md`。教室目录通常**不是**当前工作目录，
所以它**不会**自动进上下文——**你必须显式读它**。

### 第 1 步 · 每轮课前（不可跳过）

按 `AGENTS.md` 的「第一步」逐条读，其中 `<教室>/_anchor.md` **必须每轮读**：
它是这个教室最硬的教学纪律（教学取向 + 本课不许违反项 + 角色声音速查），
放在贴近本轮对话的位置才有约束力。

### 第 2 步 · 本课首次（一节课只需一次）

按 `AGENTS.md` 的「第二步」逐条读：教学法、世界观与隐喻、课程表、当讲知识点、当讲故事节点、当讲教材正文。

- **当讲讲次** ＝ `<教室>/runtime/progress.md` 里的机器可读行 `current_lesson: <整数>`。
- 故事节点是 `story/ch{NN}.md`，教材正文是 `materials/ch{NN}.md`，`NN` 是两位数字的讲次。
- 🔴 **故事节点是"节点说明"，不是可以直接念出来的正文**；教材正文是**教师侧的追问脚本**，也不是给学生念的课文。两者的用法写在各自文件头部。

### 第 3 步 · 上课

- 严格按 `<教室>/system_core.md` 的教学法走：先判断学生处在什么理解状态，再决定是追问、讲解还是换例子。
- 台词用当课老师的声音（`<教室>/_anchor.md` 的「角色声音速查」段；需要更完整的性格描写时才读 `characters/*.md`）。
- 隐喻只用来建立直觉；**正式术语与机制以 `materials/ch{NN}.md` 为准**。

### 第 4 步 · 按课堂环节换材料

插件版按"相位"自动换材料；**这里由你判断并显式去读**。六个环节（以 `classroom.yaml` 的 `phases` 声明为准）与它们对应的材料：

| 环节 | 这时该读的材料 |
|---|---|
| 开场 `open` | 当讲故事节点 `story/ch{NN}.md`（讲完开场就不要再念它） |
| 追问 `probe` | 当讲教材正文 `materials/ch{NN}.md` |
| 学生作答 `answer` | 不需要额外材料——听学生说 |
| 对答案 `check` | `materials/ch{NN}.md` + 当讲知识点 `knowledge_points.md` |
| 复习 `review` | `runtime/review_queue.md`、`runtime/mistake_log.md` |
| 收尾 `close` | `knowledge_points.md`（判档）、`runtime/*`（写回） |

不必按顺序走完六个，来回切换是常态；一节课走两三个环节完全正常。
**不需要向学生播报"现在进入追问环节"**——那是实现语言，不是课堂语言。

### 第 5 步 · 课后更新（学生说"今天到这"才做）

按 `AGENTS.md` 的「课后更新」逐条改盘，一个都不能漏。最容易忘、后果最重的一条：

> 🔴 把 `runtime/progress.md` 顶部的机器可读行 `current_lesson: <整数>` **改成下一讲**。
> 它的语义是"**本轮要讲的讲次**"，不是"已完成的讲次"。忘了改 → 下一节课仍然按上一讲的材料上课，而且不会报错。

## 自检（教室缺文件／声明对不上时用）

教室自带一个自检脚本，检查四件事：必需文件是否齐全、`classroom.yaml` 声明的材料是否真的在磁盘上、声明的讲次序号有没有超出教室讲数、教材正文还缺哪几讲。

```sh
node <本技能目录>/validate            # 检查本技能自带的教室
node <本技能目录>/validate <教室目录>  # 检查指定教室
```

退出码 `0` = 全部通过，`1` = 查出问题（逐条打印），`2` = 连检查都做不了（目录或解析器缺失）。
**报告缺教材正文是正常的**——教室正文由另一条工作线在写，没写完就会报出来，不要当成脚本出错。
