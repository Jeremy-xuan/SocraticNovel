### A2 「项目根」怎么定（**只认 `.git`**）

`:799-807`：

```js
async function findProjectRoot(cwd, fs) {
  let current = cwd;
  while (true) {
    if (await pathExists(join(current, ".git"), fs)) return current;
    const parent = dirname(current);
    if (parent === current) return cwd;      // 一路到根都没 .git → 回落 cwd

  }
}
```

### B2 bundle 名怎么解析（决定「能不能预置进 app」）

`tmp/dsh-installed/dsh-app-boot/lib/index.js:840-846`：

```js
function resolveBundleDir(binName, packageName, installAnchor, profileDir) {
  for (const anchor of [installAnchor, join(profileDir, "package.json")]) {
    const dir = packageDirFromAnchor(anchor, packageName);
    if (dir !== void 0) return dir;
  }
  throw new Error(`${binName}: cannot resolve profile bundle ...`);
}
```

🔴 **先查 `installAnchor`（＝ dsh 应用自己的 `package.json`），再查 profile 目录。** 也就是说：**把包放进桌面 app 自己的 `node_modules`，它就能被当作 bundle 解析到。**

`dsh-app-boot/lib/index.js:1551` 与 `:1577` 还有一条更明确的注释：`bareModuleBaseUrl` = *"optional installed-host base for bare package resolution … for closed packaged runtimes"*，用于让**裸包名**也从安装宿主解析。
📌 **注意版本差**：`bareModuleBaseUrl` 是**上游 main 的新能力**（安装版 0.9.1 的 `main/index.js` 里**没有**它；extraResources 里的 `build/host-module-fallback.mjs` 在上游仓库有、在 0.9.1 的 Resources 里**不存在**）。→ 0.9.1 上「bundle 名从 app 解析」成立（`resolveBundleDir` 路径），「patch 行裸名从 app 解析」不成立。

## F · Prior art（同类实现怎么做）

### F1 `dsh-tauri/deepseek-harness-desktop`（MIT，2,571★，Tauri 2）—— **最贴近「把插件预装进桌面版」的先例**

README 逐字卖点：*"🧩 插件管理 … 🎁 **内置插件** — 随安装包内置插件 … 🪶 原生轻量 — Tauri 2 外壳（非 Electron）… 🧭 **启动引导** — 首次启动可选推荐插件，也可在配置中重新选择"*

**它的两层机制（带出处）：**

**(a) 内置插件（随安装包走）**
- 清单：`src-tauri/resources/internal-plugins.json`（4,104 字节，10 条），每条 `{id, spec, name, description, repoUrl}`（必要时加 `package` 字段）
- 打包：`src-tauri/tauri.conf.json` 的 `bundle.resources = ["resources/**/*"]`
- `src-tauri/resources/README.md` 逐字：*"Plugins that must ship **with** the installer and are treated as part of the app (auto-installed and auto-healed at startup) live in `internal-plugins.json`… The entries are bundled at build time by `scripts/build-plugins.ts` (via `pnpm deploy` of the workspace packages listed in `packages/dsh-tauri-bundle`) into `resources/node_modules/<name>` (via `bundle.resources`) and never appear in the first-run checklist."*

**(b) 预设插件（首次启动向导里勾选）**
- 清单：`src-tauri/resources/preset-plugins.json`（1,742 字节，4 条），字段逐字：`id / spec / version / name / description / repoUrl / recommended / defaultUnchecked / dshSupportedVersion`
- 逐字：*"The first-run wizard / sidebar preset list is driven by `preset-plugins.json` (loaded at runtime by `src-tauri/src/service/plugin/mod.rs` — **no Rust code change needed to add a preset**)."*
- 逐字：*"The plugin itself is **not** vendored into this repository — it is installed on the user's machine from `spec` at setup time, so the PR only needs to add the JSON entry."*
- 逐字（**升级怎么发**）：*"the file ships with the installer and is force-overwritten on every install, so the app records a fingerprint of its content into the user-data settings after the wizard ends (install or skip) and re-opens the wizard on the next launch when the content differs."*
- 逐字（**兼容性/自动清理**）：`dshSupportedVersion` 比当前核心低时禁用该预设并纳入自动清理；`deprecated-plugins.json` 是独立的弃用名单。
- 另有 `version-recommend.json`：`{"dsh":"0.1.5-rc.3"}`

**(c) 它自己也用生态标准技能锁**
- 仓库根有 `skills/` + `skills-lock.json`（49,976 字节，形如 `{source, ref, sourceType:"github", skillPath, computedHash}`）→ 与下文 F4 的 `npx skills` 锁格式一致。

**(d) 它的 `$DSH_HOME` 策略**
- `src-tauri/resources/README.md` 逐字：*"The user data directory (`$DSH_HOME`) used by the running `dsh` process follows the **official dsh convention** (`${DSH_HOME:-$HOME/.dsh}`) … This way the desktop app and a `npm i -g @deepseek-ai/dsh` install share the same profiles, sessions, settings and credentials."*
  （📌 与 Electron 版不同：Electron 版用 `~/Library/Application Support/dsh-desktop/harness`。）
- 运行时资产**不在安装包里**，而是首启下载：`runtime/`(Node 运行时)、`dependencies/dsh/`(打包的 DSH 发行版)、`logs/`、`.store.dat`。→ **安装包只有 ~5 MB 的原因。**
