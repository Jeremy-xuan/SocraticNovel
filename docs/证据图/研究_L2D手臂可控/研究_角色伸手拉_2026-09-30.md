## 〇 · 一句话结论

**做得到，而且本轮已经在本机跑通并出了视觉证据。**

上一轮说"做不到"的三条依据**本身没错，但结论错了** —— 它们描述的是 **我们那次构建用的资产与分层**，
不是**这套工具链的能力**。换一个立绘姿势 + 喂对分层，**手臂参数自动就出来了，而且真的驱动几何**。


## 一 · 上一轮的结论错在哪（诚实复盘）

上一轮写的三条"做不到"依据，逐条复核：

| 上一轮的说法 | 复核结果 |
|---|---|
| 「Live2D 能程序化写的参数只有 Angle/BodyAngle/Breath/EyeBall/嘴型，**没有手臂参数**」 | 🔴 **说的是"我们那个模型里没有"，被误写成了"Live2D 没有"**。image2live2d 明确支持 `ParamArmLA/RA/LB/RB`（
`tests/test_limbs.py:111` 逐字：`{"ParamArmLA","ParamArmRA","ParamLegLA","ParamLegRA"} <= ids`）。 |
| 「模型自带动作只有通用型（Idle/Tap/Flick）」 | 说的是 **Cubism 官方样例模型**（miku 那批）。**我们自己生成的模型**动作是 image2live2d 产的：
`arms_raise` / `arms_swing` / `legs_sway` / `legs_swing` / `idle` / `blink` / `talk` … 共 22 组。 |
| 「`motion3.json` 曲线解析未做 → 给不出动作长什么样」 | 这条**没错**，但它只影响"预览别人模型的未知动作"。**我们不需要读别人的动作——我们自己生成**。 |

**根因**：把「我们手上的资产跑出来的结果」当成了「技术上限」。

## 二 · 真正的阻塞点（两个，都在我们这边）

### 2.1 喂错了分层（主要的）

P2L-2 当时给 image2live2d 喂的是 **P2L-1 的 12 层**：

```
10_hair_back 20_torso 30_blush 30_face_base 40_mouth
50_eye_l 50_eye_closed_l 60_eye_r 60_eye_closed_r
70_hair_side 80_hair_side 120_hair_front          ← 没有手臂、没有腿
```

而 **auto-layer 的 19 类输出**里本来就有 `017_handwear_l/r`、`010_legwear_l/r`、`013_bottomwear`。
**两条线从没接上。**

### 2.2 立绘的手臂压在身体上（决定性的）

同一个 19 类分割器，跑两张图：

| 图 | 命中类别 | 有手臂吗 |
|---|---|---|
| `test1`（手臂离身） | `[0,2,3,5,8,9,11,12,13,14]` 共 10 类 | ✅ handwear / bottomwear / legwear |
| `ourasset`（手臂贴身 + 只到腰） | `[0,2,3,5,7,8,9,11]` 共 8 类 | ❌ **只到 topwear** |

**分割器靠轮廓找工作**。手臂贴在身上 → 与躯干同一轮廓 → 分不出来。
`author.py:436` 的注释逐字承认这个机理：
> *「silhouette-based landmark reads the centroid of *both* arms — the body midline — and hands every [...]」*

🔴 **而这一点我们控制得住** —— 立绘是我们生成的。

## 四 · 🔴 本轮踩的坑（会让人误判"参数没用"）

**`getParameterIndex(id)` 返回的索引是错的。**

第一版探针用 `model.setParameterValueById('ParamArmLA', v)` 写值，读数 **0 像素变化**，
一度得出"参数只是声明了、不驱动几何"的错误结论。

逐层排查后：
- `getParameterIndex('ParamArmLA')` 返回 **32**
- 但 `getParameterCount()` = **30**（合法索引 0–29）
- 按运行时参数表逐个数，**真实索引是 20**

→ 用 id 写命中错位/落空，画面当然不动。**改成 `setParameterValueByIndex(20..23, v)` 立刻就是 24,008 像素。**

📌 **教训**：`setParameterValueById` 在这种模型上**静默失败**（不报错、不警告）。
判据必须是**逐像素差**，不能靠"调用没抛异常"。
📌 **与既有教训同族**：本项目已经踩过两次「量错东西」（量到插值、量到被 max-height 夹住的值）——
这次是第三种：**写错了目标**。

## 五 · 还剩什么（离"真的拉出来"还差）

已解决：**手臂能动**（本节实测）。

还欠三件：

| # | 欠什么 | 难度 | 说明 |
|---|---|---|---|
| 1 | **立绘生成规范**：手臂必须离身 | 低 | 只是提示词约束。**建议写进立绘生成模板**，并加一条程序化自检：分层后必须出现 `handwear_l/r`，否则重生成 |
| 2 | **把「拉」做成一条动作** | 低 | `arms_raise` 是"抬双臂"。我们要的是**单臂向前伸**。image2live2d 的动作是**程序生成的**（`sweep_character.py` 的 `POSES` 表就是参数配方），加一条自定义配方即可 |
| 3 | **衔接**：动作 → 面板时序 | 低 | `idle-director` 已经在程序化写参数。新增一个 `reach` 通道写 `ParamArmL{A,B}`，与面板三段时序（170/390/220ms）对齐 |

**没有一项需要新的研究或新依赖。**

## 八 · 边界与诚实声明

- 本轮所有结论**只对 `armtestchar` 这一个模型、这一次构建成立**（同一份 image2live2d 版本、同一套层）。
  换立绘必须重跑 ①②，并复核 ④ 的像素数。
- `arms_raise` 的动作值（10 / 7）**是 image2live2d 的预设配方**，不是我调的参数——本轮只是验证它能用。
- 本文的"伸手"**是指手臂几何可控**；"读起来像在拉东西"还需要 §五 第 2、3 项（单臂前伸配方 + 时序衔接）。
- 本轮**没有**验证：手臂动作与物理（physics3）的相互作用、长袖衣物在手臂运动时的形变质量。
  这两项要等 §五 做完再看。
- 全部证据落盘 `开源线/DSH定制/研究_L2D手臂可控/`；渲染对比图在
  `code/mockups/stage-modern/shots/arm-control-proof.png`。
