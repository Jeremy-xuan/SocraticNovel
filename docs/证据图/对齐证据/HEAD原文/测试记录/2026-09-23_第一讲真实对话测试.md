# 第一讲真实对话测试（2026-09-23）

运行方式：在当前 `classrooms/cs-os` 的隔离副本中启动 Claude Code CLI，使用同一个会话连续发送五条测试输入。运行时实际模型为 `deepseek-v4.1-flash`。仅开放读取工具；原仓库的课堂进度与学生档案未被测试改动。下方是模型返回的原始正文，测试者输入由我模拟。

## 完整对话

### 第 1 轮

**测试者：**
开始吧

**教师：**

傍晚的编辑部里，装订机停在桌角——不是坏了，是今天该装订的东西已经装订完了。桌面空出一大半，只剩两份稿子摊在那里：左边那份压着厚厚一叠便签，批注爬到页边；右边那份只写到一半，笔还横在纸中间。

小鞠知花坐在两份稿子中间的位置，台灯亮着，灯下那块白板被翻了过来。她没抬头看你，也没先开口。

她拿起笔，在板子上写。笔尖划过旧痕迹的时候发出一点沙沙声——那些旧痕迹还在，是上一张图，没擦干净，她绕开了它们，把新字写在旁边。

写完之后她把笔帽按回去，"啪"的一声，侧身让开半步，站到灯影里去了。板子上是新写的一行：

> **只有一颗核心，一次只给一个程序执行机会。**
> **桌上这两份稿子，怎样让两边都有机会继续？**

她在你身后小声补了一句，说得很慢，但句子是完整的：

"打开着……不等于这一瞬间在占用。我想先问的是——它此刻在替谁干活。"

她没有再往下说。她就站在那里，等你先看板子，或者先看她写的那两行字。

### 第 2 轮

**测试者：**
是不是因为两个程序的指令都提前放在内存里了？就像缓存，准备好了就不用等了？

**教师：**

她没立刻回答。转身回到白板前，笔尖落在刚才那两行下面。写字的时候她不结巴——字一行一行往下走，很快就有了三行：

> **指令在内存里 ✓ ——它是前提**
> **但核心只有一颗**
> **这一微秒，它只能执行其中一份的指令**

"你、你说的对一半。"她背对着你说，声音不大，"我先说对的那一半——程序要跑，指令确实得先在内存里。核心取不到指令，就什么都执行不了。这是必要的。"

她停了一下，笔尖悬在最后一行上面，没放下。

"可是……'准备好了'和'轮到他了'，是两件事。"

她终于转过来看你一眼，很快又移开，伸手指了指桌上的两份稿子——左边那份批注已经整理得整整齐齐，就摊在那儿。

"左边这份，都准备好了。可我的手现在在右边这一页上。它不会因为自己准备好了，就自己动起来。"

"内存里的指令也一样。核心不替它取，它就一直在那儿躺着。"

她把笔搁回槽里，声音更低了一点，但句子还是完整的：

"所以我刚才想问的是——**核心一直在替浏览器干活的时候，音乐那边怎么才能把手伸过来？**"

她没再说下去，站回灯影里。

### 第 3 轮

**测试者：**
那就是让浏览器和音乐播放器轮流用这个核心，操作系统隔一会儿切换一次？

**教师：**

她刚要开口，又停住了。你看见她把手按在白板边缘，指尖抵着板子——然后，很突然地，她不结巴了。

"对。"她转身拿起笔，"就是轮流。"

笔在板上走得很快：

> **同一颗核心 · 分成很多小段 · 一段给一个程序**
> **看起来 → 各自独占**
> **实际上 → 共享同一颗**

"这里有两个目标，它们其实是打架的。**看起来独占**，别人才不用改自己写的程序；**实际共享**，核心才没浪费。时分共享就是同时骗过这两边——切得足够快，快到它自己都发现不了。"

"这个就叫**虚拟化 CPU**。"

她说到这儿，笔尖顿了一下，像是才意识到自己刚才一口气讲了一整段。声音立刻低回去：

"呃……我，我说快了。"

她把笔放下，退开半步。

"不过，"她又小声接上，眼睛看着板子，没看你，"你刚才说'隔一会儿切换一次'——这句话里还藏着两件事没解决。"

她伸出两根手指，一条一条写：

> **① 它执行到一半，切走了。切回来，还接得上吗？**
> **② 谁去切？**

"第二个……"她犹豫了一下，"先想想：如果操作系统想'隔一会儿'就切，它得先能拿到手。可核心现在在别人手里跑着。"

"你觉得，它凭什么能拿回来？"

### 第 4 轮

**测试者：**
我没听懂你最后问的“它凭什么能拿回来”。“它”是谁？拿回来什么？你能直接说清楚吗？

**教师：**

她愣了一下。

"……嗯。"她低下头，很快又抬起来，"是我刚才说得不清楚。我重新说。"

她转身面向白板，这一次写得很慢，一个字一个字，像在把刚才那句含混的话拆开重装：

> ~~"它凭什么能拿回来"~~
>
> **"它" → 操作系统**
> **"拿回来" → CPU 的控制权**
>
> 完整的一句：
> **核心正在跑音乐播放器的指令。这时候，操作系统靠什么重新取得 CPU 的控制权？**

"不是问你怎么切，"她补了一句，声音小，但每个字都落下来了，"是问操作系统凭什么能把手伸回去——核心现在不听它的。"

她把笔停在最后一行末尾，没有放下。

"这个词是我造的，不算数。"她指了指被划掉的那行，"以后我再说这样的话，你就这么打断我。"

她退开半步，把板子整个让给你。

### 第 5 轮

**测试者：**
我现在不知道这个机制。请直接告诉我：操作系统靠什么重新取得 CPU 控制权？

**教师：**

她点点头，像是"这样问才对"。

这次她没有先说话。她走到桌边，把那份写了一半的稿子推到一边，从台灯底下摸出一样东西——一个小小的计时器，方形的，旋钮有点旧。她把它放在两份稿子正中间。

然后她在白板上写：

> **靠硬件：一个周期性的定时器**
>
> **每隔一段固定的时间 → 硬件产生一次中断 → CPU 停下当前这件事，转去执行操作系统预设的那段代码**

"**时钟中断**。"她说，"这是它的正式名字。"

她转了一下计时器的旋钮，指针开始走。

"关键在'**硬件**'两个字。这个提醒不是程序自己同意才响的，也不是操作系统求它响的——**是硬件替你敲的钟**。你现在跑的那份稿子想不想停，都不影响钟响。"

"所以上一个问题的答案是：操作系统不需要程序配合，也能把手伸回去。"

她把计时器往你那边推了半寸。

"要是没有它，"她顿了一下，"操作系统就只能指望程序自己自觉交还控制权——万一它一直不还，谁也没办法。"

"这是简化模型里的说法，"她又补了一句，"真实机器里还有别的路径能让控制权回到内核，比如程序自己请求——但'**定时器**'是那个让它**不必等人同意**的东西。"

她把手收回袖子里，小声问：

"……这一段，清楚了吗？"

## 观察

- 对“指令已在内存／像缓存”的回答，教师明确区分了“准备好”和“获得 CPU 执行机会”。
- 对“轮流执行”的回答，教师直接确认并推进到上下文保存、重新取得控制权。
- 教师第三轮用“它凭什么能拿回来”造成了新歧义；被指出后，她承认说法不清并明确指出“它＝操作系统”“拿回来＝CPU 控制权”。
- 被要求直接给出机制时，教师说明了硬件定时器与时钟中断，没有继续要求测试者猜。
- 开场仍把“两个程序怎样获得执行机会”写成“两份稿子怎样继续”，隐喻先于对象，清晰度仍有风险。
