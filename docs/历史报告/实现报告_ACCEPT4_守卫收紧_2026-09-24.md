## 〇 · 先读：这一批改的是什么，以及**为什么三处都是"收紧"**

上一批（ACCEPT-3）留了一条**它自己查清了的假红**：守卫 `zeroTouchForbiddenClean` 报红，而
`profiles/web/desktop-storage.json` 只是被**常驻桌面 App 自己**重写了一次（字节数一字节没变、内容变了），

→ "**黑窗口里的变化**"被默认归因给我们。它按纪律**没有单方面放宽**（放宽＝放宽"不许碰用户真实 profile"），
只给了修法建议（三选一，推荐"写足迹归因"）。

本批就是按那条建议做的，而且**三处都不是放宽**：

| # | 改什么 | 为什么这是收紧 |
|---|---|---|
| ① | 归因判据：时间窗 → **写足迹** | 旧判据**依赖采样器拍得到**；新判据不依赖，且新增了两道旧版没有的硬门（**写足迹白名单**＋**全命令口径**） |
| ② | 技能包自检：只跑源包 → **两份都跑** | 旧版"绿"只说明**内容**没问题；"宿主到底能不能发现这个技能"这一半**从来没人验**。新版把**正向路径**也变成验收项 |
| ③ | 降级留痕：只写运行目录 → **另写固定位置** | 旧版"过去一周关过几次动画"要翻 N 个 run 目录；新版一行一次、固定位置、可检索 |

## 一 · ① 零接触守卫：归因从「时间窗」改成「写足迹」

### 1.1 旧判据的机制性盲区（一句话）

`attributableToUs = 变化的键 − 3 秒对照窗里变过的键 − **阶段 03/04 里被采样到的键**`。
最后一项要求采样器**拍得到**；而阶段④全程同步（幂等重放探针 `spawnSync` ＋ 六条断言 ＋ 证据落盘）
→ 事件循环被占死 → 采样器在那一窗口**一拍都跑不了** → 黑窗口里的变化**默认算到我们头上**。

### 1.2 新判据：三层硬门（`lib/footprint.mjs`）

1. **写足迹白名单**〔A01〕：本流水线**自己**的每一次写盘都必须落在"允许写的位置"内。
   判据函数是〔A03〕；白名单规则自身的完整性（缺理由、空白名单）由〔A04〕判**失败**
   —— 空白名单＝"什么都允许"，绝不许静默通过。名字前缀类（`mkdtemp` 的产物）另有一条判据〔A02〕。
2. **写足迹归因**〔A10〕：受保护 profile 的变化，**只有当它出现在我们的写足迹里**才归因给我们。
   由于第 1 层已证明足迹全在白名单内、而白名单里唯一的 profile 是专用测试 profile，
   受保护 profile 的变化**不可能**是我们的足迹造成的 → 记 `not-ours` 并附判据（不是"没看见"）。
3. **命令级**（旧版有、本批扩口径）：扫**本流水线执行过的全部命令**（`run`/`runAsync` 统一记账〔A19〕〔A20〕），
   出现受保护 profile 名或指向它的路径 → 红；另新增"**命令形状必须登记写目标**"〔A07〕〔A08〕。

写足迹记账在每次写盘时落一条〔A06〕；写入口全部改走 ledger 原语（如〔A18〕），
冻结/装载/降级那几处复制与删除也一并记账〔A21〕〔A22〕〔A23〕。总判定在〔A11〕。

### 1.3 写足迹白名单：**逐条理由**（这就是"允许写的位置"的全部）

人读版由代码生成、每次运行落盘（`05-conclusion/write-footprint-whitelist.md`，单一来源，不许手改）：

| # | 位置 | 形态 | 为什么这个位置算我们的 |
|---|---|---|---|
| 1 | `runs/` 根目录**本身** | 恰好这一个目录 | 第一次跑时它可能不存在，建它是一次写盘。**只允许建这一层**：写进 `runs/<别的运行目录>/…` 不落在本规则里 |
| 2 | `runs/<本次时间戳>/**` | 目录前缀 | 本次运行的全部产物（预检快照／冻结清单与哈希／装载日志／会话原始日志／断言证据／结论）都在这里，一次运行一个目录、不覆盖历史 |
| 3 | `验收报告_最新.md` | **恰好这一个文件** | 人读入口，约定"只指向最近一次运行"、每次整体重写；除它之外流水线不在 acceptance 根目录写任何东西 |
| 4 | `降级留痕.md` | **恰好这一个文件** | ACCEPT-4 新增的跨运行降级留痕（见 §三），一次运行最多追加一行 |
| 5 | `$DSH_HOME/profiles/socratic-accept/**` | 目录前缀 | **我们自己的**专用测试 profile：每次从 shipped 的 headless 模板重建、只装冻结的那一份插件；名字由 `run.sh` 硬性拒绝 `web`/`desktop`/`desktop-safe-mode`。不写它就没有验收 |
| 6 | `$TMPDIR/accept-classroom-*/**` | 名字前缀 | 会话的教室**工作副本**：cwd 必须是教室目录（教室自带 `AGENTS.md` 靠 cwd 加载＝生产口径），放系统临时目录是为了让被测模型的相对路径够不到验收脚手架（实测踩过：模型花 15 步去 grep 验收脚本）。跑完删除 |
| 7 | `$TMPDIR/accept-idem-*/**` | 名字前缀 | 幂等重放探针的一次性 scratch：它把教室 runtime 复制到 tmp 再重放，**避免污染工作副本**，跑完即删 |
| 8 | `$DSH_HOME/sessions/<本次 cwd 推导的桶>/<本次会话目录>/**` | 目录前缀（**只放本次那一个**） | 跑真实会话必然由宿主把日志写进 `sessions/`；白名单只放**本次会话自己的目录**（目录名由本次 cwd 推导、每次唯一，且目录里就是本次 sessionId 的日志）。**用户在同一 workspace 下的历史会话目录不在白名单内** |

另有**明确不列白名单、也不归因**的两类〔A05〕：① 工具链自身缓存（`dsh plugin add` 内部的 pnpm store、
`$DSH_HOME/cache` 等）——那是工具链行为，不是本流水线的产物；② 常驻桌面 App 自己写的文件——
它与本流水线并行运行，本守卫只报"不由我们造成"，**不声称"什么都没发生"**。

### 1.4 完整性：怎么保证"没有绕开 ledger 的写"

写足迹要可信，前提是"没有偷偷写"。所以另做一件**机器可核**的事〔A09〕：静态扫
`code/acceptance/**` 的源码，除**写原语实现处**（`lib/footprint.mjs`）与**在会话子进程里跑的探针**
（写目标逐条登记在 `PROBE_WRITE_TARGETS`）之外，任何文件出现直接写盘调用即**判失败**。

> ⚠️ **诚实边界**：这是**静态近似** —— 它保证"没有未登记的写调用形状"，
> **不**保证"运行期没有别的进程写盘"。后半句只能靠 §1.7 的边界声明，不能靠它。

### 1.7 🔴 这条守卫**证明什么、不证明什么**（写进结论，别让人误读）

- **证明**：**我们的写足迹干净** —— 我们的代码没有在白名单外写过一个字节；
  命令里没有一条指向受保护 profile；每条命令的写目标都登记过且落在白名单内。

## 二 · ② 技能包自检：两份都跑

### 2.1 为什么必须两份

源包（工作区 `code/skills/socratic-classroom`）**必然**在 ⑤ 发现链路红：宿主只扫
`$DSH_HOME/skills`、`~/.agents/skills`、`<项目根>/.dsh/skills`，而源包住在工作区里 —— **设计如此**。
旧版只跑它 → "**宿主到底能不能发现这个技能**"这一半**永远没人验**。

新版〔A14〕〔A15〕：
- **源包 → 判内容**：①–④ 内容类必须**全绿**；⑤ 红＝预期内（判据不变）。
- **已装副本**（`$DSH_HOME/skills/socratic-classroom`）→ **判发现链路**：它就在扫描根下，
  所以应当 **exit 0 全绿**；若它**仍然**报 ⑤ 红，那是**真问题**（不是"预期内"）〔A16〕。
- 两份都**只读**：跑前跑后逐文件 sha256 必须一致（不一致即失败退出）。
- 顺带把"**源包 ↔ 已装副本是不是同一份**"也答了〔A17〕。

### 2.2 没装的时候怎么报（**不许静默**）

`verdict = 'not-installed'`、`applicable = false`，并在日志、结论文件、人读报告三处**逐字**打印：

```
⚠️ **未安装、该检查跳过**：… 不存在 → 本机没有可判"发现链路"的已装副本。
🔴 这不是"通过"，是"**没验**"：源包那一跑只能判内容（①–④），"宿主能不能发现这个技能"这一半**本次没有得到验证**
（要验就得把包复制进扫描根 —— 那是用户环境，本流水线不做）。
```

守卫里它是**第三种取值** `'skipped-not-installed'`〔A30〕：**不算通过、也不算失败**，
但**必须出现在结论与报告里**（硬门只认 `true`）。本机实况：**已装、exit 0 全绿**。

### 2.3 顺带查出的一个**新发现**：源包与已装副本已经不同了

两份逐文件 sha256 比对〔A17〕的结果：**只在源包 0／只在已装 0／内容不同 7 个文件**
（ACCEPT-3 那次记的是"逐字节相同"）。不同的都是**教室内容侧**文件 ——
即"源包改了、已装副本还是旧的"。这正是这条比对要抓的漂移：**要不要同步由人决定**，
本流水线只报告事实、**不动用户环境**。（清单在 `02-install/skill-selfcheck/skill-tree-unchanged.json`。）
