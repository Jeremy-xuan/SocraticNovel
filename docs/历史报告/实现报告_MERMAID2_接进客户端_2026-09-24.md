### 1.2 ① 主题常量 → 主题配置对象

**改前**（原文，两行）：

```js
		/** mermaid 的图形主题名（mermaid 自己的枚举，不是本插件的）。 */
		const MERMAID_THEME_LIGHT = "neutral";
		const MERMAID_THEME_DARK = "dark";
```

**改后**（〔M01〕〔M02〕〔M03〕）：把 `code/tools/mermaid-pretty/claude-mermaid-theme.mjs`（〔P01〕）里的
`CLAUDE_LIGHT` / `CLAUDE_DARK` / `CLAUDE_THEME_CSS` **逐字抄进来**（一个色值都没改），外加一条新的
**主题版本号** `DIAGRAM_THEME_REV = "claude-v1"`（〔M04〕）。

为什么抄进来而不是"跑时去工作区读那份 `.mjs`"：客户端产物是**手写的惰性 CJS 表**（`window.__ModuleLoader__.load({id, factory})`，宿主不转译），
跑时再读一份 `.mjs` 会多一条 IO 与一条失败路径；而主题是**纯数据**，随包走最稳。
**换色值＝改这一处 ＋ 把 `DIAGRAM_THEME_REV` +1。**

> ⚠️ **事实边界（照抄 PoC 的声明，不许含糊）**：这套色值是**按 Claude 界面观感定的设计推断**，证据是 Anthropic 官方博客截图
> （暖米底 ＋ 极低饱和色块 ＋ 发丝描边 ＋ 大圆角 ＋ 无投影）。**没有任何一手证据表明 Anthropic 的 mermaid 渲染器用了这组色值。**
> 变量名则逐个对着本仓库那份 mermaid 11.17.2 产物核过。**只对 11.17.2 验证过；换版本＝重新验证，不得外推。**

### 1.3 ② 函数改名 ＋ 返回值语义变更

**改前**：

```js
		/** 主题名 → mermaid 图形主题（图里的底色/线色跟着走，免得白底黑字糊在深色界面上）。 */
		function mermaidThemeFor(themeName) {
			return themeName === "dark" ? MERMAID_THEME_DARK : MERMAID_THEME_LIGHT;
		}
```

**改后**（〔M06〕）：`mermaidInitConfigFor(themeName)`（〔M17〕同步改导出），返回一整份

```js
{ theme: "base", themeVariables: {...}, themeCSS: "...", flowchart: {...}, sequence: {...}, state/class/er/gantt/pie: {...} }
```

**为什么必须改名**：旧名字会让人以为它还是返回字符串，从而写出 `theme: mermaidInitConfigFor(x)` —— 图会直接画不出来。
**`theme` 必须是 `'base'`**：只有 base 主题会**完整**吃 `themeVariables`；用 default/forest/neutral/dark 时一部分变量会被该主题自己的 `getThemeVariables()` 覆盖掉（PoC 实测坑 #1）。

> 🔴 **一处**有意**的偏离（对 MERMAID-1 §4.1 第 3 条）**：那一行写的是 `initialize({..., ...mermaidThemeFor(themeName)})`，
> 而 PoC 那份 `claudeMermaidConfig()` 里带 `securityLevel: 'loose'`。**直接展开就会把客户端的 DOMPurify 从 `strict` 放宽到 `loose`。**
> PoC 已实测 `themeCSS` 在 `strict` 下照样生效（`rectRx=8px` / `rectFilter=none` / `labelWeight=400`），
> 所以**没有任何理由为了主题去降安全等级** → 本轮的写法是：**主题配置里根本不放 `securityLevel`**，
> 由调用点在展开**之后**显式钉死（〔M07〕），并在测试里断言"主题配置不带 securityLevel"（〔T03〕）。

### 1.4 ③ `renderDiagram()`：展开主题配置，串行化不动

**改前**：

```js
					mermaid.initialize({
						startOnLoad: false,
						securityLevel: "strict",
						theme: mermaidThemeFor(themeName),
					});
```

**改后**（〔M07〕）：

```js
					mermaid.initialize(Object.assign(
						{},
						mermaidInitConfigFor(themeName),
						{ startOnLoad: false, securityLevel: "strict" },
					));
```

**`renderChain` 那套串行化一字未动**（〔M08〕）：`initialize` 改的是**整页共享的一份配置**，而它**不在** mermaid 自己的渲染队列里
（`render` 内部才走 `executeQueue`）→ 两条图并发时 A 的 `initialize(light)` 会被 B 的 `initialize(dark)` 顶掉，
而且**会被缓存**。这条理由**不因换主题而消失**，反而更硬（现在 initialize 塞进去的东西比以前多得多）。
测试里那条"必须是 init(light)→render(A)→init(dark)→render(B)，不许交错"的断言**保留**，只是记账方式改了（见 §4.1）。

### 1.5 ④ 缓存键加主题版本号

**改前**：

```js
			const key = options.themeName + "\u0000" + options.source;
```

**改后**（〔M09〕）：

```js
			const key = DIAGRAM_THEME_REV + "\u0000" + options.themeName + "\u0000" + options.source;
```

**为什么非加不可**：光有 `light`/`dark` 是不够的 —— 改了主题色值之后**主题名一个都没变**，旧缓存不会失效，
用户会继续看到旧配色，而且**看起来像"改了代码没生效"**（这是最难查的一类问题）。所以以后每次调主题都要把 `DIAGRAM_THEME_REV` +1。

### 1.6 ⑤ 挂载之后逐层长出（本轮的"像 Claude"那一层）

**改前**（`ClassroomDrawView` 里，图那一段）：

```js
			if (state.kind === "ok" && state.svg !== null) {
				children.push(React.createElement("div", {
					key: "svg",
					style: S.drawCanvas,
					"data-classroom-ui-draw": "svg",
					dangerouslySetInnerHTML: { __html: state.svg },
				}));
```

**改后**：同一元素加 `ref`（〔M15〕，`ref` 就挂在它上面），并新增一个 effect：

```js
			React.useEffect(() => {
				const host = canvasRef.current;                       // 〔M13〕
				if (host === null) return undefined;
				const svg = host.querySelector("svg");
				if (svg === null) return undefined;
				if (drawAnimMode() === "none") return undefined;
				const animation = animateStagger(svg, { kind: parsed.kind === null ? "" : parsed.kind });  // 〔M14〕
				recordDiag({ at: "drawAnim", mode: "stagger", total: animation.total, units: animation.units, edges: animation.edges, rawLayers: animation.rawLayers, layers: animation.layers });
				animation.play();
				return () => { animation.finish(); };
			}, [state.svg]);
```

**为什么动画必须在这里、不能放进 `renderDiagram`**：`renderDiagram` 返回的是 **SVG 字符串**（没有 DOM），
而 `getBBox()` / `getTotalLength()` / `getComputedStyle()` 都**要求元素已经在文档里** → 动画只能发生在 `dangerouslySetInnerHTML` **之后**。

**依赖只有一个 `state.svg`**：
- 依赖 `themeName` 会多跑一次（换主题已经通过 `state.svg` 变化触发了）；
- 依赖 `parsed.kind` 会在每次渲染都跑一遍（`parseDrawArgs` 每次返回新对象）。

**清理时 `finish()`**：取消定时器并**把所有元素还原成终态**（组件卸载/换图都不许留一半藏着的元素）。
`animateStagger` 本体（〔M10〕）整段抄自 `code/tools/mermaid-pretty/claude-mermaid-anim.mjs`（〔P02〕），**候选 C 的 `streamRender` 没有抄**（本轮不做 C）。

### 1.7 ⑥ 动画开关：`uiConfig().drawAnim`，默认 `stagger`

**改前**：不存在。

**改后**（〔M05〕〔M12〕）：

```js
		function drawAnimMode() {
			const configured = uiConfig().drawAnim;
			if (configured === "none" || configured === "stagger") return configured;
			if (configured !== undefined && configured !== null && configured !== "") {
				recordDiag({ at: "drawAnim", configured: String(configured), used: DRAW_ANIM_DEFAULT, note: configured === "stream" ? "候选 C（stream）本轮未接线" : "不认识的值" });
			}
			return DRAW_ANIM_DEFAULT;      // = "stagger"
		}
```

- 配置面**复用现有那一个**：`globalThis.__DSH_CLASSROOM_UI_CONFIG__.drawAnim`，与 `live2dRoot` / `mermaidPath` / `skin` / `debug` 同一处（README §4.5.5 已补上这一行〔R01〕）。
- **不改代码就能回退到候选 A**：写 `drawAnim: 'none'` 即可（实测见 §3.4）。
- **`'stream'` 本轮未接线**（用户口径：C 不做）。它和任何不认识的值**一律落到默认档，并记一条诊断**——"配了却没生效"是最难查的一类问题，必须留痕迹；**不静默装作做了**（测试断言〔T06〕）。
- 卡片上标出**实际生效**的档（〔M16〕，`data-classroom-ui-draw-anim`）：验收脚本读它，不靠猜配置有没有被读到。

### 1.8 ⑦ 面板那一处：**判定为"不需要接线"**（这一条任务书要我判）

任务书原文是"教室面板：外观自动跟着（共用 `diagramFor`）"。**我核了源码，这个前提不成立**：

- 全仓 `diagramFor(` 只有**一个**调用点，就在 `ClassroomDrawView` 里；
- 面板主体（`ClassroomBody`）渲染的是**教室文件读出来的文字**：头部元信息、立绘舞台、`当前`（讲次/环节/老师/进度/上次）、课程表 14 讲、数据来源四条 —— **一张图都没有**；
- 面板里唯一的"图"是**立绘**（Live2D canvas），那是另一条通道，与 mermaid 无关。

→ **结论：面板既不共用 `diagramFor`，也没有 mermaid 图，所以外观与动画都"无事可做"。**
（"外观自动跟着"这句话真正成立的范围是：**消息流里所有 `classroom_draw` 的图**——它们都走同一个 `mermaid.initialize`，
所以第 ①–④ 处一改，**任何**位置画出来的 mermaid 图都会跟着换；本轮会话里两张图都换了，见 §3.1。）

## §2 · 三个坑怎么避开的（＋本轮**新踩**的三个）

### 2.1 上一轮写进注释的三个坑（逐条对照本轮的代码）

| # | 坑 | 本轮怎么避 |
|---|---|---|
| 1 | **进场动画绝不能用 CSS `transform`** —— mermaid 把位置写在 `<g transform="translate(x,y)">`，CSS `transform` **会整体覆盖**它 → 节点全跳到原点、图散架（这条原始记载在 PoC 的动画模块里〔P03〕） | 只注入**独立属性** `translate` / `scale`（〔M11〕）。**并且不靠目视**：§4.2 用 `getBoundingClientRect()` 逐节点量，实测动画期间**最大偏差 1.74 px、0 个节点塌到原点** |
| 2 | **总时长只压步间隔封不住**（先合并层） | 抄的是**两步一起做**的那一版：① 层合并成至多 `maxSteps`（默认 26）步；② 再把步间隔压进 `maxTotal`（默认 2600 ms）预算。本轮会话里的图都小（2 节点 / 6 节点），走的是"层数 < 26 → 不合并"的直路 |
| 3 | **`g.label` 不能当单元选择器**；时序图消息线是 `<line class="messageLine0">` | 单元选择器表里**没有** `g.label`（注释也照抄了原因）；连线表里同时有 `line.messageLine0/1` 与 `path.messageLine0/1`。本轮实测：**6 节点图数出 8 个单元**（6 节点 ＋ 2 个 `g.edgeLabel` 之外的 `g.cluster`？——不，是两张图合计 8 个 `g.node`），**没有翻倍** |
