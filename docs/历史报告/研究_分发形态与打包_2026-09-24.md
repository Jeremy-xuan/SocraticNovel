## ① 技能包路线（主）—— 「一条命令」到底能不能做到

### 1.1 先纠正一个可能的误解：`dsh` 里**没有**装技能的命令

实测 `dsh --help`（证据：`分发证据/取证_dshCLI子命令.txt`）：

```
Commands:
  web [options] [args...]        boot the web profile …
  plugin [options] [args...]     manage a profile's plugins by forwarding the
                                 remaining arguments to pnpm in the profile directory
```

**只有两个子命令。** master 对照（`tmp/dsh-src-0923/apps/cli/src/args.ts:187`）同样只有 `plugin`。
→ **这不是「版本旧」，是设计上就没有。** 所以「一键安装」不能指望 `dsh`。

### 1.2 宿主的**真实**扫描根（六个，只扫一层）

| 序 | 路径 | rank | 备注 |
|---|---|---|---|
| ① | `<项目根>/.dsh/skills` | 100 | 项目级，最高优先 |
| ② | `<项目根>/.agents/skills` | 200 | **跨 agent 通用约定** |
| ③ | `customSkillDirs[]` | 300 | 配置给出（出厂组装里没人设） |
| ④ | `$DSH_HOME/skills` | 400 | **用户级、跨 profile**；本机**目前不存在** |
| ⑤ | `~/.agents/skills` | 500 | 用户级、跨 agent |
| ⑥ | `bundledSkillDir` | 600 | 配置或 `DSH_BUNDLED_SKILL_DIR`；**留给打包部署的挂点**，出厂无人设 |

- 「项目根」的判定**只认 `.git`**；找不到就回落成当前会话 cwd（`dsh-skill-filesystem/lib/index.js:799-807`）。🔴 **本仓库没有 `.git`**，所以「项目级」两个根会落成会话 cwd，不是仓库根。
- 只扫根的**直接子项**（目录 → `<dir>/SKILL.md`；或根下扁平 `*.md`）。嵌套的 `SKILL.md` 一律不认。

### 1.3 🔴 为什么「放错位置」＝ 双重静默（要写进安装流程）

`parseSkillFile` 的五种失败**全部只是 `ctx.logger.warn(...)` 后 `return`**（缺 frontmatter／缺 name|description／name 非法／YAML 坏／invocation 非法）；provider 抛错也只是 `skill provider "…" skipped`（`dsh-skill/lib/index.js:354`）。而**默认日志级别门连 `warn` 都挡掉**。
→ 根不存在时更彻底：遍历 0 项，**候选 0 条、告警 0 条**。

**我们的技能包自带的自检已经把这件事解决了**——`code/skills/socratic-classroom/validate` 的第 ⑤ 项就是「我到底在不在扫描根下」。**必须把它写进安装流程**，这是唯一能在装错时喊出来的东西。

**实测两种结果（本轮真跑，证据见 `分发证据/验证_技能包安装/`）：**

装错位置（原地跑）：

```

    ✗ 不在  用户级 · $DSH_HOME/skills  [user-dsh rank=400]  → …
```

### 1.4 结论：**能不能做成一条命令** —— 能，有三条，推荐第 1 条

#### 做法 1（推荐）：随包附一个 `install.sh` —— **最简单、零依赖、今天就能给**

技能包就是**一个目录**，装法就是**复制**。把它包成一条命令：

```sh
#!/bin/sh
# install.sh —— 把 socratic-classroom 装进 DSH 的技能扫描根，并当场自检
set -eu
here=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)
pkg="$here/socratic-classroom"

# 1) 目标根：默认用户级（跨 profile、不用挑项目）；$DSH_HOME 未设时按平台猜
dsh_home="${DSH_HOME:-$HOME/Library/Application Support/dsh-desktop/harness}"
target="$dsh_home/skills"
mkdir -p "$target"

# 2) 复制整包（含自带教室与 yaml 解析器）
rm -rf "$target/socratic-classroom"
cp -a "$pkg" "$target/socratic-classroom"

# 3) 当场自检（唯一能喊出「装错了」的东西）
if command -v node >/dev/null 2>&1; then
  node "$target/socratic-classroom/validate" --project-root "$target/../.." || {
    echo "❌ 自检没过，请看上面的清单" >&2; exit 1; }
else
  # 没有 node 时退化成纯 sh 的位置检查（⑤ 那一项的本体就是「文件在不在」）
  [ -f "$target/socratic-classroom/SKILL.md" ] \
    && echo "✓ 已装到 $target/socratic-classroom（未跑内容自检：本机没有 node）" \
    || { echo "❌ 复制失败" >&2; exit 1; }
fi
```

用法：`sh install.sh`（或双击 `安装.command`）。

- **优点**：零依赖、离线可用、不碰 app、不碰 profile、不联网、不装任何 `@deepseek-ai/*`。
- **代价**：它是**我们自己的脚本**，不是官方机制；升级＝重跑一次。

#### 做法 2（生态标准）：`npx skills add` —— **有戏，但【未验证】**

生态里存在一个跨 agent 的**标准技能安装器**：[`vercel-labs/skills`](https://github.com/vercel-labs/skills)（npm 包名 `skills`）。

- README 逐字：*"The CLI for the open agent skills ecosystem."*；支持 OpenCode / Claude Code / Codex / Cursor 等 **80 个 agent**
- 支持**本地路径**：`npx skills add ./my-local-skills`
- 它的目标目录表里，多数 agent 的**项目路径 = `.agents/skills/`**，全局 = `~/.agents/skills/`
- 🔴 **`.agents/skills/`（项目）与 `~/.agents/skills/`（全局）恰好都是 DSH 的扫描根**（上表 ② 与 ⑤）

→ 理论上 `npx skills add ./socratic-classroom --agent universal` 就能落到 `.agents/skills/` 并被 DSH 扫到。
**但**：① DSH/DeepSeek Harness **不在它的支持清单里**（逐字表内零命中）；② 它可能交互式提问；③ 需要 Node + 网络。
→ **【未验证】。** 要用得先实测一次；不作为主推。

#### 做法 3（生态主流）：**把技能包成插件** —— 但这就跨到路线 ③ 了

市场里 `skill`（技能包）分类有 **169 条**，而它们的**装法全是 `dsh plugin add <包>`**。典型先例（本轮读了源码）：

**`@dennisrongo/dsh-skills`**（npm，解包仅 17 KB；证据：`分发证据/dennisrongo-dsh-skills/`）—— 它把整个技能库做成**插件的一个 npm 依赖**，`dsh plugin add` 一次把插件＋整库装上，`dsh plugin update` 一起更新。它的头注释逐字解释了为什么必须是 provider 而不是一个复制脚本：

> *"That is the entire reason this is a provider rather than a link script: a script can keep an ALREADY INSTALLED catalog fresh, but it cannot install one — it presumes `<agentsHome>/skills` exists, and nothing in the harness creates it. **A missing root is discovered as an empty list, not an error, so the failure mode of getting this wrong is a silently empty catalog.**"*

它的 `cordis.patch.yml` 只有两行：

```yaml
- insert:
    - id: skills
      name: '@dennisrongo/dsh-skills'
```

并且注释里写明一条**很关键**的性质：

> *"Registration files into the calling context's layer. **Applied at profile level that is the GLOBAL layer**, which every agent preset's scope chain includes — so **one row reaches every agent without touching the presets' own `skill-filesystem` rows**."*

→ 也就是说：**只要往 profile 的 patch 层插一行，技能就能到每个 agent**，不用动预设层。

**这条路买到了什么**：一条命令（`dsh plugin add`）＋ 市场一键装 ＋ 可升级。
**这条路丢掉了什么**：它不再是「不装插件也能用」；插件加载失败时**同样静默**（只是把静默点从「根不存在」挪到了「provider 没注册上」）。
📌 所以对用户拍板的「技能包（主）」形态，我建议**做法 1 为主、做法 3 作为可选加料**——两条可以同时存在，包内容一模一样。

### 1.5 ✅ 可直接照做的安装说明（含「怎么验证装对了」）

> 这份是从 `交付走查_从零到能上课_2026-09-24.md` 第 3 步扩出来的**独立版**，可以原样抄进 README。

**前置**：一台装了 DSH（桌面版或 web/CLI 版都行）的机器。

**第一步 · 选一个扫描根，把整包复制过去**

| 你想要 | 复制到哪 | 命令 |
|---|---|---|
| 只给一个项目用（优先级最高） | `<项目>/.dsh/skills/` | `mkdir -p "<项目>/.dsh/skills" && cp -a socratic-classroom "<项目>/.dsh/skills/"` |
| 所有 profile 都能用（**推荐**，不用挑项目） | `$DSH_HOME/skills/` | `mkdir -p "$DSH_HOME/skills" && cp -a socratic-classroom "$DSH_HOME/skills/"` |
| 想同时给别的 agent 用 | `~/.agents/skills/` | `mkdir -p ~/.agents/skills && cp -a socratic-classroom ~/.agents/skills/` |

🔴 **三条硬规则**（每条都有踩坑实证）：
1. **整包复制，别只拷 `SKILL.md`** —— 教室正文与 `node_modules/yaml` 都靠「内容随包走」；
2. **必须是扫描根的「直接子项」**，不能嵌套（只扫一层）；
3. **别放在 `code/skills/` 这种地方** —— 那是「候选 0、告警 0」的双重静默。

**第二步 · 验证装对了（这一步不许跳）**

```sh
node "<你放的那个路径>/socratic-classroom/validate" --project-root "<项目根>"
```

| 看到什么 | 含义 |
|---|---|
| `✓ 在扫描根下：…` ＋ `结论：全部通过（退出码 0）` | ✅ 装对了 |
| `✗ 本包不在任何扫描根的直接子目录下` ＋ 三条可复制的目标路径 | ❌ 装错了，照着它打印的 `cp` 再来一次 |
| `✗ frontmatter name 非法` / `description` 为空 | ❌ 包被改坏了 |

**没有 Node 怎么办**：`$DSH_HOME/.desktop-bin/node` 是桌面版自带的一个 shim（指向 app 内的 Electron Helper，`ELECTRON_RUN_AS_NODE=1`），实测可用（`--version` 返回 `0.1.5-rc.2`）。若它也不存在，**最低限度**用一条纯 shell 检查位置：

```sh
[ -f "$DSH_HOME/skills/socratic-classroom/SKILL.md" ] && echo OK || echo "装错了"
```

**第三步 · 在 DSH 里开一个新对话，说一句话开始上课**

触发**完全靠 `SKILL.md` 的 `description`**（宿主只把 `name` + `description` 拼成目录行，description 截断 500 字符，**没有任何关键词机制**）。当前 description 覆盖的触发词包括「上课／开始上课／继续上课／上操作系统课／今天到这／用教室上课／教室包／讲次／相位／课后更新」，还兼「检查教室是否完整」。
→ 用户说「**上操作系统课**」即可。

**第四步 · 收尾要说「今天到这」**（那是课后存档的开关；不说就不写）。

### 1.7 🔴 一个**当下就存在**的真实故障：项目级那份装的是「残包」

本轮顺路实测发现，工作区里**已经**有一份项目级安装，而且**它是坏的**：

```
路径：/Users/wujunjie/Documents/ChatGPT/大学申请/.dsh/skills/socratic-classroom/
内容：README.md  SKILL.md  classroom/  package.json  sync-classroom.sh  validate
      🔴 没有 node_modules/   ← 少了随包的 yaml 解析器
```

`SKILL.md` / `validate` / `package.json` 与源包**逐文件哈希一致**（`shasum -a 256` 三处 SAME），但整包不完整。

**它坏在哪（实测 `node validate`）：**

```
错误：找不到 YAML 解析器（require('yaml') 失败）：Cannot find module 'yaml'
查找位置：…/.dsh/skills/socratic-classroom/node_modules/yaml
本技能包应自带该依赖（见 README.md「依赖来源」）。缺了它就无法检查 classroom.yaml，故直接失败，不跳过检查。
退出码 2
```

**这条故障同时给出三个结论：**

1. **「整包复制」不是一句客套话** —— 挑着拷会做出一个「装上了、但自检跑不起来」的残包。这正是 §1.5 硬规则 1 的来源。
2. **自检在缺依赖时是「大声失败」的**（退出码 2 + 明确的查找位置），不是静默 —— 这一点比宿主的行为好得多。
3. ⚠️ **但宿主的发现链路仍然会认它**（`SKILL.md` frontmatter 合法）→ **模型能加载这个技能，却跑不了它的自检**。这是「半坏」状态，最容易被忽略。
   → **安装流程必须把「跑一次 `validate`」当成验收，而不是可选步骤**；光看「技能出现在列表里」判不出这个故障。

📌 本轮**没有**去修它（往 `大学申请/.dsh/skills/` 补 `node_modules` 属写工作区，且不在本任务允许的两处内）。**这留给用户/主代理决定**（见「待确认清单」第 8 条）。

📌 另一个顺路实测：`~/.agents/skills/`（rank 500）**已经存在且已有 100+ 个技能**（本会话的技能目录就是从那儿来的），而 `$DSH_HOME/skills/`（rank 400）**目前不存在**。→ 想「装一次、所有 agent 都能用」，`~/.agents/skills/` 是眼下唯一现成的用户级落点；想「只给 DSH 用、跨 profile」，就得先建 `$DSH_HOME/skills/`。

## ② 🔴 完整打包的 DSH 桌面版（主，本任务重点）

### 2.1 DSH Desktop 是什么形态（**带文件清单**）

🔴 **先纠一个容易说错的事实**：桌面版**不是预装插件市场**的。出厂状态是**设置里有一个「插件市场」页 + 一个「安装插件市场」按钮**；点它、装完、**重启一次 Harness**，才出现完整的市场界面。本机之所以有市场，是因为这个用户点过装。（逐字 UI 文案与路由见证据底稿 §C4。）

**它是 Electron 应用。** 实测（证据：`分发证据/取证_机制与落点_2026-09-24.md` §C）：

| 项 | 值 | 出处 |
|---|---|---|
| 版本 | `0.9.1` | `Contents/Info.plist` 的 `CFBundleShortVersionString` |
| Electron | `43.4.0` | Electron Framework 二进制内字符串 |
| 应用体积 | **571 MB** | `du -sh` |
| 自动更新 | **Squirrel** + `app-update.yml`：`provider: generic, url: https://dshdesktop.com/updates/latest/` | `Contents/Resources/app-update.yml` |
| 主进程 | `Contents/Resources/app/out/main/index.js`（**21,577 行，已打包**） | `app/package.json` 的 `main` |
| `asar` | **`false`** → app 目录是**普通目录树**，可读可改 | 上游 `package.json` 的 `build.asar` |

`Contents/Resources/` 里的关键文件：


### 2.3 用户的模型/API 配置怎么处理（我们不可能替用户填 key）

- 出厂默认模型逐字：`provider: deepseek-official, model: deepseek-flash`，而注释逐字：*"**No key or endpoint is inlined**: both resolve per request from the `llm-deepseek:` settings section over this entry, with the key coming from the credential store below."*
- 写入方逐字：*"the web Models page writes"*（`dsh-base/cordis.patch.yml` 的 `settings` / `credentials` 两行注释）
- 实测文件形状：`settings.yaml` 有 `llm-deepseek:`（含 `models:` 列表）；`.credentials.yaml` 是 `version: 1` + `refs: { DEEPSEEK_API_KEY: sk-… }`
- 🔴 桌面版**没有**首次运行向导：`presetPlugins|onboarding|setupWizard` 在 `out/main/index.js` 里 **grep 零命中**

→ **第一次启动的引导只能是「文档 + 界面」**：用户在 README 里被引导到 **Settings → Models**，自己填 provider + key。我们**不做**任何 key 预置、不写占位 key、不代填。

**建议的引导写法**（三段，不要更多）：

1. 装好并第一次打开 DSH Desktop；
2. 打开 **Settings → Models**，选一个 provider（DeepSeek 官方或第三方）填你自己的 API key；
3. 打开一个**你的项目文件夹**作为工作区 → 新开对话 → 说「上操作系统课」。

### 2.4 产出物是什么形态 / 多大 / 用户要做哪几步

**②A 分发包（推荐）**

```

├── 读我_先看这个.md          ← 三步引导（§2.3）
```

- **形态**：一个文件夹（或打成 `.zip`）。**不含我们自己构建的 app。**
- **体积**：**约 2–3 MB**（不含官方 dmg）；若把官方 dmg 一起放，**约 180–250 MB**（官方 macOS arm64 dmg 的实测体积本轮**未取**，标【未验证】）。
- **用户要做的**：
  1. 装官方 DSH Desktop（自己下，或用我们附的 dmg）；
  2. 打开一次 → **Settings → Models** 填 key；
  3. 双击 `一键装载.command` → 看到 `✓ 在扫描根下` ＋ `结论：全部通过（退出码 0）`；
  4. 新开对话说「上操作系统课」。
- **代价**：不是「一个文件双击到底」；官方 app 更新照常走它的自动更新（每 6 小时检查一次），我们的载荷**不受影响也不跟着走**。

**②B fork 重建（真·单文件）**

- **形态**：`dsh-desktop-mac-arm64.dmg`（或 `.zip`），安装后就是 `.app`。
- **体积**：**≈ 571 MB 级**（本机 app 实测 571 MB；dmg 压缩后应显著更小，但**本轮未实测**，标【未验证】）。
- **用户要做的**：下载 dmg → 拖进 Applications → 打开 → 填 key → 上课。**这就是用户要的「完整打包好的桌面版」。**
- **代价与风险**：见 §2.5。

### 2.5 🔴 必须读现成实现：别人怎么做「把插件/配置预置进一个桌面应用」

> 项目硬规矩：技术选型类任务第一步是读现成实现，产出必须含「**它们怎么做（带出处）＋ 我们借什么、明确不借什么**」。

#### 先例 A · `dsh-tauri/deepseek-harness-desktop`（MIT，2,571★，Tauri 2）—— **最贴近，直接可抄**

README 逐字卖点：*"🎁 **内置插件** — 随安装包内置插件 … 🧭 **启动引导** — 首次启动可选推荐插件"*、*"Only 5mb installer, zero environment setup, preset plugins"*

**它做了两层，两层都有机器可读清单（这是最值得抄的地方）：**

| 层 | 清单文件 | 机制（逐字/带出处） |
|---|---|---|
| **内置插件**（随安装包） | `src-tauri/resources/internal-plugins.json`（4,104 B，10 条，字段 `{id, spec, name, description, repoUrl}`） | *"…bundled at build time by `scripts/build-plugins.ts` (via `pnpm deploy` of the workspace packages listed in `packages/dsh-tauri-bundle`) into `resources/node_modules/<name>` (via `bundle.resources`) and never appear in the first-run checklist."* 且 **auto-installed and auto-healed at startup** |
| **预设插件**（首启向导勾选） | `src-tauri/resources/preset-plugins.json`（1,742 B，4 条，字段 `{id, spec, version, name, description, repoUrl, recommended, defaultUnchecked, dshSupportedVersion}`） | *"The first-run wizard / sidebar preset list is driven by `preset-plugins.json` (loaded at runtime by `src-tauri/src/service/plugin/mod.rs` — **no Rust code change needed to add a preset**)."* / *"The plugin itself is **not** vendored … it is installed on the user's machine from `spec` at setup time"* |
| 打包入口 | `src-tauri/tauri.conf.json` → `bundle.resources: ["resources/**/*"]` | 整个 `resources/` 目录随安装包走 |
| 另有 | `version-recommend.json` `{"dsh":"0.1.5-rc.3"}`、`deprecated-plugins.json` | 推荐上游版本 + 弃用名单 |

**它怎么发「预设清单的更新」**（这条极有用，逐字）：*"the file ships with the installer and is force-overwritten on every install, so the app records a **fingerprint of its content** into the user-data settings after the wizard ends (install or skip) and **re-opens the wizard on the next launch when the content differs**."*

**它的 `$DSH_HOME` 策略**（逐字）：*"follows the **official dsh convention** (`${DSH_HOME:-$HOME/.dsh}`) … the desktop app and a `npm i -g @deepseek-ai/dsh` install share the same profiles, sessions, settings and credentials."* 且**运行时资产首启下载**（Node 运行时、打包的 DSH 发行版）→ 这就是它只有 5 MB 的原因。

#### ✅ 我们借什么 / 明确不借什么

| 借 | 出处 | 怎么用在我们身上 |
|---|---|---|
| **「内置清单 + 预设清单」两层分离** | 先例 A | 我们的「引擎/面板」属内置层；「可选加料（动画、Live2D 模型、别的教室）」属预设层 |

| **「首启向导 + 清单指纹变了就重开」** | 先例 A | 我们若做 ②B，这是发「可选加料」更新的正确姿势；不做 ②B 就不需要 |
| **「桌面壳不改上游源码，桌面能力也当插件」** | 先例 B | 印证了 **②A（不碰 app）在理念上不是将就，而是这个生态里已经有人走通的正路** |

| **市场收录＝一条 YAML 的 PR** | `awesome-dsh-plugin/contributing.md` | 路线 ③ 的落地方式（§3） |

| 明确**不**借 | 为什么 |
|---|---|
| **Chrome 式「往别人 app 的用户数据目录预置」** | 平台方明确关过这条路（Chrome 44）；我们也不该去动别人 app 的 profile 目录 |
| **VS Code 式「内置扩展不可卸载 + 哈希校验清单」** | 我们不是 app 的发行方；做哈希清单要维护一套签名/校验，收益不成比例 |
| **先例 A 的「运行时资产首启下载」** | 那是为了把安装包压到 5 MB；我们做 ②A 根本不需要自己发安装包，做 ②B 也不该引入新的下载端点 |
| **改上游源码**（`src/` 里塞我们的东西） | 先例 B 明确说「没有修改上游源码」是它的设计立场；改源码＝每次上游发版都要解冲突 |

### 2.6 🔴 一条硬风险证据：**改 app 包内文件 = 破签名**（本机已经发生）

```
$ codesign -dv "/Applications/DSH Desktop.app"
Identifier=io.dsh.desktop   TeamIdentifier=93RLD96LCP   flags=0x10000(runtime)
Sealed Resources version=2 rules=13 files=15091

$ codesign --verify --deep --strict "/Applications/DSH Desktop.app"
/Applications/DSH Desktop.app: a sealed resource is missing or invalid
file added: /Applications/DSH Desktop.app/Contents/Resources/s2-schema-check.mjs
```

- 这个文件 `mtime = 2026-09-23 21:37:45`，是**上一轮会话留下的调试脚本**（内容是 `import { defineTool, … } from '/Users/…/tmp/dsh-installed/dsh-tools/lib/index.js'`）。
- 它是**唯一**的密封违规项。**本机仍能启动**（已运行过、已批准），但这直接证明：
  1. **app 是签名+公证的**（`TeamIdentifier=93RLD96LCP`，hardened runtime）；
  2. **改 app 包内任何文件都会破密封**；
  3. 我们**无法以自己名义重签**（需要自己的 Apple Developer ID）；
  4. 带 `com.apple.quarantine` 的新机器上，破密封的 app 会被 Gatekeeper 拦；Squirrel 更新路径也可能受影响。
- 📌 本轮**没有**去删它（删除＝改 app，属禁止动作）。**这留给用户决定**（见「待确认清单」）。

### 2.7 建议路线（含代价与风险）

> **建议：先做 ②A（官方 app ＋ 一键装载脚本），把 ②B 作为「用户明确要一个单文件安装包时」的第二阶段。**

**为什么是 ②A：**

1. **零签名风险**：一个字节都不碰 app，Squirrel 自动更新照常走（每 6 小时一次，官方签名+公证）。
2. **零上游耦合**：DSH Desktop 每次发版改了什么（`$DSH_HOME` 路径、扫描根、patch 文件名）我们只受影响于**文档里写死的那几个路径**，不产生 merge 冲突。
3. **今天就能交付**：产出物只有 2–3 MB，不需要 Apple 开发者账号、不需要构建流水线。
4. **能力不打折**：技能包 + 教室 + （可选）插件三样都能装上；插件那条走**桌面版自带的市场**，用户点一下就行，连脚本都不用。
5. **理念上有先例**：先例 B（28.7k★）整个产品的立场就是「不改上游源码」。

**②A 的代价（如实说）：**

- 用户要**点两次**（装 app、跑装载脚本），不是「一个文件双击到底」；
- 我们**不掌控 app 的更新**——某天上游改了 `$DSH_HOME` 或扫描根，我们的脚本会失效（缓解：脚本里**先自检再动手**，`validate` 会把「装错了」喊出来）；
- 官方 app 若加了首启向导或改了导入语义，`web-import` 那条捷径可能变（**所以不建议把 ②A 建在 web-import 上，建在「往扫描根复制」上——那是源码级保证的契约**）。

**②B（fork 重建）的代价（如果用户坚持要单文件）：**

| 代价 | 具体 |
|---|---|
| **签名** | macOS 上要能被别人双击打开，需要**自己的 Apple Developer ID**（Developer ID Application 证书）＋ 公证（notarytool）。`package:dev:*` 能产出未签名构建，但未签名 app 在别人机器上会被 Gatekeeper 拦（用户要右键→打开，或 `xattr -d com.apple.quarantine`）。🔴 证书与费用**本轮未查**（属用户自己决定的事）。 |
| **重建频率** | 上游 push 很勤（最近一次 2026-09-24）。每次要跟就要重新 `npm ci && npm run package:mac:arm64`。 |
| **体积** | 产物是 571 MB 级的 app／dmg。 |
| **不冒名** | 上游 `electron-builder.dev.cjs` 已经给了正确姿势：**改 `appId`（`io.dsh.desktop.dev`）、改 `productName`、输出到 `dist-dev`、`publish:null`**。别沿用 `io.dsh.desktop` 与官方更新源。 |
| **本机验证成本** | 本机现有 app 已在用、且已破密封；**在别处构建、别处安装验证**才是干净做法（本轮没做）。 |

**②B 的机械做法（照抄即可，均有出处）：**

1. `git clone https://github.com/dataelement/dsh-desktop`（MIT）；
2. 把我们的载荷放进 `build/`（因为 `extraResources: build/* → Contents/Resources/*`）；
3. 加一份 `build/dsh-socratic.patch.yml`，插入我们的行；若要把包当 bundle 解析，把包放进 app 的 `dependencies`（`files: node_modules/**/*` 会带走它）——**依据是 `resolveBundleDir` 先查 app 的 package.json**；
4. 在 `src/` 里把新 patch 路径加进 `desktopResourcePath(...)` 那一组（对应 `out/main/index.js:21276-21278` 的位置）——**这一步要改源码**，是 ②B 与 ②A 的分水岭；
5. `npm run package:dev:mac:arm64` 先出未签名 dev 包做验证；确认无误再上正式签名通道；
6. 教室用**显式 `classroomDir`** 指向包内资源（`!!js` 表达式允许），**但要注意**：本机 0.9.1 的 patch 行**裸包名不从 app 解析**（`bareModuleBaseUrl` 是上游 main 才有的），所以第 3 步「放进 app 的 node_modules」这条**只在 bundle 路径成立**，行级解析要靠 profile 的 node_modules——**这一点【未实测】，是 ②B 里最需要先做 PoC 的地方**。

### 2.8 「升级怎么发」—— 桌面版路线

| 谁 | 怎么升 |
|---|---|
| DSH Desktop 本体 | **它自己的自动更新**（Squirrel，每 6 小时检查一次，用户确认后才装）。我们不参与。 |
| 我们的载荷（技能包／教室） | **重跑装载脚本**（覆盖式）。或者：把技能包也做成插件（§1.4 做法 3），让它跟着市场升级。 |

| 若走 ②B | **每次上游发版我们都要重建**；我们的载荷更新则随重建一起发（或按先例 A 的「清单指纹变了就重开向导」）。 |

## ③ 插件包路线（次）

### 3.1 现在怎么装

```sh
dsh plugin --profile <profile> add file:<插件目录的绝对路径>
```

实测落点（`profiles/socratic-dev/package.json` 逐字）：`"socratic-engine": "file:/Users/…/code/plugins/socratic-engine"` → 进 `dependencies` ＋ 进 `dsh.profile.bundles` ＋ 实物在 `profiles/socratic-dev/node_modules/socratic-engine`。

`dsh plugin` 的实现（`dsh/lib/plugin-Ddi42qoW.js:9-10,109,116`）：*"thin pnpm forwarder: initialize the profile on first use, run `pnpm <args...>` in the profile directory, then reconcile [dsh.profile.bundles]"* → **`spawnSync("pnpm", …)`，需要 PATH 上有 pnpm。**

### 3.2 对一个普通用户，门槛在哪

| 门槛 | 具体 | 能不能绕过 |
|---|---|---|
| **要打开终端** | `dsh plugin --profile web add …` 是命令行 | ✅ 桌面版设置里有**「安装插件市场」入口**（点一下 → 装 → 重启一次 Harness），之后市场里图形化一键装 |
| **要有 `dsh` 命令** | 桌面版**不注册** `dsh` 命令（实测：`/usr/local/bin`、`~/.local/bin` 无 `dsh`；`$DSH_HOME/.desktop-bin/` 里只有 `node` / `pnpm` / `pnpm-runner.mjs`。**Tauri 版先例会注册，Electron 版不会**） | ✅ 用 `$DSH_HOME/.desktop-bin/node` + app 内的 `bin.js`（**实测可用，不需要用户装 Node**）；或直接走市场 |
| **要有 `pnpm`** | `dsh plugin` 转发给 pnpm | ✅ `$DSH_HOME/.desktop-bin/pnpm` 实测可用（10.34.5）；桌面版自己也会把它前置进 PATH（`out/main/index.js:11348-11355`） |
| **`file:` 本地路径** | 我们现在的开发装法 | ❌ **普通用户拿不到我们的本地目录**；市场只认 npm 包名或 `github:owner/repo` |
| **宿主核心包铁律** | 插件不得自带 `@deepseek-ai/*`（会双实例、Symbol 失配） | 我们已遵守（`classroom-ui` 用 `dsh.client.inject` 声明，不是 dependencies） |
| **同版本不刷新** | 同版本 `file:` 依赖 pnpm 会说 `Already up to date` | ✅ 先 `remove` 再 `add` |
| **网络** | `socratic-engine` 依赖 `jsdom`/`mermaid`/`yaml`，安装要联网取 npm | 预构建 tarball 或 vendored node_modules（**未做**） |

### 3.3 🔴 「小众」这个判断要修正 —— 插件生态其实很大

- 桌面版设置里有**「插件市场」的安装入口**（点一下 → 装 → 重启一次 Harness）；装完之后市场里是 **4,262 个插件**，分类里有 **`skill`（技能包）169 条**。
- 收录门槛**极低**：`awesome-dsh-plugin/contributing.md` 逐字 —— *"Open a PR that adds **one file**, named after your repo — `data/plugins/<owner>__<repo>.yml`"*，字段只要 `url` / `name` / `category` / `description.en`（中文可选，维护者会补）。
- 硬要求只有一条：*"The repo declares a `dsh.bundle` manifest in `package.json` (this is what makes it installable via `dsh plugin add`)."*，且逐字警告 *"Most rejected submissions declare only `dsh.client` — that alone is **not** installable."*
- 建议：*"Publish your plugin to npm — prebuilt installs skip the `allowBuilds` build-approval step."*；不发 npm 也行，挂一个 GitHub Release 的 `.tgz` 用 `tarball:` 字段指过去。
- ⚠️ 一条**我们必须注意**的坑（逐字）：*"A peer range without an explicit prerelease branch silently excludes every prerelease build of the harness."* → `@deepseek-ai/*` 的 peer 范围要写成带预发布分支的形式（例：`">=0.0.1-rc.1 <0.1.0 || >=0.1.0-rc.1 <0.2.0-0"`），否则用户装不上。
- ⚠️ 另一条：**纯聚合包不收录**（*"List the plugins, not the bundle."*）→ 我们的包必须**自己带行为**（引擎确实带行为，OK）。

→ **结论**：把插件**发到 npm ＋ 收录进 awesome-dsh-plugin** 之后，「普通用户装我们的插件」＝**在桌面版设置里点一下**（先点一次「安装插件市场」，重启，再搜我们的插件）。这条路**不比技能包难**，只是它要求我们先做发布动作。

### 3.4 要不要出「给开发者用的说明」

**要，而且应该分成两份：**

| 受众 | 写什么 |
|---|---|
| **普通用户** | 只有三句：「打开 DSH Desktop → 设置 → 插件市场 → 安装插件市场 → 重启一次」；「回到插件市场搜 `<名字>` → 装」；「填 key → 上课」。**不要出现任何命令行。** |
| **开发者／我们内部** | 完整的 `file:` 装法（含 `.desktop-bin` 的用法、`remove` 再 `add`、哈希复核、`@deepseek-ai/*` 铁律、peer 范围的预发布分支坑）——就是 `交付走查_从零到能上课_2026-09-24.md` 第 1、4 步那份。 |

**能不能包一层脚本**：能。一条命令（**不需要用户装 Node 或 pnpm**）：

```sh
export PATH="$DSH_HOME/.desktop-bin:$PATH"
"$DSH_HOME/.desktop-bin/node" \
  "/Applications/DSH Desktop.app/Contents/Resources/app/node_modules/@deepseek-ai/dsh/lib/bin.js" \
  plugin --profile web add "file:$PAYLOAD/plugins/socratic-engine"
```

⚠️ 前提：`.desktop-bin/` 存在。实测它**是懒创建的**（只在 app 自己执行 profile 插件命令时生成，`out/main/index.js:11297-11345`），所以**新装的机器上可能还没有** → 脚本要先检查，不存在就提示用户「先在设置里装/卸一次任意插件」或改用市场。📌 **【未验证】这条脚本在「全新机器」上的表现**——本轮没有可用的干净环境去跑（且跑它会写 profile，属禁止动作）。

1. **② 桌面版：走 ②A（官方 app ＋ 装载脚本）还是 ②B（fork 重建出单文件 dmg）？**
