## Q1 工具系统组织

### 结论
- **不是静态工具表**。`packages/core/tools/src/index.ts:806-807` 的 `ToolRuntime extends Service` 注入 `systemPrompt` 并提供 `ctx.tools`；`register()` 将定义写入作用域注册层，返回 unregister disposer（同文件 L1056-1087）。注册变化发出 `tools/change`，并由 `ctx.systemPrompt.tools(...)` 从调用 scope 生成模型 schema（L832-834、L853）。工具插件注册即进入 prompt assembly；中文 README 明说“注册一个工具就足以让它可见”（`packages/core/tools/README.zh.md:25-32`）。
- **第三方插件可不改 core 加工具**：Cordis 插件声明 `inject = ['tools', ...]`，在 `apply()` 中 `ctx.tools.register(defineTool(...))`。例如官方 `packages/extensions/tool-cordis/src/index.ts:22,41` 和 `packages/mcp/mcp-client/src/tools.ts:124-151`；MCP 客户端枚举远端工具、转换为 `ToolDefinition` 后逐个注册，注册不涉及修改 core。工具可全局或 agent scope 注册，scope 内定义遮蔽全局同名定义；同一层重名、保留名 `run_code` 会失败（core README L79-81；`index.ts:1056-1086`）。
- **工具声明结构**：`packages/core/tools/src/schema.ts:482-545` 的 `DefineToolOptions` 要求 `name`、模型可见 `description`、参数 `parameters` schema、规范输出 `output.schema` + 纯 `output.render(args,value)`、以及异步 `execute(args,exec)`；可选 `timeoutMs`、并行安全判定、`projectContent`/`finalizeContent`、展示 presenter。参数/返回值均在执行链受校验（`schema.ts:554-597`；core README L30-60）。
- **前置条件/权限不是一张声明式“requires”字段**：Cordis `inject` 是插件依赖服务的前置条件；工具本身可在 `apply()` 期间用 `ctx.inject(['attachments'], ...)` 条件注册（`packages/fs/tool-fs/src/index.ts:18-23,53-71`）。调用授权可通过 `tools/pre-execute` waterfall 做 allow/deny/ask，并由后续不可放宽的 `tools.guard()` 强制策略，见 `packages/core/tools/src/index.ts:142-176`、`packages/core/tools/README.zh.md:83-87`。实际能力仍须在 execute 中检查调用权限/业务状态，不能只靠模型提示。
- **插件生命周期**：注册属于 Cordis effect；`ctx.tools.register()` disposer 解除注册并触发可见集更新（`index.ts:832-834,1082-1086`；仓库 `packages/AGENTS.md` 规定贡献必须经 `ctx.effect()`/`ctx.on()` 并验证 disposer）。

### SocraticNovel 裁定
引擎行为（逐字回查、课程笔记读写、相位状态推进、复习队列更新）适合做**独立服务端 Cordis 插件**，用 `defineTool` 暴露窄 schema API，核心无需改动。教室课程内容本身应遵从已裁定的“内容数据包、引擎插件”分离，不要把章节/题目硬编码进工具定义。若插件依赖 file/session 等现有服务，用 `inject` 明确依赖；只有 core 缺少所需扩展点或所需持久化抽象时才考虑改 core。

**本题裁定：部分覆盖要扩展**（现成工具注册表/API可复用；教学领域工具和课程状态服务尚需新插件）。

### 覆盖结论

**本题裁定：部分覆盖要扩展**（复用现成文件/图像/检索工具；逐字核验和教学状态需插件工具；实际 profile 启用集合待确认）。

## Q3 记忆机制

**结论：源码无 memory/memento 专属机制**；有可复用的结构化存储 `packages/storage/storage-domain`：
- `storage-domain/src/index.ts:41-62,84-103`：声明插件、backend 路由、open typed domain。
- `domain.ts:18-118`：global/table API（get/entries/put/delete/update）；写入走 per-domain serial queue，**先 backend durable write 成功，再更新内存、发 `domain/changed`**（`domain.ts:1-8,148-153,194-199`）。

- Session 持久化是 append-only 对话事件日志（`packages/session/session-persistence/src/index.ts:116-135`），不是掌握矩阵。
- 未发现 memory 审批门；`tools/pre-execute` 可插件化 allow/deny/ask——那是调用策略，不是 storage 内建（`packages/core/tools/src/index.ts:142-176`；README.zh L83-87）。

**建议**：教学状态 = engine Cordis 插件 own domain ＋ typed schema/state tables，底层复用 storage-domain；专用工具读写业务动作；课程包只读。

- `skill-filesystem/src/index.ts:45-89,133-147,186+`——发现路径并解析 Markdown frontmatter；

🔴 **插件+skill 共存有明确机制**：skill provider（skill-filesystem）提供内容/metadata；tool-skill 是独立插件才注册 skill 工具与自动注入；**教学插件可同时注册确定性工具+服务，两个插件在相同 agent scope 下共存，skill 只做引导后备**。frontmatter 可设 `disable-model-invocation`／`user-invocable` 控制暴露（默认模型/用户均 invocable）——`skill/src/index.ts:48-54,94-100,430-459`、`filesystem/src/index.ts:248-262,797-828,1003-1009`。

→ **对"教室双模式"的意义**：同一教室包，装了注入引擎插件走确定性注入；没装插件时 skill（tool-skill 自动注入）做模型自律后备——**双模式共存是宿主原生支持的，不用我们发明**。

**本题裁定：现成机制直接用**（skill 三件套＋frontmatter 控制全现成；双模式共存零开发）。
