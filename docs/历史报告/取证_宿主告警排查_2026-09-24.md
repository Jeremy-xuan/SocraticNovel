## §3 实测：我们的技能包能不能被装上并加载

> ✅ **能被正常加载。** 把 `code/skills/socratic-classroom/` 放进**任一合法扫描根**，宿主都能发现它、目录行（`name`＋`description`）能取到、`get()` 能取到全文（**2510 字符**），且**零告警**。

## §4 权限预设那条（只看不动）

### 4.1 它是什么

宿主 `permission-preset-service`（`@deepseek-ai/dsh-permission-presets` 的 `PermissionPresetService`，`super(ctx, "permissionPresets")`，`lib/index.js:106`）在挂载时，把 `permission` 段注册进 settings，并**用 schema 校验**该段的值：

```js
// dsh-permission-presets/lib/index.js:116-123
const presetChoices = this.names.map((name) => {
    const choice = z.const(name);
    const label = this.presets[name]?.name;
    return label === void 0 ? choice : choice.description(label);
});
const settingsSchema = z.object({ defaultPreset: z.union(presetChoices).required() });
ctx.inject(["settings"], (settingsCtx) => {
    settingsCtx.settings.installSection(ctx, PERMISSION_SETTINGS_NAMESPACE, settingsSchema, baseSettings, {…});
});
```

其中 `get names() { return Object.keys(this.presets); }`（`:186-188`）。

### 4.2 合法取值有哪些

**合法取值 ＝ `presets` 表的键（＋任何部署在 `presets` 里自定义的键）。** 内置表键为：

```js
// dsh-permission-presets/lib/index.js:81-94
presets: z.dict(z.object({ sandbox: …, approval: …, name: z.string(), description: z.string() })).default({
    "workspace-write":   { sandbox: "workspace-write",   approval: "ask",   name: "workspace-write",   description: "Write inside the workspace and permitted temporary directories; wider retries require approval." },
    "danger-full-access":{ sandbox: "danger-full-access",approval: "never", name: "danger-full-access",description: "Full file access without approval prompts." }
}),
```

`read-only` 也在可选集合里——它出现在 `permissionStateSchema` 的 `sandbox` 联合类型中（`:27-31`）：

```js
sandbox: z$1.union([ z$1.literal("read-only"), z$1.literal("workspace-write"), z$1.literal("danger-full-access") ]).nullable(),
```

报错文案 `expected "read-only" | "workspace-write" | "danger-full-access"` 正是这个联合类型展开后的样子，**不是** `presets` 表的键列表。

> ⚠️ **一处需要用户自己确认的歧义**：报错文案列出的三个值来自 `permissionStateSchema.sandbox`，而实际校验用的是 `presets` 表的键。**本报告无法在只读前提下确定本机部署是否在别处（例如某个 profile 的插件配置）扩展过 `presets` 表**——我搜遍 `settings.yaml` 与安装版资源目录，`full-access-ask` 这个字符串**只在 `settings.yaml:667` 出现一次**，安装版代码里零命中。

### 4.3 当前值与期望值的差异

| 项 | 值 | 出处 |
|---|---|---|
| 当前配置值 | `full-access-ask` | `$DSH_HOME/settings.yaml:666-667`：`permission:` ⏎ `  defaultPreset: full-access-ask` |
| 期望值 | `presets` 表的键之一（本机至少含 `workspace-write`、`danger-full-access`） | `dsh-permission-presets/lib/index.js:81-94, 116-121` |
| 差异 | `full-access-ask` **不是**任何一个内置 preset 名。它的形态像是"`danger-full-access` 沙箱 ＋ `ask` 审批"的**手写组合描述**——但 preset 是**命名表项**，不是一个可自由拼写的字符串 | 同上；且 `:243-247` `resolve(name)` 对未知名字会 `throw new Error(\`permission: unknown preset "${name}" (known: …)\`)` |

**后果（静默部分）**：`installSection` 的 schema 校验失败 → **整个 `permission` 段被拒绝**，`defaultSettings` 退回构造期的 `baseSettings = { defaultPreset }`，其中 `defaultPreset = config.defaultPreset ?? inferredDefault`（`:110-115`）。也就是**用户写的那一行不生效，生效的是"推导默认"**，而用户只能从这条 error 里间接知道。

> 📌 **本机现状旁证**：本次会话的运行时策略是 `danger-full-access`（`Current DSH file policy: danger-full-access`）——与"退回推导默认"一致，但**这不能证明用户原意就是想设 `danger-full-access`**；两者只是结果相同。

### 4.4 给用户的一句话建议（**不许改任何配置**）

> **`$DSH_HOME/settings.yaml` 第 667 行的 `permission.defaultPreset: full-access-ask` 不是合法预设名（合法值＝预设表里的名字，本机至少是 `workspace-write` 或 `danger-full-access`），所以整段 `permission` 设置被拒绝、退回推导默认值；请你自己决定是把它删掉（接受推导默认）还是改成上面某个合法预设名。**
