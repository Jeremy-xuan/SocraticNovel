## 一 · 找到的东西（都是实测，不是听说）

### 1.1 现成的 DeepSeek Live2D 模型 —— 有

插件 [`lrplrplrp/dsh-live2d`](https://github.com/lrplrplrp/dsh-live2d)（**MIT**，39 commits，v0.1.4）自带：

| 文件 | 内容 |
|---|---|
| `assets/deepseek_l2d/deepseek.moc3` | **83 KB 真模型** |
| `assets/deepseek_l2d/deepseek.2048/texture_00.png` | 单张 2048 贴图 |
| 5 个表情 | `happy` / `happy2` / `puzzled` / `relax` / `unhappy`（`.exp3.json`） |
| 4 段动作 | `idle`（58 KB）/ `speak`（73 KB）/ `thinking`（53 KB）/ `thinkend`（9 KB） |
| 物理 | `deepseek.physics3.json` |

我用我们自己的 `live2d-host`（Cubism Core 6.0.1）渲染过，**加载正常**，形象就是社区里的「蓝色大肥鱼／鲸鱼娘」：蓝长发、女仆装、鲸鱼尾、围裙上有鲸鱼图案。

**参数 26 个，五官完整**（这是关键）：

```
ParamEyeLOpen / ParamEyeROpen        眨眼
ParamEyeLSmile / ParamEyeRSmile      眼睛微弯（笑）
ParamEyeBallX / ParamEyeBallY        视线（可做眼动跟随）
ParamBrowLY / ParamBrowRY            眉毛上下
ParamBrowLAngle / ParamBrowRAngle    眉毛角度
ParamMouthForm / ParamMouthOpenY     嘴型 / 口型
ParamAngleX/Y/Z ＋ ParamBodyAngleX/Y/Z  头与身体朝向
ParamBreath                          呼吸
ParamHairFront / ParamHairBack / ParamTwinTails   头发
ParamSkirtSway / ParamSkirtFlap      裙摆
```

对照：**我自己用 auto-layer 做的 komari 模型没有 eyebrow / eye_white / pupil**（SAM 的 19 类里就没有），所以那个模型眨眼、眉毛做不出来。**换成 DeepSeek 这个现成模型，这个问题直接消失。**

### C. 舞台接入层（这是主要工作量，3 处）

| # | 位置 | 现在 | 要改成 |
|---|---|---|---|
| C1 | `classroom-stage-warm/lib/client.js` 的 `.cast` | `<img src=teacher_gen.png>` | 换成 `<canvas>` ＋ `pixi-live2d-display` 渲染。**可以借 `dsh-live2d` 的 `lib/src/40-engine.js`（MIT）**，它已经处理了 PIXI 7 ＋ Cubism Core 的加载与模型装载 |
| C2 | 舞台的 `/stage-static/assets/*` 路由 | 只静态发 PNG | 要能发模型目录（`model3.json` / `moc3` / 贴图 / `motion3.json` / `exp3.json`）——加一条 `/stage-static/models/*` |

🔴 风险提示（已踩过的坑）：`dsh-live2d` 是**浮动看板娘**（`shell.overlay`），我们是**全屏舞台**。借它的引擎代码可以，但**不要借它的落点**——`shell.overlay` 那套的 pointer-events 与 errorBoundary 规则和我们舞台不兼容（`开源线/AGENTS.md` 里有三条红线）。

## 三 · 工作量与顺序（我的建议）

| 步 | 做什么 | 估时 | 依赖 |
|---|---|---|---|
| 1 | 把 `deepseek` 模型装进 `live2d-host` 并渲染验证 | ✅ **已完成**（首帧已出） | — |
| 2 | 舞台加 `/stage-static/models/*` 路由 ＋ manifest 报 models | 1–2 h | — |
| 3 | 舞台 `.cast` 换 canvas ＋ 接 `40-engine.js` 的装载逻辑 | 2–4 h | 步 2 |
| 4 | 相位 → 动作映射（D1/D2） | 1 h | 步 3 |
| 5 | 表情表对齐（E1） | 1 h | 步 3 |
| 6 | 角色卡与 persona 换人（A1–A3） | 1–2 h | 可与 2–5 并行 |
| 7 | 补五官部件（给**我们自己**的 komari 管线，不是给 DeepSeek 模型） | 数天 | 需要新的分层输入（SAM 给不了 eye_white/pupil/eyebrow） |

**关键判断**：DeepSeek 现成模型有完整五官（26 参数含眉毛/眼球/眨眼），所以**第 7 步对演示不是必需的**——它只影响「以后用 auto-layer 自己做新角色」这条能力线。

## 四 · 待你定的两件

1. **模型资产能不能用**：`dsh-live2d` 的代码是 MIT，但 `assets/deepseek_l2d/` 的模型没有出处与授权说明。用之前你要不要先去问作者 / 找原始出处？我按规矩只列事实，不替你判断。
2. **场景要不要跟着换**：现在是「编辑部 + 两份稿子」的比喻（讲单核并发效果很好）。换成鲸鱼娘后，是保留这套比喻只换说话的人，还是换成海洋／数据流的语汇？
