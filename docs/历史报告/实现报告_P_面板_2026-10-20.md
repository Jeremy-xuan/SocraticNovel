## 二、最重要的三条事实（都是实测，不是推的）

### 2.1 「立绘装载失败」的第一因：`readAll` 在 0.2.1 里**不存在**

真浏览器（0.2.1-rc.2 隔离 profile）里，面板一挂上就出现：

```
[data-classroom-ui-live2d="failed"]
内文 = "立绘装载失败：remote.workspaceFiles.readAll is not a function"
```

0.2.1 的 `workspaceFiles` Remote 只注册 `read` / `readBytes` / `list` / `stat` / `changes`
（逐字读自宿主 `dsh-api-workspace-files/lib/typert.host.js`）——**没有 `readAll`**。
所以「缺 `clients/live2d-host/out/`」只是**第二因**：代码在"读文件"之前就断了。

### 2.2 第二个坑：`readBytes` 的 `bytes` 字段装的是**字节数**，负载在 `data`

改调 `readBytes` 后仍然失败，真浏览器里的报错是：

```
读字节的返回形状认不出（number）：clients/classroom-stage-warm/assets/l2d/live2dcubismcore.min.js
```

即 `value.bytes` 是个 **number**（字节数），真正的负载在 `value.data`。
`bytesOfWorkspaceFile` 因此改成**两个字段都试**，谁装着字节就用谁；两个都不是字节容器时抛，
并把 `bytes=` / `data=` 各自的类型写进文案（不许静默返回空字节）。
支持形状：`Uint8Array` / `ArrayBuffer` / 任意 `ArrayBufferView`（含 Buffer）/ 数字数组 / base64 字符串（0.1.5 的形状）。

### 2.3 因此 D3 的选型：面板立绘改用**舞台那套** `PIXI.live2d`，不用 `live2d-host`

证据链：
1. `clients/live2d-host/out/{live2d-host.bundle.mjs, shaders/WebGL/*}` **不在仓库里**，且 `clients/live2d-host/vendor/`（esbuild ＋ CubismWebFramework ＋ Core）也没随仓库分发 → 那条腿在本仓库**永远跑不起来**（不是配置错）。
2. 舞台 `/stage-static` 实测能发全部需要的东西：`l2d/{pixi,live2d,live2dcubismcore,index}.min.js` ＋ `models/deepseek/*`（清单来自 `manifest.json` 的 `l2d` / `models` 字段，**不猜路径**）。
3. 舞台装了的时候 `window.PIXI` / `window.Live2DCubismCore` **已经在页面上**；面板按**全局**判"已就绪就跳过"，不重复插脚本 → 满足 EC「两边对 Core 的加载不能重复执行也不能冲突」。
4. EC「不能同时跑两个 PIXI 应用」由 D2 保证：舞台铺满整屏时面板 `ticker.stop()`（实测 2 s 0 帧）。**这是选型的依据，不是事后辩护**。

真浏览器实测（舞台已装、Ctrl+Shift+M 关掉舞台后看面板）：

```
data-cui-portrait-mode = "pixi-idle"
board 状态 = "raised"（画布没被折起）
PIXI = object, PIXI.live2d.Live2DModel = function, Live2DCubismCore = object
页面上没有任何 pageerror
```

### 2.4 谁负责谁（EC 的落地口径）

| 资源 | 谁装 | 面板怎么做 |
|---|---|---|
| `Live2DCubismCore`（整页唯一全局） | 舞台先装（`<script src="/stage-static/l2d/live2dcubismcore.min.js">`）；**舞台没装时**面板自己从同一条路由装 | 按全局判：已在 → **跳过**（`portraitSources.core` 记来源）。两边指向**同一个文件**，不存在版本差 |

## 三、D1 · 只播待机动作 ＋ 约 15fps

- `PORTRAIT_FPS = 15`、`PORTRAIT_FRAME_MS = 1000/15`。**不是删 rAF**：rAF 照旧每帧回调，只有距上一张画超过 `PORTRAIT_FRAME_MS` 才真的 `host.step(dt)`（`live2d-host` 那条腿）／才走 ticker 回调（PIXI 那条腿）。
- `dt` 取**真实流逝时间**（`(timestamp - last)/1000`，上限 0.1 s）→ 呼吸/眨眼/物理仍按真实时间推进，只是每秒画 15 张。
- PIXI 那条腿：`app.ticker.maxFPS = 15` ＋ `autoUpdate: false` ＋ 在同一个 ticker 回调里 `model.update(deltaMS/1000)` → **渲染与模型推进同频**（不是"渲染 15fps、模型还在 60fps 空转"）。
- `PORTRAIT_IDLE_ONLY = true`：相位**不换表情**（`applyPhase` 只把 `Idle` 运动起起来）、引擎的 `runtime/expression.md` **不上脸**。解析与读数代码一行没删；`readout().expressionApplied.status = "idle-only"` 并把原因写清（**不假装成功**）。
- 待机动作：模型自己 `model3.json` 的 `Groups` 只有 `EyeBlink` / `LipSync`（**没有 Idle 运动组**），所以把 `motionManager.groups.idle = "Idle"` 交给管理器（库内 `shouldRequestIdleMotion() → startRandomMotion(groups.idle)` 就会自动接下一段），并先 `model.motion("Idle", 0)` 起一段。

**实测**（真浏览器，舞台已装、舞台关闭）：`帧` 计数 3 s 内 +45 ＝ **15.0 fps**。

## 四、D2 · 不可见就暂停

三个开关，任一命中即暂停：

1. `document.visibilitychange` → `visibilityState === "hidden"`；
2. `IntersectionObserver` 观测画布（滚出视口 / 被祖先折起）；
3. **舞台铺满整屏**：`#stage-warm-root` 里有一层 `.stage-warm-root` 且不是 `data-killed="on"`（关闭态不算打开）。舞台随时可开可关（Ctrl+Shift+M / U、地址栏开关），只有 1 s 轮询能跟上，只读一个布尔。

暂停＝**取消已排的 rAF 且不再排**（`raf = null`）／`ticker.stop()`；恢复＝重新排一帧并把 `lastTimestamp` 归零（不归零会在恢复帧拿到一个从暂停前算起的巨大 dt，画面跳一下）。
解绑方式照 `dispose()`：三个监听各自在 cleanup 里摘掉。
没有 `document` / `IntersectionObserver`（node 侧、老环境）时**不暂停**——"观测不到"不等于"不可见"。

另外：面板内 tab 切到「板书」时 `PortraitStage` **卸载**，渲染随之停（这一层是天然的，不需要额外开关）。

**实测**：舞台打开后 `data-cui-portrait-paused="true"`，`帧` 计数 2 s 内 **+0**；切到「板书」页后 `[data-classroom-ui-portrait="canvas"]` 计数 0。

## 六、「能力缺席」与「装载故障」分开（D4 收尾）

这两件事语义不同，原来被混成同一个 `failed`：

| 状态 | 判据 | 界面 | DOM |
|---|---|---|---|
| `absent`（能力缺席） | 舞台不可达 **且** 自带渲染宿主 bundle 读不到 | 静态图 ＋ 一行**中性**说明「立绘：静态图（本 profile 没有可用的 Live2D 源）」 | `data-classroom-ui-live2d="absent"`、`data-cui-portrait-mode="static-fallback"`，**没有** `[data-cui-live2d-failure]` |
| `failed`（故障） | 有源（bundle 读得到）但装载中途坏了 | 「立绘装载失败：…」照旧 ＋ 画布折 0 高 | `data-classroom-ui-live2d="failed"`、`data-cui-portrait-mode="failed"` |

判据是"失败路径里再读一次渲染宿主 bundle"，**不是给报错文案做字符串匹配**。
`test/panel.test.mjs` 的 10.8 因此从**一条**拆成 **A / A+ / B 三条**（更严，不是放宽）：

- **A**：无来源 → 中性说明 ＋ 折叠 ＋ **无失败行**；
- **A+**：无来源但静态图读得到 → `data-cui-board="static"` ＋ 真 `<img>`（blob URL）＋ 无失败行；
- **B**：故意喂"bundle 读得到、Core 读不到" → 仍必须出现 `[data-cui-live2d-failure]` 且文案仍是「立绘装载失败：…」（**原始文案与判据一个字没改**）。

> 原文案、原判据（`test:1302-1318` 与 `test:362-369`）都没动；放开的是"缺资产就报失败"这一条**行为假设**。

## 七、W-p · 板书只读历史

### 7.1 数据源
`<教室>/runtime/diagrams/index.md`，走 `remote.workspaceFiles.read`（分页文本通道）。
**不碰 `whiteboardStore`**（那个服务端服务没有任何写入者）。索引不存在＝正常态（这节课还没画过图）→ 空表 ＋ 一句说明，**不报错**。

### 7.2 解析：**按表头名取列**
引擎给索引加过一列（末尾「会话」），表头从 7 列变 8 列。按固定列数/下标写死的解析器会在那一刻把**每一行**判成"列数对不上"，整张表变空、而且不报错。
所以：先认出含「源文件」的那一行当表头，建 `列名 → 下标`，数据行按名字取。

- 只有「源文件」是必需列；「会话」缺/空 → `session: null`（**不等于"不属于本会话"**）；
- 「讲次」为 `—` → `lesson: null`（**不填 0**）；
- 没认出表头的老索引 → 按老版 7 列**位置**解析（`legacy: true`，界面上会如实写出来）；
- 列数对不上的行 → 跳过并记账（`skipped`，界面上显示）；
- 输出时间倒序；同一分钟按回合倒序；再同则"后追加的在前"（索引 append-only）。

### 7.3 界面（**只读**）
- 面板内 tab 栏「教室 ／ 板书」（方案甲：**不新增侧栏 tab 类型**）；默认在「教室」，那一页一个区块都没动。
- 每行「标题 ＋ 讲次 ＋ 回合 ＋ 图类型」；当前讲那一行底下走金褐发丝线。
- 「会话」列只**标注**不过滤（`data-cui-board-session = current|other|unknown`）：过滤会把"引擎写的会话号与面板 sessionId 不是同一个"的图整批藏起来，而这种不一致在客户端没有第二条判据。宁可多显示一行，不可静默丢。
- 点开 → 读 `.mmd` 全文 → `diagramFor`（vendored mermaid 11.17.2，**未引入新依赖**）；读不到/渲染失败 → **原因 ＋ 完整源码**，不白屏。
- 没有任何编辑入口（无 input/textarea/contenteditable）；有「重新读盘」与「收起这张图」两个按钮。
- 列表每次都真读盘（挂载时 ＋ 重新读盘）→ 刷新页面能从磁盘重建，不依赖内存状态。

### 7.4 W-p 的缺口
隔离 profile 的会话工作区里没有 `runtime/diagrams/`（也没有教室文件），所以**"点开一张真图渲染出来"没在真浏览器里跑通**——只跑到"空表 ＋ 正确路径 ＋ 诚实说明"。数据层（解析/排序/8 列/老索引/非法文件名拒绝）与列表渲染由 node 侧断言覆盖。

## 八、0.1.5 → 0.2.1 的 API 变更对照表（供 B4 迁移说明）

| 能力 | 0.1.5（原实现） | 0.2.1（实测） | 本车道的处置 |
|---|---|---|---|
| 整流读字节 | `workspaceFiles.readAll(sessionId, path, signal)` | **方法不存在**；改叫 `readBytes`（同形参数：scope + path + 可选 window） | 全部换 `readBytes`；`lib/client.js` 里调用点只有 1 处 |
| 字节负载形状 | `value.data` ＝ **base64 字符串** | `value.bytes` ＝ **number（字节数）**，负载在 `value.data`（本机实测；`Uint8Array`/`ArrayBuffer` 都可能） | `bytesOfWorkspaceFile`：两个字段都试、解 5 种形状、其它当场抛并点名文件 |
| 文本读 | `read` 分页（`text` 不含末行终止符） | 不变（面板已能读 `classroom.yaml` / `runtime/progress.md` 并渲染 5 个 section） | 沿用 |
| 错误码 | `result.error.message` | 多一个 `result.error.code`（如 `workspace-file/not-found`） | `readText` 把 code 带到异常上；"文件不存在"用 **code** 判，不靠文案正则 |
| 侧栏指南条目 | 读 `entry.kind` | 不变（仍是 `kind`；只写 `id` → `openTab(undefined)` → 面板永远打不开） | 已补回归断言（`test/panel.test.mjs` §1.5） |
| Cubism Core / PIXI 全局 | 面板自带 | 舞台装了就在页上 | 按**全局**判"已就绪就跳过"，不重复插脚本 |

## 十、已知技术债（本批不处理）

- `clients/live2d-host/out/` 与 `clients/live2d-host/vendor/` 不随仓库分发 → **`live2d-host` 那条腿在本仓库永不执行**（`mountCustomPortrait` 及其能力发现/驱动器/provider 代码成了"睡着的代码"，它们的单测仍在跑）。
  建议未来二选一：① 补齐 `vendor/` 让 `npm run build` 能出 `out/`，这条腿复活；② 正式下线这条腿，并**同步下线**它那批单测（不要只删实现）。

- 隔离 profile 里 `clients/classroom-ui/classroom.config.json` 读不到（工作区不是仓库）→ 部署一致性自检报 `unreadable`（**这是设计**：没核成就要出声）。真部署需要把该文件放进会话工作区。
