## 〇 · 一句话结论

上一版原型的问题**不是"不够精致"，是形态选错了**：

> 我们做的是**「底部一张带描边、带大投影、12px 圆角的半透明卡片」**——那是**聊天软件**的形态。
> 魔夜（以及日式 galgame 的正统做法）**根本没有那张卡片**：
> 它是一层**铺满全屏、左右羽化的压暗层**（实测 60% 黑），文字**直接排在全屏宽度的 80.8% 那一列上**，
> 上下各一条**发丝花饰**划出文本带；**零边框、零投影、零圆角滥用**；强调色是**青**不是暖琥珀；正文字族是**明朝体（衬线）**而不是单一无衬线。

差距可以量化成 **16 条**（§三），每条都给"我们现在是多少 → 该改成多少"。

## 一 · 取证方法：24,284 张图里怎么把 UI 找出来

素材是**无分类目录**的 24,284 张 PNG（混着背景／立绘／UI／特效）。定位靠**三路交叉**，不靠猜：

1. **归档分档**：KIRIKIRI 的资源按 `data<NNNNN>.hfa` 分档，解包后成同名目录。**每档的职责由"命名段 + 尺寸众数"判定**——`data00000` 全是可读命名（`txtwindow*`／`btn_base*`／`teatime_*`／`title_*`／`archive_*`／`conf_*`）＝**系统 UI 总档**；`data00100` 全是 `FONT_*` 且 155 张同为 1025×1025＝**位图字体图集**；`data02100`–`02235` 按角色代号（`aok`／`ari`／`beo`…）分档＝**立绘**。
2. **尺寸众数**：同类资源会挤在同一尺寸簇（`2552×1272` 出现 761 次＝宽幅背景；`165×99` 出现 447 次＝表情小件；`1025×1025` 出现 155 次＝字形页）。
3. **接触表目视复核**：把候选组拼成接触表（缩放到统一网格 + 棋盘底看透明区 + 烧入文件名与原尺寸）后逐张看。

🔴 **第 3 步不能省，而且命名会骗人**——实证：`wik_sel00`–`wik_sel13` 从名字看像"选择肢按钮"，**目视发现是 14 张全身立绘**（`_mono` 是灰度版）。若只靠命名，整份清单会错一大块。

**产出**：`code/prototypes/stage2/魔夜UI构件清单.md`（74 条构件，每条带"凭什么判定"）+ `assets/contact_sheets/`（19 张接触表）。

**打样素材**已挑出并拷进 `assets/`：43 件 UI 件 + 4 张背景 + 3 张全身立绘 + 3 页字形图集（共 46 MB）。

## 二 · 魔夜界面实测：设计语言与令牌表

以下全部是**从魔夜自己的资源里量出来的**，不是看截图估的。

### 2.1 🔴 最根本的一条：对话框不是"框"，是"整屏压暗层"

| 文件 | 尺寸 | α 实测 | 横向覆盖率 | 判定 |
|---|---|---|---|---|
| `txtwindow00.mzp.png` | 1921×1081 | 中心 `(0,0,0,153)` = **60% 黑** | **每一行恒 80.9%**（y=0 到 y=1080 都一样） | 全高纵向压暗层 |
| `txtwindow01.mzp.png` | 1921×1081 | α=129 = **51% 黑** | 恒 80.0% | 同上（较弱一档） |
| `txtwindow02.mzp.png` | 1921×1081 | α=102 = **40% 黑** | 恒 78.4% | 同上（最弱一档） |

**"每一行覆盖率恒定"这一条是决定性的**：如果它是底部文本框，靠近底部的行覆盖率会高、顶部接近 0。恒定 ⇒ **它是全屏高度的竖条**，左右边缘羽化（α>32 的 x 范围 184–1737，到 x=100 已归零）。

把它叠到一张真背景上合成出来看（`assets/contact_sheets/25_composite.png`）：**整屏压暗，上边缘与下边缘各一条居中的细藤蔓花饰**。三档 α 是三种呈现强度。

> **结论**：魔夜的"对话框"＝**一层调暗 + 两条发丝花饰**。**没有任何九宫格/边框件参与对话呈现**。

### 2.2 形状与描边（1:1 实测，见 `assets/contact_sheets/28_tokens_1to1.png`）

| 构件 | 实测几何 | 实测配色 |
|---|---|---|
| **列表/选择项**（`mu_text1_select_ja`，1072×1024，两列） | 每项**高 64px**、**行距 72px**（间隙 8px）、**列宽 516px**、列间距 12px、**圆角 r≈7px**（≈高度的 11%） | 未选：填充 `rgba(30,64,80,.90)`（深青）＋**3px 青描边**（`#155873`→`#0E869D` 渐变）；选中：**描边变 5px 亮青 `#46FFFD`**；文字纯白 |
| **配置药丸**（`btn_base1_ja`，940×364，4 行 × 4 枚） | 每枚**宽 212px**、**高 70px**、间隙 24px、**圆角 r≈16px**（≈高度的 23%） | 未选：深青底＋亮青发丝描边＋白字；选中：**青渐变填充**（左上亮青→右下深青）＋亮青描边＋白字带柔和辉光 |
| **提示条**（`system_popup_ja`，720×104） | 高 89px，左右各一枚**卷草纹装饰** | 深青底＋亮青发丝描边＋白字居中，字距大 |
| **短册纸牌**（`nz13LU/LB/RU/RB/CC`，各 1018×396） | **五片切**（四角 + 中心平铺），三套尺寸：`nz13` 1018×396 / `nz19` 1342×454 / `nz26` 1710×488 | 奶白纸面＋**淡黄发丝描边**＋上下边缘轻微不规则（手撕纸感）＋极淡投影 |
| **配置面板**（`conf_frame`，1820×936） | 小圆角（拟合 r≈20–59px，受圆角外渐变干扰，取"小圆角"结论） | 青蓝渐变底＋青色发丝描边 |

🔴 **可抄的三条形状规律**：
1. **圆角一律很小**（列表项 11%、药丸 23%），**魔夜没有一个"全圆角胶囊"**。我们上一版把按钮做成 `border-radius:999px` 是**错的方向**〔A15〕。
2. **描边是发丝级**（2–3px），颜色是**亮青**；"选中"靠**描边变粗变亮**，不靠换底色块。
3. **纸面（短册/存档）是奶白 + 淡黄边**，与深色 UI 形成材质对比——这是魔夜唯一的"亮面"。

### 2.3 字阶（1:1 于 1920×1080 屏，实测字形高度）

| 角色 | 文件 | 字形高度 | 占屏高 |
|---|---|---|---|
| 配置页标题 | `conf_title_ja`（600×88） | **55px** | 5.1% |
| 书脊章名 | `archive_010_ja`（244×60） | **38px** | 3.5% |
| 系统菜单项 | `teatime_archive_w_ja`（440×457） | **33px** | 3.1% |
| 提示条 | `system_popup_ja`（720×104） | **32px** | 3.0% |
| 列表/选择项 | `mu_text1_select_ja` | **29px** | 2.7% |
| 配置项按钮 | `btn_base1_ja` | **29px** | 2.7% |

**两条行业对照**（见 §四）：
- **Ren'Py** 默认正文 `gui.text_size = 22` @ 1280×720 = **3.06% 屏高**；姓名 30 = **4.17%**（姓名:正文 = **1.36 倍**）；快捷菜单 14 = **1.94%**。
- **KAG3**（日式 galgame 的事实标准）默认 `defaultFontSize = 24` @ 640×480 = **5.0% 屏高**；`defaultLineSpacing = 6` ⇒ **行高系数 1.25**。

### 2.4 字族：**明朝体（衬线）做叙事，ゴシック（无衬线）做 UI**

| 文件 | 页数 | 目视字形 | 判定 |
|---|---|---|---|
| `FONT_ja_000`–`027` | **28 页**（1025×1025） | 假名与汉字**有明显衬线与三角收笔** | **明朝体**（正文族，页数最多） |
| `FONT_ja_font3_00`–`09` | 10 页 | 笔画等宽、无衬线 | **ゴシック**（UI 族） |
| `FONT_ja_italic_*` | 3 页 | 整体倾斜 | 斜体（内心独白/强调） |
| `FONT_GAIJI_00` | 1 页 | ♥→♪✕ 与表格线 | 外字符号 |

🔴 **技术事实**：魔夜**把字体烘成位图图集**（共 155 张 1025×1025 页），**不走系统字体**。所以它的字形、字距、描边完全可控——这是它能做到"字阶那么准"的前提。

**【推断·待确认】**：正文用明朝体是从**页数**（28 页 vs 10 页）推断的，未经真实截图确认。

### 2.5 系统功能与存档

- **系统菜单**：`teatime_archive/next/save/title` **四张字图，每张内烘焙 4 行状态**（常态→悬停→按下→禁用，由亮到暗）；`_w`＝白字（深底用）／`_b`＝黑字（浅底用）。另有侧边菜单窗 `menu_window`（700×1080 竖向渐变板）。
- **存档 = 书架（書庫）**：`archive_010_ja`–`archive_120` 是**每章一条书脊**（「一章」「一.五章」…「十三章」「番外編」）；`archive_read/unread` 是书脊上的既读/未读标记；`archive_frame` 是满屏**木框**；`archive_window_ja` 是**米色纸面板 + 金褐发丝框**；`archive_txtsentaku` 是**三色选中行高亮条**。
- **回想**：`bg_backlog`（1920×1080 深蓝渐变）。
- **配置项全表**（从 `panel1_ja`／`panel3_ja` 的整列字图 + `btn_base*` 拼出）：BGM音量／语音音量／效果音音量／系统SE音量／影片音量／BGM自动调整／BGM音源／文字显示速度／自动模式速度／**窗口透过率**／**文字描边**／语言／**已读文字颜色**／跳过模式／选择肢时解除跳过／帮助显示／画面模式／缩放。

### 2.6 立绘与背景

- **立绘是"身体 + 头"分离的部件系统**：`aok_a_02_17_00_b` 是**无头身体**，`data02020` 里 **10,821 张 165×99 / 260×157 的小件**是头/眼/嘴的差分——运行时合成表情。这是"表情切换零成本"的实现方式。
- **立绘本身不带投影**；景深由背景与压暗层提供。
- **背景是宽幅**（`2552×1272`，2.007 宽于 16:9）→ **为镜头平移预留**；同场景有**昼夜/天气差分**（761 张同尺寸）。
- **章节过场用全黑剪影**：`img1946/1947/1950/1973`（2552×6632）是纯黑人物剪影；`img0409`–`img0422`（2042×5082）是**四语章名 + 剪影**的章节标题画面。**这是成本最低、收益最大的一个可复用设计点**。

## 三 · 诊断：我们现在到底差在哪（16 条，逐条给数值）

> 每条格式：**现状（我们的数值，带锚点）→ 对照依据（魔夜实测／行业通用值）→ 该改成什么（可照改的颗粒度）**
> 上一版原型的真实截图见 `assets/contact_sheets/30_prev.png`。

### D01 对话框形态：**"底部卡片" → "整屏压暗 + 发丝花饰"**（最根本的一条）

- **现状**：底部一张卡片，宽 `min(1080px, 94vw)`〔A06〕、最小高 `148px`〔A07〕、底 `rgba(18,16,22,.86)`〔A03〕、`border:1px`、`border-radius:12px`〔A01〕、双重大投影〔A05〕、毛玻璃〔A25〕。
- **对照**：魔夜 `txtwindow00` 是 **1921×1081 全屏层**，α=153（**60% 黑**），**每行覆盖率恒 80.9%**，左右羽化，**无边框无阴影无圆角**（§2.1）。
- **该改成**：
  1. 删掉 `.dialogue__box` 的底、边框、圆角、投影、毛玻璃；
  2. 新增**全屏压暗层** `.dimmer`：`position:absolute; inset:0; background:rgba(6,8,12,.55)`，并加**三档**（叙述 .40 / 对话 .55 / 内心 .68）；
  3. 新增**上下两条发丝花饰**：`1px` 渐变横线（`linear-gradient(90deg,transparent,rgba(200,235,245,.35),transparent)`）＋居中一枚 SVG 藤蔓（宽 `14%`、高 `2.2vh`）；
  4. 文本带定位：`left:19.1%; right:19.1%`（＝宽 **61.8%**）、`bottom:6.2%`、**无底无框**。

### D02 边框与投影：**我们有 3 处大投影，魔夜 0 处**

- **现状**：对话框 `0 26px 60px rgba(0,0,0,.6)`＋内阴影〔A05〕；姓名条 `0 8px 20px`〔A09〕；投影区 `0 22px 50px`〔A14〕；立绘 `drop-shadow(0 24px 40px)`〔A12〕。
- **对照**：魔夜 UI 件**只有发丝描边**（2–3px 亮青），**无投影**（唯一例外是短册纸牌有极淡投影）（§2.2）。
- **该改成**：**全删**。层次改由 ① 压暗层 ② `1px` 发丝线 ③ `2px` 亮青描边 承担。文字可读性由压暗层兜底（这正是魔夜"默认 `frameGraphic=""`、纯色半透明板"的逻辑）。

### D03 圆角：**12px 圆角矩形 + 999px 胶囊 → 小圆角（11%–23% 高度）**

- **现状**：`--radius:12px` 用在框/面板〔A01〕；系统按钮 `border-radius:999px`；选择肢 `border-radius:10px`。
- **对照**：魔夜列表项 **r≈7px / 高 64px = 11%**；配置药丸 **r≈16px / 高 70px = 23%**；**没有一个全圆角胶囊**（§2.2）。
- **该改成**：面板/文本框 `border-radius:2px`；列表项 `border-radius:4px`；按钮 `border-radius:6px`；**取消所有 999px**。

### D04 字号阶梯：**整体偏小 1.4–2 倍**

- **现状**：正文 `17px`〔A10〕（1440×900 下 = **1.89% 屏高**）；系统按钮 `12.5px`〔A16〕（1.39%）；姓名 `14.5px`（1.61%）；教室标 12px（1.33%）。
- **对照**：魔夜实测 **2.7%–5.1%**（§2.3）；Ren'Py 正文 **3.06%**／姓名 **4.17%**（1.36× 正文）／快捷菜单 **1.94%**；KAG3 正文 **5.0%**。
- **该改成**（用 `vh` 让它在任何窗口都成立）：
  | 角色 | 我们 | 改成 | 依据 |
  |---|---|---|---|
  | 正文 | 17px 固定 | `clamp(20px, 3.2vh, 40px)` | 魔夜 2.7–3.5%／Ren'Py 3.06%／KAG3 5% 之间取偏 Ren'Py |
  | 说话人姓名 | 14.5px | `clamp(19px, 2.9vh, 36px)`（≈正文 0.9×，配字距拉层级） | Ren'Py 姓名 4.17% 偏高，中文用字距而非字号拉层级 |
  | 系统按钮 | 12.5px | `clamp(13px, 1.9vh, 24px)` | Ren'Py 快捷菜单 **1.94%** |
  | 小标签/教室标 | 12px | `clamp(12px, 1.7vh, 21px)` | 与 Ren'Py 通知 2.22% 同档 |
  | 章节/地点字幕 | 无 | `clamp(22px, 3.4vh, 42px)` | 魔夜书脊章名 **3.5%** |

### D05 行高与字距：**行高 1.95 太松、字距几乎没加**

- **现状**：`line-height:1.95`〔A11〕；`letter-spacing:0.015em`。
- **对照**：KAG3 `lineSpacing 6 / fontSize 24` ⇒ **行高系数 1.25**；Ren'Py 文本框 185px 容纳约 6.1 行 22px 正文 ⇒ **≈1.5**；魔夜的 UI 文字**字距明显放宽**（目视 0.06–0.10em）。
- **该改成**：正文 `line-height:1.55`、`letter-spacing:0.02em`；UI 标签 `line-height:1.2`、`letter-spacing:0.08em`；标题/章节 `letter-spacing:0.16em`。
  （中文方块字需要比日文假名更松的行高，故取 1.55 而非 KAG 的 1.25。）

### D06 姓名条：**橙色渐变气泡 → 无底板文字（或短册）**

- **现状**：`.namebar` 贴在框顶外沿 `top:-15px`、`border-radius:8px 8px 8px 2px`〔A08〕、玫瑰渐变底〔A04〕、投影〔A09〕、前面一根 3px 白竖条。**这是聊天软件的气泡形态。**
- **对照**：魔夜全档按"宽 150–900 × 高 30–140"筛出 139 件，**逐件看后全是章节书脊标签，没有对话姓名牌**（§2.5）→ 姓名是**直接排版的文字**（【推断】）。Ren'Py 的姓名**无固定底板**（`namebox_width=None` 自动宽度），位置相对文本框 `x=240`、正文 `x=268`（**正文比姓名右移 28px**）、姓名 `y=0`、正文 `y=50`（**下移 50px**）。
- **该改成**：
  1. 姓名去掉底与投影，改为**文本带上沿上方的一行小字**：`letter-spacing:0.14em`、颜色 `#9fe6f2`、`margin-bottom:0.45em`；
  2. **正文相对姓名左移 0**（魔夜是右移，但中文左对齐更自然）——**唯一借的是"姓名独立一行 + 正文另起"这个错位结构**；
  3. **短册（`nz13` 五片切）只用于章节/地点字幕**，不用于姓名。

### D07 立绘：**尺寸/站位/投影/亮度差**

- **现状**：`height:88%; bottom:0`〔A13 同块〕、站位 `left:52%`〔A13〕、`drop-shadow(0 24px 40px rgba(0,0,0,.55))`〔A12〕、说话 `brightness(1.04)` / 非说话 `brightness(.7) saturate(.85)`。
- **对照**：魔夜立绘**无投影**（§2.6）；景深由背景与压暗层给。
- **该改成**：
  1. **删掉 `drop-shadow`**；

  3. 站位：单人 `left:47%`（略偏左，给右侧系统条留位）；双人 `left:30%` / `left:70%`；

- **该改成**：① 背景改**真 16:9 宽幅图 `cover`**（打样素材已备 `assets/moye_bg/mansion_night.png` 2552×1272）；② 删掉模糊铺底；③ 暗角减到 `transparent 52% → rgba(0,0,0,.50)`；④ 压暗层三档（同 D01）。

### D15 动效节奏：**偏慢，且缺 `dismiss` 语义核对**

- **现状**：立绘 `opacity 620ms / transform 700ms`〔A17〕；投影 `380ms/460ms`。
- **对照**：Ren'Py 的 `dismiss` 语义 = **打字未完成时点击只补全当前行并吞掉这次点击**，第二次点击才推进（见 §四）；ONScripter 把"推进"做成**行内标记** `\`（一段文字里可有多个停顿点）。
- **该改成**：① 立绘进场 **480ms**、退场 **340ms**；② 投影淡入 **280ms** + `translateY(1.5%)`；③ 打字机 **40 字/秒**（KAG3 三档预设的中档），"流畅"段落用 **60 字/秒**；④ **核对并保留 `dismiss` 语义**（上一版 index.html 声明已实现"点一下补全、再点下一句"，需在代码层核对，见 §九 未做到项）；⑤ 新增**行内停顿标记**（`[[pause]]`／`[[投影:xxx]]`）——一个标记同时是"停顿点"和"事件触发点"。

### D16 章节过场：**我们完全没有 → 加一屏剪影过场**

- **现状**：上一版明确"没有标题画面"〔A27〕。
- **对照**：魔夜 `img0409`–`img0422` 是**四语章名 + 全黑人物剪影**的章节标题画面（2042×5082）；`title_bg1/2` 1920×1080 + logo 952×303 + 菜单 991×1068 + 光标 1200×160（§2.6）。
- **该改成**：加**章节过场**（1 屏：纯黑底 + 全黑剪影 + 章节名 + 上下发丝线，**2.2 秒自动过**）。**成本极低、收益极大**——它一次性把"这是一部作品"的体感立起来，而上一版最缺的就是这个。

## 四 · prior art：现成实现（借什么 / 明确不借什么）

> 完整版见 `code/prototypes/stage2/研究_prior_art.md`（含逐字源码引用与 URL）。本节只摘**决定我们怎么做**的部分。
> 🔴 交付自检：本节 §4.5 是一张**照着就能写**的表——每行都带具体数值或可直接粘的代码。

### 4.1 Ren'Py GUI（**最有用的一条：整套数值就是一张设计令牌表**）

- **它是什么**：视觉小说引擎 Ren'Py 的官方 GUI 模板。仓库 <https://github.com/renpy/renpy>；文档 <https://www.renpy.org/doc/html/gui.html>。数值出自 `gui/game/gui.rpy`。
- **怎么用**：**照抄数值并按屏高比例换算**。
- **【可直接复用】**：
  - **参考系**：`gui.init(1280, 720)`，所有数值是 1280×720 下的硬像素 → **换算成 `vh` 就能直接用在我们的 CSS 里**。
  - **字号阶梯**：`14 / 16 / 22 / 24 / 30 / 50`，其中 **正文 22（3.06vh）／姓名 30（4.17vh）／快捷菜单 14（1.94vh）／标题 50（6.94vh）**。**姓名:正文 = 1.36×**。
  - **对话框几何**：`textbox_height 185`（**25.69vh**）、`yalign 1.0`（贴底）、`dialogue_xpos 268`（20.94vw）、`dialogue_ypos 50`（6.94vh）、`dialogue_width 744`（**58.13vw**）。
  - **选项按钮**：`choice_button_width 790`（61.72vw）、`choice_spacing 22`、**文字居中**、`idle #cccccc → hover #ffffff`（**只提亮度，不改色相、不加描边**）、`insensitive #444444`。
  - **快捷菜单集合与顺序**：Back / History / Skip / Auto / Save / Q.Save / Q.Load / Prefs。
  - **`dismiss` 语义**（来自 `renpy/text/text.py`）：打字未完成时点击**只补全当前行并吞掉这次点击**，第二次点击才推进。
  - **打字机模型**（来自 `renpy/text/textsupport.pyx` 的 `max_times()`）：**给每个字形预计算一个出现时刻**，渲染时只问"现在超过了哪些字的 time"——天然支持变速、停顿、逐字淡入。
  - **`gui.kind_属性` 命名法**：`kind_borders / kind_width / kind_height / kind_text_size / kind_text_idle_color / kind_text_hover_color` → **可以直接当我们的 CSS 自定义属性命名蓝本**。
- **【明确不借】**：Ren'Py **默认 GUI 是亮色/圆角卡通风**（默认 `DejaVuSans`、亮色 accent、圆角按钮），与我们"暗色电影感 + 发丝线 + 小圆角"直接冲突 → **只借数值与语义，不借任何默认皮肤**。另外它的 `quick_menu` **贴底居中**会与对话框重叠（靠 `quick_button_borders` 下边距 0 共处一条带）→ 我们改放**文本带右下角**。

### 4.2 KAG3 / 吉里吉里（**日式 galgame 的事实标准：经典"黑底 50% 面板"的原始数值**）

- **它是什么**：Kirigiri Adventure Game 3，日式商业 galgame 的默认脚本层。<https://github.com/krkrz/kag3>；数值出自 `data/system/Config.tjs`。
- **怎么用**：这是我们想要的"近黑半透明板"的**原始出处**，直接引它的数值当基准。
- **【可直接复用】**：
  - **对话框 = `rgba(0,0,0,0.5)`**：`frameColor 0x000000` + `frameOpacity 128/255 = **50.2%**`。🔴 **不是 0.75、不是 0.86**——就是**一半黑**。我们上一版用的 `0.86`〔A03〕**明显过重**。
  - **`frameGraphic = ""`：默认不画边框图** → **"纯色半透明板"本身就是日式 galgame 的正统做法**，边框是可选装饰。这一条**直接支持我们"发丝线而非九宫格花边"的选择**。
  - **满宽流派**：`ml 16 / mw 640−32=608`（左右各留 16px）→ 对话框**几乎满宽 95%**，与 Ren'Py 的 58% 窄栏是两个流派。
  - **字号 = 屏高的 5%**（`defaultFontSize 24 @480`），**行高系数 1.25**（`defaultLineSpacing 6 / 24`），**字间距 0**（`defaultPitch 0`），**正文颜色纯白**，**默认字体 `ＭＳ Ｐ明朝`（衬线）**。
  - **注音字号 = 正文的 0.42 倍**（`defaultRubySize 10 / 24`）。
  - **三档打字速度预设**（`Config.tjs`）。
- **【明确不借】**：🔴 `defaultBold = true` + `defaultShadow = true` —— KAG3 靠**加粗 + 投影**保证文字在任意背景上的可读性。**这套做法与我们"全部字重 400、不用投影"的项目口径直接冲突**。我们的替代方案是**近黑半透明底板本身就在做对比度兜底**，不需要字重与投影。另不借它的 640×480 低分辨率 + 点阵字体观感。

### 4.3 ONScripter（**"推进"是行内标记，不是"一句一停"**）

- **它是什么**：开源 NScripter 兼容引擎。API 文档 <https://kaisernet.org/onscripter/api/NScrAPI.html>。
- **【可直接复用】**：**`\` = 点击等待（click wait）**、`@` = 换行并点击等待、`!` = 等待换行。→ **一段文字里可以有多个停顿点**，点击推进的是"到下一个 `\` 为止"。
- **我们怎么用**：把"投影区出现时立绘让位"这种**段中事件**做成**行内标记**（如 `[[投影:xxx]]`），解析时**一个标记 = 一个停顿点 + 一个事件触发点**。这样"老师边说边把图推上来"就变成一句台词内部的事，不需要拆成两句。
- **【明确不借】**：它的脚本语法（`*label`/`goto`/`bg`/`ld`）是为无 GUI 的命令式脚本设计的，与我们的 DOM 驱动模型不同；它的 **NVL 全屏文本覆盖式**推进与"底部文本带 + 投影区"形态冲突。

### 4.4 CSS 原生九宫格：`border-image-slice`

- **它是什么**：CSS 规范里原生的 9-patch 支持，与 Ren'Py 的 `Frame()` / `Borders(l,t,r,b)`、Unity NaniNovel 的九宫格、Godot 的 `NinePatchRect` 是**同一个东西**。
- **【可直接复用】**：魔夜短册是**五片切**（`nz13LU/LB/RU/RB` 四角 + `nz13CC` 中心平铺，各 1018×396）。把它合成为一张 9-patch 图后：
  ```css
  .slip{
    border-style:solid;
    border-width:1.1em 1.4em;              /* 显示时的边框厚度（拉伸区） */
    border-image-source:url("assets/moye_ui/slip_9patch.png");
    border-image-slice:150 120 fill;       /* 上 右 下 左（像素，相对源图） */
    border-image-repeat:stretch;           /* 角不拉伸、边拉伸 */
  }
  ```
  **打样阶段的简化**：先把四角片 + 中心片合成一张 9-patch（脚本已备），或用纯 CSS 画等效形状（奶白底 + 淡黄 1px 边 + 2px 圆角 + 轻微 `skew` 模拟手撕边）。
- **【明确不借】**：魔夜短册**图上已印日文章节名**，只借"形状与材质"，文字必须重做。

### 更正 1 · 对话框形态（**最根本的一条**）

- **本文原文**（§2.1 结论）：*「魔夜的"对话框"＝**一层调暗 + 两条发丝花饰**。**没有任何九宫格/边框件参与对话呈现**。」*
  以及 §〇：*「它是一层**铺满全屏、左右羽化的压暗层**（实测 60% 黑），文字**直接排在全屏宽度的 80.8% 那一列上**」*。
- **真实图依据**：U1（`steam_store/store_09_9.jpg`，1920×1080 官方商店截图）、U2、U3、U10 —— **四张不同来源的真实画面，没有一张有对话框**。
  实测文字带内行亮度 **76.0** vs 带上方 **78.2** / 带下方 **71.7**，差异在噪声级 ⇒ **文字背后没有底板、没有半透明压暗层**。
- **改成什么**：**删掉「整屏压暗层＝对话框」这个推断**。
  **真机主对话视图是「无框直排」**：白字＋深色描边，直接压在全屏画面上。
  那三张 `txtwindow00/01/02.mzp`（60%/51%/40% 黑）**在真实游玩画面里不生效**，
  更可能属于**菜单/回想页的压暗层**（U6 选择肢与 U4 回想页的背景**确实被大幅压暗**）——**【推断·待确认】**。

### 更正 2 · 文字列边界（**右对左错**）

- **本文原文**（§D14）：*「该改成：正文列 **61.8%**（`left:19.1%; right:19.1%`）」*，
  §D01 第 4 条：*「文本带定位：`left:19.1%; right:19.1%`（＝宽 **61.8%**）」*。
- **真实图依据**：U1 实测文字列**左起 x=331（17.2% 屏宽）**、**右至 x=1539（80.2%）**。
- **改成什么**：**左边界 19.1% → 17.2%；右边界 19.1%（＝80.9%）→ 19.8%（＝80.2%）**。
  即「右边界方向是对的、左边界错了」；文字列实际只占 **62.9% 屏宽**，**不是**从 0 铺到 80.8%。
  🔴 另补一条本文没有的：**文本带是顶对齐的**——三条独立真实帧的首行都在 **14.4%–15.3% 屏高**（U1 y=156／U3 y=165／同源帧 t005328 y=70·480），**不是贴底**（本文用的 `bottom:6.2%`）。

### 更正 3 · 正文字号（**本文偏小约 2.6 倍**）

- **本文原文**（§D04 表）：*「正文 ｜ 17px 固定 ｜ 改成 `clamp(20px, 3.2vh, 40px)`」*（1080 下约 34.6px）。
- **真实图依据**：U1 实测**当前行字面高（含描边）45px ＝ 4.17% 屏高**、旧行 44px ＝ 4.07%；
  **行距 80–90px ＝ 7.4%–8.3% 屏高**（U3 交叉验证：相邻行顶差 81／81）。
- **改成什么**：正文 **`font-size: 47px`（固定，基准 1920×1080 画布）**、**`line-height: 1.74`**。
  本文的 `clamp(20px,3.2vh,40px)` 在 1080 下只有 34.6px，**比真实字面高小约 1.4×**；
  若按「本文上一版原型」的 17px 算，则**小 2.6×**。

### 更正 4 · 姓名条（**不是"没查到"，是根本不存在**）

- **本文原文**（§D06）：*「对照：魔夜全档按"宽 150–900 × 高 30–140"筛出 139 件，**逐件看后全是章节书脊标签，没有对话姓名牌**（§2.5）→ 姓名是**直接排版的文字**（【推断】）。」*
- **真实图依据**：U1 / U2 / U3 / U10 **四张对话画面**里，*「**没有任何姓名牌、姓名条、名字气泡**」*；

- **改成什么**：**「姓名条不存在」由【推断】升为【证实】**——**魔夜根本不用姓名牌**。
