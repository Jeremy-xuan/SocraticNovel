## 5 · 我认为的差距在哪（以及量表的毛病）

**分数低的地方集中在 D1（3.7，唯一接近阈值的维度），原因是我自己的量表写法，不是产出质量问题。**

D1 的档位写了一条「对对方都是**你**」。但日记是写给她自己的，里面把学生称作「他」——这是**日记应有的写法**
（规则原文：只写她注意到的具体细节、第一人称、不解释），不是称呼不一致。评审严格照档位判，于是 10 组里有 8 组被这条扣分，
D1 从本该 4–5 掉到 3–4。它在理由里写得很直白：

> 「扣分在 C 段，它改用了第三人称「他」……按档位仍算一处不一致。」

> 「A 通篇没有「我」，用的是旁白式第三人称「她把手从板面上收回来，等你」」

后半句暴露了第二个真问题：**课堂段经常用旁白 + 引号台词的形式**（「她放下笔，把板子转回来一点。」「看这条线。…」）。
这是这个教室本来的叙述风格（角色卡写的是「动作带水感」，`_anchor.md` 也要求「要台词时先想她是写出来还是说出来」），
但 D1 的档位只按「自称/称呼」判，把旁白里的第三人称也当成不一致。三组 D1=3 的课堂段全是这种旁白式（g05、g02、g10）。

**我没有改档位把它们捞回来**——那正是任务书禁止的事。改成「旁白第三人称不算不一致」会立刻把 D1 抬到 4 以上，
但那样这份报告就没法回答「评审到底看到了什么」。**下一个版本要做的是重写 D1 的档位**（把「叙述视角」与「称呼轴」分成两条判据），
不是在报告里解释过去。这件事留给你决定。

**另外两处（属于采样，不属于量表）**：

1. **g09 / g05 的课堂段很短**（40 / 38 字），g09 甚至是纯选项清单（「1. 忽略它…2. …3. …」）。这是这个教室真实的相位行为
   （`answer` 相位出选项卡、`check` 相位只递一块板等你），但它让「课堂段的声音」几乎没有取样面积。十组里有 2 组这样，
   样本对「课堂声音」的代表性因此偏弱。要修是采样策略（每个相位多跑一组、或同一组连跑两回合再取最后一条），
   不是量表的事。
2. **g02 / g06 的课堂段很长**（570 / 608 字），是她「上浮」的时刻（角色卡点名的最值得抓的教学时刻）。评审给 D2 打了 4，
   理由是「有一处偏长」，这是**符合档位的**判法——但严格说，上浮时句子变密变长正是她的辨识特征，档位在这里偏保守。
   这一条我也没改，记在这里。

**盲性边界（诚实）**：样本正文里有她自己的渠道自指（群聊那句「群里说不清，上课我画给你看」；日记里是「他……我……」）。
评审能猜到某段大概属于哪一类。这是文本本身的痕迹，不是提示词泄漏（`课堂/群聊/日记/读者/面板/emoji/120 字/2 行` 在评审的系统位与量表里命中数均为 0）。
它不影响「是不是同一个人」这个判断，只影响「猜中比例」这类指标——本轮不测猜中比例。

## 6 · 途中发现的问题（**只记录，没有改**）

### 6.1 🔴 `~/.dsh/.credentials.yaml` 里的 `DEEPSEEK_API_KEY` 已失效（401）

```
401     {"error":{"message":"Authentication Fails, Your api key: ****2b68 is invalid"}}
```

所以本轮的模型通道改用 `llm-pi-ai` 的 `me` 提供方（同 `desktop` profile 的配置，`ME_API_KEY` 有效）。
**这不影响 N6 的结论**（三个 agent 走的是同一条 `ctx.llm` 通道，与 provider 无关），但谁要在这个仓库里重跑
「默认 provider = deepseek-official」的活体验证，会撞到同一个 401。要不要更新那条凭据由你决定（我没动凭据文件）。

### 6.2 `acp` / 账户型 provider 在 headless 下不可用

`provider: deepseek-account` 在 headless profile 里报
`ACCOUNT_SIGN_IN_REQUIRED: … The request destination must allow account authentication`。
同样是「换个 provider 就好」，记在这里省下一个人半小时。

### 6.3 NE 报告 §9.1 说的「参考口吻被并进最后一条日记」——**已修，本轮复核通过**

所以引擎下节课注入的「最近一条日记」是干净的。这一条可以销掉。

### 6.4 群聊样本里出现「群里」这个自指

她自己在群里说「群里说不清」——符合规则（群聊不承载知识点、约到课上讲），但对盲评是个小噪声（见 §5 末）。
如果下一轮要更硬的盲评，可以让采样时的触发语避免引出与她自身渠道相关的回复（那会损失一点真实性，取舍由你定）。

## 8 · 我替你做的假设 / 没做的

**假设**

1. **课堂「一次真回合」用 `followup(学生一句话)` 驱动**，不等一整讲。任务书允许（「一次真回合即可，不必上完一整讲」）。
2. **每组一份独立教室副本**，前置状态（讲次/相位/日期）由我写进副本的 `progress.md`。理由：日记的「最近三条」与
   `session_log.md` 若跨组累积，「同一时期」就不成立了。代价是这 10 组不共享同一份教室状态——这不是真实的上课序列，
   是 10 个独立的取样点。
3. **群聊的触发方式是「学生先在群里说一句」**（真实入口），不是让服务自己开场。开场（`kind: open`）会多一次调用且内容与话题无关。
4. **D4 交给脚本而非评审**：它查的是 emoji/行数/字数/第一人称四条可机检的规则，让模型去数行数不可靠。
5. **日记日期用 10-12 … 10-21 连续十天**，每组一天；「同期」指同一组内的三段，不是十组同一天。

**没做到的**

1. **评审只跑了一轮**（10 次）。没有跑第二轮评估稳定性——同一个人写的三段，换一次采样分数会不会变，本轮不知道。
2. **没有测「同一话题的群聊 vs 课堂是否互相矛盾」的知识一致性**：那属于教学正确性，量表明确把它排除在外。
3. **课堂段仍然是「单回合切片」**，有些相位（`answer` 出选项卡、`check` 只递一块板）天然声音很薄，见 §5。
4. **舞台/面板上没跑**（N6 不涉及 UI）：本轮全部在 headless + 隔离 profile 里。AC 的最后一环是**你看那张对照表**。
