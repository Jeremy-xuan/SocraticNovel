## §1 三个缺陷的根因复述与我的判定

### ① P0 · `classroom_list` 在显式 `classroomDir` 时整体失败

**I2 的根因表述（复述）**：`lib/discovery.mjs` 的 `depthOf()` 对不在 `workspaceRoot` 下的路径返回 `Number.POSITIVE_INFINITY`；而显式路径经 `absolutize()` **不做 realpath**，`workspaceRoot` 却是规范化路径（macOS `/tmp` ↔ `/private/tmp`）→ `depth = Infinity` → 宿主 `snapshotJsonValue` 拒非有限数 → **整个工具输出被拒**。

**我相不相信它：相信，但认为 I2 的表述只覆盖了「一半」，而这一半不是生产环境的主因。**

逐条核过的事实（我自己重跑过，见 §3）：

| I2 的说法 | 我的核对 | 判定 |
|---|---|---|
| `depthOf` 对不在 root 下的路径返回 `Infinity` | 逐行读到（原 `lib/discovery.mjs:84`），并用复刻的修复前变体复现出 `depth=null`（`JSON.stringify(Infinity)`） | ✅ 属实 |
| `absolutize` 不做 realpath | 逐行读到（`isAbsolute(p) ? p : nodeResolve(base, p)`） | ✅ 属实 |
| `workspaceRoot` 是规范化路径 | `process.cwd()` 返回 `/tmp/…`（未规范化）；但**宿主** `sandboxPolicy.resolve().workspaceRoot` 返回 `/private/tmp/…`（规范化） | ✅ 属实（两条来源的口径本来就不一致，这本身就是问题） |
| 宿主拒非有限数 | 读源码：`dsh-tools/lib/index.js:2479-2486` `snapshotToolValue` → `snapshotJsonValue` → `walkJsonValue` 的 `!Number.isFinite(current)` 判不合格；再用真实宿主包跑出 `isJsonValue=false` ＋ `ToolOutputError: … value is not lossless JSON` | ✅ 属实 |
| 「`depth = Infinity` 是常态，不是例外」（§6.3） | **我同意，而且这条比 I2 说的更严重**：生产配置是「会话在项目目录、教室在 worktree」，**两者本来就不在同一棵树下** → 这条**realpath 修不掉** | ✅ 属实，且是**必须单独修**的一层 |

**🔴 我加的一层判定（这是本次修复与 I2 建议 (a) 的唯一实质差别）**：
I2 的 Q1 倾向 (a)「显式路径也走 realpath」，并说它「修的是同一目录三种来源口径不一致这个根」。**我采纳 (a)，但认为 (a) 单独不够**：

- realpath 能修的是「**同一目录、两种写法**」（`/tmp/X` 与 `/private/tmp/X` 指同一个目录）；
- 修不掉的是「**教室真的在工作区根之外**」（教室在 `~/SocraticNovel-…`、会话在项目目录）—— 这时**无论怎么规范化，`posix.relative` 都是 `../…`** → 仍会返回 `Infinity`。
- 而 I2 §6.3 自己已经量出「生产配置就中招」，且给出的例子**正是第二种**（`classroomDir = /Users/wujunjie/SocraticNovel-wt/plugins/…`，`cwd = /Users/wujunjie/Documents/ChatGPT/大学申请`）——这两个路径**没有符号链接关系**，realpath 之后仍然互不为祖先。
- 所以：**只做 (a) 的话，I2 §6.3 那个「生产影响面」的例子修完还是坏的**。我用 `host-validate2.mjs` 把这一点做成了对照实验：修复前 `depth=null`→被拒；只做 (a) 的话 `depth` 仍是 `Infinity`→仍被拒；加 (b) 之后 `depth=-1`→被接受。

**→ 故我同时采纳 (a) ＋ (b)，但 (b) 的落点与 I2 的选项不同**：I2 的 (b) 说「`depthOf` 不返回 `Infinity`（改 `-1`／`null`），**并在 schema／渲染侧一并处理**」，并担心「改动点更多（schema 是 `required integer`）」。我核过后认为**不需要动 schema**：
- `depth` 的 schema 是 `{ type: 'integer', required: true }` —— **`-1` 本身就是合法 integer**，schema 一个字不用改；
- 渲染侧只需把哨兵值渲染成可读文本（我加了一个 `describeDepth()`，正数情形**沿用 I2 §5.3 的逐字措辞** `距根 N 层`，只把 `-1` 渲染成 `不在工作区根下`）；
- 故 (b) 的代价从「schema＋渲染＋排序三处」降到「一个纯函数 ＋ 一个渲染函数」。

**（我未采纳 (c)「把 `depth` 从 `required integer` 放宽」**：它只是让输出能过关，`summary` 里仍会渲染 `距根 Infinity 层`（I2 §6.3 已指出），且掩盖了口径不一致这个根。**）**

**根因的最终表述（我认可并落进代码注释的版本）**：不是「`depthOf` 写错了」，而是**「深度」这个量在三种来源之间没有统一基准**：
1. 深度基准（`workspaceRoot`）与候选路径（显式指定的目录）**各自做不做规范化不一致**；
2. 深度**没有定义「不在基准之下」时的取值**（用 `Infinity` 当哨兵，而 `Infinity` 恰好是宿主明确拒收的值）。

两条都修才算修完：① 统一规范化口径；② 给「不在基准之下」一个**有限**的取值。

### ② P2 · `skipped` 重复登记同一个符号链接

**I2 的根因表述（复述）**：同一符号链接被「约定目录扫描」与「深层扫描」各登记一次；`candidates` 有 `found` Map 按路径去重，**`skipped` 数组没有去重**。

**我相不相信它：相信。** 我在源码里把两条登记点都读到了，并且**因果链完全自洽**：

- 约定目录扫描（原 `lib/discovery.mjs:394-397`）：`classrooms/` 下的 `linked` 目录项 `type === 'symlink'` → `skipped.push(...)`；
- 深层扫描（原 `lib/discovery.mjs:425-428`）：`classrooms/` 本身就在深层扫描的路径上，`linked` 被**第二次**遇到 → `skipped.push(...)`；
- 两处的 `path` 完全相同（都是 `join(conventionRoot, 'linked')`），`reason` 也完全相同 → 逐字重复。

**我补的一条观察（I2 未写）**：这两条记录的 `source` **不同**（`convention` vs `deep`）。所以「去重」必须**明确保留哪一条**，不能只做 `new Set()`：
- 若按 `path+source` 去重 → **修不掉**（两条的 key 不同）；
- 若只留最后一条 → 来源会从 `convention` 变成 `deep`，与「来源优先级 explicit > convention > deep」的既有语义**矛盾**。
- **→ 我选「按 path 去重、保留首次出现」**：约定目录扫描先于深层扫描执行，故保留 `convention`，与排序键的优先级方向一致。

### ③ 测试脚本 `multiturn.mjs` 硬编码 `phase: 'boot'`

**现象**：对 cs-os 报 3 项假失败（cs-os 真实相位是 `open`）。

**我相不相信它：相信，并且我认为「3 项」这个数字可以由代码精确推出，不只是观测。**

`multiturn.mjs` 的 `expectedPerTurn()` 里 `phase: 'boot'` 是硬编码的，它喂给生产纯函数 `planTurnInjections()` 算「本 turn 应该注入哪些块」。cs-os 的 `phases:` 声明是 `open/probe/answer/check/review/close`（`classroom.yaml:50-56`），**没有 `boot`**；cs-os 里有一批块的 `frequency.every: phase` ＋ `phase.phases: [open]`（例如 `curriculum.map`，`classroom.yaml:150-157`）。于是：

- 用 `boot` 算期望 → 相位门 `phaseGate({phases:['open']}, 'boot')` → `false` → **这些块全被排除**；
- 实际注入里它们**在**（真实相位是 `open`）→ `expected ≠ actual` → **每个 turn 报 1 项失败**（`turn N 注入块集合 = manifest 计划`）；
- 再加「相位门块在 boot 相位不注入」这一项（用 `boot` 判实际，必然违例）→ **第 3 项**。

**→ 与「TURNS=2 → 3 项假失败」的观测完全吻合（2 个 turn 各 1 项 ＋ 相位门 1 项）。** 这不是「数字对上了」的巧合，而是逐条可推导。

**我补的一条判定**：这个脚本的问题**不是「硬编码了错的相位」，而是「把 fixture 的相位当成了全世界的相位」**。故修法必须是**可覆盖**（`SOCRATIC_PHASE=`），而不是「把 `boot` 改成 `open`」——后者只会把假失败从 cs-os 挪到 minimal-classroom。**默认值必须保持不变**（否则既有的 fixture 用法会反过来坏掉）。

## §4 有没有改既有断言（逐条给理由）

### 4.1 🔴 唯一被改的断言：`显式指定为符号链接时拒绝（不跟随）` → `显式指定的符号链接目录：解析到真实目录（realpath）并按 explicit 登记`

**旧断言**（原文）：
```js
const result = await discoverClassrooms({ workspaceRoot: ws, explicitDirs: [link], maxDepth: 1 })
// 显式链接被拒 → 回退到 deep 扫描发现真实目录
assert.equal(result.selected.source, 'deep')
assert.equal(result.selected.path, real)
assert.ok(result.skipped.some((s) => s.source === 'explicit' && s.reason.includes('符号链接')))
```
**新行为**：`selected.source === 'explicit'`、`selected.path === real`、`skipped` 里**没有** `source==='explicit'` 的条目。

**判定过程（是「断言在测旧行为」还是「实现真错了」）**：

1. **先看它是不是我改动的必然后果**：是。`absolutize()` 对绝对路径原样返回 → 旧代码**从不**对显式路径调 realpath → 末段符号链接因此**从未被跟随**。FIX-1 ① 让显式路径走 `realpathPath()`，而 `realpath` **定义上**就跟随末段符号链接 → 「显式符号链接目录」**必然**被解析成真实目录。**这是根因修复的直接推论，不是副作用。**

2. **再看新行为是否正是生产需要的**：是，而且**必须**是这样。I2 §6.2 的决定性对照里 `classroomDir=/tmp/socratic-discovery-it/classrooms/beta` —— `/tmp` 本身就是符号链接。**「显式路径不跟随符号链接」这一条一旦保留，用户显式配置的教室就会被判成「不可用」**，P0 修不掉。

3. **再看「拒绝符号链接」这条安全约束有没有被削弱**：**没有**。这条约束的本意（文件头 ③ 与取证 C3 逐字写明）是**防止自动扫描走出工作区**，它作用于「约定目录扫描」与「深层扫描」两条**自动**路径。这两条路径的行为**完全未变**，且仍由另外两条断言守着（本次均保持全绿）：
   - `符号链接目录一律拒绝（不跟随），并记入 skipped` —— 期望 `symlinkSkips.length >= 2`，实测仍通过；
   - `classroom.yaml 本身是符号链接时不算教室` —— 仍通过。
   即：**自动扫描拒绝符号链接（安全），用户显式配置允许（可用性）** —— 这个区分是**正确**的：显式配置是用户主动给出的路径，不是扫描边界。

4. **再看是不是「为了让红变绿而放宽」**：不是。新断言**比旧断言更严**：
   - 旧断言只查 `selected.source` / `selected.path` / `skipped` 里有符号链接条目；
   - 新断言额外钉住 **`candidates.length === 1`**（证明「显式解析后的路径」与「deep 扫描发现的路径」**被 `found` Map 正确合并成一条**，不去重就会变成 2 条）＋ **`skipped` 里没有 `explicit` 条目**（证明它被成功解析、不是被当成不可用目录）。
   - 也就是说，这条断言在改后**覆盖了 ① 的 I 项（`registerCandidate` 也走 realpath）**这个新改动点，**没有**覆盖损失。

**→ 判定：旧断言在测旧行为。改动合法，且理由写进了测试注释。**
