## 🔴 先说清楚这一轮的交付形态

**这是"给用户挑方向的预览"，不是已定稿。**

用户原话：*"皮肤是开始做了吗？我觉得先让我看一眼打算改成什么样吧。"*
→ 所以本轮**没有**交一版做完的皮肤，而是交了 **3 个方向**：

- 3 个方向在**同一份代码**里以**可切换的皮肤预设**（`SKIN_PRESETS`）存在，参数不同、代码同一份；
- 每个方向都在**真实面板上**截了图（不是示意图）；
- 每个方向都过了**同一套 22 项程序化断言**；
- **没有**替用户决定，**没有**把任何方向涂成"已采纳"。代码里有一个 `DEFAULT_SKIN = "quiet"`，
  那只是**代码的默认值**（总得默认一个），不是选择结果；用户拍板后改这一行 ＋ 删掉没选的两个即可。

### 为什么**不**用 `ctx.theme.overrideTokens()`（P3 §4.1 的 A 档）

`overrideTokens` 是**全局**的（把 token 层叠到整个界面上），而 SKIN-1 要的是**教室面板这一块**变样、
**不能把 DSH 整体界面搞坏**。用全局换肤去改一个面板，等于让左栏/输入框/其他面板一起变色。
→ 所以我们走 **P3 §4.2 的 B1 档（纯增）**：只在**本插件自己的 DOM 子树**里做样式，
宿主界面一个像素都不碰（§7 有实测对照）。

### 2.3 🔴 立绘舞台的底**必须是白的**（实测，不是选择）

Cubism 框架的**裁剪遮罩**那条路会在**共享的** WebGL 上下文上 `gl.clearColor(1, 1, 1, 1)` 并且**不还原**
（`live2d-host/out/live2d-host.bundle.mjs` 里三处逐字；Haru 有裁剪遮罩 → 触发），
于是渲染宿主每帧的 `gl.clear(COLOR_BUFFER_BIT)` 用的是**不透明白**。

浏览器里实测（`_skin1_probe_white.cjs`）：

```
gl.getParameter(gl.COLOR_CLEAR_VALUE) === [1, 1, 1, 1]      ← 主帧缓冲的清除色是「不透明白」
canvas 的 CSS background-color === rgba(0, 0, 0, 0)         ← 不是我们画的
portraitBox 的 background 也是 transparent
```

→ **画布的可绘区在深浅两种配色下都是白的，CSS 改不了**（那是帧缓冲里的像素）。
→ 所以三个方向都把舞台底做成"白纸/白板"，让这块白成为设计的一部分。
**改前是白方块直接压在深色面板上**（见 `before/09-dark-panel-zoom.png`），很刺眼。
**真正的修法在 `code/clients/live2d-host/**`（不在本插件可改范围）**——已写进 README §4.7.3，交给那一侧。

### 2.4 顺带发现并修掉的一个真 bug：`--dsw-alias-fill-l2` 根本不存在

改前 `FILL = "var(--dsw-alias-fill-l2, rgba(0, 0, 0, 0.045))"`。
穷尽检索安装版 token 定义（`dsh-client-ui-theme/lib/client.js`）：
**`--dsw-alias-fill-*` 家族零命中** → 这个 var **永远取不到**，一直退回写死的浅色值
→ **深色下几乎看不见**（黑 4.5% 叠在近黑底上）。
改后换成真存在的 `--dsw-alias-interactive-bg-hover`（浅 `#2631480f` / 深 `#ffffff14`）。

## 3 · 皮肤参数集中在哪（**一处**）

`code/clients/classroom-ui/lib/client.js` 里的 **`SKIN_PRESETS`** 是唯一的皮肤参数表。
渲染层由 `buildStyles(skin)` 从它派生样式表，**代码里不再有任何颜色/字号/间距/圆角的字面量**
（只剩 0/1 这类结构性数字与 flex 基准值）。

```
SKIN_PRESETS = {
  quiet / board / syllabus: {
    ink: {1,2,3,4}            四级字色阶梯（1 最重 → 4 最轻）
    fill: {hover, plate, code, canvas}      交互填充 / 区块板面 / 代码底 / 图形画布底
    line: {hair, box}         分节发丝线 / 盒边界发丝线
    radius: {card, block, inner, pill}
    space:  {xxs,xs,sm,md,lg,xl,xxl,xxxl}
    type:   {title, head, body, label, meta, prose, code}   七个排版角色
    section: 'rule' | 'plate' | 'card'      区块成形方式
    portrait: {maxWidth, maxHeight, background, border, radius, pad, floor}
    draw:     {background, border, radius, pad}             板书图卡片
  }
}
```

切换（**只注入配置，不改代码**）：

```js
globalThis.__DSH_CLASSROOM_UI_CONFIG__ = { skin: 'board' }   // 'quiet' | 'board' | 'syllabus'
```

认不出的名字**退回默认**，不抛错、不白屏（有测试断言）。

**唯一的例外**（必须单独说明）：`PORTRAIT_PAPER = "#ffffff"` 是一个**写死的白**。
理由见 §2.3——它必须匹配 Cubism 帧缓冲里那个不透明白，**不是主题 token 能表达的**。
代码里在它旁边写了完整理由。

## 4 · 三个方向

| | `quiet`（默认） | `board` | `syllabus` |
|---|---|---|---|
| **一句话定位** | 像一间安静的教室：纸面、发丝线，没有框，信息自己排好队 | 像一块黑板＋讲台：区块是一块块板面，立绘站在衬板上，板书图像挂在板上的图 | 像一本摊开的讲义：字号整体上一档、行距更松，区块是带发丝线的卡片，课程表像目录 |
| 区块成形 | `rule`：只有一条发丝线分节，无框无底 | `plate`：每块一块板面（`--dsw-alias-bg-layer-2`）＋ 发丝线 | `card`：每块一张发丝线卡片 |
| 圆角 | 6px | 2px（直角感） | 8px |
| 字号阶梯 | 11 / 12 / 13 / 14 | 11 / 12 / 13 / 14 | 12 / 13 / 14 / 16 |
| 标签字距 | 0.08em | **0.14em**（粉笔字那种疏） | 0.06em |
| 段落行距 | 1.55 | 1.60 | **1.65** |
| 立绘舞台 | 撑满列宽、高 340px、无框、脚下一道**地平线**（发丝线） | 撑满列宽、高 420px、白衬板＋2px 边框 | 撑满列宽、高 320px、白卡＋8px 圆角 |
| 板书图卡片 | 无外框，只留 mermaid 自己的白底块 | 板面底＋2px 边框（"挂图"） | 板面底＋8px 圆角卡片 |

### 每个方向的代价与风险（如实写）

| 方向 | 代价 / 风险 |
|---|---|
| `quiet` | ① 与宿主界面的**差别最小**——它本来就该"安静"，好处是不打架，坏处是"换了跟没换差不多"的第一印象风险；② 立绘被压到 340px 高，想要"大立绘"的用户会觉得小；③ 无框无底全靠发丝线，**发丝线在低分屏/缩放下可能糊**（0.5px 在 1x 屏上由浏览器决定怎么落像素）。 |
| `board` | ① **与宿主自己的圆角语言不一致**（宿主卡片 8px、药丸 24px，这里是 2px 直角）→ 看起来会"像另一个 app 里的东西"；② 板面底色用 `--dsw-alias-bg-layer-2`，**浅色模式下它是纯白**（该 token 浅色就是 `bluish-00`），所以浅色里"板面"其实只剩边框——**实测过**，我因此把 `board` 的板面改成 `interactive-bg-hover`（浅 `#2631480f`）才在浅色里看得见；③ 深色下板面若与底差不够会糊（当前 `bg-layer-1` 与 `bg-base` 差一档，实测可辨）。 |
| `syllabus` | ① 字号上移一档 → **右栏更挤、长标题更容易换行**（窄屏 720 实测无溢出，但比另两个方向满）；② 五个区块都是卡片，**层级"重"**，信息密度低的用户会觉得啰嗦；③ 16px 的教室名与宿主右栏 tab 芯片（13px）形成跳档，可能显得"头重"。 |

### 我推荐哪个、为什么

**推荐 `quiet` 作为起点**（一句话理由）：它是三者里**唯一完全靠宿主 token 活的**方向——
深浅色天然正确、不引入宿主没有的视觉语言、窄屏最稳；而"去掉开发者工具味"这个目标
它已经达成了（四级字色阶梯 ＋ 四档字号 ＋ 字距 ＋ 发丝线 ＋ 立绘从 825px 方块变成有地平线的讲台）。

**但这是我的推荐，不是选择。** 如果你要的是"一眼就像教室"，`board` 是三者里辨识度最高的；
如果你要的是"读起来像讲义"，`syllabus` 的信息层级最清楚。

## 8 · 顺手修掉的一条**静默失效**（单独一节，**不算皮肤那一版的功能改动**）

> 来源：另一路（立绘试装）查实，接线说明在 `code/clients/live2d-host/README.md` §三。
> 因为那个文件正是本轮我在改的，由我顺手做（避免两个写者撞车）。

### 8.1 改前 / 改后

**改前**（`applyPhase()` 里逐字一句）：

```js
applyPhase(state) {
  if (state.expressionIndex === null) return;
  const expressions = capability.expressions;
  if (expressions.length === 0) return;          // ← 🔴 静默吞掉：什么都不做、也不报提示
```

换到「表达式个数 = 0」的立绘模型时，「相位 → 表情」这条路**彻底无声失效**
（9 个候选模型里 **5 个**是 0 表情：Hiyori / Wanko / Mark / Rice / Teacher）。

**改后**：

1. 那句 `return` 前先记一次「报过了」（去重标志 `phaseExpressionReported`，不每帧刷）；
2. 讲台区**常显**一条提示（**生产路径也看得见**，不只是调试读数）：
   - `expressions === 0` → `data-classroom-ui-expression="unavailable"`
     「相位 → 表情不可用：本模型表达式个数 = 0，切环节不会换表情（判据与处置见 live2d-host/README.md §三）。」
   - `1 ≤ expressions < 6` → `data-classroom-ui-expression="partial"`
     「表情只有 N 个 → 多个环节会共用同一张脸（下标回绕，可用）。」
   - `≥ 6` → 不出现任何提示。
3. `readout()` 多带两项：`phaseExpression`（宿主能力发现的那条判据**原样透传**，不重新解析）
   与 `phaseExpressionReported`（去重标志）；
4. 调试读数行也加了后缀：`表情 —/0（0 个 → 相位不改表情）` / `表情 —/5（不足 6 → 下标回绕）`。

### 8.2 判据（**别写歪**）

| 表达式个数 | `status` | 面板怎么报 |
|---|---|---|
| ≥ 6 | `ok` | **不报**（6 个相位各取一个表情，正常） |
| **1–5** | `partial` | 报 **「可用但下标回绕」**——🔴 **不许报成失效** |
| **0** | `unavailable` | 报 **失效**（这一条才是原来静默的那个） |
