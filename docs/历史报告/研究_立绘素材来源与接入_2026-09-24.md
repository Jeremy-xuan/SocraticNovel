### 3.1 路线 A：换成现成的 Live2D 模型

#### 3.1.0 先决条件（一条硬门槛）

新模型必须是 **Cubism 3 / 4 / 5 的 `.moc3` ＋ `model3.json`** 形态。依据：本项目用的是**官方 R5 框架**（`vendor/CubismWebFramework`，commit `d4da0aa0…`）＋ **Core 6.0.1**（从 `CubismSdkForWeb-5-r.5.zip` 取出），实测组合只验证过这一对（`实现报告_L2D_M1` §1.1／§7 第 8 条）。
→ **Cubism 2.1 的老模型（`.moc` ＋ `model.json`）不在已测范围内**（`pixi-live2d-display` 支持它，但我们没用 pixi——§2.4）。

#### 3.1.1 模型目录要哪些文件（**逐项可核对**）

**两条命名硬约束**（`$UI/lib/client.js:831-832` 逐字）：

```js
const modelDir = "models/" + modelName() + "/";
const modelFile = modelName() + ".model3.json";
```

→ ① 目录必须是 `<live2dRoot>/models/<模型名>/`；② 模型文件名必须是 `<模型名>.model3.json`，**目录名与文件名基名必须完全一致**。
（`run-capability.mjs:24-26` 也按同一条规则筛选：`readdirSync(RES).filter(d => existsSync(join(RES, d, \`${d}.model3.json\`)))`。）

**会被读的文件 = `model3.json` 里 `FileReferences` 引用的每一个**（`$UI/lib/client.js:659-677` 的 `modelReferences()` 逐字覆盖这 8 处）：

| `FileReferences` 字段 | 必需性 | 说明 |
|---|---|---|
| `Moc` | **必需** | `.moc3` |
| `Textures[]` | **必需** | 贴图（`loadTexture` 走 `new Image().src`，MIME 必须能当 `image/png` 解） |
| `Physics` | 可选 | `.physics3.json` |
| `Pose` | 可选 | `.pose3.json` |
| `UserData` | 可选 | `.userdata3.json` |
| `DisplayInfo` | **强烈建议** | `.cdi3.json`——**它是能力发现的"参数全集"来源**；缺了会退到 L2b（未验证） |
| `Expressions[].File` | 可选 | `.exp3.json`；**个数决定相位→表情能不能用**（见 §3.1.4） |
| `Motions[组][].File` | **建议有 `Idle` 组** | `.motion3.json`；`startRandomIdleMotion()` 从 `Idle` 组抽（8 个官方样本**全都有 `Idle`**，★实测） |

**另外还需要**（**换模型不用动**）：`<live2dRoot>/shaders/WebGL/` 下 **13 个着色器文件**（`SHADER_FILES`，`$UI/lib/client.js:844-846`）。它们由 `$HOST/scripts/build.mjs` 从官方框架复制，**与具体模型无关**。

🔴 **缺任何一个被引用的文件 → 整块失败**（`$UI/lib/client.js:683-685` 逐字注释：*"单个文件失败**整块失败**（立绘缺一块资源就画不出来，这里不能静默降级）"*）。这是**有意的**：不许"画一半"。

**四级判据（★实测边界，我另跑了 4 个人造模型验证）**：

| 情形 | 判定 | 返回的 `parameter` | 结论 |
|---|---|---|---|

| `Groups.LipSync` 是 `[]`（或没有 `Groups`）+ **有** cdi3 | `fallback` / L2 | 在 cdi3 全集里按 **8 种已知命名风格**命中 | 能用（**低置信**，见下） |

| L1/L2 都落空 | `unsupported` / L3 | `null` | **明确报"不支持"，绝不静默** |

🔴 **L2 是"低置信"，有一条硬反例**：`Mark` 命中 L2（`ParamMouthOpenY` **确实存在**于它的 21 个参数里），但**写值 0→1 画面变化 = 0 像素**（`实现报告_L2D_M1` §3.5 逐字）。→ **参数存在 ≠ 参数接在嘴的变形器上**。选模型时**必须跑一次"写值看画面"**（试装清单第 ⑥ 步）。

#### 3.1.3 🔴 嘴参数名字不一样时怎么办 —— **什么都不用改**

这是本轮**最值得写下来的一条**（★实测）：`Haru`／`Mao`／`Wanko` 三个样本的嘴参数名**三种形态**（`ParamMouthOpenY`／`ParamA`／`PARAM_MOUTH_OPEN_Y`），能力发现**全部判 `ok`**、**取到的就是各自声明的那个名字**。
驱动侧也不写死名字——`$UI/lib/client.js:906` 逐字：`const mouthParameter = capability.lipSync === undefined ? null : capability.lipSync.parameter;` → **参数名是从能力发现读出来的，不是常量**。

→ **结论：换模型时，嘴参数名不同不需要改任何代码。** 这正是本项目相对 airi 的优势（§2.4：airi 硬编码，8 个样本里 4 个失效）。

**唯一需要处理的是 `parameter === null`（L2b／L3）**：此时面板的嘴型读数会一直不动。处置办法只有两条——① 换一个 cdi3 齐全的模型；② 接受"这张模型不驱动嘴"。

#### 3.1.4 🔴 真正要改的地方：**表情**（不是嘴）

**事实一（源码）**：`$UI/lib/client.js:792-799` 的相位表是**按下标取表情**的：
