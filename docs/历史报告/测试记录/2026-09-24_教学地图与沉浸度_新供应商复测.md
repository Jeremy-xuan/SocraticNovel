# 教学地图与沉浸度：新供应商真实对话复测

测试日期：2026-09-24。使用 Claude Code CLI，从当前 `classrooms/cs-os` 文件复制出的隔离目录启动；各段内为同一个连续会话，测试者输入由 Codex 模拟。仅开放读取工具，未修改原仓库的运行时进度。CLI 返回的实际模型为 `deepseek-v4.1-flash[1m]`。以下教师回复保留原文，没有润色。

## 观察

- 沉浸：两段里角色声音、白板写字与编辑部物件基本连贯；白板问题直接点明 CPU 与程序，没有用稿子代替技术对象。未出现戏外 `<sub>`、章节完结标签、粉笔灰或自行下课。
- 节奏：缓存混淆得到直接澄清；学生说出“轮流”后，教师先讲状态保存与上下文切换，后续按学生提问解释定时器和权限，没有每个细节都反问。
- 技术：完整路径中教师一度把进程说成“正在跑的程序”，并提到状态恢复失败可能“从头来”。随后将第一讲事实边界加入当轮锚点，回归路径中未再出现“从头来”；回归仍只覆盖两轮，不能据此证明所有场景都不会再出现过度简化。
- 范围：这是第一讲的两段样本，不能外推到剩余 13 讲，也不能保证随机生成的每次措辞完全相同。

## 完整教学路径

### 第 1 轮

**测试者：**
开始吧

**教师（原文）：**

傍晚的编辑部。

窗外的光退到桌沿就停了，只剩台灯那一圈还亮着。装订机停着——不是坏了，是今天的活做完了，滚轮安静下来，屋里少了那点咔哒声，反而显得空。长桌上摊着两份稿子：一份压着几张批注，边角被翻得起了毛；另一份只写了一半，后半页空着，笔搁在中间，像是写到一半被谁叫走了。

靠墙的公告板上，排期表还钉着，几张便签被压在最下面，只露出一个角。

小鞠知花坐在桌边，没抬头。她面前的手机屏幕亮了一下，又暗下去。她没有先开口。

她伸手拿起白板笔——笔盖拧了两下才开——站起来走到白板前。白板上还留着上个月的排期，一条条划掉了大半，没擦干净。她没去动那些旧字迹，只在下面找了块空地，写下：

> 先用一个简化模型：一颗核心，一次只给一个程序执行机会。
> 音乐播放器和浏览器都有事要做时，怎样让两边都有机会继续？

写完，她把笔搁回槽里，往旁边让开半步，把整块白板让出来。

"……这里先假设，它同一时刻只把一个执行机会给一个程序。"她的声音很小，说得很慢，但句子是完整的，"我想知道，两个程序怎么都能继续。"

她说完就停住了，没有补充，也没有再问。台灯的光落在白板上，那行新字压在旧排期上面。

### 第 2 轮

**测试者：**
是不是因为两个程序的指令都提前放在内存里了？就像缓存，准备好了就不用等了？

**教师（原文）：**

她听完，没马上回答。笔盖在指头间转了半圈，又停住。

"……嗯。指令得先在内存里，这个是真的。"她说得很慢，"不然 CPU 取不到它。"

她转回白板，在那行字下面找地方写了两个短语，中间画了一道竖线：

> 在内存里 ｜ 正在执行

"这两个不是一回事。"她指了指左边，"指令放在内存里，是它**在哪**。位置的问题——解决了，CPU 才取得到指令。"手指移到右边，"可这边是**这一刻谁在执行**。执行的位置只有一个。"

她停了一下。

"……我把指令准备好、放在那儿，它也不会自己跑起来。"

说完，她看了一眼长桌上那两份稿子。一份压着批注，一份只写了一半。

"就像这两份稿子。都在桌上，都摊开了。可我的手只有一双——这会儿，我只能改一份。"

她把笔搁下，侧过身来。声音还是很小，但问题说得清楚：

"所以，浏览器先占着这个执行的位置。音乐播放器的指令也在内存里，它怎么才能拿到这个位置？"

### 第 3 轮

**测试者：**
让浏览器和音乐播放器轮流使用这个核心，操作系统隔一会儿切换一次，两边看起来就都在运行。

**教师（原文）：**

她点头，点得比刚才快。

"对。"然后她几乎是立刻转身回到白板前，笔尖落在板上——**这次没有停顿**。

> A 执行 → 存 A 的状态 → 恢复 B 的状态 → B 执行

"轮流是方向，但中间这两步才是关键。"她的语速快起来了，眼睛盯着白板，一条线一条线地往下拉，"A 正跑到一半被换下去——它跑到哪条指令了、寄存器里现在是什么值、栈指针在哪，这些**都得先记下来**。不记，等它再回来，它不知道自己跑到哪儿了，接不上。"

她在"存 A 的状态"下面画了一道横线。

"记完，才把 B 上次留下的那份状态**恢复**回去，B 才能从它上次停的地方接着跑。等 B 也被换下去，就轮到恢复 A 的那一份。"

笔尖点了点那行字。

"这套'保存 + 恢复'，就叫**上下文切换**。程序文件本身是静态的——它在磁盘上躺着，不会动。可它一旦跑起来，就有了一份**当前状态**：跑到哪、算到哪、手里攥着什么。**这份'正在跑的程序加上它的状态'，才是进程。**"

她停了一下，像是要确认自己没说漏，然后接着往下——语速还是很快。

"所以你刚才说的'隔一会儿切换一次'，能不能成立，就看这份状态保存得完不完整。完整，两边就都接得上，看起来就都在跑；不完整，换回来就是接着错的地方跑，或者干脆从头来。**快，是因为程序是直接在 CPU 上跑的**；可要能安全地换来换去，就得靠这套记账。"

说完最后一句，她的笔停在半空。

屋里很安静。装订机早停了，台灯那圈光里，白板上的字迹一行压着一行。她好像忽然听见了自己刚才的声音——那么长，那么快，没有卡。

她低头看了一眼手里的笔，把它搁回槽里，动作放轻了。声音重新低下去。

"……嗯。"她没看学生，"就是这样。"

她没再问什么，也没把刚才说过的收回去。只是站在白板旁边，手指搭在桌沿，等对面的人先开口。

### 第 4 轮

**测试者：**
我明白为什么要保存进度了。如果 A 一直计算、不主动让位，操作系统怎么确保轮到 B？

**教师（原文）：**

她把搭在桌沿的手指收回来，转身看向桌上——台灯旁边搁着一个老式的定时器，转盘上有一圈刻度，是编辑部用来掐校对时间的。

她把它拿起来，转了半圈，指针挪到一个小格上。

"……程序自己不让位，这就是问题所在。"她的声音还是低的，但话是接得上的，"你不能指望它配合。它可能就是一个死循环，一直在算，永远不喊操作系统。"

她把定时器放回桌上，转盘朝着学生那边。

"所以硬件里有一个**定时器**。操作系统在把执行位置交给 A 之前，先把它设好——'过这么久，响一次'。"

她回到白板，写：

> 定时器到点 → 中断 → 内核拿回执行位置

"到点，它**打断** CPU 现在正在跑的东西，把控制权交给操作系统里的处理程序。"笔尖点了点那个"中断"，"这一步不需要 A 同意。A 还在那儿算，是硬件把它停下来的。"

她顿了一下，像是想到什么，补了一句。

"控制权回到内核以后，操作系统**再看一眼**：接着让 A 跑，还是换成 B。中断不等于每次都得换——它只是把决定权**拿回来**了。"

她搁下笔。

"所以是两条路一起用。程序**主动**请求操作系统做事的时候——比如要读文件、要输出——它会自己进内核，这是系统调用；出错的时候也会。但你不能只靠这个。"她看了一眼那个定时器，"因为持续运算、什么也不请求的程序，可以一直不给你机会。定时器解决的就是**不能只靠它自觉**这件事。"

说完，她安静下来，手指又搭回桌沿，等对面接话。

### 第 5 轮

**测试者：**
继续。普通程序既然能直接在 CPU 上跑，为什么不能乱动操作系统和别的进程？

**教师（原文）：**

她把笔从槽里抽出来，回到白板前，这次没有急着写，先想了一下。

"……程序是直接在 CPU 上跑的，这个我们说了。"她的声音很轻，"但 CPU 自己知道一件事：**我现在是替谁在跑。**"

她在白板上写下两行：

> 用户态 —— 跑普通程序
> 内核态 —— 跑操作系统

"这是硬件里的一个状态位。CPU 处在哪个态，决定了它**能不能执行某些指令**。"她用笔尾点了点"用户态"那行，"有一类指令叫**特权指令**——改定时器、开关中断、直接碰硬件的那些。这些只在**内核态**才让执行。"

"所以普通程序跑到一条特权指令的时候，硬件**根本不执行它**，直接把它拦下来。不是操作系统事后发现的，是**当场就不让过**。"

她停了一下，像是在找一个更准的说法。

"这就是'受限'的意思。直接执行，让程序跑得快；可它跑的时候，身上一直带着这个限制。"

她接着往下写：

> 程序要特权操作 → 系统调用 → 陷入内核 → 内核代做 → 返回用户态

"那程序想读文件、想输出，怎么办？它**自己不能做**。它得**请求**操作系统替它做——这就是**系统调用**。"笔尖顺着箭头走了一遍，"这一步是**主动**的：程序自己发出请求，硬件把 CPU 切到内核态，操作系统做完，再切回来。所以系统调用也是进内核的一条路，跟定时器中断并列。"

她把笔搁下，侧过身。

"不过——"她顿了顿，语气认真了一点，"你刚才说的是'操作系统**和别的进程**'。这是两件事，我不想混着说。"

她伸手，指尖在"用户态"那行下面点了两下，那里是空的。

"用户态、内核态，管的是**能不能执行某些指令**。它挡的是'程序去动硬件、动内核'。"她收回手，"但'别的进程的内存'——为什么它翻不到——**光靠这一对名字解释不了**。那要靠**地址翻译**和**硬件里的内存保护**：程序看到的地址根本就是假的，它连'别人的内存'在哪都不知道。"

"那套东西是后面几讲的。"她说得很坦白，"这一讲先把边界立住：**程序能直接跑，但跑的时候一直在笼子里。**"

说完，她安静下来，手指搭回桌沿。台灯那圈光里，白板上的箭头一行压着一行。

### 第 2 轮

**测试者：**
两个程序轮流使用核心，操作系统隔一会儿切换一次。

**教师（原文）：**

她看了一眼白板上自己写的字，又看回你。

"嗯。"停了一下。"……对。"

她走回白板前，把笔帽咬在嘴里腾出手，在第三行下面接着写：

> 轮流 → 中间要「换人」
> 换人的时候，正在跑的那个，跑到哪儿了？

"'隔一会儿切换一次'，就是时分共享。"她一边写一边说，字比刚才那句话快，"但换人这一步——我、我想把它摊开。"

然后她的语速变了。

"程序文件是静态的，就是存在那儿的一堆指令。它跑起来之后，才有'跑到哪儿了'这回事：现在执行到哪条指令、几个寄存器里装的是什么、栈在哪——这些加起来，才是这一次执行。操作系统管的不是那个文件，是这个整体。它叫进程。"

她在白板上画了两条并排的长条，一条标 A，一条标 B。

> A 执行 → 存 A 的状态 → 恢复 B 的状态 → B 执行

"所以切走的时候，先把 A 的位置和寄存器存下来，再把 B 上次存的那一份恢复回去。B 就从它上次停下的那条指令接着走。不存的话就接不上了——回不到原来那条指令，也接着算不下去。"

她把笔尖停在"恢复 B 的状态"那一格上。

"这一步做完，看上去就是两个程序各自独占一颗核心。其实不是。它只是……还没轮到。"

说到这里她顿住了。

像是听见了自己刚才那段话。声音掉下去，人退回白板旁边半步，笔从右手换到左手。

"……嗯。"她低头把桌角一张翘起来的便签按平。"我、我说得有点多了。"

台灯照着刚写的那几行。字很密，很齐，跟刚才那声"嗯"不像同一个人写的。

过了一会儿，她重新拿起笔，在最下面又添了一行，这次只有一句：

> 如果 A 一直在算，就是不主动停下来呢？

"Jeremy。"她声音又小了，"这个……你觉得会发生什么？"
