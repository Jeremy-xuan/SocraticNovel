## 〇 · 一句话结论（给赶时间的人）

1. **它把 Live2D 挂进 DSH 的真实机制不是"右栏面板"**，而是：
   **`shell.overlay` 座（全窗口浮层，`list` 型）＋ 一个 `position:fixed` 的可拖拽/可缩放 iframe 壳**，iframe 里装**插件自带的 HTML 面板**（`panel.html`），面板经**同源 HTTP**（`/sakiko/*`）与宿主半边通信。
   出处：`client.mjs:800-803`（注册 `shell.overlay`）＋ `client.mjs:473-599`（`FloatShell`）＋ `client.mjs:402-448`（`SakikoFrame` iframe）＋ `host.mjs:4619-4646`（三条静态路由）。
2. **情绪不是模型打分，是宿主侧一段 13 条正则的优先级表**（`host.mjs:392-420`）；**表情/动作是面板侧三张静态表 ＋ 每帧参数平滑**（`plugin/web/emotion.js:21-133`、`plugin/web/panel.js:1186-1240`、`1459-1500`）。
3. **嘴型是"词级时间戳包络 ＋ AnalyserNode 能量"双驱动，外加一条程序化正弦兜底**（`plugin/web/panel.js:1257-1275`）。词级时间戳来自 edge-tts 的 `WordBoundary`，经响应头 `X-Sakiko-Words`（base64）传回面板（`host.mjs:4247-4249`、`tools/tts_emote.py:126-138`）。
4. **以上四件事全部可直接借**——它们解决的是与我们**同一个问题**，且都给了可抄的字段与公式（§七）。
5. 🔴 **一处必须点出的发现**：上游 amadeus 的面板只挂在 `details` 座上（`amadeus/client.mjs:409-418`），而**当前安装版 DSH 的 66 个座里没有 `details`**（两条独立证据，见 §3.2.3）→ 上游那份面板在当前版本上不渲染。sakiko 的浮窗（`shell.overlay`）**正是为绕开这一点才做的**——这是我们从它们的演进里能拿到的最值钱的一条教训。

## 三 · 逐题源码取证

### 3.1 装载：`dsh plugin add github:…` 到底发生了什么

**结论：与我们在 T1 轮实测出的机制**完全一致**，他们只是在上面多叠了两个约定。**

#### 3.1.1 `package.json` 里的两个声明块

`sakiko/package.json:14-22`（amadeus 为 `amadeus/package.json:33-41`，逐字同构）：

```json
"dsh": {
  "client": { "platform": "web", "inject": [] },
  "bundle": { "patch": "./cordis.patch.yml" }
}
```

- `dsh.bundle.patch` → 使本包成为该 profile 的**一个 bundle 层**（这是"装完即生效、不用手改 profile"的全部秘密）；
- `dsh.client.platform: "web"` → 让宿主 Loader **扫到浏览器半边**（与 `exports["./client"]` 配对）。

#### 3.1.2 `exports` 与 `files`（两处易踩的坑，他们都写对了）

`sakiko/package.json:7-13`：

```json
"exports": {
  ".": "./host.mjs",
  "./index.js": "./index.js",
  "./client": "./client.js",
  "./cordis.patch.yml": "./cordis.patch.yml",
  "./package.json": "./package.json"
}
```

`sakiko/package.json:23-41` 的 `files` 里**明确列了 `cordis.patch.yml`**（这正是我们 T1 实证过的坑：不列它 → pnpm 打包不带 → 启动报 `failed to read overlay … ENOENT`）。

#### 3.1.3 `index.js` 是给"裸包名做 CJS 式目录解析"的入口

`sakiko/index.js`（全文 2 行）：

```js
// Sakiko 静态包入口（内部加载器对裸包名做 CJS 式目录解析，找 index.js）
export * from './host.mjs'
```

（amadeus 同构，`amadeus/index.js:1-2`。）

#### 3.1.4 `cordis.patch.yml` 的**唯一真源**教训（🔴 这条值得逐字抄进我们的规范）

`sakiko/cordis.patch.yml` 全文 21 行，其中 `:12-17` 是一段**踩坑记录**，逐字：

> ⚠️ 本文件是**版本控制里的唯一真源**（2026-09-13 复审 B1）：它必须被 git 跟踪。旧版把它放在 `build_dist.py` 的 publish-files/ 里打包时才注入，于是从 GitHub 源码装（`dsh plugin add github:hg4/sakiko-for-dsh`）拿到的那份**没有 bundle 声明** ⇒ DSH 打 `declares no dsh.bundle` 警告 ⇒ **插件永不加载**。

补丁本体只有 3 行（`sakiko/cordis.patch.yml:19-21`）：

```yaml
- insert:
    - id: sakiko
      name: sakiko-for-dsh
```

→ 语义：向组合树**插入一个加载行**，`name` 由 dsh 加载器按包名解析。**同一个 `id` 若在 profile 手工补丁里也写过，会出现两次**（`:9-10` 逐字警告）——这是我们自己做 P1 装载时必须写进文档的一条。

#### 3.1.5 他们的安装/升级/卸载约定（`sakiko/README.md:88-110`）

#### 3.2.2 浮窗是什么机制：`shell.overlay` ＋ `position:fixed` 的 iframe 壳

`client.mjs:602-609`（挂在 `shell.overlay` 上的常驻宿主）：

```js
function FloatHost() {
  const config = useStore(configStore)
  const floatOn = !config || config.floatPanel !== false
  return React.createElement('div', { className: 'amad-float-host', style: { pointerEvents: 'none' } },
    React.createElement(RootPoller),                      // 每 2s 轮询 getStatus（client.mjs:297-304）
    floatOn ? React.createElement(FloatShell) : null,
  )
}
```

`client.mjs:473-599` 的 `FloatShell` 是全部 UI 机制所在：

| 机制 | 实现 | 出处 |
|---|---|---|
| 层级 | `const FLOAT_Z = 2147483000`（`position:fixed` 的 `zIndex`） | `client.mjs:471`、`:561` |
| 位置/尺寸 | 内联 style `left/top/width/height`，默认 **320×640**、右下角 **24px** 锚定 | `client.mjs:310-314`、`:556-564` |
| 最小尺寸 | `FLOAT_MIN_W = 320` / `FLOAT_MIN_H = 480`，随视口收窄 | `client.mjs:312-313`、`:491-492` |
| 拖拽 | 顶部 10px 的 `.amad-float-strip`，`onPointerDown → startDrag('move')`，`setPointerCapture` | `client.mjs:70`、`:516-523`、`:568` |
| 缩放 | 右下角 16px 的 `.amad-float-grip`，`startDrag('resize')` | `client.mjs:77-78`、`:588` |
| 折叠 | `collapsed:true` → 壳 `display:none` ＋ 右下角 48px 圆点按钮 `.amad-float-dot` | `client.mjs:562`、`:590-597` |
| 持久化 | `localStorage['sakiko.float.v2'] = {x,y,w,h,collapsed}`（读时兼容旧键 `amadeus.float.v2`） | `client.mjs:307-309`、`:339-373` |
| 视口夹取 | `clampFloatRect()`：宽高夹到视口、x/y 夹到 `[0, vw-w]` | `client.mjs:320-329` |
| 关闭/还原 | `—` 折叠、`⤢` 还原默认（`defaultFloatState()`） | `client.mjs:534-539`、`:572-587` |

🔴 **一条花了大代价才换来的 CSS 经验（他们自己逐字写在注释里，`client.mjs:53-64` 与 `:543-554`）**：

> Chrome 给子框架文档画布填**不透明白**（`html/body` 的 `background:transparent` 只作用于元素、不作用于画布——实测清空面板内容后整块 iframe 呈纯白 `255,255,255`），且 **composited iframe 会逃逸祖先的 `overflow:hidden` + `border-radius` 圆角裁切**。
> 下列手段**全部无效**（黑底实测，圆角外白像素 12400~28651 一个都没消掉）：壳的圆角边框 / 同色 border / 同色画布 / `clip-path`（壳·body·root）/ `contain:paint` / `transform` / `filter` / `isolation` / iframe 自身 `border-radius`。
> **唯一有效**：给 **iframe 自身**加圆角遮罩（`mask` 由合成器作用在 iframe 自己的层上）。

可用写法（`client.mjs:65-69` 逐字，含他们踩过的两个坑：data URI 里 SVG **属性值必须加引号**、必须带 `;utf8` 参数）：

```css
.amad-float-frame{
  position:absolute;inset:0;width:100%;height:100%;border:0;display:block;
  background:transparent;pointer-events:auto;
  -webkit-mask-image:url("data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg'><rect width='100%' height='100%' rx='36' ry='36' fill='%23fff'/></svg>");
  -webkit-mask-size:100% 100%;-webkit-mask-repeat:no-repeat;
  mask-image:url("data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg'><rect width='100%' height='100%' rx='36' ry='36' fill='%23fff'/></svg>");
  mask-size:100% 100%;mask-repeat:no-repeat;
}
```

#### 3.2.3 🔴 `details` 座在当前安装版里**不存在**（这条最值钱）

三条证据：

1. **sakiko/amadeus 的座注册表里写了 `details`**（`sakiko/client.mjs:790-793`、`amadeus/client.mjs:409-418`），注释逐字说是「牧濑红莉栖 Live2D **常驻右侧栏（details 列）**」（`amadeus/plugin/src/client.js:3`），且 sakiko 自己在设置页写了警告（`client.mjs:773` 逐字）：「右侧栏为 SAKIKO 专用，原「工具详情」面板在插件运行期间被替代，停止插件后恢复」。
2. **本项目 P3 轮从安装版取出的机器可读座目录里没有 `details`**：`取证_P3_客户端槽位与派发语义_2026-09-24.md:469-518` 列出的 **66 个座 key** 里无 `details`（该目录来自安装版 `dsh-cordis-client-runner/lib/client.js`，含每座的 `kind`/`scope`/`replaceRisk`/`source` 指针）。

→ **对我们的直接价值**：我们 P3 已经裁定「右栏正确入口＝`sidebar.right.pane.tab`（`replaceRisk:"none"`）」。这条是**第三方的反面实证**：有人**先按 `details` 做、发现不显示、于是另开 `shell.overlay` 浮窗**。我们**不需要**重走这条弯路。

### 3.3 文本情绪 → 表情 / 动作（他们怎么做）

**结论：不是模型打分，也不是 LLM 输出情绪标签（那是播报路径），而是宿主侧一段 13 条正则的优先级表。整条链路只有 4 步，全部可抄。**

#### 3.3.1 第 1 步：文本 → 情绪名（18 个枚举之一）——**纯正则，带优先级**

`sakiko/host.mjs:392-420`（**逐字全文**，这是整条链路的入口）：


**逐字要点**（照抄时必须原样保留的设计）：

1. **优先级顺序即语义**——先看「感叹号＋负面」= `furious`，再「感叹号＋正面」= `elated`，最后才落到单独的正/负面。顺序错了整张表就废；
2. **中日常用词混在一张表里**（角色说日语、用户说中文，两边都要能判）；
3. **标点独立成一维**（`！`→ 强度、`？`→ question、行尾 `…`→ soft）；
4. 返回的是**情绪名**（`'furious'`），不是表情名——表情名由第 2 步的静态表翻译。

**18 个情绪枚举**（`host.mjs:138` 逐字）：
`happy, excited, elated, sad, angry, furious, question, soft, blush, annoyed, thinking, surprised, disappointed, eyes_closed, indifferent, side, winking, neutral`

#### 3.5.2 算法（**逐字抄得动**）

`sakiko/plugin/web/panel.js:1257-1275`（**全文**）：

```js
function computeMouth(now, energy) {
  // ── 档 1：词级时间戳包络（有 words 且音频在播）
  if (mouthWords && mouthWords.length > 0 && audioEl && !audioEl.paused) {
    var t = audioEl.currentTime * 1000
    var wordAmp = 0
    for (var j = 0; j < mouthWords.length; j++) {
      var w = mouthWords[j]
      var on = typeof w.o === 'number' ? w.o : 0
      var dur = typeof w.d === 'number' && w.d > 40 ? w.d : 60
      if (t >= on && t <= on + dur) {
        var p = (t - on) / dur
        var env = p < 0.18 ? p / 0.18 : 1 - Math.pow((p - 0.18) / 0.82, 1.6)
        if (env > wordAmp) wordAmp = env
      }
    }
    return Math.min(1, Math.max(energy, wordAmp * 1.5))
  }
  // ── 档 2：只有音频能量
  if (analyser) return Math.min(1, energy * 1.6)
  // ── 档 3：程序化兜底（没有 Web Audio 时）
  return 0.6 + 0.4 * Math.abs(Math.sin(now / 70))
}
```

**逐字参数（照抄清单）**：
- 包络：**起音段占 18% 线性上升**；衰减段 `1 - ((p-0.18)/0.82)^1.6`；
- 多词**取最大值**（`if (env > wordAmp)`），不是求和；
- 词时长下限 60ms（`w.d > 40 ? w.d : 60`）；
- 词包络 × **1.5**，能量路径 × **1.6**，两路 `Math.max` 后夹 `[0,1]`；
- 兜底正弦：`0.6 + 0.4*|sin(now/70)|`。

**能量从哪来**（`panel.js:1244-1255`）：

```js
function getAudioEnergy() {
  if (!analyser) return 0
  var data = new Uint8Array(analyser.frequencyBinCount)
  analyser.getByteFrequencyData(data)
  var sum = 0; for (var i = 0; i < data.length; i++) sum += data[i]
  var raw = sum / data.length / 255
  energySmooth += (raw - energySmooth) * 0.45          // 一阶低通，系数 0.45
  return Math.max(0, Math.min(1, energySmooth * 1.8))  // ×1.8 后夹取
}
```

`analyser` 的建立（`panel.js:502-516` 的 `attachAnalyser()`）：`AudioContext` → `createMediaElementSource(audioEl)` → `createAnalyser()`，**`fftSize = 512`、`smoothingTimeConstant = 0.55`**，`src→analyser→destination` 串起来，`state==='suspended'` 时 `resume()`；**失败置 `graphFailed = true` 且不再重试**（→ 自动降级到档 3）。

**写参数（带平滑）**（`panel.js:1070-1088`）：


#### 3.5.3 与我们的「文字节奏嘴型」的关系（谁更好，见 §四）

| 维度 | 他们（音频驱动） | 我们（文字节奏驱动，`实现报告_L2D_M1…md` §5） |
|---|---|---|

#### 3.6.4 语音服务自管理（比我们多的一层）

`sakiko/host.mjs:968-1037`＋`watchdog.mjs`（672 行）：插件**自己拉起 GPT-SoVITS api 与协议桥**，并在 DSH 非优雅退出时回收。看门狗的设计（`watchdog.mjs:11-40` 逐字）值得单独记：

- **为什么不能用 `ctx.subprocess`**：那一套挂在 DSH 退出钩子上会被回收，而看门狗**必须活得比退出钩子久** → 用 `node:child_process.spawn`（`detached` + `stdio:['pipe','ignore','ignore']`）；
- **主信号 = stdin 管道 EOF**（DSH 进程消失 ⇒ 写端被 OS 关闭），比轮询 pid 可靠、无 PID 复用风险；
- **兜底信号**：每 2.5s `process.kill(dshPid, 0)`；
- **所有权令牌（fail-safe）**：触发回收时**重读**令牌文件，`token` 与"本代"相同才动手；不同/读不到 ⇒ **什么都不杀**（逐字：「宁可漏杀，绝不误杀」）；
- **真实进程形状**（`watchdog.mjs:22-28` 逐字，在真实强杀上实测）：`DSH node(被杀) → api 启动器(随父同刻死) → api-worker(监听端口,活) → api-grandchild(活)`；Windows libuv 的 Job Object 只收走直接子进程，孙辈 breakaway 逃逸继续占端口 → **必须按 `ParentProcessId` 链递归找后代再杀**。
- **进程级共享状态防热重载双实例**：`host.mjs:32-33` 用 `Symbol.for('sakiko-for-dsh/voice-module-state')` 挂 `globalThis`，并带 `epoch` 让**只有最新一代实例**有权排队停止服务（`host.mjs:5150-5164`）。

## 五 · 🔴 冲突清单（它们有没有踩我们的铁律）

> 判据是**本项目已立的铁律**（`AGENTS.md`「DSH 插件开发两条铁律」＋「DSH 客户端插件：装载机制与两个实测坑」＋「DSH 技能机制」＋ Live2D 线纪律）。逐条对，**踩了就说清"我们照抄会踩什么"**。

### 铁律 ①：插件**绝不能把宿主核心包**（`@deepseek-ai/*`）装进自己的 `node_modules`

**判定：✅ 未踩。而且他们做对了三件事，我们可以直接确认。**

| 检查项 | 实测结果 | 出处 |
|---|---|---|
| 依赖声明里有没有 `@deepseek-ai/*` | **零**。`sakiko/package.json` **没有 `dependencies` 字段**；`amadeus/package.json` 只有 `devDependencies: {esbuild}`；`amadeus/plugin/package.json` 连依赖都没有 | 三个 `package.json` 逐字 |
| 全仓有没有 import 宿主包 | 全仓 `grep -rn '@deepseek-ai'` **唯一命中**是 `amadeus/README.md:141` 的**版本兼容声明**（"DSH（@deepseek-ai/dsh）0.1.x / DSH Desktop 2.0.x：已按新版 API 适配"），**无任何 import** | 逐字 |
| 根目录有没有 `node_modules` | **两仓库都没有**（本轮 clone 后实测） | `ls` |
| 宿主能力怎么拿 | 全部走**注入服务**：`ctx.get('fs'/'webServer'/'subprocess'/'systemPrompt'/'sandboxPolicy'/'layout'/'theme'/'slots'/'llm'/'sessions'/'agentDefaultModel')`；host 半边 `export const inject = ['timer','fs','webServer','subprocess']`（`sakiko/host.mjs:21`），client 半边 `inject = ['timer','slots']`（`client.mjs:10`） | 逐字 |
| `react` 怎么来 | **外部化**：esbuild `external: ['react']`（`amadeus/tools/build_client.mjs:37`），产物里是 `require("react")`（`sakiko/client.js:37`）由**宿主 loader** 解析 | 逐字 |

🔎 **附带发现（不是铁律冲突，但是一条可借的教训）**：他们的 `inject` 声明**不全**——`sakiko/host.mjs:64-65` 取 `ctx.get('systemPrompt')`、`ctx.get('sandboxPolicy')`，`:3790-3792` 取 `ctx.get('llm')`、`ctx.get('agentDefaultModel')`，`:2568` 取 `ctx.get('sessions')`，**这些都没写进 `inject`**。他们的做法是**到处判空**（`host.mjs:5167` 逐字 `if (systemPrompt !== undefined) { … }`；`:2568-2570` 注释逐字「宿主提供该服务时；sakiko 未注入 `sessions`，通常为 `undefined`」）。
→ **我们的做法应该反过来**：要用的服务**全部写进 `inject`**（让 cordis 负责就绪顺序），不靠判空兜。**【待确认 §九-4】**

### 铁律 ②：**本地包用 `file:` 装**、别用 `link:`

**判定：🔴 amadeus 明确踩了；sakiko 合规。**

| 仓库 | 本地装法 | 出处 |
|---|---|---|
| **amadeus** | `dsh plugin --profile desktop add link:<本仓库根>` | `amadeus/plugin/README.md:16` 逐字；`amadeus/install.ps1:19` 逐字「本地为 `link:<本目录>`」；`install.ps1:232` 逐字 `$spec = if ($isOnline) { $GithubRepo } else { 'link:' + $PSScriptRoot }` |
| **sakiko** | `dsh plugin --profile web add file:<下载目录>\sakiko-for-dsh-2.2.1.tgz` | `sakiko/README.md:90` 逐字 |

**如果我们照抄 amadeus 的本地开发流程会踩什么**：我们的铁律来自实测——`link:` 会让插件**从自己的路径解析依赖**，找不到宿主核心包（→ 就是我们踩过的 `Cannot read properties of undefined (reading 'prepare')` 那一类双实例/Symbol 失配崩溃的诱因之一）。amadeus 之所以能用 `link:` 而没炸，是因为它**根本不依赖宿主核心包**（铁律 ① 那条实测：零 `@deepseek-ai` 依赖）——**它的写法能成立，是因为它的依赖面比我们窄，不是因为 `link:` 没问题**。
→ **结论：不借 `link:`。** 另外注意一个**细节差异**：sakiko 的 `file:` 指向 **`.tgz` 文件**，我们的是**目录**——pnpm 对"目录 `file:`"与"tarball `file:`"的处理不同（我们的硬链接镜像坑来自前者）。**【待确认 §九-5】**

### 铁律 ③：**不许往 `/Applications/DSH Desktop.app` 包里写任何文件**（会破签名）

**判定：✅ 未踩。**

全仓 grep 无 `/Applications`、无 macOS app 资源路径。所有写路径都是这三类：
- **安装目录**（由 `import.meta.url` 推导）：`sakiko/host.mjs:80` 逐字 `const ROOT = process.env.SAKIKO_ROOT || MODULE_DIR`（注释逐字「静态安装后 `ROOT` = 插件安装目录」）；
- **DSH 数据目录**：`host.mjs:83-88` 逐字 `env.DSH_HOME || env.USERPROFILE + '\\.dsh'`，子目录 `<DATA_DIR>/sakiko`；
- **profile 目录**（见铁律 ④）。

`sakiko/host.mjs:74-78` 还写明了迁移映射（`config/amadeus.json → config/sakiko.json`、`memory/amadeus-memory.json → memory/sakiko-memory.json`）——是**数据目录内部**的迁移，不涉及 app 包。

### 铁律 ④：**不许碰用户的真实 web/桌面 profile**（我们的纪律是测试 profile 隔离）

**判定：🔴 踩了（但性质要分清）。**

| 行为 | 出处 | 性质 |
|---|---|---|
| 安装时**默认选用户真实 profile**（先 `desktop`，再 `web`） | `amadeus/install.ps1:55-63` 逐字 `if (Test-Path (Join-Path $profilesDir 'desktop')) { return 'desktop' } if (Test-Path (Join-Path $profilesDir 'web')) { return 'web' }` | **产品语义正确**（用户就是要装进自己用的 profile）；**对我们做开发迭代而言是禁止的** |
| `dsh plugin --profile <p> add` 会写该 profile 的 `package.json` 依赖 | `amadeus/install.ps1:19-21` 逐字「dsh 会把它写进该 profile 的 `package.json` 依赖（pnpm 安装）」 | 同上 |
| **直接改写 profile 的 `cordis.patch.yml`** | `amadeus/install.ps1:73-89`：读 `profiles\web\cordis.patch.yml` → 正则删掉自己那一段 → **备份 `.bak-<时间戳>`** → 写回（UTF-8 BOM）；文件变空时写回 `[]` | **一次性 legacy 清理**（带备份）；但它确实**动了用户的 profile 补丁文件** |
| **改写 agent preset** | `install.ps1:91-99`：读 `.agent-presets\anchored-standard\agent.cordis.yml`，删掉 `id: amadeus` 行，写回 | 同上 |

**如果我们照抄会踩什么**：
1. **开发期就污染真实 profile**——我们的 P1/M3 教训是"测试只在 `socratic-dev`/`socratic-headless`，**web/桌面 profile 零接触**"。它们这套脚本**没有测试 profile 的概念**，默认就打真实 profile。→ 我们的开发脚本必须**强制 `--profile <测试 profile>`**，并加一条"profile 名不含 `dev`/`headless` 就拒绝执行"的闸门。
2. **它们改写 `cordis.patch.yml` 的手法值得抄一半**：正则只删**自己那一段**、**改前先备份带时间戳**、**空文件写回 `[]`**（而不是留空文件让 YAML 解析失败）——这三条都是**正确的工程手法**，可借；**"直接改"这个动作本身**不可借（我们应通过 `dsh plugin add/remove` 让官方管线去改，脚本不自己动 profile 文件）。
3. 🔴 **一条我们必须自己补的**：他们的 `install.ps1:236` 只提示「`dsh plugin add` 失败（可能需要 pnpm：`corepack enable` 或 `npm i -g pnpm`）」——**没有**"同版本 `add` 不刷新"的闸门（那条只在 README 文字里，`README.md:106-110`）。我们的铁律是「本地包改代码后重装：**先 `remove` 再 `add`**」——**照抄他们的脚本会漏掉这一步**。

### 铁律 ⑤：技能包"放错位置＝双重静默"、**类加载失败是静默的**

**判定：⚠️ 他们知道并写下来了，但**没有做自动化**；我们可以比他们做得更好。**

### 铁律 ⑥（非铁律，但值得记的一条"改了不生效"）

`sakiko/README.md:100-104` 逐字：

> ⚠️ **改动过 `host.mjs` 的版本需要重启 `dsh web` 才生效** —— profile patch 的热重载只会重新 `apply()` 同一个**已加载模块**，不会重新 import 宿主模块。

→ 这与我们 2026-09-24 实测的**硬链接镜像不抗"替换式写入"**是**同一类症状（改了不生效）、不同机制**：

| | 机制 | 触发条件 |
|---|---|---|
| 他们 | **模块缓存**：热重载只重 `apply()`，不重新 `import` 宿主模块 | 改了 `host.mjs`（宿主半边） |
| 我们 | **inode 断链**：`edit`/`write` 是"写新文件再替换"，硬链接在第一次编辑就断 | 改了**任何**文件，只要装法是 `file:` 目录 |

→ **两条都要写进我们的装载文档**：他们那条说明"改宿主半边必须重启"，我们那条说明"改完必须显式同步/重装"。**我们的坑更狠**（他们的客户端半边能热重载，我们的连客户端半边也可能停在旧版本）。

### 铁律 ⑦（非铁律，但照抄会带走的安全缺口）

🔴 **sakiko 相对上游丢掉了 `/rpc` 的本机回环校验。**

- amadeus 有：`amadeus/host.mjs:66-72`（逐字见 §3.2.6）；
- sakiko **没有**：全仓 `grep -rn 'remoteAddr\|isLocalHost\|forbidden'`（限 `.mjs/.js/.py/.json/.yml`）**零命中**；对照 amadeus 有 4 处（`tools/build_static.mjs:26-27` 与 `host.mjs:71-72`）。

→ 如果我们要自建 HTTP 桥（比如立绘面板要 RPC），**必须照抄 amadeus 那一版**（`remoteAddr ∈ {127.0.0.1, ::1, ::ffff:127.0.0.1}` 才放行），不要照抄 sakiko 的。另注意：**sakiko 的 `/sakiko/memory` 路由直接回 `facts` 与 `history`**（`host.mjs:4452-4462`），同样没有闸门。

**步 3｜算法（三档，常数逐字）**

```js
function computeMouth(currentTimeMs, energy) {
  // 档 1：词级时间戳包络
  if (words.length > 0 && playing) {
    let wordAmp = 0
    for (const w of words) {
      const on  = typeof w.o === 'number' ? w.o : 0
      const dur = (typeof w.d === 'number' && w.d > 40) ? w.d : 60      // 时长下限 60ms
      if (currentTimeMs >= on && currentTimeMs <= on + dur) {
        const p = (currentTimeMs - on) / dur
        const env = p < 0.18 ? p / 0.18 : 1 - Math.pow((p - 0.18) / 0.82, 1.6)  // 起音 18% 线性；衰减 ^1.6
        if (env > wordAmp) wordAmp = env                                  // 多词取 max
      }
    }
    return Math.min(1, Math.max(energy, wordAmp * 1.5))                   // 词包络 ×1.5
  }
  // 档 2：音频能量
  if (analyser) return Math.min(1, energy * 1.6)                          // ×1.6
  // 档 3：程序化兜底
  return 0.6 + 0.4 * Math.abs(Math.sin(nowMs / 70))
}

// 能量：AnalyserNode
const data = new Uint8Array(analyser.frequencyBinCount)
analyser.getByteFrequencyData(data)
const raw = data.reduce((s, v) => s + v, 0) / data.length / 255
energySmooth += (raw - energySmooth) * 0.45                               // 低通 0.45
const energy = Math.max(0, Math.min(1, energySmooth * 1.8))               // ×1.8 后夹取

// 写参数前再低通一次
lastMouthValue += (target - lastMouthValue) * 0.85                        // 低通 0.85
if (Math.abs(lastMouthValue - target) < 0.004) lastMouthValue = target
```


### R4 · TTS 通道抽象（若我们要让教室出声）

**步 1｜唯一分发点签名**

```js
async function synthesize(text, voice, rate, pitch, emotion) -> { bytes, mime, words: [{o,d}], slotPath? }
```

**步 2｜provider 枚举与语义**（照抄 `host.mjs:2004-2099` 的结构，通道可换）：

| provider | 形态 | 依赖 | 情绪能影响什么 |
|---|---|---|---|
| `edge` | Python `edge-tts`（SSML） | **Python 3 + `pip install edge-tts`** | style/pitch/volume（**语速不变**） |
| `voicevox` | 本地 HTTP `127.0.0.1:50021`（`audio_query`→`synthesis`） | 本地服务，**无 Python** | speaker |
| `quest` | 公共 VOICEVOX API | 网络 | speaker |
| `openai` | OpenAI 兼容 TTS 端点 | 网络 + key | voice/speed |
| `aqua` | GPT-SoVITS `POST {url}/tts/file?…` | 本地服务 | voice |
| `auto` | 级联 Aqua→VOICEVOX→（可选）quest | 视配置 | — |

**步 3｜三条必须保留的纪律**

1. **`voiceStability`（默认 true）＝失败不降级**——失败就抛错，**不切音色、不切浏览器语音、不切公共 API**；只有显式关掉才允许降级（`host.mjs:2051-2070, 2086-2094`）。理由：**声线突变比"不出声"更糟**。
2. **缓存键必须含 provider 专属参数**——`[providerKey, text, voice, rate, pitch, emotion]`，其中 `providerKey` 至少含 `emotionIntensity` 与 `questSpeaker`（`host.mjs:1954-2002`）；**`auto` 模式不写共享缓存**（`:2007`）。
3. **8 槽 round-robin ＋ sidecar 键**——音频写 `TMP/tts-<seq>-<slot>.mp3`，同目录写 `<同名>.key` 存缓存键；重播时**比对 key 且比对文件大小**（`host.mjs:827-905, 2106-2107`）。这是"聊天记录能重播"的完整解。

**步 4｜常驻 worker 的握手协议**（若要省掉每句 Python 启动）：

```
spawn(argv=[python, tts_server.py, '--root', TMP_DIR], cwd=TMP_DIR, graceMs=5000)
子进程 stdout 打印 "READY:<port>"   ← 宿主 10s 内解析出 port，失败回退逐句调用
POST http://127.0.0.1:<port>/synth  {text, voice, emotion, rate, pitch, intensity, out}
→ 200 {ok:true, out:<abs>, words:[{o,d}]} | 500 {ok:false, error}
```

🔴 **`cwd` 必须是数据目录，不能是安装目录**（`host.mjs:922-923` 逐字：Windows 上常驻进程的 cwd 会锁住安装目录，导致下次重装时删不掉）。**我们的 `file:` 装法同样要重装删目录**，这条必须照抄。

**步 5｜SSML 情绪参数（若用 edge 通道）**

```
情绪 → (express-as style, rate, pitch, volume)
happy:(cheerful,+0%,+8Hz,+6%)  excited:(cheerful,+0%,+18Hz,+12%)  elated:(cheerful,+0%,+24Hz,+16%)
sad:(None,+0%,-14Hz,-10%)      angry:(None,+0%,-4Hz,+16%)        furious:(None,+0%,+2Hz,+22%)
question:(chat,+0%,+14Hz,+4%)  soft:(customerservice,+0%,-6Hz,-12%)  neutral:(chat,+0%,+0Hz,+0%)
```
（`tools/tts_emote.py:30-38` 逐字；其余 9 个情绪见 `:40-48`。）

两条硬约束：**语速恒 `+0%`**（`:28`）；`style` 只有 `ja-JP-NanamiNeural` 支持，其他音色**强制置 `None`**（`:19-21, 106-109`）。`intensity`（0.2–2.0）按比例缩放 emotion 增量后再与用户全局 rate/pitch **相加**（`:77-99`）。

### R6 · 文档行号自检（解决我们正在流血的问题）

**我们的现状**：取证件（含本件）**大量散写 `文件:行号`**，任何一次插行都会让一批行号悄悄失准——这正是 `check-anchors.mjs` 头部逐字描述的病症（`check-anchors.mjs:3-5`：*"文档正文里散写 host.mjs 行号时，任何一次插行都会让一批行号悄悄失准（2026-09-20 实测：一个提交在三个位置插了行，只更新了表、正文里约 15 个行号全漂）"*）。

**落地规则（三条，照抄）**：
1. **行号只允许出现在文档的"行锚表"里**；正文一律用锚点编号（如 `〔A07〕`；区间写 `〔A04〕~〔A05〕`）。
2. **表行格式**：`| A07 · <说明> | <文件> | <行号> | \`<该行含有的唯一片段>\` |`（片段里 `⏎` 表示换行，用于多行锚点）。
3. **六条判据，任一不成立即 `BAD`**：① 文件存在；② 片段在该文件里**恰好命中一次**；③ 命中行号 === 表里写的行号；④ 正文里每个 `〔Axx〕` 都能在表里找到（**悬空引用**）；⑤ 表里每行都至少被正文引用一次（**孤儿锚点**）；⑥ 表内 **id 不得重复**。
4. **产物文件特殊处理**：文件列写 `<file>#unescape`，核对前先把 `\uXXXX` 解码（1:1 解码不产生换行 → 行号不受影响），避免"纯粹的产物重生成"造成假红。
5. **退出码**：坏 0 条 → 0；否则 → 1（可直接进 CI）。

**我方落点**：`报告构建/check-anchors.mjs`（自写实现，按我们自己的文档格式与锚点命名），并在 `报告构建/verify.js` 里挂上；同时把这条规则写进 `AGENTS.md` 的文档纪律。

**另两条测试纪律（照抄）**：
- **锚点找不到就 FATAL，不允许"测了个空壳还全绿"**（`test/provider-cache-key.test.mjs:9-11` 逐字）；
- **测试必须在头部声明"本测试不覆盖什么"**（`test/voiceoff-no-audio.test.mjs:6-14` 逐字：逐条列出产品里另外三条"语音关也会出声"的通道及其行号，明说不在本测试作用域）——这条**比测试本身更值钱**，直接可用于我们验收流水线的"作用域声明"。
