## 2 · 四件事逐条

### 2.1 注入 narrative 服务（服务缺失也要能启动）

**做法**：引擎顶层 `export const inject` **保持** `['systemPrompt','tools']`；叙事服务用
`ctx.get('narrative')` 判空取值，另用一个**嵌套** `ctx.inject(['narrative'], callback)` 把服务键登记在案
（callback 只写一行日志：`叙事层已接上（narrative）：…`；服务缺席时这段 fiber 一直 PENDING，不影响引擎本体）。

**为什么不照 README §7 第 1 条把 `'narrative'` 写进顶层 `inject`**（这是本轮唯一一处**有意偏离**任务书字面要求）：
cordis 4.0.5 的 `inject` 全是**硬依赖** —— `node_modules/@deepseek-ai/cordis/src/fiber.ts` 的 `_refresh()`：
`for (const name of Object.keys(this.inject)) { if (!this._store[name]) { epoch = INACTIVE; break } }`，
而 `INACTIVE` 的 fiber **不会执行 `apply`**。把名字列进去＝没装叙事层时引擎 **never started**，
正是任务书点名禁止的形态。cordis 4.0.5 也没有"可选依赖"的写法（`Inject.resolve` 只认数组/映射，映射值是
intercept config，不是可选性）。

**EC 实测**：`lane-e2-nonarr` profile（只装引擎、不装叙事层）跑一整轮 → **退出码 0**，引擎日志：
`叙事服务未装载（或没有 readRecentDiaries）→ 日记注入块用占位行（不是错误）`，
`turn 1 注入 12 块：…,state.diary.recent,state.wechat.recent,…`（块仍在，正文是占位行）。
请求体里逐字有 `（这次读不到你的日记：叙事服务没有装载。）`（`req-38.json`）。

### 2.2 收课触发日记（N2.1 主规则）

```js
// index.mjs · classroom_set_phase.execute（节选）
phase.setPhase(args.phase)
const persisted = await persistPhase(phase.phase)          // 🔴 先写盘
log(`相位切换：${previous} → ${phase.phase}（persisted=${persisted.persisted}）`)
if (phase.phase === 'close' && previous !== 'close') {      // 只认"切进来"，close→close 是 no-op
  triggerCloseDiary({ sessionId: exec?.agent?.session?.id ?? null, turn: phase.turnCount, persisted: persisted.persisted })
}
```

- **顺序**：`persistPhase` 的 `await` 返回之后才触发。活体证据：日记替身在被调用的那一刻读 `progress.md`，
  逐字读到 `current_phase: close`（单测 `narrative-wiring.test.mjs` 第一条直接断言这一点）。
- **不阻塞**：`fireDiary` 只拿 `handle` 就返回，`handle.done` 在后台 `then` 里写日志；
  `accepted:false` / `runDiary` 抛错 / `done` 拒绝都**只记日志**（三条单测）。
- **同一回合只调一次**：`createTurnLedger()` 的 `claim(sessionId#turn)`（第二道幂等是叙事包的 `sessionId+lesson` 账本）。
- **model 路由**：`classroom.yaml` 顶层 `narrative.models.diary`（可选）→ 作为 `runDiary({model})` 第①档传入；
  没声明就不传（叙事包按自己的顺序解析）。

**活体**（mock）：`相位切换：open → close（persisted=true）` → `日记已排队（trigger=close，第 1 讲，不阻塞课堂）`
→ 17–23 ms 后 `[narrative] 日记已写入（第 1 讲）` → `日记跑完（trigger=close，第 1 讲）：ok，写 2 个文件`。

### 2.3 闲置兜底（N2.1 兜底）

`lib/postclass.mjs` 的 `agent/turn-stopping` 处理器里：

1. 先从**整段会话事件**数学生发言：`summarizeStudentActivity(events)` →
   `{ studentTurns, lastActivityAt }`（只数 `user/message` 且 `source.kind==='user'`；**时刻取学生最后一次发言**，
   引擎自己的注入块与工具调用不算"学生还在"）。
2. `narrative.isLessonIdleClosed({ studentTurns, lastActivityAt, now })`（判据在叙事包，引擎不另写阈值）。
3. `closed===true` → `fireDiary({ trigger:'idle', … })`（同样不 await）。

**红线**：判定放在「空回合早退」**之前**（空回合正是"学生走了"要覆盖的形状）；整段包在自己的 try/catch 里，
`isLessonIdleClosed` 抛错 / 服务没有该方法 / `runDiary` 抛错 → 都只记日志，`turn-stopping` **不外抛**
（三条单测 ＋ 一条"空回合也扫"的单测）。同一回合被派发两次 → `idleLedger.claim(sessionId#turn)` 只扫一次。

**已知边界（诚实）**：这是**回合边界**上的扫描，不是定时器。学生走了之后宿主不再产生回合时，这一轮扫描不会自己发生；
它命中的现实形状是"一轮被触发时距学生最后一次发言已 >2h"（例如会话恢复）。定时器不在本模块。

### 2.4 下节课注入（N2.4 / N3.5）

`classroom.yaml` 新增两块（现盘 **49→51** 块）：

```yaml
- id: state.diary.recent
  dynamic: { kind: diary }
  position: { target: chat, depth: 0 }
  frequency: { every: once, anchor: lesson_start }   # 每讲一次（injectedLesson 记账）
  phase: { phases: [open] }                           # 🔴 必须带 phase：
- id: state.wechat.recent
  dynamic: { kind: wechat, limit: 8 }                 # N=8（可改；上限 50）
  …（频率/相位同上）
```

- **不加 `lesson:` 讲次门**（跨讲常驻块，挂上讲次门就会在换讲时整块消失）。
- **去重不新造表**：`once + anchor: lesson_start` 用的是既有 `injectedLesson`（讲次一变重新注入）；
  "同一回合只注一次"仍是既有 `(sessionId, turn)` 门。
- **内容现取**：`dynamic` 是继 `path` / `text` 之后的**第三种内容来源**；`agent/pre-step` 里
  `resolveDynamicBlocks` 只给 `isBlockDue` 为真的块取正文，然后照常交给 `planTurnInjections`（记账仍归它）。
  `isBlockDue` 是从计划器里**抽出来的同一套门**（讲次门→频率→相位门），`test/injector.test.mjs` 逐格比对两边；
  🔴 **频率语义一个字没改** → `acceptance/lib/asserts.mjs` 的第二份实现不需要动，`frequency-parity` 逐格一致。
- **空内容不吞块**：服务没装 / 日记为空 / 群聊文件不存在 / 读失败 → 注入一行诚实的占位行
  （`（你还没有写过日记。）` / `（群里还没有消息。）` / `（这次读不到你的日记。）`）。
  🔴 为什么不"整块跳过"：频率门过了就必须出现——否则验收侧 `predictTurnBlocks`（独立推导）会预测它、
  生产侧却不注入，A2 立刻红；而且"没生效"会静默消失。

**活体**（5 回合一条会话，证据见 §4）：turn 1（第 1 讲 · open）注入 `state.diary.recent`（占位）＋
`state.wechat.recent`（3 条群聊）；turn 2 收课 → 日记落盘；turn 3 进第 2 讲；turn 4 切 open；
**turn 5（第 2 讲 · open）注入 `state.diary.recent`，正文就是 §4 那条日记**。

## 5 · 与验收侧的关系（为什么没改 `acceptance/**`）

- 两块新块的频率是 `once + anchor: lesson_start` ＋ `phase` 门 **＋ 讲次门缺席**——这些都是
  `predictTurnBlocks` 已经实现的语义，**没有新增频率模式**，所以第二份实现不用改；
  `node check.mjs` 的 ⑦ frequency-parity **逐格一致**（6 教室/40 序列/240 格）。
- 动态块没有进 `predictAllTurns` 的「运行期动态块」名单（那是给 `prep-list:` / `animation-notice:` 这两类
  **不经规划器**的自产块用的）；我们的两块**走规划器**，因此按 manifest 字段就能推出来，A2 的逐回合集合比对
  会自动包含它们。**这正是"必须给占位行、不能整块跳过"的原因**（否则预测有、实际无 → 假红）。
- 完整 A2 需要一次真跑（会花钱），本轮**没有跑**；`--skip-session` 以外的完整性由 `node check.mjs` 覆盖。

## 7 · 给面板接线时需要在哪加什么（P 车道 / N2.5）

引擎侧**不提供**远程方法，面板要加的是**读叙事服务**（照契约 K4.1 的 typert Remote 三件套）：

1. **服务**：在面板插件宿主半边注册 `classroomNarrative`（名字可改），方法至少两个：
   - `status(sessionId)` → 直接返回 `ctx.get('narrative').status()`（`ok / active / lastError / lastSuccess / recent`）；
   - `diaries(sessionId, limit)` → 返回 `await narrative.readRecentDiaries({ classroomDir, limit })` 的 `entries`。
   `classroomDir` 的面板侧来源与 `clients/classroom-ui` 现在读教室文件的那一套一致（`__DSH_CLASSROOM_UI_CONFIG__.root` 或现有 remote 的 workspaceFiles 路由）。
2. **浏览器半边**：新增「日记」tab（N2.5）：按时间倒序展示 `entries`（标题里的日期/讲次已经是结构化的）；
   顶部一行错误状态：`status().lastError` 非空时显示 `code + message`（这正是 N1.4「面板可见的错误状态」的消费方）。
3. **注意**：`status()` 是**冻结深拷贝**，可以直接进 UI；`readRecentDiaries` 的 `entries[].text` 是正文，
   标题行（`### 日期 · 第 N 讲`）**不在** text 里（叙事包已切成 `{date, lesson, text}`）。
4. 面板**不要**读 `runtime/.narrative/` 里的账本与运行日志（那是运行过程，不是展示内容）；
   跨重启历史用 `narrative.runLogPath(classroomDir)` 或 `status().recent`。

## 9 · 给别人发现的问题（不是本车道能改的）

### 9.1 叙事包 `readRecentDiaries` 把文件末尾的「参考口吻」当成最后一条日记的正文

活体证据（§4 的注入文本）：最后一条日记的 `text` 里带着

```
> 参考口吻（不是模板，别照抄）：
> 抽屉卡了一下。按了两下才关上。上次也是这样，没修。
```

成因在 `plugins/socratic-narrative/lib/diary.mjs`：`parseDiaryEntries` 从 `### 日期` 之后一直收到**下一个条目标题**
为止；而 `runtime/diary.md` 的「参考口吻」块在最后一个条目之后、且**不是标题**，于是被算进最后一条的正文。
新条目插在「条目区」末尾（正好在参考口吻之前），所以**最新那一条**必然带上它。

**影响**：老师下节课读到的"自己的日记"里混着写作示例。不是致命错误（内容确实是教室文件里的），
但语义不对。**修法在 N 车道**（比如把 `>` 引用块排除出条目正文，或只取到空行/`>` 之前的正文）；
我没有在引擎侧过滤——那会变成"引擎改写教室内容"，也踩了不许碰 `plugins/socratic-narrative/**` 的边界。
建议：N 车道修 `parseDiaryEntries`，并补一条"条目正文不含参考口吻"的单测。

### 9.2 `classroom_enter_lesson` 在活体验证里把第 1 讲记成「跳过」

为了让讲次推进到第 2 讲，我用 `classroom_enter_lesson(2)` 驱动了换讲；它按 J 的语义写
`skipped_lessons: 1`（因为 `progress.md` 里第 1 讲没被标成已完成）。这不影响注入链路的验证，
但**说明"换讲"在真实课堂里应走课后更新（`current_lesson: 2`），而不是跳讲工具**——跳讲工具的语义是
"学生要求从第 N 讲开始"。记录在此，避免后来者把这条活体日志当成真实课堂的顺序。
