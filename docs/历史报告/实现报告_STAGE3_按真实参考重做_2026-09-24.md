## 〇 · 一句话结论

**真实截图推翻的不是细节，是骨架**：STAGE-2 那套「底部卡片 → 整屏压暗层」的替换，**方向反了**——真实界面**根本没有框，也没有压暗层**，文字是**直接排在全屏画面上**的白字＋深色描边；**旧行整体压暗、当前行亮白，字号完全相同**。

本件做了四件事：① 用 `huashu-design` 技能的「设计方向顾问」流程**并行跑三套逻辑**出三版真实视觉；② 把真实图的数值**逐项落成设计令牌并标注依据哪张图**；③ 按令牌重做**三个形态层不同**的方向（0 容器 / 分栏＋常驻位 / 整屏换材质）——上一版「三个方向看不出区别」的根因是**三个方向共用同一骨架、只差几个百分点的边距**；④ 把 STAGE-2 的旧结论**逐条列出并改正**，并给旧研究件与旧原型**加勘误指针**（不改写原文）。

**一个副产品**：上一版把「正文用明朝体」当成设计依据（依据是日文版资源里明朝 28 页 vs 黑体 10 页的**页数推断**）。真实中文版截图放大 4× 一看，正文是**无衬线（黑体）**＋重描边。这一条**只能标【推断】**——因为中文版可能换了字体族，不能断言日文版也是黑体。

## 一 · 借 `huashu-design` 做了什么

### 1.1 先加载技能，按它的「设计方向顾问（Fallback 模式）」流程走

技能的定位逐字是「**三套逻辑并行出 3 版真实视觉**」，并有一条**选择无效铁律**：*绝不让用户在「只有文字、没看到视觉」时选风格*。这正是「三个方向没看出区别」的解药——上一版是**先定一个骨架、再微调**，而这条铁律要求**三版各自独立成形**。

按它的 7 个 Phase 逐条落地：

| Phase | 技能要求 | 本件怎么做 |
|---|---|---|
| 1 · 对话澄清 ＋ 索要参考 | 问受众／信息／基调／格式，并**主动索要参考** | 🔴 **不能问**（本次是子代理，询问类工具会永久卡死）→ 用**已知的真实需求**填：教室＝暗色电影感、内容自由输入、有投影区、**多角色同台是硬需求**、系统功能六件、**色调走用户点过的「B 那一版方向」**（深色场＋奶白纸面作为唯一亮面材质）。**参考不用要——137 MB 真实界面素材就在盘上** |
| 2 · 顾问式重述（≥200 字） | 把需求嚼透，以「我直接做 3 个不同方向的真实版本给你看」结尾 | 见 §1.2 |
| 3 · 固化设计 spec（≥500 字，三版唯一共同输入） | 覆盖产品／受众／场景／内容要点／气质／**输出尺寸**／约束／图片需求 | 见 §1.3 |
| 3.5 · 图片素材前置 | 判断「图片是不是内容必需」→ 先取齐真图再 spawn | **是本件最特殊的一步**：这是个**界面**，不是介绍某事物的内容页——**"真图"就是真实界面素材本身**，不需要去图库取图。我先把 U1–U12 的真实图**量成令牌**（§二），**再**动设计。等价于技能要求的「素材齐了再设计，不是边设计边占位」 |
| 4 · 三套逻辑并行 | 三个独立 context 各产一版，**互不参考** | 🔴 **见 §1.4 的诚实说明**——本件**串行**跑三套（技能为「不支持 spawn 的 runtime」留的降级路径），用三个**物理隔离的 anchor** 防止趋同 |
| 5 · 一次性摆出三版 | 用「看得见的东西」代替文字单选 | 见 `code/prototypes/stage3/index.html`：三方向 × 四屏 = 12 张整屏截图，每张写「**该看什么**」 |
| （可选）5 维评审 | 哲学一致性／视觉层级／细节执行／功能性／创新性各 0–10 | 见 §1.5 |

**技能里我明确借用的做法**（可逐条对照）：

1. **反 AI slop 清单**——本件主动规避：紫色渐变、emoji 当图标、**圆角卡片＋左彩色 border accent**、SVG 手画人脸、用 Inter/系统字当 display、以及「GitHub-dark 偷懒解」（均匀深蓝底＋通用霓虹 glow）。
   > ⚠️ 技能特别提醒「**别把整片暗色大胆派一起误杀**」——要禁的只是那**一种**偷懒组合。本件的暗色是**电影级戏剧光影**（真实背景＋渐晕＋发丝线），不在禁区内。
2. **「诚实 placeholder 好过拙劣的真实尝试」**——C 方向的木框、书脊、短册目前是 **CSS 手绘**，报告里**明说它们是手绘、正式做要出图**，不假装是美术资产。
3. **「一个细节做到 120%，其他做到 80%」**——本件把 120% 投在**文字**上：描边、旧行压暗、行距、字面高，因为真实界面里**文字是唯一的主角**（没有框、没有按钮、没有底板）。
4. **核心原则 #0「事实验证先于假设」**——技能要求涉及具体产品先 `WebSearch`。本件把这一步**换成「先读真实素材＋实测」**：任何数值不靠记忆、不靠资源推测，一律**从真实截图量**（§二 每项标了依据哪张图）。
5. **固定尺寸内容自己实现缩放**——舞台是固定 `1920×1080` 画布，由 JS 整体 `scale` 到窗口并 letterbox〔A16〕，**不用 vh 做布局**。

### 1.2 Phase 2 · 顾问式重述

用户要的不是「一个好看的界面」，而是**一个能把「上课」这件事演出来的舞台**。它的使用场景极其特殊：**内容不由我们写，由模型实时生成**——所以版式必须能吞下任意长度、任意角色数、任意时刻的插画与板书；它的观众是**一个人对着整屏**（1 米距离、笔记本站姿），不是投屏给一屋子人——所以字号必须够大，但**信息不能一次全给**；它的情感基调是**暗色电影感**，因为上课要有「沉进去」的感觉，而不是「打开一个面板」。

用户已经踩过一次坑：上一版三个方向**共用同一个骨架**，只是边距各差几个百分点，他原话是 *"三个方向我没看出区别怎么办？…区别真的不大啊"*。这说明他要的不是「配色变体」，而是**形态层的不同选择**。他另外给了两条硬约束：**多角色同台是肯定要的**（教室里"谁在说话"是真需求）；**色调走 B 那一版的方向**（深色场＋奶白纸面作唯一亮面）。

基于这个理解，我**直接做 3 个不同方向的真实版本给你看**——不是三套配色，而是三种**骨架**：一个是「**零容器**」（文字直接压在画面上，最像读物）；一个是「**分栏＋常驻位**」（正文收窄、右边永远有一块黑板、左边永远有一列在场者，最像课堂）；一个是「**整屏换材质**」（板书时整屏变成奶白纸＋木框，最像翻讲义）。

### 1.3 Phase 3 · 设计 spec（三版唯一共同输入）

**产品**：DSH 教室舞台——把苏格拉底式教室的上课过程渲染成 galgame 式全屏界面（不是聊天窗口）。

**受众与使用场景**：单个学习者，1 米距离，1920×1080 桌面／浏览器；一节课 20–60 分钟；内容由模型实时生成，长度不可预知。

**内容要点**（四类屏）：① 开场（对话推进）；② 板书／投影（讲解）；③ 选择肢（元层面：继续说／画给我看／我自己写一步…）；④ 多角色同台（老师＋学生同时在场）。

**气质关键词**：暗色、电影感、读物感、克制、**发丝线而非投影**、**青系强调**、**奶白纸面是唯一的亮面**。

**输出格式与尺寸**：固定 `1920×1080` 画布，整屏截图；**三版必须用同一尺寸**，否则无法横向对比。

**已知约束（硬）**：
- 🔴 **必须用真实界面的形状**：无框直排 ＋ 旧行压暗 ＋ 发丝花饰 ＋ 真实字阶行距。**不许回到「底部圆角卡片」**。
- 🔴 **多角色同台**每一版都必须有。
- 🔴 纯前端、`file://` 可开、**零外链、零新依赖**。
- 🔴 三版**形态层不同**，且**每个方向要能一眼说出「它是给谁用的」**。

**图片需求**：**内容必需的图＝真实界面素材本身**（已齐，见 §二）；场景与立绘用工作区既有的《魔法使之夜》解包素材打样，标注「参考用途」。

### 1.4 Phase 4 · 三套逻辑：我借了什么、怎么落地的（**含一处诚实偏差**）

**技能要求**：三个独立 context 并行、互不参考。**技能同时给了降级路径**：*"不支持 spawn subagent 的 runtime（Codex / Cursor / 纯对话）：改**串行**跑三套……并用三个不同 anchor（轮盘号 / 参照案例 / 设计师名）物理隔离趋同。串行也**必须出三版**"*。

🔴 **本件走的是串行路径，理由是如实记录的**：① 本次是**子代理**会话，本仓 `AGENTS.md` 明确记着「**子代理文件权限不保证**」（同批派发里出现过读工作区外路径被拒、写盘反复被拒的实例）；② 这一版的核心风险是**保真度**（真实界面的几何必须一个数不差地落进 CSS），把三版交给三个独立 context 反而放大「各自漂一点」的风险；③ 串行不等于趋同——**趋同的根因是共用骨架，不是共用 context**，所以隔离手段换成**三个物理不同的 anchor**（见下）。**这一处是我对技能的偏离，如实写在这里。**

| 逻辑 | 技能要求 | 本件的 anchor | 落成哪一版 | 明确**不借**什么 |
|---|---|---|---|---|
| **一 · 秒数轮盘（随机）** | 跑 `date +%S`，`秒数 % 20 + 1` 取风格库对应号 | 实跑 `date +%S` = **41** → `41 % 20 + 1` = **2** → 网页库 **#2「新粗野主义撞色信息流 Neo-Brutalism」** | **B · 讲台**（取它的**信息密度基因**） | 🔴 **不借撞色（电光紫/品红/亮黄）与 2–4px 粗黑描边**——真实界面的描边是**发丝级**，粗描边直接违背真实图。**只借两样**：① **1px 规则线分栏**（换成同族的发丝线语汇）；② **极端字号反差**（正文 4.1% 屏高 vs 说话人标签 1.7% vs 板书标题 5.1%） |
| **二 · 现实参照（标杆迁移）** | 选一个世界上与该需求最相关、且明确知道设计极出色的真实作品，拆解其设计语言再迁移 | **《魔法使之夜》本体**（本件全部真实素材的来源） | **A · 夜读** | 不借它的**剧情与美术资产**（只作形态打样）；不借它的**日文版字族结论**（中文版真实图是黑体，见 §〇） |
| **三 · 最佳设计师（顶级定制）** | 想「预算无上限时，最适合为这个产品做设计的是谁」，启用其设计哲学 | **原研哉（Kenya Hara）**——「白」的空寂 ＋ 瑞士网格混血（技能风格库里对应「**日式留白白盒画廊**」） | **C · 書庫** | 不借它的**近全白底**（我们的场景是暗色电影感）；只借**「内容图提供全部色彩、UI 退到背景」**与**极致留白**这两条，落在書庫的奶白纸面上 |

**三版采用哪一版？** —— 技能的原意是**三版都交给用户挑**，本件照此执行（§三 摆出全部 12 张）。
**我自己的倾向是 B**：因为用户把「多角色同台」列为硬需求，而**只有 B 把「谁在说」做成了常驻信息**（姓名牌＋在场者栏＋立绘亮度三处冗余）；A 与 C 都依赖读者自己从正文里读名字。
**但 C 最能承载用户点过的「色调方向」**（深色场＋奶白纸面／暖木是唯一亮面）。**A 最接近真实界面本体**，也最省实现成本（零容器＝零组件）。

### 1.5 5 维自评（技能 `critique-guide` 的维度）

| 维度 | 分 | 依据 |
|---|---|---|
| 哲学一致性 | **8** | 三版都把「发丝线承重、不用投影」贯彻到底（全原型零 `box-shadow` 装饰投影，只有一处 2px 硬阴影用于短册）；A 与真实界面同源 |
| 视觉层级 | **8** | 层级只靠**字号 · 字距 · 字色阶梯 · 字面**——正文 47px 亮白／旧行 47px `#cccccc`／旁白 `#d8d8d8`／说话人 26px；**没有一处靠加粗**（全原型 `font-weight:400`） |
| 细节执行 | **7** | 令牌逐项标了依据图；扣分项：C 的木框／书脊是 CSS 手绘（**已如实标注**），書庫只有 576×360 不够量数值，木框宽度是目视值 |
| 功能性 | **7** | 四屏（开场／板书／选择肢／多角色）都跑通、`file://` 零报错；扣分项：选择肢选完怎么回到对话、自由输入要不要做成第七条，**没定**（§五） |
| 创新性 | **6** | 「无框直排」是**抄**真实界面（不是我们发明的）；真正的原创只有 C 的「整屏材质切换」与 B 的「在场者栏」。这一版的价值在**保真**，不在发明 |
