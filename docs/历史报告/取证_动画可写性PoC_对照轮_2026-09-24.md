## 4. ③ 🔴 LaTeX 那条：发生了什么（本轮最重要的发现）

### 4.1 事实经过（逐条，不加工）

| 步骤 | 发生了什么 |
|---|---|
| 1 | A 组 P4 的子代理**第一版**写了 `NumberLine(x_range=[0,120,20], length=10, include_numbers=True)` |
| 2 | 它在自己沙箱里 `manim -ql` 跑，**崩了** |
| 3 | 它自己判断出：`include_numbers=True` 在 ManimCE 里走 `DecimalNumber` → **`MathTex` → 调 `latex` 可执行文件** |
| 4 | 它**自己改掉**：改成用 `Text` 手写轴刻度数字，并在收尾消息里报告"全脚本零 LaTeX 依赖" |
| 5 | 交到我手上的版本 → **我亲自渲染，退出码 0，一次过** |

### 4.2 报错原文（逐字）

子代理交回的是**已修好的版本**，所以它的日志里没有报错。
→ **我自己写了一个最小复现脚本**（`scripts2/latex_probe2.py`），在**同一个 venv（0.21.0）**上跑，
拿到逐字报错原文，落盘 `logs2/latex_probe_numberline_include_numbers.log`：

```
FileNotFoundError: [Errno 2] No such file or directory: 'latex'
```

**调用栈的关键帧**（同一日志）：
```
manim/.../tex_file_writing.py  →  print_all_tex_errors(log_file, compiler, tex_file)
subprocess.py:1038  →  self._execute_child(...)
subprocess.py:1974  →  raise child_exception_type(errno_num, err_msg, err_filename)
FileNotFoundError: [Errno 2] No such file or directory: 'latex'
```

> ⚠️ **口径澄清**：这条报错原文**不是**"模型那一版"产生的（那一版我没拿到），
> 而是**我用等价最小脚本在本机复现出来的**。两者是同一根因（`NumberLine(include_numbers=True)` → `MathTex` → `latex`），
> 但**我不声称它是模型那次运行的逐字日志**。这一点必须写清楚，不许含糊。

### 4.3 🔴 这条的结论（比"会不会用 LaTeX"更重要）

1. **不给提示，模型确实会踩 LaTeX 的坑** —— 它**自己没想到**本机没有 LaTeX，第一版就直接用了会走 LaTeX 的 API。
   → **上一轮报告 §7.4 的推断被证实了一半**：那条提示**确实挡掉了一个真实存在的坑**。
2. 🔴 **但这个坑被"模型自己能跑一次"挡住了，不是被提示挡住的。**
   → **这是本轮对上一轮结论最重要的修正**：
   **"渲染成功率"这个指标，测的不是"模型写得对不对"，而是"模型写 + 跑 + 自修"这个闭环的结果。**
   本轮的 12/12 里，**至少有 1 例（A_P4）是靠自修换来的**，不是一次写对。
3. **因此"删掉提示"的真实代价被沙箱自修掩盖了** ——
   如果生成方**没有执行权限**（例如直接吐代码给用户、不落盘不跑），A_P4 那一版会**当场失败**。
   → 🔴 **记入待确认**：真实教室场景下生成方是否有执行权限，决定了这条提示的必要性。

| **报错原文（根因等价复现）** | `FileNotFoundError: [Errno 2] No such file or directory: 'latex'` |
| **根因** | 第一版用了 `NumberLine(x_range=[0,120,20], length=10, include_numbers=True)`；该参数在 ManimCE 内部走 `DecimalNumber → MathTex → latex` |
| **模型怎么改** | 把 `include_numbers=True` **删掉**，改成 `include_numbers=False`，并**用 `Text` 手工逐个摆放刻度数字**（`ticks = VGroup(*[Text(str(v), ...) for v in range(0, 121, 20)])`） |
| **改后是否过** | ✅ **过**（我亲自渲染：退出码 0，mp4 293,399 B，时长 13.00 s） |
| **是否被我的提示引导** | ❌ **没有** —— 本轮提示词里**完全没有** LaTeX 相关的字样（这正是本轮的变量） |

### 6.3 这条链路的读法

🔴 **它是"渲染→报错→修正"循环的一次真实样本，只是发生在我观测不到的地方。**
- **对上一轮 §9 未取证 #1 的补答**：上一轮说"没有拿到任何报错原文回喂模型后它怎么改的证据"。
  **本轮拿到了一个等价物**：报错原文（根因等价复现）+ 模型改了什么 + 改后过不过。
- 🔴 **但它不是"我回喂"的那种 RITL** —— 是**模型自发的"先跑再交"**。
  两者对**工程结论**的意义不同：前者证明"外循环有用"，后者证明"**生成方自己能跑**这件事本身就吸收了大部分失败"。
- **对 B/C 组的直接后果**：因为生成方已经先跑过一遍并修好了，**我这一层的 RITL 就无事可做** ——
  **这很可能是上一轮"RITL 循环零触发"的真正原因**，而不是"模型一次就写对"。

> ⚠️ **【推断】**：若把生成方的执行权限去掉（让它只能吐代码、不能跑），
> 那么 A_P4 那类失败就会**落到我这一层**，RITL 循环才会被真正触发。
> **本轮没有做这个对照**（不在任务书预算内），**记入待确认**。

### 7.3 🔴 两处"模型比教材更严谨"的发现（值得单列）

2. **B_P3**：主动把"示例数据"的标注写进画面，与教材原文的标注口径一致。
