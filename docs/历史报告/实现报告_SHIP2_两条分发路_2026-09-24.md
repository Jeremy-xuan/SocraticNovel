### 1.4 🔴 修掉的两个真 bug（都是我自己写出来的，实测才暴露）

**bug 1 · 判据用错了关键词。**
第一版写的是 `grep -q '发现链路'` —— 但 `validate` 的**第 ⑤ 节标题每次都打印**（无论过没过），
所以「内容问题」被误报成「发现链路问题」。
→ 改成看**汇总段**里顶格的"失败小节"行（形如 `⑤ 发现链路（1）`），并支持"只有 ②/④"时
识别成"内容进度"。

**bug 2 · BSD grep 的多字节字符类静默失效。**
改成 `grep -E '^[①②③④⑤] '` 之后，**零命中**（实测：同样三行输入，字符类版本 rc=1，
交替 `(①|②|③|④|⑤)` 版本 rc=0）。
→ **BSD grep 的方括号表达式按字节处理，多字节汉字在字符类里匹配不上**。
必须写交替。这条已写进脚本注释（防重犯）。

### 2.4 「能上课」冒烟是怎么设计的（**不花钱、不调模型**）

为什么这条能代表"能上课"：引擎的全部价值就是"把该讲的材料在正确的时机喂进上下文"。
它从**已安装的那一份插件**里 `import` `lib/manifest.mjs` / `lib/injector.mjs` /
`lib/animationstore.mjs`，所以它同时证明：
① 插件装上了且能被 import；② `classroom.yaml` 能解析；③ `runtime/progress.md` 的
机器可读行读得出来；④ **讲次门真的在挡材料**；⑤ 动画渲染环境过引擎自己那个检查函数。

### 2.5 🔴 三个必须处理的坑（都真踩到了）

**坑 1 · `plugin add` 对同版本会说 `Already up to date` 不刷新 → 必须先 `remove` 再 `add`。**
装载器一律先 remove 再 add。📌 实测里仍会**打印**这行（属于 pnpm 对 lock 条目的说法），
所以脚本把它降级成一条**提示**而不是失败 —— 真正的判据是下一步的**逐文件哈希**（实测全一致）。

**坑 2 · 硬链接不抗替换式写入 → 装完必须逐文件核哈希。**
`file:` 安装后 profile 里的副本与载荷**共享 inode**，但 `edit`/`write` 这类"写新文件再替换"的
写入会**打断硬链接** → profile 里停在旧版本。→ 装载器对每个包做 `cmp` 逐字节复核。

📌 **配套发现（第一次跑就是这么挂的）**：载荷里**不能放"装不进去的文件"**。
插件的 `package.json` 有 `files` 字段，pnpm 只拷那里面列的；我一开始把 3 份开发文档
（`接线说明_S1/S2/S3.md`）也放进了载荷 → 哈希复核报"3 个缺失"。
→ 改成 `build-dist.sh` 组装时就排除它们，**载荷 = 装得进去的东西**。

🔴 **这里还踩到一个 rsync 的真坑**：`rsync --exclude` **会顺带保护被排除的文件不被 `--delete` 删掉**
—— 也就是说上一次组装留下的文件会**一直赖在产物里**，加再多次 exclude 也没用。
→ 排除项必须**显式删一遍**（已写进 `build-dist.sh` 的注释）。

**坑 3 · 不许把 `@deepseek-ai/*` 装进插件的 `node_modules`。**
会出现同一包的第二个实例 → Symbol 键失配 → 工具调用崩
`Cannot read properties of undefined (reading 'prepare')`。
装载器装完**逐包检查** `node_modules/@deepseek-ai` 是否存在（实测三处都不存在）。

### 4.4 🔴 签名与公证：技术上需要什么，不签名会怎样

> 只陈述**技术事实与现象**。合规/许可判断不在这里做。

`electron-builder` 日志逐字：

```
• skipped macOS application code signing
  reason=cannot find valid "Developer ID Application" identity or custom non-Apple code signing certificate,
  it could cause some undefined behaviour, e.g. macOS localized description not visible,
  see https://electron.build/code-signing
  allIdentities=
   1) B82764719EA87C91F59B2A6DA5937ABDC3D3AD4D "www.dingtalkcs.com" (CSSMERR_TP_CERT_EXPIRED)
   2) 0C95D00796D154E9457BF5D93C636523324B96B1 "localhost" (CSSMERR_TP_NOT_TRUSTED)
     2 identities found
     Valid identities only
     0 valid identities found
```

→ **本机 0 个有效身份**。

**技术上需要的东西**（macOS 上要能被别人**双击直接打开**）：

1. 一个 **Apple Developer Program 账号**；
2. 从账号签发的 **Developer ID Application 证书**（.p12 ＋ 私钥）装进构建机钥匙串；
3. `electron-builder` 据此签名 —— 上游 `package.json` 的 `mac` 段已经备好
   `hardenedRuntime: true`、`gatekeeperAssess: false`，用的是 Electron 的 entitlements；
4. 签名后还要**公证**：把 dmg 交给 Apple 的 notary 服务（`notarytool`），
   等回一个 "Accepted"，再把票据 **staple** 进 dmg。
   上游仓库里有 `scripts/prepare-macos-signing-keychain.mjs`，
   README 逐字写着 *"macOS releases are code-signed and notarized by Apple."* ——
   但**那些脚本要的凭据我们没有**。

**不签名直接发，实际会发生什么**（现象，逐条）：

| 现象 | 说明 |
|---|---|
| **本机不会拦** | 自己构建出来的 app 没有 `com.apple.quarantine`，双击能开 |
| **别人机器上会被拦** | 经浏览器/网盘/AirDrop 传过去的文件会带上 quarantine → 首次双击弹"**无法打开，因为 Apple 无法检查其是否包含恶意软件**"，**没有"仍要打开"按钮** |
| **绕过的动作** | 用户必须**右键 → 打开 → 打开**（每次升级后重做一次），或 `xattr -dr com.apple.quarantine "<app>"` |
| **`codesign --verify` 会失败** | 实测这个产物：`Signature=adhoc`、`TeamIdentifier=not set`、`Sealed Resources=none`；`codesign --verify --strict` 报 `code has no resources but signature indicates they must be present` |
| **自动更新失效** | 本次配置 `publish: null`，等于关掉发布；而且 appId 是 `.dev`，**不该拿到官方更新** |
| **可能的能力缺失** | 未签名 app 用不了某些需要 entitlement 的能力（TCC 授权、部分系统权限），electron-builder 的原话就是 *"it could cause some undefined behaviour, e.g. macOS localized description not visible"* |

**一句话**：**不签名能构建、本机能用、别人机器上首次打开要绕一下。**
要不要买证书、要不要公证 —— **由用户决定**。

### 4.5 `--with-payload`：把我们的载荷塞进 app

`build.sh --with-payload` 会：把 2A 载荷拷进 `upstream/build/socratic/`，

### 4.6 🔴 维护代价：上游每次发版我们都要重建

- 上游 push **很勤**（本次 ref 是 **2026-09-23** 的，仓库最近 push 是 **2026-09-24**）。
- **每次跟版重跑 `sh build.sh`**：约 5 分钟 ＋ 约 2.3 GB 磁盘。
- **我们不改上游 `src/`**（那是维护地狱）。只借两个现成挂点：
  `extraResources`（加文件）与 `dependencies`（让包被当 bundle 解析，本次**没用**）。

**下次上游发版后要改哪几步**（`README_构建说明.md` 里有完整表）：

| # | 改什么 | 怎么判 |
|---|---|---|
| 1 | 重跑 `sh build.sh` | 它会记录新 ref 到 `work/build-report.txt` |
| 2 | 核对 harness 版本 | 上游 `@deepseek-ai/dsh` 版本 vs 我们的插件/教室假设的版本 |
| 3 | 核对 `extraResources` 清单 | 上游改了 `build/* → Resources/*` 映射 → `--with-payload` 生成的配置要跟着改 |
| 4 | 核对 `electron-builder.dev.cjs` | appId / productName / 输出目录变了，产物名与"不冒名"的隔离性要重核 |
| 5 | 重跑 2A 装载验收 | 新 app 的 `$DSH_HOME` 路径、技能扫描根、`.desktop-bin` 都可能变 |
| 6 | 签名 | 若买了 Developer ID：装证书、去掉 `--config electron-builder.dev.cjs`、加公证步骤 |
