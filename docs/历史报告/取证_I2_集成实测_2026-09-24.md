### §2.4 🔴 3 项断言失败的根因初判 —— **测试脚本的 fixture 硬编码，不是插件 bug**（已用纯函数离线复核）

**失败项**：`turn N 注入块集合 = manifest 计划`（2 项）＋ `相位门块在 boot 相位不注入`（1 项）。

**根因**：`test/integration/multiturn.mjs` 的 `expectedPerTurn()` **硬编码 `phase: 'boot'`**：

```js
function expectedPerTurn(manifest, turnIndex) {
  const state = { turnCount: turnIndex, phase: 'boot', injectedOnce: new Set() }   // ← 硬编码
  return planTurnInjections(manifest.blocks, state, { classroom: manifest.classroom.id }).map(d => d.id).sort()

```
该硬编码是为 **fixture 教室**（`minimal-classroom`，相位语义用 legacy `boot`）写的；**cs-os 的默认相位是 `open`**，故相位门块的期望值算错。

if (turnEnds && this.inbox.nextStep.length === 0) {

}
