## 1 · 任务 1（C1）· Soullink Emotion SDK 适配验证

### 1.1 结论：`采用 Soullink`

### 1.2 三条依据

**依据一 · 浏览器构建形态与体积可接受（实测数字，不是估计）**

| 产物 | 字节 | 说明 |
|---|---|---|
| 上游 ESM（tsup 默认） | `index.js` 1,572 + `chunk-*.js` **247,268** | 上游**只发布 ESM**（`packages/engine/tsup.config.ts`：`format:["esm"]`, `splitting:true`） |
| 本仓库自打的 IIFE（未压缩） | **263,073** | `esbuild 0.28.2 --bundle --format=iife --global-name=SoullinkEmotion` |
| **本仓库自打的 IIFE（minify）** | **135,914** | 实际 vendor 进仓库的就是这个 |
| **同一份的 gzip** | **40,776** | 相对舞台现有 `pixi.min.js` 476,988 B / `index.min.js` 126,602 B，属同一量级 |
| 生成的 profile | 7,123 | 静态 JSON，一次生成即可 |

- 引擎包**没有任何运行时依赖**（`packages/engine/package.json` 只有 devDependencies：tsup / typescript / vitest），也不引用 `node:*`、`process`、`Buffer`、`document`、`window`（`grep` 0 处命中），所以 `platform: neutral` 的 IIFE 能在舞台的经典 `<script>` 通道里跑。
- 舞台加载静态 JS 的唯一通路是 `loadOneScript()`（`client.js:708`，`async=false`），**不支持 `type=module`**。上游没有 UMD/IIFE 产物，这是本次唯一需要"我们自己做"的一步：从同一份源码用 esbuild 打 IIFE，未改一行源码。产物与 LICENSE/NOTICE 落在 `assets/l2d/vendor/soullink/`。
- 🔴 一个真实代价：**上游 ESM 的分包产物不能直接塞进 `assets/l2d/`**（`index.js` + 相对 chunk 的 `import` 在经典 script 下直接语法报错）。要么打 IIFE（本方案），要么改舞台支持 module script（会动 S 车道的加载器）。选前者。

**依据二 · profile-generator 对 DeepSeek 模型的适配覆盖（实测输出，非推测）**

用 `@soullink-emotion/profile-generator`（0.2.0-beta.1，**heuristic 路径**，未接任何 LLM/API key）扫 `assets/models/deepseek/deepseek.model3.json` + `deepseek.cdi3.json`：

```
facsKeyCount: 24        mappedKeyCount: 20
cdiParameterCount: 26   usedCdiParameterCount: 19
unmappedKeys: mouthPucker / blush / tear / sweat
capabilities: head/body/eyeBlink/eyeSmile/gaze/mouthOpen/mouthSmile/brow/breath = true
              blush / tear / sweat = false
```

- 模型 26 个参数里的 7 个是物理/装饰参数（`Param2` 呆毛、`Param` 尾巴、`ParamHairFront/Back`、`ParamTwinTails`、`ParamSkirtSway/Flap`），不该由情绪层直写 —— 生成器正确地把它们留给了 physics。
- **眉、眼球、眨眼、嘴形、呼吸全部被映射**（`browInnerUp/browOuterUp/browDown → ParamBrowLY/RY/LAngle/RAngle`、`gazeX/Y → ParamEyeBallX/Y`、`mouthOpen/mouthSmile/mouthFrown → ParamMouthOpenY/Form`、`breath → ParamBreath`），正好是"五种情绪可辨认"所需要的全部通道。
- 缺口是 `blush`（脸红）—— 这个模型**根本没有**脸红参数，`capabilities.blush = false`。也就是说"害羞"只能靠眼笑 + 视线偏移 + 头倾表达，不能靠脸红。这一点写进报告，避免以后有人以为是驱动没生效。

**依据三 · 五种状态在本机浏览器里肉眼可辨认（证据见 §2）**

不是"引擎返回了不同的数字"，而是**通过我写的 `stage-emotion.js`**（情绪事件 → 引擎 → 每帧写参数）驱动真模型、真渲染，得到五张可区分的脸。参数差异（经模块驱动 220 帧后的实读值）：

| 状态 → 引擎情绪 | `ParamBrowLY` | `ParamBrowLAngle` | `ParamEyeLSmile` | `ParamEyeLOpen` | `ParamMouthForm` | `ParamAngleZ` |
|---|---|---|---|---|---|---|
| calm（平静） | 0.084 | 0 | 0.300 | 0.826 | 0.256 | 0.675 |
| happy（开心） | 0.059 | 0 | 0.362 | 1.000 | 0.546 | −3.305 |
| shy（害羞） | 0.182 | 0 | 0.399 | 0.855 | 0.251 | −2.217 |
| puzzled → confused（困惑） | 0.170 | **−0.191** | **0.000** | 0.999 | −0.015 | −3.968 |
| excited（兴奋） | 0.000 | 0 | **0.649** | 1.000 | **1.000** | 0.368 |

判读（哪条通道在起区分作用）：**困惑**靠抬眉 + 眉角下压 + 眼笑归零 + 嘴变平；**兴奋**靠眼笑最大 + 嘴角拉满；**害羞**靠眼笑中等 + 头倾；**平静**靠眼半闭 + 轻度嘴笑；**开心**居中间偏笑。

### 2.2 复现方法（照抄可重跑）

1. 用 `esbuild` 把 `packages/engine/src/index.ts` 打成 IIFE（命令见 `vendor/soullink/NOTICE`）。
2. 起一个静态服务，把舞台现有的四个 Live2D 库（`pixi.min.js` → `live2d.min.js` / `live2dcubismcore.min.js` / `index.min.js`，加载顺序取自 `lib/index.js:196` 的 `listLibs()`）、`deepseek/` 模型目录、`vendor/soullink/soullink-engine.iife.min.js`、`l2d/stage-emotion.js` + 同目录 profile 放进去。
3. 页面里**只实现 K0 契约**（`version/app/model()/setExpressionDriver`），其余全交给 `stage-emotion.js`；每 16ms 调一次 `driver.drive({active,dt}, stage)`。
4. headless Chromium 启动参数（**必须有**，否则 canvas 停在 300×150、模型根本不画）：
   ```
   --headless=new --enable-unsafe-swiftshader --use-gl=angle --use-angle=swiftshader
   ```

### 2.3 两个会坑下一个人的实测事实（给 S 车道，重要）

1. **参数必须写在 `internalModel` 的 `beforeModelUpdate` 之后**。挂在 `app.ticker` 上直接 `setParameterValueById` 时，`idle.motion3.json`（58,890 B 关键帧）与 speak motion 会**在之后覆盖**同一批参数 —— 实测表现是"表情几乎看不出变化"（`ParamEyeLSmile` 恒在 0.00x）。改用 `internalModel.on('beforeModelUpdate', …)` 后同一套 VAD 输入立刻显出差异。`stage-emotion.js` 已经这么写了，S 车道**不需要**再处理顺序。
2. **headless 的虚拟时间下 `requestAnimationFrame` 不回调**（实测 `ticks` 恒为 0），而 `setInterval` + `--virtual-time-budget` 会让虚拟时间永远跑不完（Chrome 挂住）。取证时用**有界的 setTimeout 链** + 显式 `app.renderer.render(app.stage)`。这条只影响取证脚本，不影响产品代码。

## 4 · K1.3 解析器：契约逐条落地

`assets/l2d/stage-emotion-parse.js`，零依赖纯函数，同时是经典 `<script>`（挂 `window.__SOCRATIC_EMOTION_PARSE__`）与 Node 可 import 的 UMD 兜底形态。

| 契约条款 | 实现 | 测试 |
|---|---|---|
| 跨 chunk 拼接；`〔` 出现而 `〕` 未出现时该段不往下传 | `drain()` 见到 `〔` 找不到 `〕` 就把尾巴留在 `held`，只把 `〔` 之前的文本推给 sink | 「跨 chunk 拼接」「任意 1/2/3 段切分」 |
| `flush()` 仍不完整 → 原样交回、不发事件 | 返回 `{text: held}`，且**没有** `events` 字段 | 「flush：未闭合的尾巴原样交回」 |
| 非法标签 / 越界 / 缺两位小数 → 剥掉、不发事件、不报错 | 形态以 `〔emo:` 开头但过不了严格正则 `^〔emo:(calm\|happy\|shy\|puzzled\|excited):(0\.[0-9]{2}\|1\.00)〕$` 的一律剥掉 | 「非法形态一律剥掉」9 个反例 |
| 一句多个 → 取第一个 | `gotOneThisSentence` 只在传出的文本里出现句末标点时复位 | 「一句多个取第一个」「换句后可以再收一个」 |
| **判据：任意切分逐字节相同** | 状态只有 `held` 与 `gotOneThisSentence`，两者都由"已收到的字符"决定，与 chunk 边界无关 | 穷举 1/2/3 段全部切点（9 段样本）＋ 300 组随机切分（含空 chunk） |

附带的一句设计判断：**非 `〔emo:` 的方括号内容原样保留**（例如正文里的 `〔注一〕`）。契约第 3 条只规定"情绪标记剥掉"，如果把所有 `〔…〕` 都当标记吃掉，会误伤正文。

## 5 · C2 表情驱动模块：EC 逐条

`assets/l2d/stage-emotion.js`，IIFE，只读 K0 的 `window.__SOCRATIC_STAGE__`。

### 5.1 分层结构（不是一个 if 链）

```
待机层  ← engine 的 IdleEngine（呼吸/眨眼/视线微动/身体摇摆），setIdleEnabled(true)，持续不断
反应层  ← 情绪事件队列（FIFO，上限 8）→ runtime.triggerIntent()，每条之间 ≥ MIN_APPLY_GAP
情绪层  ← VAD（hold 窗口内压在目标上，窗口外交给 engine 以 decayRate=0.018 回落）
说话层  ← 口型源（可替换）→ mixLayers() 里对 ParamMouthOpenY 取 max、对 ParamMouthForm 做小幅调制
```

`mixLayers(baseParams, speechLayer, profile)` 是纯函数、可单测：**张嘴是叠加语义**（取 max），不能把表情已有的嘴压小。

### 5.2 EC 逐条

| EC（开发文档 §四 C） | 处理 | 测试/证据 |
|---|---|---|

| 一句多个标记：取第一个 | 解析器句界标志 | 同上 |

### 5.3 模块对外的接口

```js
window.__SOCRATIC_EMOTION__ = {
  version: 1, queueMax: 8, labels: [...],
  createDriver(stage, { engine, profile }),   // 单测/嵌入用

   return function () { app.ticker.remove(tick) }
   ```
   `emotionRef.current` = 当前**正在显示的句子**的情绪（`{label,intensity}` 或 `null`）。顺序上模型先 update、我们再 drive 也没问题：模块把参数写在下一帧的 `beforeModelUpdate` 里，延迟 1 帧、肉眼不可见。

5. **纸带口型**：舞台现在是"消息流到达就整段渲染"（没有逐字机），所以口型的"逐字节奏"= **流式文本增量**。在 `data.messages` 的那个 effect（`client.js:1050` 附近）里，记录最后一条 assistant 文本长度，把增量字符数报给模块：
   ```js
   const n = lastText.length - prevLenRef.current
   if (n > 0 && expressionDriverRef.current) expressionDriverRef.current.tapeTyped(n)
   prevLenRef.current = lastText.length
   ```

6. **喂情绪事件（K1.4 到货后）**：250 ms 轮询拿到 `events` 后，逐条
   ```js
   expressionDriverRef.current && expressionDriverRef.current.pushEmotion(ev.label, ev.intensity)
   ```
   并把当前句子的 `emotionRef.current` 设成最后一条（同句只设一次，别每帧新对象）。

7. **防御性剥离**（K1.4 红线，纸带不许显示 `〔emo:…〕`）：纸带渲染前过一遍
   ```js
   var P = window.__SOCRATIC_EMOTION_PARSE__
   if (P) text = P.strip(text)
   ```

## 7 · 我替你（主代理/用户）做的判断

1. **采用 Soullink，不退回手写** —— 依据见 §1.2 三条。手写分层混合等于重抄一遍 VAD→FACS→分层混合，且没有 profile 适配的机械保证。
2. **自打 IIFE 而不是要求舞台支持 `type=module`** —— 后者要动 S 车道的 `loadOneScript`（既有文件），越界；前者只多一条可复现的 esbuild 命令。
3. **profile 放在 `assets/l2d/` 同目录、用 `document.currentScript.src` 解析 URL** —— 不依赖舞台的 `ROUTE` 常量（那个常量在 `client.js` 闭包里，模块拿不到）。
4. **`vendor/` 用 `git add -f` 入库**，不改 `.gitignore`（既有文件）。
5. **口型源接口定为 `{update(dt), level(), form?()}`** —— 舞台只需"报几个字"，将来换音频源只换对象。
6. **`blush` 不做** —— 模型没有这个参数（`capabilities.blush=false`），硬做只能靠改贴图，超出本车道范围。
7. **`puzzled` 在引擎里映射到 `confused`** —— 引擎的 VAD 预设表里没有 `puzzled`，`confused` 是它的同义项（`valence −0.1 / arousal 0.35 / dominance −0.3`）。
