# SocraticNovel · 方法论审视：我们的规划还差什么（2026-09-19）

> **触发**：用户 —— *"上层设计还是需要更多的讨论。我不知道还缺什么但是总感觉不太对劲……找些比较常用的产品设计思路和方法论（比如我们之前是不是使用了亚马逊的一个方法，就是在项目开始时就准备好最后的'发布会'？），审视一下我们现在的规划还差什么？"*
> **先回答那个问题**：那个方法叫 **Working Backwards（逆向工作法）**，它的核心工具是 **PR/FAQ**。**我们没有用过它。** 我们做的是"从 1,000★ 倒推排期"——那是**目标倒推**，不是**客户体验倒推**。这两件事长得很像，但结论完全不同（§1.1）。
> **结论先行**：我们缺的不是功能，是**"从客户体验倒推"的那一半**，外加**留存设计**和**机会层**。共 **14 个缺口**，其中 4 个是结构性的（§3）。

---

## §1 四个主力方法论（为什么选它们）

| 方法论 | 一句话 | 补我们的哪个洞 |
|---|---|---|
| **① Amazon Working Backwards / PR-FAQ** | 建之前先写"发布稿 + FAQ"；**写不出有说服力的发布稿，就说明这个想法还不成熟** | 缺"发布那天要说什么" |
| **② April Dunford 定位十步** | 第一步不是"竞品是谁"，而是"**如果我们的产品不存在，客户会怎么做**" | 缺"真实替代方案"与"市场类别" |
| **③ Hook Model（Nir Eyal）** | Trigger → Action → Variable Reward → **Investment** | 🔴 **缺留存**（最大结构性洞） |
| **④ Opportunity Solution Tree（Teresa Torres）** | Desired Outcome → **Opportunities** → Solutions → Experiments | 缺"机会层"（我们直接从目标跳到功能） |

**引用出处**（避免我概括失真）：
- Working Backwards / PR-FAQ：Amazon 官方摘录 —— *"Its key tenet is to start by defining the customer experience, then iteratively work backwards"*；PR **"a few paragraphs, always less than one page"**，FAQ **"five pages or less"**；以及那句判据 —— *"If the press release doesn't describe a product that is meaningfully better (faster, easier, cheaper) than what is already out there, or results in some stepwise change in customer experience, then it isn't worth building."*（[aboutamazon.com](https://www.aboutamazon.com/news/workplace/an-insider-look-at-amazons-culture-and-processes)、[workingbackwards.com](https://workingbackwards.com/concepts/working-backwards-pr-faq-process/)）
- 定位十步：*"begins by identifying what customers would do if your product did not exist"*（[Qualz 研究指南](https://qualz.ai/research-guide/frameworks/positioning-process/)、[Gavel 模板](https://usegavel.com/april-dunford/positioning-process)）
- Hook Model：trigger / action / variable reward / investment（[The Behavioral Scientist](https://www.thebehavioralscientist.com/glossary/hooked-model)、[Nir Eyal 原文](https://medium.com/googleplaydev/optimize-app-retention-with-the-hooked-model-a0781f8e5d29)）
- Opportunity Solution Tree（[producttalk.org](https://www.producttalk.org/opportunity-solution-trees/)）

**其他可备用**（本轮不逐条审）：Crossing the Chasm 的"滩头阵地"、Fogg 行为模型（B=MAP）、Kano 模型、AARRR 海盗指标、North Star + 输入指标、Working Backwards 的 6-pager 与输入/输出指标（[workingbackwards.com](https://workingbackwards.com/concepts/input-metrics/)）。

## §2 逐方法论审视：我们缺什么

### 2.1 用 PR/FAQ 审 —— 🔴 我们写不出发布稿

**PR/FAQ 要三件东西，我们一件都没有：**

| 件 | 要求 | 我们的现状 |
|---|---|---|
| **发布稿（PR）** | < 1 页，从**客户视角**写"今天发布了什么、它让谁的生活变好了" | ❌ **完全没有**。我们所有文字都是**给技术圈看的**（README、架构文档、★ 目标） |
| **外部 FAQ** | 客户会问的硬问题 | ❌ 没有。"和 ChatGPT 有什么区别？""要花钱吗？""我的教材能用吗？""我英语不好行不行？""要装什么？"——**一个都没答** |
| **内部 FAQ** | 成本 / 单位经济学 / **最大的失败风险** / 为什么不做 X | ❌ 没有。**成本我们只提过一句"$350 要打下来"** |

🔴 **"so what?" 测试现在过不了**：Amazon 那句判据要求发布稿说出"**更快 / 更容易 / 更便宜**"或"客户体验的台阶式变化"。我们现在能说的是"教材是为你写的、老师是故事里的人"——**这是"不一样"，不是"更好"**。**"不一样"不能说服人换掉已经在用的东西。**

🔴 **而且 PR/FAQ 暴露了一个更根本的没解决的问题**：**发布稿写给谁？**
- 我们的**受众**（涨★）= 觉得有意思的人
- 我们的**用户**（真用）= 有截止日的学习者
- **PR 要面对的是"要不要用"的人 —— 那是用户，不是受众。**
→ 这两个人群刚分开（受众 ≠ 用户），但**发布稿只能写给一个**。这个选择没做。

### 2.2 用定位十步审 —— 🔴 我们搞错了"竞争对手"是谁

**Dunford 第一步：如果我们的产品不存在，客户会怎么做？**

我们列的是**竞品**（Bloom 269★、ChatTutor 1316★、learn-anything 458★）。但真实的替代方案大概率是：

| 客户现在的替代方案 | 我们有没有针对它设计？ |
|---|---|
| **直接问 ChatGPT / Claude**（免费、已经开着、零安装） | ❌ **没有**——而这才是最常被雇用的那个 |
| B 站网课 / 公开课 | ❌ 没有 |
| 补习班 / 家教 | ❌ 没有 |
| 硬啃教材 | ❌ 没有 |
| **什么都不做**（承认学不下去） | ❌ 没有 |

🔴 **如果客户的真实替代是"问 ChatGPT"，那我们的竞争对手不是 Bloom，是"已经打开的 ChatGPT"。** 那么"专属教材 × 沉浸叙事"必须证明它**比问 ChatGPT 好得多**——而不是比 Bloom 好一点。**我们整个论证目前是对着 Bloom 做的。**

**另外缺的三件**（Dunford 后半段）：
- ❌ **独特能力 → 价值主题**（我们只列了能力，没说这些能力合起来对客户意味着什么）
- ❌ **最佳客户画像**（best-fit customer）：我们列了 8 类人群，**没有说"哪一类最该先打"**
- ❌ **市场类别**：我们属于哪一类？"AI 家教"／"学习工具"／"gal game"／**"一个全新的类别"**？🔴 **类别选择本身就是定位决策**——选"AI 家教"就要跟 1316★ 比，选新类别就要自己定义规则。**我们没做这个选择。**

### 2.3 用 Hook Model 审 —— 🔴 这是最大的洞：我们没有留存设计

| Hook 四步 | 我们有吗 |
|---|---|
| **Trigger**（触发） | ✅ **有**——"我真的不会"是内部触发；作业/考试截止日是外部触发。这是 AnimaTutor 的"连接理由"理论，最扎实的一块 |
| **Action**（行动） | ✅ **有**——一道题。门槛已经降到很低 |
| **Variable Reward**（可变奖励） | ❌ **没有设计**。"搞懂了的爽感"太抽象；**不确定性的部分在哪？** 她今天会是什么反应？会怎么讲？——**这是"再来一次"的动力来源，我们完全没设计** |
| **Investment**（投入） | ❌ **没有设计**。用户每一次来，往系统里存了什么？**"累积物"（卡点清单、她的记忆）是"系统存"的，不是"用户存"的**——Hook 理论里 Investment 是**用户自己的投入**（存的东西越多、越难离开）。 |

🔴 **为什么这是最大的洞**：**我们整个计划是"涨 ★"的，但没有任何一个"第二周还会回来"的设计。**
- ★ 是**输出**，不是价值
- 如果留存是 0：① 涨来的★是空的；② **招生官问"有谁在用"我们答不出来**（而"used by many people"正是 NUS 那条官方条款的字面要求）
- 我们自己推的"受众 ≠ 用户"是对的，但**用户线只设计了"怎么进来"（砍门槛），没设计"进来之后怎么留下"**

### 2.4 用 Opportunity Solution Tree 审 —— 我们跳过了"机会层"

Torres 的树：**目标 → 机会 → 方案 → 实验**。机会（Opportunity）是**用用户视角描述的痛点/需求/愿望**。

**我们的结构**：目标（1,000★）→ **直接跳到方案**（13 个能力域、30 天渠道排期）。

🔴 **我们是 solution-first 的**：先有 13 个域的能力清单，再回头找理由。**中间那层"用户真正的痛点是什么"从来没被独立写下来过。**
→ 后果：**能力清单里有相当一部分是"看起来该有"，而不是"某个具体的人在某个具体处境下需要"。**

### 2.5 通用产品纪律的缺口（不依赖特定方法论）

| # | 缺什么 | 为什么是问题 |
|---|---|---|
| a | **MVP 的边界没定** | 30 天要做：CLI + Live Demo + 录屏 + 教室 + 碎片化入口 + 升级阶梯 = **全部**。**没有"砍到只剩一件"的决策**——这正是"6 个仓库一起停摆"的重演风险 |
| b | **没有"第一个人"** | 只有 8 类人群，**没有一个具体的人**（谁、什么处境、想完成什么） |
| c | **没有滩头阵地** | 8 类人群全都要 = 一类都打不透 |
| d | **没有输入指标** | 只有 ★（输出）。**输入是什么？**（每周完成第一节课的人数？被引用次数？外部贡献者数？） |
| e | **没有 kill criteria** | 什么情况下承认这条路走不通？没有 |
| f | 🔴 **资源约束没有进入设计** | 你 10–11 月有 **TMUA / UCAS / 托福 / 主文书 / EA / 香港 / UC**。**整个计划隐含假设有一个全职的人在推进**——这不是小事，它决定 MVP 能有多大 |
| g | **没有"内容冷启动"的解** | 教室库是社区贡献的产物，**但社区需要先有教室**（鸡生蛋）。这个循环没解 |
| h | **没有叙事质量的下限** | 沉浸是放大器，**叙事写不好会反噬**（AnimaTutor 自己都写了"角色开始漂移、规则开始失效"） |
| i | **没有竞品反应** | Bloom 269★ 已经在做 skill+web，**如果它加个"专属教材"呢？** |
| j | **没有平台风险** | 依赖 Claude Code / Anthropic 生态；平台一变，适配层全废 |
| k | **没有命名与叙事资产** | 项目名、slogan、README 第一屏——PR/FAQ 一写就会暴露这个洞 |
| l | **没有"为什么是我们"** | unfair advantage。你有真实运行过的教学系统（这是真的优势），**但没被写成一句话** |

## §3 缺口汇总（按严重度）

| 级别 | 缺口 | 后果 |
|---|---|---|
| 🔴 **结构性** | **① 留存设计缺失**（Hook 的 Variable Reward + Investment） | ★ 是空的；答不出"有谁在用" |
| 🔴 **结构性** | **② 真实替代方案搞错**（对着 Bloom，而不是"已经打开的 ChatGPT"） | 整个差异化论证打偏 |
| 🔴 **结构性** | **③ 没有发布稿**（PR/FAQ） | "不一样"≠"更好"，说不服人换掉现在在用的东西 |
| 🔴 **结构性** | **④ MVP 边界未定** | 30 天必然又变成"什么都做"，重演 6 仓库停摆 |
| 🟠 重要 | ⑤ 机会层缺失（solution-first） | 能力清单里有"看起来该有"的东西 |
| 🟠 重要 | ⑥ 没有滩头阵地 + 没有"第一个人" | 8 类人群全打 = 一类都不透 |
| 🟠 重要 | ⑦ 市场类别未选 | 定位悬空（跟 1316★ 比还是自己定义规则？） |
| 🟠 重要 | ⑧ 资源约束未进入设计 | 计划不可执行 |
| 🟡 一般 | ⑨ 输入指标 ⑩ kill criteria ⑪ 内容冷启动 ⑫ 叙事质量下限 ⑬ 竞品反应 ⑭ 平台风险 ⑮ 命名资产 ⑯ "为什么是我们" | 见 §2.5 |

## §4 补齐的动作：先产出这三份文档

按"最便宜 × 最能暴露问题"排序：

### ① `PR-FAQ.md`（🔴 最优先，正好回答"总感觉不对劲"）
- **发布稿**（< 1 页）：今天发布了什么、让谁的生活变好了、**为什么它比"直接问 ChatGPT"更好**
- **外部 FAQ**：客户会问的硬问题（和 ChatGPT 的区别 / 花钱吗 / 我的教材能用吗 / 英语不好行不行 / 要装什么）
- **内部 FAQ**：成本与单位经济学 / **最大的失败风险** / 为什么不做 X
- 🔴 **写作要求**：**先定"写给谁"**（用户还是受众——§2.1 那个未解决的选择），**全文不许出现技术词**，长度硬上限（PR ≤1 页）

### ② `留存设计.md`（补 Hook 的后两步）
- **Variable Reward**：不确定性的部分是什么（她的反应？讲法？今天的故事？）
- **Investment**：**用户每次来往系统里存了什么**（不是"系统记得你"，是"你存了什么"）
- 配一个**"第二周为什么会回来"的机制**，并给出可测指标

### ③ `MVP-边界.md`（砍到只剩一件）
- 输入：**你的真实可用时间**（10–11 月的硬约束先摆出来）
- 输出：**30 天只做一件事是什么**，其余全部推到第 3 层
- 附：**kill criteria**（什么情况下停）

**做完这三份，再回头改能力清单**（把"看起来该有"的删掉，把"机会层"补进去）。

## §5 一个观察

我们这一路做得很扎实——**竞品、赛道、护城河、复用、碎片化机制都查得很实**。但回头看，**所有工作都是"往外看"**（看竞品、看全球开源现状、看★ 数字）。

**Working Backwards 要求的是"往客户那边看"**：写一段发布稿，假装它已经发布了，然后问自己"看完这段，我会想用吗？"

**这一步我们一次都没做过。** 我觉得你那句"总感觉不太对劲"，指的大概就是这里。
