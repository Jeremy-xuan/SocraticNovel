## 2. N3 · 群聊

### 2.1 真源为什么是 JSONL（N3.2 要求我判断并写明）

三条理由，逐条对应契约里的硬要求：

1. **未读只能靠 `seq`**：K4.2 写死「`seq` 是排序与未读的唯一依据」。markdown 没有可靠序号，用行序＝把「未读」押在解析器稳定性上。
2. **两个标签页同时发言不能丢消息**（K4.3 的 AC）：一行一条 JSON 的追加在 `O_APPEND` 下是单个写操作；markdown 必须整文件重写，「读—改—写」之间必丢写。
3. **坏数据隔离**：一行坏 JSON 只丢那一行（`bad` 计数上报）；markdown 一处坏格式会让整份读废。

`ts` 一律 `+08:00`：群聊的一切时间语义（N4 的 8:00–23:00）都在北京时间，EC 说服务器时钟不可信，所以不跟进程本地时区走。

### 2.2 四个方法（K4.3）

| 方法 | 关键实现细节 |
|---|---|
| `history(scope, limit)` | limit 收敛到 1..200（默认 50）；`nextSeq = maxSeq+1`；`unread = seq > readSeq 的条数` |
| `send(scope, text, clientId)` | 1–2000 **码点**（空白串 `EMPTY`、超长 `TOO_LONG`）；`clientId` 幂等；一分钟 >30 条 `RATE_LIMITED`；**真源有坏行 → `STORE_CORRUPT` 拒写**（否则 seq 依据不完整会撞号）；成功后排入回复批次 |
| `poll(scope, afterSeq, waitMs)` | 长轮询，`waitMs` 收敛到 0..25000；返回 `{messages, typing, nextSeq, unread, serverTime}`；`typing = 有待回复批次` |
| `markRead(scope, seq)` | 游标只前进不回退，钳在 `maxSeq` 以内 |

`send` **不抛异常**（契约要求让人能重试），失败一律 `{ok:false, error:{code,message}}`。错误码与使用场合：

- `EMPTY` / `TOO_LONG` / `RATE_LIMITED`：入参问题；
- `STORE_CORRUPT`：真源坏行、或找不到教室目录、或存储 IO 出错；
- `AGENT_FAILED`：**消息落盘了但排不进回复队列**（可重试）；
- **回复生成本身失败不在 `send` 里**（那是异步的）：本包重试一次，仍失败就发一条 `role:'system'` 的消息（K4.2 允许 system 作为「无法回复的说明」），并把错误写进 `agent-runs.jsonl` 与 `narrative.status()`。契约里 `AGENT_FAILED` 因此没有被用来表示「模型回复失败」——这一点如实写在 README §7.2。

### 2.3 并发

- **跨进程**：`lib/lock.mjs`（`wx` 建 `<file>.lock`、写 `{pid,token,acquiredAt}`、30 秒陈旧锁可回收、释放前核对 token 不删别人的锁）。为什么不用 `@deepseek-ai/dsh-atomic-write` 的 `withFileLock`：踩「宿主包不进 profile」的铁律。
- **同进程**：`lib/serial.mjs` 按 key 串行。
- 单测：12 条并发发言 → seq 连续 1..12，一条不丢。

### 2.4 节奏与课堂判据（N3.4）

- 学生发言 → 立刻落盘、立刻返回；批次记 `dueAt = now + 10..30s 随机`；再发一条 → 同一批次重置 `dueAt`（服务端去抖，不靠前端）。
- 课堂进行中（相位不是 `close` **且**最近回合活动 ≤30 分钟）→ 挂着不回；收课后 `tick` 补回。
- 相位来源两级：① 引擎每回合调 `setClassroomActivity({sessionId, classroomDir, phase, lastActivityAt, lesson})`（**推荐**）；② 没有就读 `runtime/progress.md` 的 `current_phase:` 行 —— 那时拿不到回合活动时间，判据按「不在上课」处理。**这条边界会让「课堂进行中不回群」在引擎不接线时失效**，写进 README §8 与 §12。

### 2.5 谁能开口（N3.3）与三条写死规则（N3.6）

- 名字来自 `characters/*.md` 的一级标题（`# 鲸（DeepSeek 娘）· 本教室版本` → `鲸（DeepSeek 娘）`，短名 `鲸` 也认）；一次性路人 `路人·<称呼>`；**其它名字直接 `INVALID_OUTPUT`**，不静默改名。当课角色卡从 `classroom.yaml` 的 `path: characters/*.md` 解析（**不硬编码文件名**——这一版教室已从 `komari.md` 换到 `deepseek.md`，N2 的硬编码在这轮一并修掉）。
- 代码兜住三条：≤2 行、无 emoji（`\p{Extended_Pictographic}`，Unicode 属性，不是人肉清单）、speaker 合法。
- 🔴 面向群聊/日记/审阅 agent 的文本里**没有**「有读者／面板／未读」——有一条机器守卫把群聊那 5 段提示词拼起来做检查（与 N2 的日记守卫同款）。

### 2.6 🔴 `notes.jsonl` 的边界（开发文档给的「两个写入者」决定）

- 本包**只追加一行 JSON**（`O_APPEND` 单次写，单行 < 4KB），`type: "group_question"`、`origin: "group_agent"`。
- **绝不重算三份投影**（`mistake_log.md` / `review_queue.md` / `knowledge_points.md` 的状态位）——那只有引擎（`classroom_note`）能写。
- 字段对齐引擎：`id` = `N-<yyyyMMddTHHmmss>-<三位序号>`（同一秒取已有最大序号 +1）、`ts` 带**本地**时区偏移（一份文件不混两种时间写法）、`quote` 已剥 K1 情绪标记与 markdown、`resolved` 不写、`kp` 只在 `knowledge_points.md` 里真实存在时才写（否则 `null`）、`session` 无宿主会话时写引擎同款兜底 `"unknown"`。
- 已知边界：同一秒、两个进程同时追加时 id 序号可能撞（引擎追加时也不持锁）。

## 3. N4 · 定时主动消息

### 3.1 分工

**说什么**交给模型（当天一次调用，`messages` 数组）；**什么时候发、该不该发**是确定性代码。

### 3.2 时间（EC）

`lib/time.mjs` 只做「epoch + 8 小时 → 用 UTC 取值」：不读进程时区、不读 ICU、不读系统钟。窗口 08:00–23:00（23:00 整不发），每天 1–3 条；**剩余窗口不足 1 小时时只排 1 条**；生成后第一条至少等 5 分钟（不「刚生成就发」）。

### 3.3 队列与检查

- 队列 `runtime/.narrative/proactive.json`：`{date, plannedCount, generateAttempts, replacements, sentSinceLastStudent, lastStudentSeq, slots[], voided[], lastError}`。
- 到点前检查（N4.3）：`messages.some(seq > slot.context.maxSeq)`（新的群聊消息）/ `lastActivityAt >= generatedAt`（上课）/ 课堂进行中 → 作废。作废后当天还有额度（≤3）、仍在窗口、补位次数未满（≤2）→ `now + 5..30 分钟` 重生成一条。
- 退避（N4.4）：`sentSinceLastStudent >= 2` → 连「到点发」都不做，记 `voidReason: "backoff"`；学生新发言（seq 变大）清零。

### 3.4 EC 三选一：**重启时恰好跨过发送时刻 → 不补发**

- 迟到 ≤ 10 分钟：照发（还是那个时刻）。
- 超过 10 分钟：作废；有额度就在 `now + 5..30 分钟` 重生成一条。
- **理由**：一条迟到半小时的「刚看到」读起来像程序在补作业，而不是她想起你；而「什么都不发」会让当天少一条且没人知道——重生成既保住当天配额，又不会出现「五分钟前的消息现在才弹出来」。
- 队列文件损坏：丢队列、按今天重建（`queue-rebuilt`），**不崩溃**。
- 跨天：昨天整份丢弃，按今天重建。
- 生成失败：当天最多 3 次，之后停手，错误留在 `lastError` 与日志里。

## 5. typert / 0.2.1 的 codec：为什么可以零依赖

逐条核对了 0.2.1-rc.2 安装版源码：

| 结论 | 出处 |
|---|---|
| 清单只校验**结构**：`mode==='strict'`、`typeSymbol` 是非空字符串、`create` 是函数、`jsonSchema` 是对象（不要求 zod 实例） | `dsh-typert-loader/lib/index.js` 的 `requireStrictCodec` / `requireSchemaProjection` |
| 边界解码调 `codec.create().parse(value)`，所以 `create()` 返回带 `parse` 的对象就够 | `dsh-api-gateway/lib/index.js` 的 `decode` |
| 服务发现 = 类原型上的 marker 描述符（字符串键 `@deepseek-ai/dsh-typert-protocol/remote-methods`）+ 实例上的 `typertRemote` 绑定；两者都是纯数据 | `remoteMethods` / `validateBinding` / `collectSrcClaims` |
| lookup 参数的 `typeSymbol` 必须与提供方逐字一致 | `dsh-api-workspace-files/lib/index.js:399-410`（`wireTypeSymbol: "@deepseek-ai/dsh-session/types#SessionId"`） |
| 第一参数在 SRC 模式下按**参数名**匹配 lookup（必须叫 `workspaceFileScope`） | gateway 的 `srcDescriptor` → `methodParameterNames` |

所以：`lib/typert.host.mjs` 自带 codec（`create: () => ({parse})`）、类原型手工打 marker、实例挂 `typertRemote`，**没有 import 任何 `@deepseek-ai/*`，也没有 zod**。参数名同时满足 strict 与 SRC 两条路（第一条叫 `workspaceFileScope`，wire 名 `workspaceFileScopeId`），所以即便某天 loader 解析不到本包（例如装法不同），SRC 回退也能工作。

**代价**：① `jsonSchema` 手写，要与 `create()` 的校验保持一致（现在两者都是我写的，且单测同时覆盖）；② 参数校验只覆盖 string/number（本服务用不到别的）；③ 将来若要给结果做严格探针/客户端生成，得补更完整的 JSON Schema。

**活体证据**：在隔离 profile `lane-n` 里，`ctx.typert.local.list()` 里出现四个端点：

```

socratic-narrative#classroomGroup/send
socratic-narrative#classroomGroup/poll
socratic-narrative#classroomGroup/markRead
```

## 8. 给引擎 / 面板接线要加什么（具体到函数）

**引擎（车道 J/E）**

1. **课堂状态（🔴 不做这条「课堂进行中不回群」不生效）**：在已有的回合活动记账处（`plugins/socratic-engine/lib/postclass.mjs` 的 `agent/turn-stopping`，与 N2 闲置兜底同一处）调
   `ctx.classroomGroup.setClassroomActivity({ sessionId, classroomDir: current.dir, phase: current.phase, lastActivityAt: Date.now(), lesson })`。
   `phase` 取 `lib/phasestore.mjs` 的 `get phase`；`inject` 里加 `classroomGroup`（或 `ctx.get('classroomGroup')` 判空）。
2. **群里的知识题不用再写一遍**：本包自己写 `runtime/notes.jsonl`（`group_question`）；引擎只需按 K3.4 把它注入下一节课开头。
3. **课堂老师也能提世界观提议**：教师觉得该加角色/改设定时调
   `ctx.narrative.appendProposal({ classroomDir, origin: '课堂老师', content, reason, quote })`。
4. **N2 的两条接线照旧**（收课触发 `runDiary`、闲置兜底 `isLessonIdleClosed`），本轮没改。
5. **`classroom.yaml` 的 `narrative.models.*`**：想给 `diary` / `group` / `review` 分别指定模型就在这里写，引擎读出来当调用参数传（本包不硬编码模型）。

**面板（车道 P）**

1. 群聊 tab 用 `templates/wechat-chat.html` 的版式，数据只走 `ctx.remote.classroomGroup.*`（**不读 md/jsonl**）。
2. 「对方正在输入」= `poll().typing`；未读 = `poll()/history()` 的 `unread`，读完 `markRead(maxSeq)`。
3. 长轮询：`poll(afterSeq, 25000)`（服务端可能提前返回）。
4. 发送失败：`send` 返回 `{ok:false, error:{code,message}}`——按 code 提示（`EMPTY`/`TOO_LONG`/`RATE_LIMITED`/`AGENT_FAILED`/`STORE_CORRUPT`），`AGENT_FAILED` 与 `STORE_CORRUPT` 可重试。
5. 「她那边卡住了」会以一条 `role:'system'` 的消息出现在消息流里（不需要面板另做错误态）。
6. 日记 tab / 错误态照 N2：`ctx.narrative.status()`（`task:'review'` 的失败也会出现在这里）。

## 9. 我替你做的假设 / 已知边界 / 需要你决策的事

**替你做的假设**

1. **写死规则搬到了 `runtime/wechat_group.rules.md`**（N3.6 的规则必须有个不被机械重画的地方）。`wechat_group.md` 因此变成纯投影。规则内容逐字沿用旧文件头 + 加了「谁能开口」与「不加会反复出场的人，先走提议」。
2. **`ts` 用 `+08:00`**（群聊时间语义全在北京时间），而 `notes.jsonl` 的 `ts` 用**本地时区**（跟引擎同口径）——两个文件两种口径是有意的。
3. **重启跨过发送时刻 → 不补发，10 分钟宽限，超出就重生成**（§3.4 给了理由）。
4. **`notes.jsonl` 的 `session` 在群里提的问题上写 `"unknown"`**（引擎同款兜底），引擎报过 `sessionId` 时写它。
5. **`_anchor.md` 整份拒绝**（不做段落级「教学法部分」解析）。
6. **世界观审阅的接受 = 重写一个文件**（`path` + 完整 `content`），一条提议只改一个文件。
7. **`AGENT_FAILED` 只表示「排不进回复队列」**，回复生成失败走 system 消息 + 日志 + `status()`。
8. **`typing` 在课堂挂起期间仍为 true**（契约措辞是「已被排入回复队列」）；要不要在面板上对「被推迟」另作显示由 P 决定。

**需要你决策的事**

1. 🔴 **部署脚本那条 EC（`tools/deploy/**`，不在我的范围）**：`--update-only` 不能覆盖 `world/`、`characters/`、`runtime/`。这条要落在部署线上，否则 stage 上演化出来的世界（含 `changelog.md` 这份观察窗口）会被一次部署冲掉。要我另派人做，还是你直接改？
2. **世界观审阅可以整体重写 `characters/` 与 `world/` 下的任意 `.md`**（两份日志除外）——这是 N5.2 给的范围。它的风险是「一次接受把 `world/setting.md` 改写跑偏」。现在唯一的刹车是 changelog 可读 + 你可以回滚。要不要再加一条「只能新增文件、不能改既有文件」的收窄？
3. **同一条提议被两条不同的提议接受成同一个 `path`** 时，后写的覆盖先写的（活体里两条都写 `characters/an.md`，后一条覆盖前一条）。要不要加「目标已存在就要求追加而不是覆盖」的规则？

**已知边界**

- `notes.jsonl` 的 id 序号在**同一秒、跨进程**时可能撞（引擎也不持锁）。
- 群聊「课堂进行中」判据需要引擎报活动时间（见 §8 第 1 条）。
- 跨进程锁是**建议性**的：不参与本协议的写者（引擎自己的 `withFileLock`）不会看这份锁文件。
- 世界观审阅每条一次模型调用（顺序保证「后来的看到先前的结果」），积压多时这一轮会慢；没有批量优化。
