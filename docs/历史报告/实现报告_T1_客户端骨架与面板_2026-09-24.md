## 1 · 数据通道取证结论（源码级，逐字）

### 1.1 四条通道的可行性与代价

| # | 通道 | 源码依据 | 可行性 | 代价 | 本批选择 |
|---|---|---|---|---|---|
| A | **客户端直读工作区文件**：`ctx.remote.workspaceFiles.read(sessionId, path, range)` | `packages/api/workspace-files/src/index.ts:227` 逐字：`@param path - absolute path or path relative to the workspace root; files outside it are allowed.`；分页语义 `types.ts:41-62`；页大小默认 5000 行 `src/index.ts:189`；该包**已在 web 面装配**：`dsh-web-app/cordis.patch.yml:110-111` | ✅ **完全可行** | **零服务端工作** | ✅ **采用** |
| B | 服务端插件把数据推给客户端 | 需要宿主半边 + 自建推送通道；本批未设计 | 可行但无必要 | 写宿主插件、设计协议、双端联调 | ❌ 不需要 |
| C | 会话投影 `useProjection` | 座目录 `sidebar.right.pane.tab` 的 `standardProps` 含 `useProjection`/`useSession`/`useChat` 等（`tmp/dsh-installed/dsh-cordis-client-runner/lib/client.js:4161` 附近） | 存在 | 要服务端注册投影，且投影值是「引擎算过的状态」 | ❌ 本批不用（若将来要「引擎内部相位」而非「文件里的相位」，再评估） |
| D | 组件 local state 存数据 | — | — | 重开面板即丢、且真源仍是文件 | ❌ **未采用** |

**选定通道 A 的完整链路**（都已实测跑通，非推断）：

1. 客户端 Remote 面由 `@deepseek-ai/dsh-api-remotes` 提供；`workspaceFiles` 命名空间由 `@deepseek-ai/dsh-api-workspace-files` 提供 → 本插件在 `dsh.client.inject` 与 cordis `inject` 两处都声明依赖（前者管模块到达顺序，后者管服务就绪）。
2. `read` 的**相对路径按会话工作区根解析**（`resolve` 走 `workspaceFileScope`，`src/index.ts:200-224`：`workspaceRoot: header.cwd ?? scope.sandboxPolicy.workspaceRoot`）→ 教室在工作区内，用相对路径即可，工作区搬家不受影响。
3. 返回值是 `RemoteResult<T>`：`packages/typert/protocol/src/types.ts:76-78` 逐字
   `export type RemoteResult<T> = { readonly ok: true; readonly value: T } | { readonly ok: false; readonly error: RemoteFailure }`
   → 失败**不 reject**，由 `ok` 分支携带（`RemoteError extends Error`，有 `.message`/`.code`）。
4. 分页：本插件**不传 limit**（用宿主默认页大小），循环直到 `eof`；若某页返回 0 行却未到末行＝宿主违约 → **报错**，不空转、不静默截断。

### 1.2 客户端插件的装载机制（三条关键事实，全部实测）

1. **必须有 `dsh.bundle.patch` 才是 profile 的一层**：
   `@deepseek-ai/dsh/lib/plugin-Ddi42qoW.js:53-57` —— `const isBundle = exportsPatch(packageName, profileDir)`；非 bundle 的依赖只当普通包装进去（并 warning）。**实测**：装上后 `socratic-dev/package.json` 的 `dsh.profile.bundles` 自动多出 `classroom-ui`。
2. **浏览器 roster = 宿主 Loader 条目扫描**：`dsh-client-modules/lib/index.js:672-691` 读 `package.json`，要求 `dsh.client.platform === 'web'`，产物路径取自 `exports["./client"]`（`clientExportOf` `:156-166`；缺了直接抛 `:681`）；**boot 图的行 id 就是包名**（`:860 entry: graphRow(packageName, rev, source.meta)`）。
3. **产物不是 ESM，是惰性 CJS 表**：`window.__ModuleLoader__.load({ id, factory: (require) => {...} })`（官方样例 `tmp/dsh-installed/dsh-client-ui-jobs/lib/client.js:1-5`）。宿主**不做任何转译**，读产物字节直接下发 → 所以 `lib/client.js` 是**手写产物**：`require("react")`（平台种子模块）＋ `React.createElement`，不用 JSX、不用 CSS 模块 → **不需要打包器**。

### 1.3 客户端有没有 node 侧半边？——有，且是官方常态（"双半插件"）

- 实证：`tmp/dsh-installed/dsh-client-ui-sidebar-right/package.json` 同时有 `main: lib/index.js`（宿主半边）、`dsh.client: { inject: [...], platform: 'web' }`、`exports["./client"]: lib/client.js`（浏览器半边）。
- **本插件也按双半形态交**：`lib/index.js` 是**空宿主半边**——它存在的唯一理由是「Loader 行需要一个可 import 的宿主模块」。**它不是占位符，也不是给未来预留的扩充点**；面板所需数据全部由浏览器半边读文件取得（见 §1.1）。

### 1.4 有没有会话级共享存储？（禁止塞组件 local state）

- **官方座位**：slot 注册选项有 `store`（`ui-slots/src/index.ts` 的 `StoreDecl` / `FactoryStoreOf`），可把 store 交给框架按会话生命周期托管；session 作用域的 `inject` 回调实参是 `(sessionId, actions)`，注释逐字（`:614`）：`strict session slots receive a definite framework-resolved sessionId`。
- **本插件做法**：数据缓存在**插件作用域的 `Map<sessionId, store>`**（`lib/client.js` 的 `storeFor`），主体与标题共享同一实例；组件只用 `React.useSyncExternalStore(subscribe, getSnapshot)` 订阅。**数据源始终是磁盘文件**，组件 local state 只保存 UI 无关的渲染派生值（本插件甚至一个都没有）。
- 未用官方 `store` 座位：本插件的 store 生命周期不需要框架托管（首次挂载触发一次读盘、之后只在按「重新读盘」时重读），用框架座位只会增加装载面。**这是取舍，不是遗漏。**
