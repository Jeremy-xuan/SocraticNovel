**6.2 的机制证据（运行时判定，不是读源码下的结论）**：探针在同一个进程里同时做两次调用——

```
正向对照：ctx.logger("[socratic-accept-probe:positive-control]").warn(text)   → 收到 1 条
```

两次调用的**级别相同、出口相同、时间相同**，唯一差别是调用形状。运行时观测还给出了形状的直接证据：

```json
"engineShape": {
  "shape": "ctx.logger('[socratic-engine]', ...args)",
  "returnedType": "object",
  "returnedConstructor": "Logger",
  "returnedHasWarn": true,
  "received": 0,
  "shapeControlReceived": 1
}
```

→ `ctx.logger('[socratic-engine]', ...args)` **返回了一个 Logger 对象、把全部参数丢掉了**。被测插件 `index.mjs:75-81` 的 `log()` 就是这么写的：

```js
const log = (...args) => {
  try {
    ctx.logger?.('[socratic-engine]', ...args)   // ← 参数被丢弃，返回的 Logger 被抛弃
  } catch {
    /* logger 不可用不致命 */
  }
}
```

正确形状（安装版自己的用法，`@deepseek-ai/dsh-app-boot/lib/index.js:202`）：

```js
this.ctx.root.logger?.("loader").warn(message, ...args)
```

## 8 · 覆盖不了什么（诚实清单）

1. **只覆盖"引擎注入"这条路，不覆盖"教室自带 AGENTS.md"之外的其他加载路径的交互**。
   会话 cwd 是教室工作副本，所以教室 `AGENTS.md`/`CLAUDE.md` 会作为系统指令加载（生产口径）；但**宿主 `agent-instructions` 对多层目录的拼接、以及它和引擎注入之间的顺序/去重**，本次没有单独断言。
2. **只验 `cs-os` 这一个教室、只验"第 1 讲 + open/probe/close 三个相位"**。
   `check` / `review` / `answer` 相位、`n_turns`（第 5/10/15 回合）路径、`on_demand` 块、换讲（`current_lesson` 变化后 `curriculum.map` 的"每讲一次"重新注入）**本次都没被压到**。
