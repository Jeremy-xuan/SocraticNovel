## 一 · ① A2 的推导模型：显式建模两类运行期动态块

> 📌 **三个新脚本的分工与写盘边界**：两个**只读不写盘**（`frequency-parity.mjs`〔A27〕、
> `dynamic-blocks.test.mjs`〔A28〕），一个**只写 `$TMPDIR`**（`a2-replay.mjs`〔A29〕，写目标已在
> 写足迹名单里登记〔A20〕〔A21〕）。三个都**不在流水线运行路径上**（人手工跑）。

### 1.1 先把规则读准（读引擎源码得出，只读）

这两类块**不经过** manifest 频率规划器〔A30〕——它们由引擎在**回合边界**自产（收集处见〔A32〕），
块 id 由代码**拼字符串**得出（两个前缀常量〔A03〕〔A04〕，判定与取值见〔A01〕〔A02〕）。逐条规则如下（每条的源码锚点见旁挂锚点表）：

**① `prep-list:<讲次>` · 备课清单**（"这一讲预先备好了哪几段动画"）

| 维度 | 规则 |
|---|---|
| 出现条件 | 教室启用了动画（`classroom.yaml` 顶层 `animation.enabled === true`）**∧** 本讲有备课条目（`prep.items` 里 `lesson === 本轮讲次` 的条数 > 0，条目按讲次取见〔A43〕）**∧** 这一讲**还没发过**〔A33〕（讲次一变重发，见同处） |
| 数量 | **一讲至多一条**；发过就记下讲次，**讲次一变重发**（变回上一讲也重发）〔A33〕 |
| 时机 | **本轮讲次的第一个回合**（引擎在回合边界的 pre-step 里判，判完就在本回合注入）——**确定** |
| 块 id | `prep-list:L${currentLesson}` —— **讲次不补零**〔A34〕 |
| 可预测性 | 🔴 **完全可预测**：讲次号就是 `runtime/progress.md` 的 `current_lesson`，其值域来自教室 `prep.items[].lesson`〔A43〕 → **逐字比对** |

**② `animation-notice:<任务号>` · 动画就绪通报**（"你上一轮起的／课前预热的那段片子有结果了"）

| 维度 | 规则 |
|---|---|
| 出现条件 | 存在**终态（ready/blocked/failed）且尚未播报**的动画任务〔A37〕 |
| 幂等门 | `task.json.announcedAt`〔A36〕是唯一凭据（落盘、跨回合有效）；引擎**取到就当场标记**〔A38〕 → **同一任务至多通报一次** |
| 数量 | **每条终态未播报的任务各一条**；上界 = **这一讲声明的备课条目数**（预热是这些条目的唯一来源） |
| 任务号形状 | `L<两位讲次>-T<两位回合>-<yyyyMMdd-HHmmss>`，同一秒内冲突时加 `-<n>` 后缀〔A35〕；生成函数见〔A41〕，判据正则见〔A05〕；讲次为空时是 `Lxx`〔A42〕，其判据见〔A06〕 |
| 块 id | `animation-notice:${taskId}`〔A40〕（`source` 上的跨端契约字段见〔A39〕） |

### 1.2 逐维判可预测性：**哪些维度进严格比对、哪些只做等价处理**（本节的要点）

> 判据实现（源码位置）：模型在〔A01〕，条目计数在〔A02〕，前缀常量在〔A03〕〔A04〕，
> 任务号形状正则在〔A05〕〔A06〕，会话级子判据在〔A07〕–〔A14〕，
> 证据可读性折算在〔A15〕〔A16〕。

| 维度 | 可预测？ | 依据（逐条可核） | 本批怎么处理 |
|---|---|---|---|
| `prep-list` 的**讲次与时机** | ✅ | 讲次来自教室 `prep.items[].lesson`；时机是"本轮讲次第一个回合"，由引擎在 pre-step 里**同步**判定 | **进逐回合严格集合比对**，字面比（`prep-list:L1` 就是 `prep-list:L1`，不归一、不补零） |
| `animation-notice` 的**讲次** | ✅ | 任务由"这一讲的备课条目"预热而来 → 任务号的 `L<NN>` 段就是该讲 | **会话级严格比对**（观察到的通报讲次 ⊆ 可能出现的讲次） |
| `animation-notice` 的**条数上界** | ✅ | 每条终态未播报任务一条；来源 = 该讲备课条目 | **会话级子判据**：每讲条数 ≤ 该讲声明的备课条目数 |
| `animation-notice` 的**出现与否** | ❌ | 取决于"那段渲染在**本次会话结束前**有没有变终态"。**两次真跑就是两种事实**：`runs/2026-09-24_150308` 有 1 条、`runs/2026-09-24_152050` 也有 1 条，而更早的 `runs/2026-09-24_135114` **0 条**（`prep:` 段当时还没加） | 不逐回合比；改用"⊆ 可能集合"＋条数上界 |
| `animation-notice` 的**回合号** | ❌ | 通报发生在"任务变终态**之后的下一个回合**"；渲染耗时可长可短 | 不参与比对；改用"通报时刻不得早于任务创建回合"钉住 |
| `animation-notice` 的**时间戳** | ❌ | 任务创建时刻**到秒**，冲突时还带后缀 | 不参与比对（结构上不存在可推导的值） |

### 1.3 🔴 一次**我自己造的假红**：把通报当成"每回合必有"是**过预测**

本批**第一次完整跑**（`runs/2026-09-24_152050`）A2 报红，逐字是：

```
turn 3 实际注入 ["anchor.lesson_ban","anchor.rules","material.current.01","state.progress"]
      ≠ 独立推导 ["anchor.lesson_ban","anchor.rules","animation-notice:L01","material.current.01","state.progress"]
```

**性质判定：假红，而且成因是我自己的模型过预测。** 证据（三条，逐条可核）：

1. 那一跑**确实**有 1 条通报，落在 **turn 2**（`animation-notice:L01-T00-20260924-152106`，
   引擎日志逐字 `动画通报 1 条：L01-T00-20260924-152106=ready`）；
2. 通报**只发一次**：幂等门是落盘的 `task.json.announcedAt`〔A38〕 → turn 3 **不可能**再发同一条；
3. 我第一版的模型把"该讲有备课条目"翻译成"**每一回合**都预测一条通报" → 于是在 turn 3
   期望一条**根本不该存在**的块。**是我推错了，不是插件错了、也不是判据太松。**

🔴 **修法不是放宽，而是把这一维的可预测性判对**：`animation-notice` 的**出现与否**本身就是
不可预测的（渲染有没有赶上会话结束），所以它**不进**逐回合严格比对；但**块本身留在模型里**
（`possibleAnimationNoticeBlocks` → A2 里的"可能集合"），由**会话级**判据比。
**逐回合的严格集合比对仍然施加在** manifest 静态规划结果 ＋ 备课清单（`prep-list`）上。

### 1.4 会话级子判据（把"不进逐回合比对"的那一维钉住）

在 A2 里对**全部**注入做一遍（判据全量落进证据文件〔A09〕）：

1. **形状**：每个通报的任务号必须匹配 `L<两位讲次>-T<两位回合>-<yyyyMMdd-HHmmss>`（可带 `-<n>`）〔A05〕；
   形状不合法（或任务号缺失）即失败〔A10〕；无讲次的形态 `Lxx-…` **单列一条失败**（形状合法但**讲次归属判不了**，不能混过去）〔A06〕〔A11〕；
2. **归属（＝⊆ 可能集合）**：通报的讲次必须落在**本次会话可能出现的通报讲次**里〔A07〕〔A08〕〔A12〕；
3. **数量上界**：每一讲的通报条数 ≤ 该讲声明的备课条目数〔A02〕〔A13〕；
4. **时刻一致性**：通报所在回合必须**晚于**它自己任务号里记的创建回合（`T<回合> <= 通报回合 - 1`）〔A14〕。

这四条合起来把"出现时机不可预测"这件事**约束回一个可判定的形状**。

🔴 **诚实边界（这一维到底还差什么）**：**"该出现而没出现"判不了。** 因为"渲染有没有在会话结束前
变终态"是**运行期事实**，`classroom.yaml` 里没有它的值。所以本判据的方向是
"**观察到的 ⊆ 可能出现的**"，而不是双向相等 —— 若某次会话一条通报都没有，A2 **不会**因此报红
（这是**结构上不可判**，不是"放过"）。A2 的通过文案里**逐字写出**这一点，让读者自己看得见：

```
动画通报：本次会话 0 条（可能出现的是讲 [1]；通报取决于渲染有没有在会话结束前变终态 → **0 条不算失败**）
```
