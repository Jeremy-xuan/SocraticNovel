## §1 ① 夹取：先纠正任务书的一个误判，再夹

### 1.1 任务书的前提与实测不符（这条必须先说，否则会改错东西）

任务书说：*"实测：模型写 `ParamEyeLOpen = 1.3`，读回就是 1.3（引擎不夹、客户端也不夹）"* → 推断"越界值没被夹取"。

**实测（无头读框架，不经浏览器）**：Haru 的 `ParamEyeLOpen` **真实值域是 `min=0, max=2`**〔A38〕。
→ **1.3 在值域之内**，框架不夹、也不该夹；EXPR-4 把"1.3"当成越界值**是误判**（它按"常规 0…1"猜的值域）。

同一批实测还给出两个决定性的数字（13 个模型 / 754 个参数，逐条见 `evidence/expr5/parameter-ranges.md`）：

| 事实 | 数字 | 意义 |
|---|---|---|
| `repeat`（循环）参数 | **0 个** | 框架走的一律是 `getParameterClampValue`（**clamp**），不是 `getParameterRepeatValue`（wrap）→ "渲染器会夹取"这句对这批模型**成立** |
| 值域超出 `[0,1]` 的参数 | **Haru 42 个里 33 个**（`ParamAngleX` ±30、`ParamBodyAngleX` ±10、`ParamArmLB` −1…5…） | 任务书那条兜底"找不到 min/max 就按 **0–1 归一化**夹"**在这里会把合法值改坏**（把 ±30 的角度夹成 1）→ **比不夹更糟**，本轮**不用**它 |

**那真正的缺口是什么**：框架夹取是**静默的**——
`setParameterValueByIndex()` 非 repeat 参数走 `getParameterClampValue()` → `CubismMath.clamp(value, min, max)`〔A10 附近源码在 `live2d-host/vendor/CubismWebFramework/src/model/cubismmodel.ts`〕，
而**面板读数、状态文件、日志都不体现"你要 3、实际是 2"**。于是"面板说已应用 `ParamEyeLOpen=3`"与"模型里是 2"可以**同时为真**，没有任何一处说得出差别。

### 1.2 夹在哪一侧：**客户端（渲染侧）**，四条理由

| 理由 | 说明 |
|---|---|
| **权威值域只有渲染侧有** | `getParameterMinimumValue / getParameterMaximumValue` 是**运行时模型**的方法（Cubism Core 的 `csmGetParameterMinimumValues/MaximumValues` 经框架透出）〔A38〕。**能力发现产物里没有 min/max，`cdi3.json` 里也没有**——引擎侧拿不到权威值域 |
| **描述里那句话的主语就是"renderer"** | 原文 `the renderer clamps them` → 在渲染侧夹，这句话**逐字成立**，不必改描述 |
| **两侧都夹＝两份值域副本** | 引擎要夹就得自带一份快照（产物会过期、新模型没有）→ 一旦与运行时不一致，**状态文件与脸上的值就分叉**，正是本项目反复踩的那类坑 |
| **别的消费者读状态文件读的是"请求"** | 状态文件是**老师要什么**的请求日志；"实际是多少"是**逐模型的事实**，只有渲染侧能给出。故面板把夹取结果**逐条显示**（下条） |

> **🔴 任务书那句"找不到就用 0–1 归一化范围"我没有采用**，理由即上表第 2 行的实测数字（33/42 个参数会被改坏）。这是**有依据的偏离**，不是省事。

### 1.3 客户端怎么夹（显式 + 按次记账）

- 逐参数驱动器的 `setTargets()` 里，对每个 id 先取该参数在**模型里**的下标，再读它的 `min/max`；越界就夹到边界〔A23〕〔A24〕。
- 夹取结果进 `readout().clamped`（`{id, requested, applied, min, max}`）与 `clampRange`〔A25〕；**合法值不记账**。
- 面板把每一条说成一句人话〔A26〕：`夹取到模型值域：ParamEyeLOpen 3 → 2（本模型值域 0…2）`。
- 🔴 **按次**：`setTargets()` 一进来就清空本表〔A24〕——见 §1.6。
- 宿主没暴露值域（框架 API 缺失）时**不假装夹过**：记 `clampRange: "unavailable"`，面板明说"这次没有夹取"。

## §2 ① 工具描述：改前 / 改后（逐字）

**改前**（Path B 那一句，逐字）：

```
Values are plain numbers; the renderer clamps them to the model's own range.
```

**改后**〔A10〕〔A11〕（Haru 夹具上生成出来的逐字，`face` 里含嘴型参数时）：

```
Values are plain numbers; the renderer clamps each one to that parameter's own range in the model and tells you in the panel when it had to change a value. One exception: ParamMouthOpenY belongs to the mouth channel, so `face` does NOT drive it — the renderer skips it and reports that too.
```

（模型**没有**嘴型参数声明时，`One exception: …` 那一句**不出现**——单测钉住了这一点〔A16〕。）

**为什么改**（三条，每条都有依据）：

| # | 依据 | 改动 |
|---|---|---|
| 1 | 夹取**确实发生**，但**要报出来**：框架自己会夹（`getParameterClampValue`），而面板与状态文件都不体现差别；本轮客户端把它变成显式的并写进面板 → 描述补上"会告诉你" | `and tells you in the panel when it had to change a value` |
| 2 | 值域是**逐参数**的（实测 Haru：`ParamEyeLOpen` 0…2、`ParamAngleX` ±30、`ParamArmLB` −1…5）→ 原文的 `them / the model's own range` 容易被读成"整个模型一个范围" | `clamps each one to that parameter's own range` |
| 3 | 🔴 **漏了嘴型通道那一条**：那个参数**不归** `face` 管。实测（EXPR-4 会话 B）模型把 `ParamMouthOpenY=0.6` 写进 `face`，客户端报 `skippedLipSync`，从模型里读回的是嘴型通道当时的 `0.0432` —— **不写清就是"描述与实测不符"** | 新增 `One exception: …` |

> 第 3 条是**本轮唯一判定"描述仍不准"的地方**，按任务书要求逐字给出改前/改后。
> 第 1、2 条属于"把已经成立的事说全"，一并改在同一句里（改一处，不留半句旧话）。

## §3 ② 「面板读的目录」与「引擎写的目录」必须同一个 → 机核

### 3.1 约束形态：**一处声明 ＋ 两侧各自核对**（为什么不能只靠状态文件）

面板按 `__DSH_CLASSROOM_UI_CONFIG__.root`（缺省＝代码常量）读教室文件；引擎按 `config.classroomDir`（缺省＝工作区自动发现）写 `runtime/expression.md`。

**为什么不能"引擎把写的目录写进状态文件、面板读出来比对"**：两边指不同目录时，**面板读的根本不是引擎写的那份文件**——
面板看到的是"还没有表情"，它没有任何途径知道"引擎写在别处"。**文件通道在这种失效模式下必然沉默**。

→ 所以要有**一处两边都能读到的声明**，各自拿**自己那个目录**去比对：

```
                  ┌──────────────────────────────┐
                  │ classroom.config.json（声明）  │
                  │   classroomRoot / portraitModel│
                  └───────┬──────────────┬────────┘
        （绝对路径读）      │              │   （工作区相对路径读）
                  ┌───────▼──────┐  ┌────▼────────────┐
                  │ 引擎（装载时）│  │ 面板（启动时）   │
                  │ 我写盘 = 声明？│  │ 我读的 = 声明？  │
                  └───────┬──────┘  └────┬────────────┘
                    不一致 → 🔴 日志      不一致 → 🔴 面板上一条＋控制台
```

**两侧任一偏离声明就出声**；两边同时偏离到同一个目录（例如都把副本当教室）时**不出声**——因为那时**它们是一致的**，"引擎写了面板看不到"这条失效根本不成立。

### 3.2 声明文件：`clients/classroom-ui/classroom.config.json`

```json
{
  "classroomRoot": "开源线/DSH定制/code/classrooms/cs-os",
  "portraitModel": "Haru",
  "note": "…（改这里＝两侧同时生效）"
}
```

〔A30〕〔A31〕（文件名常量〔A05〕；客户端按工作区相对路径读它，那个常量是〔A17〕）。**为什么放在面板这个包里**：面板是"必须被告知模型名"的那一侧，而引擎本来就已经用**绝对路径**读另一个包里的产物
（`live2d-host/evidence/capability_table.json`）——同一手法，不新增机制。
🔴 **它不进 `package.json` 的 `files`**：客户端按**工作区相对路径**读工作区里那一份，引擎按**绝对路径**读同一份；
进 `files` 只会多出一份**永不读**的副本（实测 `pnpm add file:` 会按 `files` 白名单裁剪安装副本，见 §6）。

### 3.3 引擎侧（装载时）

- 新增配置项 `config.classroomDeclaration`（**绝对路径**；相对路径当场判失败，与 `capabilityFile` 同一口径）〔A04〕。
- 声明文件的**解析**〔A06〕与**读取＋核对**〔A07〕各自一个纯函数／一个 IO 函数（后者可注入 fs，故单测不需要真盘）。
- 装载时读声明 → **realpath 逐字比较**「引擎装载的教室目录」与「声明里的教室目录」〔A01〕〔A09〕
  （🔴 必须 realpath：macOS 上 `/tmp` 是 `/private/tmp` 的符号链接，词法比较会把同一个目录判成两个——`lib/discovery.mjs` 的 FIX-1 已踩过）。
- 结论翻成日志〔A03〕〔A08〕：一致时一句"两侧同一路径"；**不一致时一条带后果＋三条修法的响亮日志**；没配/没读成也**明说"没有机核"**（不静默）。
- 声明还决定**立绘模型名**（见 §4）。

### 3.4 客户端侧（面板启动时）

- 面板启动时读同一份声明（走现成的 `ctx.remote.workspaceFiles.read`，工作区相对路径）〔A20〕，解析用与引擎同口径的纯函数〔A18〕；
  路径可由 `__DSH_CLASSROOM_UI_CONFIG__.declarationPath` 覆盖（换部署／取证用）〔A21〕。
- `loadClassroom()` 里做一次自检〔A27〕：`checkDeployment()`〔A19〕比「面板有效教室根 / 有效模型名」与声明，
  结论进快照（`data.deployment`）；不通过时**面板顶部出一条报警块**〔A28〕并**在控制台留一条**〔A27〕。
- **不通过才显示**：通过时**不出声、不占地方**（避免"天天报没事"）。
- 声明读不到/写坏了 → `unreadable`，也出声（**"没核成"不等于"没问题"**）。

### 3.5 验收：故意不一致 → **两边都报警**（原文）

**做法**：声明指**副本 A**、引擎的 `--patch classroomDir` 指**副本 B**（引擎侧）；面板注入 `root`＝副本、`declarationPath`＝**真声明**（声明指真教室）（面板侧）。

**引擎侧原文**（真会话，隔离 DSH_HOME，cordis 日志桥捞取）：

## §4 ③ 立绘模型名：一处声明、两侧读

### 4.1 落点与优先级

| 侧 | 从哪来 | 优先级 |
|---|---|---|
| **引擎** | 声明的 `portraitModel`〔A02〕 | 声明 > `config.expression.model`（两者冲突时**以声明为准并出声**〔A08〕） |
| **面板** | `declarationSync().portraitModel`〔A22〕 | 页面注入 `__DSH_CLASSROOM_UI_CONFIG__.model` > 声明 > 代码常量 `DEFAULT_MODEL` |

🔴 面板**先读声明再装载立绘**〔A29〕——不先读就会"先用默认模型加载一遍、再换一次"（画面闪一下，
   而且"改一处模型名两侧生效"这条验收会看到两次装载）。

**面板为什么保留"页面注入优先"**：注入是**显式的、单页的**覆盖，取证脚本与 `test/panel.test.mjs` 都靠它切模型；
但它一旦与声明不一致，面板会**出声**（`modelOk: false`）——那种错位是静默的（引擎按声明挑清单、脸上是另一个模型），不许不响。

### 4.2 「改模型名」要动几个地方：**2 处 → 1 处**

| | 改前 | 改后 |
|---|---|---|
| 引擎 | profile 的 `config.expression.model` | —— |
| 面板 | 客户端代码里的 `DEFAULT_MODEL`（或页面注入） | —— |
| **声明** | —— | `classroom.config.json` 的 `portraitModel` |
| **合计** | **2 处**（且靠人记得同步；不同步＝静默错位） | **1 处** |

> profile 里仍要写的只有**路径类**配置（`capabilityFile`／`classroomDeclaration` 的绝对路径）；
> **模型名本身**不再出现在 profile 里——profile 的那一项已被删除，冲突时会出声（§4.1）。

### 4.3 验收：改一次模型名，两侧同时生效

**只把声明里的 `portraitModel` 从 `Haru` 改成 `Mao`**（其余一个字不动，profile 里**没有** `expression.model`）：

| 侧 | 观测 | 结果 |
|---|---|---|
| 引擎 | 装载日志 `部署声明：立绘模型 Mao（两侧都读这一处）` ＋ `表情通道已启用：模型 Mao｜命名表情 8 个（exp_01…exp_08）｜参数 132 个…` | ✅ 清单跟着换（Haru 是 42 参数 / `F01…F08`） |
| 面板 | **不注入** `model`，只把 `declarationPath` 指到同一份声明 → 运行时模型**参数个数 = 132** | ✅ 面板装载的也是 Mao |

（面板那一侧另有 node 侧断言〔A35〕：声明说 Mao → `modelName()` 返回 `Mao`；注入 Haru → 注入优先且自检报 `modelOk:false`。）

## §6 装载纪律（逐条）＋ 本轮新踩到的三个坑

| 要求 | 实际 |
|---|---|
| 隔离 `DSH_HOME` | ✅ `/tmp/expr5-dsh-home`（`cp -Rc` clonefile）；真 harness **只**被动读过（见下面第 1 个坑的如实交代） |
| `plugin rm` ＋ `add file:` | ✅ 在**克隆的** profile 上对 `classroom-ui` 与 `socratic-engine` 各做了一次 `remove` → `add file:<工作区路径>`（两个 profile 都做） |
| 逐文件 sha256 核对 | ✅ 引擎 **24/24 SAME（DIFF=0）**（`rm`＋`add file:` 之后安装副本只剩 `files` 白名单里的文件，见坑 2）；客户端 **319/319 SAME（DIFF=0）**（最后一次改动后又显式 `rsync` 了一遍，保证跑的是最终代码）；**核对脚本 `/tmp/expr5-sha-verify.sh`** |
| 不许装任何 `@deepseek-ai/*` | ✅ 未装；`add` 只装了自家两个 `file:` 包 |
| 不许 git commit／push | ✅ 未执行任何 git 写操作（本工作区也不是 git 仓库） |
| 不许新增依赖 | ✅ 未改任何 `package.json` 的依赖项、未跑 `install` |
| 不许碰 web／desktop profile | ✅ 只用了 `socratic-headless`（真目录只读）与**克隆**的 `socratic-dev` |
| 不许碰 `live2d-host/**`、`classrooms/**`、`skills/**`、`tools/**`、`acceptance/**` | ✅ 全部只读；`live2d-host` 只被**读**（值域探针读 Core 与框架源码、`run-capability` 产物只读） |
| 判改动只用 sha256 | ✅ §9 全用 sha256（mtime 只当线索） |

### 坑 1（🔴 最重要）：`DSH_HOME=…` 前缀**并不能**隔离——环境里本来就有它

**实测**：本脚本通常在**一个 DSH 会话内部**被调用，那种环境里 `process.env.DSH_HOME` **本来就指向真 harness**
（实测值 `…/dsh-desktop/harness`）。而 EXPR-4 报告的跑法写的是 `DSH_HOME=/tmp/expr4-dsh-home … node run-session.mjs`——
若脚本内部按 `process.env.DSH_HOME ?? '/tmp/…'` 取默认值，**那个前缀永远不生效**，脚本会**静默地在真 harness 上跑**：
真 harness 的 profile 里那份插件是**改动前的旧副本**（`file:` 硬链接被 `edit` 打断，项目已有教训），
于是表现成"**改了代码却毫无效果**"——本任务连续 4 次会话都跑了旧引擎，最后靠"模块顶层打印 `import.meta.url`"才定位。
→ 处置：脚本改成**硬判据**（`DSH_HOME` 不含 `expr5-dsh-home` 就**拒绝运行**）〔A37〕，并在命令里显式导出。
→ **如实交代**：那 4 次未隔离的会话把 **session 记录写进了真 harness 的 sessions 目录**
（`…/harness/sessions/--Users-…-大学申请--/session-{acfa1bd7,70e2c4b9,1d586cf8,…}`）；
**未改真 harness 的任何 profile 配置、未写任何教室文件**（引擎的写盘目录来自 `--patch`，指向工作区内的副本）。

### 坑 2：`pnpm add file:` 会按 `package.json` 的 `files` 白名单**裁剪**安装副本

**实测**：`remove` ＋ `add file:` 之后，克隆 profile 里 `socratic-engine` 只剩 **24 个文件**（`files` 里列的 `index.mjs`/`lib`/`README.md`/`cordis.patch.yml`），
`test/`、`接线说明_*.md` **全没了**；`classroom-ui` 只剩 **7 个**（`lib/index.js`、`lib/client.js`、`cordis.patch.yml`、`README.md`、`vendor`）。
→ 影响：**运行期代码一字不差**（DIFF=0），但"安装副本＝工作区副本"这个假设**对未列入 `files` 的文件不成立**。
→ 本轮的处置：`add` 之后**再显式 `rsync` 一次**（两个包都做）——引擎那侧刻意**没有再 rsync**（保留"pnpm 装出来长什么样"这个事实，
   而 `index.mjs`／`lib/**` 已逐文件 DIFF=0），客户端那侧 rsync 是为了把**最后一次编辑**送进去（`file:` 安装的硬链接会被 `edit` 打断）。
→ 顺带说明为什么 §3.2 的声明文件**不该**进 `files`（进了也只是多一份永不读的副本）。

### 坑 3：探针文件**不能躺在别的插件包里**

第一次起 `socratic-dev` 直接失败：

```
client-modules: package classroom-ui resolves from multiple active Loader sources:
"classroom-ui" from …/profiles/socratic-dev/, "…/classroom-ui/tmp_expr5/log-bridge.mjs" from …/profiles/socratic-dev/; remove one entry
```

原因：日志桥 `.mjs` 直接躺在 `classroom-ui/` 目录树里 → 客户端 `client-modules` 注册表按**最近的 `package.json`** 认包
→ 同一个 `classroom-ui` 被两个 Loader 源解析 → 冲突。
→ 处置：探针挪进**自带 `package.json`** 的 `tmp_expr5/probe/`〔A39〕。

### 坑 4（小）：`pkill -f "port 4399"` 会**杀掉自己**

把 `pkill -f "port 4399"` 与"启动 `--port 4399`"写进**同一条命令**时，pkill 的命令行里也含 `port 4399` → 自杀（实测 exit 1）。
→ 分开两条命令；停后台实例用 `job_kill`。
