## 0. 一句话结论

1. **N1.5 的结论是 `ctx.llm.stream()`，不是 subagent。** 决定性的一条是 `startActivation` **要求传进来一个「活着的父 agent 对象」**（`dsh-subagent/lib/index.js:3046`：`if (this.ctx.get("agents")?.get(spec.request.parent.id) !== spec.request.parent) throw … UNAUTHORIZED`）——日记的触发点（收课相位 / 闲置 2 小时）恰恰是**父回合已经结束**的时候，这条路要么逼引擎长期握着 agent 引用，要么在会话卸载后直接失败。
2. **N1 真的在真宿主里跑通了「读文件 → 调模型 → 写文件」**：隔离 profile `lane-n` + 本机 mock，一次运行 21 ms 写出 `runtime/diary.md` 与幂等账本，`status().ok === true`。**并且这一路上没有创建任何会话**——实测「跑完一个有模型调用的日记」前后 `~/.dsh/sessions/--private-tmp--` 的目录数 **delta = 1**（那 1 个是 headless 主会话本身），日记 **0 个**。
3. **N1 的 AC 四种情况全部既有单测、也有活体验证**：成功 / 模型报错（`MODEL_ERROR`，`finishKind=error`）/ 超时（`TIMEOUT`，实测 2007 ms 到点返回，不靠适配器肯不肯停）/ 输出格式不合法（`INVALID_OUTPUT`，`reason=NOT_JSON`）。四种都同时落进 `runtime/.narrative/agent-runs.jsonl` 与 `status().lastError`，没有一条走「返回 null / 当成功」。
4. **N2 的幂等与写法校验都是确定性的**：键＝`sessionId + lesson`（账本 `runtime/.narrative/diary-ledger.jsonl`）；日记正文 **> 120 字直接判 `INVALID_OUTPUT`，不截断、不补默认值**；字数按 **Unicode 码点**算。活体验证里第二次触发同一节课 → `state: 'skipped'`，`diary.md` 里只有一条。
5. 🔴 **「不许让日记 agent 知道有读者」这条是用机器守卫住的，不是靠自觉**：面向日记模型的文本只在一个文件里产出（`lib/diary.mjs` 的 `buildDiarySystem` / `buildDiaryPrompt` / `describeSchema`），`test/diary.test.mjs` 有一条测试断言这三段拼起来**不许命中** `读者/观众/面板/展示给/给别人看/有人会看/会被看到/公开/学生/同学`。活体上抓到的日记请求里，**系统位 0 命中**（命中只出现在教室自己的文件内容里，见 §5 的边界说明）。
6. **一个真 bug 是活体验证抓出来的**：第一版把新日记**接在整个文件末尾**，结果掉到 `diary.md` 那句「参考口吻（不是模板，别照抄）」**下面**去了，读起来像它的注解。改成「插在最后一条条目之后、页脚提示之前」，并补了 3 条单测锁住这件事（§4.5）。

## 2. N1.5 调研：三个候选与三条依据

**限时内做的是「读安装版源码 + 在真宿主里实测」**，不重做契约附二已经给出的结论，只验证并选一个。

### 2.1 候选 A：`ctx.subagents.startActivation({ delivery: 'caller' })`

| 项 | 实测到的事实 | 出处 |
|---|---|---|
| 能力存在 | `async startActivation(spec)`；`spec.childId` 需要 local backend（`provider.prepareContinuable`） | `dsh-subagent/lib/index.js:3037`、`:3039` |
| 子会话不进会话列表 | 子会话 `meta.origin = 'subagent'`；前端 `sessionVisible()` 第一行 `if (session.origin === "subagent") return false` | `dsh-subagent/lib/index.js:355`、`dsh-client-ui-workspace/lib/client.js:965-966` |
| 🔴 硬门槛 | **必须传一个「活的父 agent」**：`if (this.ctx.get("agents")?.get(spec.request.parent.id) !== spec.request.parent) throw new SubagentError(…, "UNAUTHORIZED")`；后面还有 `assertAdmitting(parent)` | `dsh-subagent/lib/index.js:3046`、`:1395` |
| 上下文不是空的 | `childSessionMeta()` 把父的 `agentPreset` 复制进子会话（`const agentPreset = selectedPreset ?? parent.ctx.get("agentPresets")?.composedPreset(parent.ctx)`） | `dsh-subagent/lib/index.js:347-357` |

### 2.2 候选 B：`ctx.llm.stream()`

`LlmRuntime.stream(options: GenerateOptions)` 是**插件可直接调**的公开面；`GenerateOptions` 明确为「手搓一次性调用」留了位置——`system` 是「one-shot callers 的系统位」，且注释写着 *"a hand-built one-shot may include identity-free user inputs"*（`dsh-llm/lib/types/index.d.ts:433`、`lib/types/types.d.ts:506-527`）。流里带 `usage` 与 `finish`（`kind ∈ stop | tool-calls | max-tokens | aborted | error`，后两者带 `failure`）。

### 2.3 候选 C：`ctx.workflowEngine.start()`

`dsh-workflow` 只是一个 **Service Definition（seam）**，真正干活的 `dsh-workflow-ptc` 在 `:331` 调 `this.subagents.startActivation({...})`、在 `:644-645` 要求 `request.parent`。也就是说**它是「subagent 的扇出编排」，不是另一条更轻的通道**，并且把候选 A 的硬门槛原样继承过来。

### 2.4 三条依据（选 B）

| # | 依据 | 为什么它对 N1 是决定性的 |
|---|---|---|
| 1 | **门槛**：A/C 都要求「精确的活父 agent」（`dsh-subagent/lib/index.js:3046`）。日记的触发点是**收课相位之后**与**闲置 2 小时之后**——父回合早已结束。要满足它，引擎就得在相位切换的瞬间把 agent 对象抓出来并长期持有，会话卸载/重开就断。B 只需要 `ctx.llm`，**任何时候都能跑**。 | N1.3「异步、不阻塞课堂回合」的下限是「回合结束后还能跑」，A 在这一点上最脆 |
| 2 | **上下文**：A 的子会话继承父的 `agentPreset`（同上 `:347-357`），教室工具与教学系统提示会一起进日记上下文——这与 N1.1「输入 = 本次需要的文件 + 任务说明」直接冲突，也让「日记 agent 以为自己在写私人本子」更难守住。B 手搓 `messages`，连 `tools` 都不传（单测里有一条断言 `llm.calls[0].tools === undefined`）。 | N1.1 与 🔒 两条都指向「上下文必须是空的、且只有我要的东西」 |
| 3 | **可测与可证**：AC 要求四种情况都用替身覆盖。B 的替身就是一个 `{stream()}` 对象（`test/fake-llm.mjs`），55 项测试离线跑完 0.45 s。A 要造「活父 agent + 注册 provider + 会话持久化」，单测基本不可能；而且 A 的「不进会话列表」是**靠前端过滤补上的**，B 是**根本不存在会话**——本机实测「跑完一次有模型调用的日记，会话目录数 delta=0（相对主会话）」，这是更强的证据。 | AC 与 N1.3 都要证据，不要承诺 |

**结论**：N1 用 `ctx.llm.stream()`。A 与 C 留作将来的「需要多步 tool-use 的子代理」场景，不进这一轮。

## 3. N1 实现

### 3.1 一次运行的形状

```
spec = { task, system, prompt, inputs[], root, schema, model?, timeoutMs?, signal?, apply? }
  ↓ ① resolveRoute(task, model)            —— 四档取值，取不到抛 ROUTE_MISSING
  ↓ ② readInputs(inputs, root)             —— 逐字读盘，包成 <<<FILE label … FILE label>>> 块
  ↓ ③ prompt = prompt + 文件块 + describeSchema(schema)   （确定性拼接，不看内容）
  ↓ ④ llm.stream({ provider, model, system, messages, signal })  —— 唯一一条 user 消息
  ↓ ⑤ decodeStructured(text, schema)       —— 不合法即 INVALID_OUTPUT（不截断/不补默认值）
  ↓ ⑥ apply(value, { root, task })         —— 任务自己决定写哪些文件、写什么
  ↓ ⑦ return { value, text, usage, writes[], elapsedMs, provider, model }
```

**每次运行都是全新上下文**：运行器**不持有任何历史**（两次调用之间零状态），单测里有一条断言「连续两次调用，每次都只有 1 条 user 消息、且 `tools` 是 undefined」。

### 3.2 失败分类（N1.4）

`lib/errors.mjs` 是唯一错误类型。6 个稳定 code：`MODEL_ERROR` / `TIMEOUT` / `INVALID_OUTPUT` / `ROUTE_MISSING` / `IO_ERROR` / `ABORTED`。

两条出口**都必须走**（`index.mjs` 的 `runDiary` 里同一个 `catch` 分支）：

1. `runtime/.narrative/agent-runs.jsonl`：一行一次运行，成功/失败/跳过都记，含 `code`/`message`/`detail`。
2. `status().lastError`：面板要读的只读出口。返回值是**深冻结**的拷贝（单测里试着改它 → 抛错，且内部值不变）。

`ok` 的判据只有一条：**最近一次跑完的运行没有失败**。`lastError` **不会被后来的成功清空**——面板要能回答「上次为什么红」。

### 3.3 超时：自己计时，不靠适配器

`streamText()` 同时做三件事：① `AbortController` 挂到 `options.signal`；② 一个计时器与 `consume` 做 `Promise.race`；③ 超时胜出后 `abort` + `iterator.return()` 并抛 `TIMEOUT`。所以**即便适配器完全忽略 signal，服务也不会挂住**。活体验证：把预算压到 2000 ms 对上「永不回包」的 mock → **2007 ms 返回**。

另外，`finish.kind === 'max-tokens'` 单独报一条 `MODEL_ERROR / reason=MAX_TOKENS`——截断的 JSON 一定解析不了，先给出准确原因，别让下游误判成「模型乱写」。

## 4. N2 实现

### 4.1 输入（N2.2）

`collectDiaryInputs()` 收 7 份，缺哪份就如实写「（缺失）」而不是静默省略：

| 输入 | 来源 |
|---|---|
| 这节课的摘要 | `runtime/session_log.md` |
| 这节课的课堂记录 | `runtime/notes.jsonl` —— **只读 JSONL，不读三份 markdown 投影**（契约 K3.5）；按 `lesson` 过滤；`type` 映射成「误解 / 卡点 / 掌握证据 / 群里提的问题」；坏行跳过并计数 |
| 她最近 3 条日记 | `runtime/diary.md` 里解析出的最后 3 条（**不含**文件头与口吻提示） |
| 她是谁 | `characters/komari.md` |
| 她的声音 | `_anchor.md` 的「角色声音速查」段（按标题切，切不到就是「没有这一段」，**不回退成整篇**） |
| 她的世界 | `world/setting.md` |
| 最近群聊 | `runtime/wechat_group.md` |

### 4.2 写法规则不另抄一份

N2.3 说「规则就是 `runtime/diary.md` 的文件头」。所以运行时从那份文件里**抽出连续的 `>` 引用行**，逐字作为系统提示的一部分（`extractDiaryRules`）。文件头改了就跟着改；抽不到 → 抛 `NO_DIARY_RULES`（不拿默认值顶上）。单测直接读**真盘上那份** `classrooms/cs-os/runtime/diary.md` 做断言。

### 4.3 校验是确定性的（120 字）

- 输出契约：`{"text": "…"}`，`text` 必填、`minChars: 1`、`maxChars: 120`。
- **超了判 `INVALID_OUTPUT`，不截断**（N2.3 明写）。121 字与 120 字各一条单测。
- 「字」＝ **Unicode 码点**（`[...s].length`）。理由：`"𠮷".length === 2` 但人读是 1 个字。有一条单测用 120 个代理对字符验证「按码点算才不误判超长」。
- 只剥**一层** markdown ``` 围栏（协议层包装），其余原样；不「尽量解析」。

### 4.4 幂等（N2.1）

- 键 `diaryKey(sessionId, lesson)`；无讲次的课记作 `0`。不同会话的同一讲次＝不同课（有单测）。
- 账本 `runtime/.narrative/diary-ledger.jsonl`，一行一条：`{key, sessionId, lesson, date, at, task, chars}`。
- **写序：先正文、后账本；账本失败就回滚正文再抛。** 反着来会在两次写之间崩溃时留下「记过但没写」的键 → 下次静默跳过 → 一条永不出现的日记且无任何报错——那正是 A6 红线的形状。回滚有单测（注入一个「写账本必失败」的 `write`，断言 `diary.md` 逐字节恢复、账本里没有键）。
- 幂等键**不写进 `diary.md`**：面板用 markdown 渲染，0.2.1 前端把 html 节点**原样转义显示**（契约附二），一条 `<!-- … -->` 会被学生读成乱码。

### 4.5 条目插在哪（活体验证抓出来的 bug）

第一版实现是「接在整个文件末尾」。活体跑完一看：

```
---
（空行）
（空行）
> 参考口吻（不是模板，别照抄）：
> 抽屉卡了一下。……
### 2026-10-21 · 第 99 讲      ← 掉到提示块下面了
回程时浪把浮标推歪了一格。……
```

改成按块的结构化插入：`---` 之后的**条目区**里，新条目插在**最后一条条目之后、页脚提示块之前**；「（尚无…）」占位块丢掉；没有条目时所有提示块都算页脚（第一条紧跟 `---` 出现）。口吻提示**一个字不删**。修完的活体产物：

```
---

### 2026-10-21 · 第 99 讲
回程时浪把浮标推歪了一格。我把它扶正，手在水里停了两秒。

> 参考口吻（不是模板，别照抄）：
> 抽屉卡了一下。按了两下才关上。上次也是这样，没修。
```

补了 3 条单测（第一条在页脚前 / 第二条在第一条之后且在页脚前 / 无页脚时就是纯追加）。

### 4.6 读取出口（N2.4）

`narrative.readRecentDiaries({ classroomDir, limit })` → `{ entries: [{date, lesson, text}], bad }`，按文件顺序（＝时间顺序）取最后 N 条。下一节课注入最近一条＝`limit: 1` 取 `entries.at(-1)`。

### 4.7 兜底触发判据（N2.1）

`isLessonIdleClosed({ studentTurns, lastActivityAt, now })` → `{ closed, reason }`。纯函数，**本包不起定时器**（定时/扫描是引擎的活）。语义按文档措辞：**学生 ≥5 回合** 且闲置 **严格大于** 2 小时（正好 2 小时整不算，有边界单测）。缺时间数据时判「不算」而不是猜。

## 5. 🔒 那条怎么保证的

**做法（三道）**

1. **单一产地**：面向日记模型的文本只有三处，全在 `lib/diary.mjs`：`buildDiarySystem()`（系统位）、`buildDiaryPrompt()`（正文位）、`describeSchema()`（字段说明）。没有第二处，也没有从别处拼进来的字符串。
2. **机器守卫**：`test/diary.test.mjs` 有一条测试，把三段拼起来断言**不许命中** `读者 / 观众 / 面板 / 展示给 / 给别人看 / 有人会看 / 会被看到 / 公开 / 学生 / 同学`。红了就是做错了，不是文案问题。
3. **不传工具**：日记走 `llm.stream` 且**不传 `tools`**，所以不存在「工具描述泄露」这条路。

**写出来的系统位（原文）**

```
你叫小鞠知花。课已经上完了。
现在是收工之后，你把本子摊在膝上，写今天的日记。

日记本第一页上写着这样的规则：
**写法规则**：第一人称、短、不解释、不抒情。……（逐字取自 diary.md 文件头）

你写的时候不做别的事：不解释规则，不复述规则，也不写标题。只写那一段文字本身。
```

**活体验证取到的日记请求（12987 字节）**：`system` 里命中数 **0**。

> **诚实的边界**：在同一份请求的**输入部分**能搜到「读者」和「学生」——但它们来自**教室自己的文件**：`characters/komari.md` 里「结果意外有了读者」说的是她写的网络小说有读者（不是日记有读者），`runtime/session_log.md` 的压缩规则里有「学生」。这些是教室内容（车道 E 的地盘），**不是本包写的提示词**。要不要再收一层由 E 判断；本轮不动 `classrooms/**`。

### 6.2 AC 四种情况（活体）

| 情况 | mock 怎么造 | 实测结果 |
|---|---|---|
| 成功 | `MODE=text` | `ok:true / state:"ok"`，写 2 个文件，21 ms |
| 模型报错 | `MODE=error-diary`（只让日记那次失败） | `MODEL_ERROR`「模型以 error 结束：mock 说这条要失败」，`detail.finishKind="error"`、`failureCode="SERVER"`，**日记 0 条** |

## 9. 给引擎接线时要加什么（具体到函数与文件）

本轮**没有**改引擎。接线需要四处：

1. **装载**：`plugins/socratic-engine/index.mjs` 顶部 `export const inject = ['systemPrompt', 'tools']` → 加上 `'narrative'`（或在钩子里 `ctx.get('narrative')` 判空，二选一）。
2. **收课触发**（N2.1 主规则）：相位切到 `close` 的地方——`classroom_set_phase` 工具处理器调用 `lib/phasestore.mjs` 的写入之后——调
   `ctx.narrative.runDiary({ sessionId, classroomDir, lesson: currentLesson, trigger: 'close' })`，**不要 await `done`**（`handle.done` 永不 reject，浮空安全）。
3. **闲置兜底**（N2.1 兜底）：在 `lib/postclass.mjs:400` 附近的 `agent/turn-stopping` 处理器里加一个扫描：
   `const verdict = ctx.narrative.isLessonIdleClosed({ studentTurns, lastActivityAt, now }); if (verdict.closed) void ctx.narrative.runDiary({ …, trigger: 'idle' })`。
   `studentTurns` 用「`user/message` 且 `source.kind === 'user'`」的事件数（`lib/postclass.mjs` 里已有这个判据）。
4. **下一节课注入**（N2.4）：`classroom.yaml` 加一块注入，内容取
   `(await ctx.narrative.readRecentDiaries({ classroomDir, limit: 1 })).entries.at(-1)`；频率按 K3.4 的口径写（**必须带 `phase:`**，且 `acceptance/lib/asserts.mjs:43-77` 有第二份频率实现，动就得两处同改）。

面板（N2.5，车道 P）：只读 `ctx.narrative.status()` 拿 `lastError`/`recent`，按时间倒序展示用 `readRecentDiaries({ limit: N })`。**本轮未改面板**。

## 10. 我替你做的假设 / 没做到的 / 已知边界

**替你做的假设**

1. **日记条目的标题行**是我加的（`### 2026-10-21 · 第 3 讲`）。理由：面板要按时间倒序展示（N2.5）、`readRecentDiaries` 要确定性切条，没有标题就只能靠空行猜。**120 字上限只量正文**，不量标题（标题在落盘前由代码生成，模型碰不到）。若你不想要标题，`renderDiaryEntry()` 是一处改动，单测会跟着报出来。
2. **幂等账本放 `runtime/.narrative/`**（隐藏子目录）而不是 `runtime/diary_ledger.jsonl`：不占教室内容命名空间，也不与 K3 的 `notes.jsonl` 混淆。
3. **`maxChars` 按 Unicode 码点**（不是 UTF-16 长度、不是字节）。
4. **闲置兜底的边界取「严格大于 2 小时」**（文档措辞是「超过」）。
5. **超时默认 60 s**（AC 要求收课后 2 分钟内出日记，留余量）。

**没做到的**

1. **没有真凭据下的验证**：全部活体验证走本机 mock。真 provider 下的首个真实日记还没跑过（需要你给一个能用的 profile；我没碰 `desktop` 与别人的凭据）。
2. **面板的错误状态没接**（N1.4 只要求「提供只读状态出口」）：`status()` 有了，但没有远程方法也没有 UI。要接需要照 K4 的 typert Remote 三件套加一个 `classroomNarrative.status(sessionId)`。
3. **跨进程并发不保护**：同进程内按文件串行；两个 DSH 实例指同一教室目录时 `diary.md` 的读改写可能互相覆盖。要修得引文件锁，而那会踩铁律③（见 §7），得先定方案。
4. **`runtime/session_log.md` 整份进提示词**：教室现在 14 行量级没问题；长到几十 KB 时应由引擎按压缩规则先压。
5. **N3/N4（群聊、定时消息）没做**：`runTask()` 是给它们留的通用口子，本轮没有调用方。

**证据留在哪**

`/tmp/lane-n-mock/`（`server.mjs`、`req-*.json` = 每次请求体、`run-*.log`、`live-report.json`）、`/tmp/lane-n-classroom/`（教室副本与三份产物）、`/tmp/lane-n-probe/`（一次性探针）。都是 `/tmp`，**没有进仓库**。
