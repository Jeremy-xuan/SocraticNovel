## 〇 · 先读：相邻项目 R6 是怎么做的，我们照抄了什么

**出处**：`开源线/DSH定制/研究_同类DSH立绘插件_2026-09-24.md` **§七 R6**（第 1490–1505 行）
＋ 其引用的 `同类实现证据/sakiko/tools/check-anchors.mjs`（173 行，**我逐行读过**）。

**它怎么做的（逐字要点）**：
1. **行号只允许出现在文档的「行锚表」里**；正文一律用锚点编号（`〔A07〕`；区间写 `〔A04〕~〔A05〕`）。
2. 表行格式：`| A07 · <说明> | <文件> | <行号> | \`<该行含有的唯一片段>\` |`；片段里 `⏎` 表示换行。
3. **六条判据**：① 文件存在；② 片段在该文件里恰好命中一次；③ 命中行号 === 表里写的行号；
   ④ 正文每个 `〔Axx〕` 都能在表里找到（**悬空引用**）；⑤ 表里每行都至少被引用一次（**孤儿锚点**）；⑥ 表内 id 不得重复。
4. **产物文件特殊处理**：文件列写 `<file>#unescape`，核对前先把 `\uXXXX` 解码（1:1 解码不产生换行 → 行号不受影响）。
5. 退出码：坏 0 条 ⇒ 0，否则 ⇒ 1。
6. 它头部逐字写着**我们要解决的同一个病**：*"文档正文里散写 host.mjs 行号时，任何一次插行都会让一批行号悄悄失准
   （2026-09-20 实测：一个提交在三个位置插了行，只更新了表、正文里约 15 个行号全漂）"*。

**我们照抄了什么**：锚点语法 `〔Axx〕`、六条判据的核心、`⏎` 多行片段、退出码语义、
"锚点找不到就 FATAL，不允许测了个空壳还全绿"这条纪律。

**我们落在什么不同的形态上**（**这是本件的设计增量**，不是照抄）：
1. 🔴 **锚点表是旁挂文件**（`<文档名>.anchors.md`），不是文档内的一个 §。理由见 §一.2。
2. 🔴 **加了"版本"这一维**：表里多一列 `V1`，指向一张**版本表**（文件 → sha256 前 16 位）。
   → 解决"这段代码我引用的是哪个版本"。**相邻项目没有这一列**（它只对行号，不对版本）。
3. 加了**判据 ⑨：正文不得散写行号**（相邻项目靠"人守约定"，我们**用机器抓**）。
   这是本件的**核心增量**——因为我们的病就是"散写"，不是"表写错"。
4. 加了**判据 ⑦ 一行一锚**（同一行号不得被两个锚点占用）与**⑧ 孤儿版本**。
5. **没有抄** `#unescape`（我们目前没有"把非 ASCII 写成 `\uXXXX`"的产物文档；见 §七 未做到项 4）。
6. 加了 `--scan` **病灶计数**模式：不建锚点表也能量出"某份文档散写了多少处行号"。

## 一 · 锚点格式（先定格式，再实现）

### 1.1 语法（机器可解析，逐字规定）

**正文里的引用**（只有这一种形态）：

```
〔A07〕              # 单点
〔A04〕~〔A05〕      # 区间（两端都必须在表里存在）
```

**锚点表**：每份文档一份**旁挂文件** `<文档名>.anchors.md`（例：`README.md` → `README.anchors.md`），内含三张表。
**标题必须逐字**（机核按整行相等查找，写错就报 `missing-heading` ＝ FATAL）——
`## 版本表`、`## 锚点表`、`## 行号散写豁免`（第三张可选，缺了不报错）。下面用**行内代码**给格式，
避免这份报告自己出现二级标题（示例里的标题在真实锚点表里是 `##` 开头）：

`| V | 文件 | sha256 前 16 位 |`（版本表 · 表头）
`| V1 | code/clients/classroom-ui/lib/client.js | 3ee2e80beda97ecf |`

`| 锚点 | 说明 | 版本 | 行 | 片段 |`（锚点表 · 表头）
`` | A01 | applyPhase() 开头 | V1 | 1535 | `applyPhase(state) {⏎					if (state.expressionIndex === null) return;` | ``

`| 文件 | 行 | 理由 |`（行号散写豁免 · 表头）
`| doc.md | 511 | 代码块里的示例，不是引用 |`

（三张表各自前面要有上面那三个逐字标题行。）

**规则**：
- 片段用反引号包住；片段内 `⏎` 表示换行（多行锚点）；片段内**不得含 `|` 或反引号**（含了会被机核报 `bad-row`）。
- `行` 可写区间 `1553-1557`：机核**只按起始行核对**，区间给人读。
- 文件列写相对路径时，机核按 ①仓库根 → ②文档所在目录 → ③**从文档目录逐级向上** 的顺序试（见 §三.4 的真实坑）。
- 版本列必须指向版本表里存在的 `Vxx`（**这就是"引的是哪个版本"**）。

### 1.2 为什么表要"旁挂"，而不是文档内一节

**理由一：能定位"是文档哪一行散写了行号"**。若表在文档内，工具扫描"正文散写行号"时会把表本身
（里面有行号）也算进去 → 必须写"跳过第 N 行到第 M 行"的脆弱逻辑。旁挂后，正文与表是两个文件，**判据干净**。

**理由二：不打扰正文阅读**。我们要改的是"正在用的文档"（README、实现报告），
这些文档的第一读者是人。旁挂 = 正文零负担。

**代价（诚实说）**：多一个文件；引用时要从正文跳一次。**权衡后仍选旁挂**，因为"能机器判"比"少一个文件"重要。

### 1.3 为什么不直接用行号（本件存在的理由）

**三条，都是本仓库已真实发生过的**：

| # | 真实事件 | 后果 |
|---|---|---|
| 1 | 另一路改客户端，行号从 `f269` 飘到 `f279` | **接线说明当场失效** |
| 2 | 皮肤那一路 `lib/client.js` **sha256 变了两轮、行号漂了一次** | 引用不可信 |
| 3 | 🔴 **本件实测**：同一份 `lib/client.js`，13:5x 是 `f0a6356a…`（2144 行）→ 13:57 `10efcc45…`（2302 行）→ 14:03 `3ee2e80b…`（2901 行） | README §3.2 引的 3 处行号**全部失准**（1282→1535、1798→2414、1342→1606） |

**行号本身不是错**，错的是"**把行号写在没有核对机制的地方**"。行号是**会漂的坐标**，
而锚点（片段＋版本）是**自证的坐标**：片段在不在、在哪一行、文件是不是那个版本，**机器能判**。

### 1.4 🔴 锚点表自己会不会漂？—— 会。诚实说清

**会漂，而且一定会漂**。它记的是"**取数那一刻**的哈希＋行号"。源文件一改，表立刻过期。

**但它与散写行号有本质区别**：

| | 散写行号 | 锚点表 |
|---|---|---|
| 源文件改了 | **悄悄失准**（没人知道） | **机核当场报 ERROR**（`version-drift` / `line-drift`） |
| 失败模式 | 静默 | 响亮（非零退出码） |

**换句话说：本工具不消除漂移，它把"静默漂移"换成"响亮报错"**。
这是**有意的**——我们项目里已经有过一次"静默失效"的教训（§三的 `applyPhase` 那句 `return`）。

**本件的四条已知局限（不得当成"锚点表万能"）**：
1. **语义漂移看不见**：片段文字仍在原行、但含义已变（例如函数体被改），机核判不出来。
2. **版本哈希是"整文件"粒度**：文件任何一处改动都让全表变红，**即使你引的那段没动**。
   代价是"假红"，收益是"绝不漏"。**我们选绝不漏**（可加 `--list` 看哪几条其实行号还对）。
3. **不自动修**：报错了要人去重取行号。**刻意不做自动改写**——静默自愈＝下一次静默漂移。
4. **覆盖率取决于人**：没建锚点表的文档，机核直接 SKIP（`--scan` 只量不判）。

## 二 · 工具：一条命令、零依赖、幂等

### 2.1 用法

```bash
# 机核（需要锚点表）
/opt/homebrew/bin/node 开源线/DSH定制/code/tools/anchors/check-anchors.mjs <文档.md | 目录> [--root <仓库根>] [--list] [--quiet]

# 量现状（不需要锚点表）—— 病灶计数
/opt/homebrew/bin/node 开源线/DSH定制/code/tools/anchors/check-anchors.mjs <文档.md | 目录> --scan
```

- **退出码**：ERROR 0 条 ⇒ `0`；有 ERROR ⇒ `1`；用法/目标错 ⇒ `2`（**可直接进 CI**）。
- **零依赖**：只用 node 内建（`fs` / `crypto` / `path` / `child_process`）；**未新增任何依赖**。
- **幂等**：连跑两次输出**逐字一致**（自测第 12 条断言）；**只读**，从不改文档。

### 2.2 报的九类问题（每类都带文件与行号）

| 类别 | 含义 | 报什么 |
|---|---|---|
| `scattered-line-number` | **正文散写行号** | 文档行号 ＋ 散写的原文 |
| `dangling-ref` | **悬空引用**（引了表里没有的锚点） | 文档行号 ＋ 缺哪个 id |
| `orphan-anchor` | **孤儿锚点**（表里有、正文没人用） | 锚点表行号 ＋ 是哪个 id |
| `anchor-id-duplicate` | **id 重复** | 重复的 id 与出现次数 |
| `version-drift` | **代码与所记版本对不上** | 表里记的哈希 vs 现盘哈希 |
| `line-drift` | 行号漂了 | 「表写第 X 行，实际在第 Y 行」 |
| `snippet-not-unique` | 片段 0 次（**锚点失效**）或 >1 次（**锚点不唯一**） | 命中次数 |
| `line-collision` | 同一行号被两个锚点占用 | 抢行的两个 id |
| `orphan-version` / `dangling-version` | 孤儿版本 / 指向不存在的版本 | 是哪个 Vxx |
| `source-missing` / `missing-heading` / `bad-row` | 源文件读不到 / 缺标题 / 行格式不合规 | **缺标题＝FATAL**，不许静默全绿 |

**另有一个真 bug 是"真文档跑"才暴露的**（自测当时用的是 `--root` 绝对路径，没覆盖默认路径）：
3. 不传 `--root` 时 `repoRoot` 是 `null`，`resolve(null)` 抛 `ERR_INVALID_ARG_TYPE` → 工具崩。
