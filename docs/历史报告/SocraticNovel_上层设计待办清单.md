## 先回答：PR/FAQ 到底覆盖哪些？

| 我们审出来的问题 | PR/FAQ 覆盖吗 |
|---|---|
| **发布稿** | ✅ **就是它本体** |
| **竞争对手 / 真实替代方案** | ⚠️ **部分**。写发布稿时会**被迫**回答"为什么它比 X 更好"（so what 测试），内部 FAQ 的"为什么不做成 X"也会碰。**但 Dunford 那第一问（"如果产品不存在客户会怎么做"）不会自动被问到**，而且**市场类别选择** PR/FAQ 完全不管 |
| **内部 FAQ**（成本 / 单位经济学 / 最大失败风险） | ✅ **覆盖** |
| **外部 FAQ** | ✅ **覆盖** |
| **Variable Reward / Investment（留存）** | ❌ **完全不覆盖** |
| **机会层**（用户视角的痛点） | ❌ 不覆盖 |
| **滩头阵地 / 第一个人** | ❌ 不覆盖 |
| **输入指标** | ❌ 不覆盖 |

🔴 **精确表述**：**PR/FAQ 是"暴露问题"的工具，不是"解决问题"的工具。**
写它的时候那些洞会自己浮出来（因为**写不出来**）——但补齐要靠别的方法论。
例：发布稿里可以写"用户第二周就回来了"，但 **PR/FAQ 不会逼你设计"他为什么会回来"**。

## A 组 · 定位与需求（最上层，先讨论）

### ✅ A1 · 真实替代方案是什么【已答，2026-09-19 用户】
**用户原话**：*"如果是我们高中生的话，成体系的学习基本就是机构/网课/公开课或者生啃课本了。gpt 一般不会用来学完整的一门课程，而是用于答疑一些相对琐碎——不过这是我们的..第二曲线？就是 anima tutor 这个。"*

🔴 **结论：替代方案分两条曲线，对手完全不同**

| 曲线 | 客户现在用什么 | 对手 |
|---|---|---|
| **成体系学习**（完整一门课） | 机构 / 网课 / 公开课 / **生啃课本** | 内容供给者（重资产、有品牌） |
| **碎片答疑**（一道题、一个概念） | **GPT** | 零成本的通用 AI |

→ **AnimaTutor 被定位为第二曲线 = 打"琐碎答疑"这个市场。**（详见下方 A2）

### 🔄 A2 · 竞争对手重定位【已讨论，助手判断——待你确认】
**成体系学习这条线，四个对手有一个共同弱点**：

| 对手 | 强项 | 🔴 弱点（我们的机会） |
|---|---|---|
| 机构 / 补习班 | 有老师、有节奏、有压力 | 贵；时间固定；**不可能为你一个人调教材** |
| 网课（录播） | 便宜、有画面、名师 | **被动**——听不懂它不会停；**不能提问**；进度它定 |
| 公开课（免费） | 免费、优质 | **不是为你设计的**（语言/难度/前置都不匹配）；不能提问 |
| 生啃课本 | 免费、权威、可反复 | 枯燥；**卡住没人问**；【原文】"启动学习仍要克服畏难情绪" |

🔴 **共同弱点 = 都不能"为你一个人调整"**：机构是一个老师对 N 个学生、网课是一次录制对所有人、公开课是一个老师对全世界、课本是一个作者对所有人。
**而我们的护城河（专属教材 + 一对一苏格拉底 + 记得你的卡点）恰恰打在这个共同弱点上。**

→ **成体系线的定位一句话**：**"一个只教你的老师"** —— 机构教一群人，网课教所有人，**教材是为你写的，进度跟着你的卡点走**。

**碎片答疑这条线（AnimaTutor），对手是 GPT**：
- GPT 强项：免费、零安装、答得准、**已经在用**
- 🔴 **GPT 弱点（用户 2026-09-19 补充，共四条）**：
  1. **不讲人话——不会按你能够理解的方式讲清楚**（🔴 这条是**功能性**差异，比情感更硬）
  2. 没有情感与场景——问完就走，没有关系
  3. 不记得你的**学习卡点**（它的 memory 是通用偏好记忆，不是学习记忆）
  4. 它的回答是**"展示"不是"引导"**（【原文】把"教"变成了"展示"，你是观众不是参与者）
- 🔴 **第 1 条的根因与我们的答案**：GPT 不讲人话，是因为**它不知道你的理解水平在哪**，只能按"平均读者"讲。而**我们记得你的卡点，所以能判断"该从哪一层讲起"** → **"按你能懂的方式讲" = 诊断能力（B3）× 记忆（D 域）**，而记忆是我们独有的。
  → **这把"情感差异"升级成了功能性差异，而且它直接连到护城河。**
- ⚠️ 残余风险：情感与场景这一层容易被说成花架子，且 GPT 在补 memory
- 🔴 **所以碎片答疑的定位不是"比 GPT 答得好"，而是"比 GPT 更讲得懂你 + 更让你想再来一次"**

**🔴 关键发现：两条曲线在"差异化强度"和"传播效率"上是反的**

| | 成体系学习 | 碎片答疑 |
|---|---|---|
| 差异化强度 | 🔴 **强**（打在所有对手的共同弱点上） | ⚠️ **弱**（只剩情感+场景，GPT 在补） |
| 承诺门槛 | 高（几十小时） | 低（一道题） |
| 传播效率 | 低 | 🔴 **高** |
| 留存价值 | 高（真有用） | 中（高频但轻） |

→ **所以不是"主+次"，是分工**：
- **碎片答疑 = 传播与留存层**（低门槛、高频，负责涨★ 与"第二周还会回来"）
- **成体系学习 = 价值与护城河层**（高门槛、低频，负责"真的有用"与招生官能读懂的那句话）
- **升级阶梯 = 连接两者的桥**

⚠️ **资源风险**：两条线会分散资源（你已经因分散停摆过一次）→ 建议 **AnimaTutor 不做独立产品，而是主仓库里的"碎片模式"**（它自己就已经有"有主线版"和"无主线纯场景版"两个极端）。

### 🔄 A3 · 市场类别选择【已讨论，助手判断——待你确认】
🔴 **关键发现：类别声明和传播素材可以不一致，而且应该不一致。**

| | 选什么 | 为什么 |
|---|---|---|
| **类别声明**（对招生官/用户说"我们是什么"） | **成体系学习** | 差异化最强、最可叙述（"我做了一个能替代补习班的东西"） |
| **传播素材**（用什么吸引人点进来） | **碎片答疑的片段** | 门槛低、有画面、能涨★ |

→ 两者不一致不矛盾：类别是"我们是什么"，传播素材是"我们拿什么吸引你"。

### 🔄 A3-b · 主线选哪条【已讨论，助手判断——待你确认】
**用户的问题**：*"Anima 似乎更加好宣传，但另一条线很明显是更加好的主线。"* —— 产品是不是该选一条主线做核心定义？

🔴 **答案：主线选成体系；但"更好宣传"和"更好的主线"不是二选一，而是「入口」与「主线」的关系。**

**为什么主线必须是成体系（三条理由，按硬度排序）**：

| # | 理由 |
|---|---|
| 1 | 🔴 **护城河决定主线**。护城河是**专属教材**，而**专属教材只在成体系学习里才有意义**——碎片答疑的用户只需要"这道题讲清楚"，不需要"为我生成一套教材"。→ **成体系是唯一能承载护城河的那条线。** |
| 2 | **顺风局 vs 逆风局**。碎片答疑的对手是 **GPT——免费、无限供给、还在快速变强**，这是逆风局；成体系学习的对手是机构/网课/公开课/课本——**重资产、慢、且有一个结构性弱点（不能为你一个人调整）**，这是顺风局。→ **主线选顺风局那条，即使它更难宣传。** |
| 3 | **宣传素材不需要当主线也能拿到**。一段"她按你能懂的方式讲清楚了一道题"的 30 秒录屏就是宣传素材——**但产品体验的第一步也可以是碎片**（"今天想搞懂这个"）。→ **入口是碎片，主线是成体系。** |

🔴 **但这个结构成立有一个前提**：**从入口到主线的引力（升级阶梯）必须真的 work。**
否则用户会**卡在入口不动**——"我搞懂了这道题，走了"。→ 这是 D 组（产品契约）里最关键的一环。

### 🔄 A4 · 滩头阵地【已讨论，用户主张"大学生"——助手判断附下】
**用户原话（两步）**：*"人群选择我觉得是不是反而大学生是最好的卖点？因为首先人群最多容易宣传，第二也有 ddl，第三他们学校也是半自由学习，有空间那 AI 搞自定义学习，第四他们也很愿意接触新事物"* → *"不一定是大学跟不上，很多大学的课程极度死板，这正中我们下怀"*

🔴 **第二步的修正才是战略级的**：

| 表述 | 人群 | 心理门槛 |
|---|---|---|
| ❌ "大学跟不上的人" | 小 | 高（**失败者标签**，不愿意承认） |
| ✅ **"被死板课程困住的人"** | **大（包括成绩好的）** | 低（**结构性抱怨**，有正当理由、愿意表达） |

→ **用户不需要承认"我落后了"，他是在"绕过一门死板的课"。这直接降低 Activation 的心理门槛。**

**大学场景的天然优势**：
- **人群最多**，而且更重要的是——**痛点已被公认，不需要教育用户"你需要这个"**（这是"降维打击"级别的前提）
- **有 DDL**（期中/期末/作业/论文）= 真实且不可协商的时间压力
- **半自由**：大学本质上就是"**老师讲一遍，你自己回去啃书**"——**大学不是学习系统，是"学生被迫自学"的场所**
- 愿意接触新事物；且有付费意愿（我们不做收费版，但意愿是留存信号）

🔴 **实测：这个位置全球空着**
搜 `college course AI study companion`／`textbook explainer AI`／`course material personalized explainer`／`syllabus AI learning` → **最高 124★**（`Blueturboguy07/NitroAI`，而且它是"把讲座/PDF 变成**笔记**"，是笔记不是教学，工作不同）；其余全是 **0–18★**。

#### 🔴 连锁反应：护城河的形态要改

大学生**已经有教材**（权威但难读）→ 需求是"**按我能懂的方式重讲**"，**不是"凭空生成一套教材"**。

| | 原表述 | 修正后 |
|---|---|---|
| 护城河 | **生成**专属教材 | **把任何教材变成属于你的教材** |
| 本质 | **创作**（从零生成） | **翻译**（把别人的教材变成你的） |

🔴 **"翻译"的市场大得多，而且更容易做**：有明确参照物、可验证对错、不需要从零构建知识体系。
技术上正好用上已查过的复用件：**E2 教材导入（4 个成熟开源项目）+ A8 画像 + A2 隐喻映射**。
→ 🔴 **"翻译"才是真正的降维打击：因为每个大学生都有一本必须读但读不懂的书。**

#### ⚠️ 三个风险
1. **大学生是最难留住的人群**——需求是任务导向的（过了这门课就走）。🔴 **这正好打在 B 组（留存）的洞上。**
   🔴 **修正（2026-09-19 用户指出，助手原判断错误）**：我原写"留存设计要围绕一门课的生命周期做，不是长期陪伴"——**这是错的**。
   **正确**：**正因为大学生任务导向，才必须以长期陪伴（情绪价值）为留存目标**。因为靠课程需求的留存**上限就是课程长度**，而且"**搞懂了这个知识点**"本身就是流失时刻（需求被满足 → 用户走了）。
   → 详见下方 **A4-c**。
2. **大学生的替代方案最成熟**——B站/YouTube 网课、往年题、学长笔记、题库、**GPT**；而且**大学生是最会用 GPT 的人群** → 这里是**碎片答疑线与 GPT 正面竞争的地方**。
3. **与"我要申请大学"的错位** —— 其实是加分：**有真实的大学生用户**比"我自己用"强得多（这正是"外部认可"）。

#### 🔴 A4-c · 留存：课程是「锚」，情绪是「帆」？【用户 2026-09-19 提出，**并要求批判性意见——本节是批判，不是肯定**】
**用户原话**：*"我觉得要做到高留存反而最需要搞定长期陪伴，情绪价值比课程更加重要，否则他可能这堂课的这个知识点搞懂了，或者这门课的学分修够了就不回来了，会不会啊？"*
**用户随后补充**：*"这点是我个人的想法，我不确定是否成立，希望你不要直接肯定我的 idea……希望你有批判性意见"*

##### ✅ 先承认对的部分
**"只靠课程需求，留存上限 = 课程长度"这个逻辑成立**——这是任务导向产品的通性。而且"**搞懂了就是流失时刻**"（需求被满足 → 人走了）也是真的。

##### 🔴 但由它推出"情绪比课程更重要"，有四处问题

**问题一：与原作者立场相反（硬证据）**
【原文】逐字：
> *"这个系统的**情感发展只是无固定目的的背景，主线就是学习本身**。"*
> *"当情愫滋长**完全依托学习过程**，渗透进唱和问答的字里行间，无处可寻又无处不在，它反而恒久芬芳。"*
> *"大多数战斗游戏利用的是人的狩猎采集本能，恋爱游戏利用的是性欲的本能，而这套系统则诉诸人对'友谊'、'陪伴'、'同行者'的需要……**要拿它做游戏，它对多巴胺刺激可能不够，但对学习系统来说，它的火候恰到好处**。"*
> *"如果这个系统做成产品，我希望它能向这个方向发展，**而不要去搞战斗、后宫那一套**。"*

→ **原作者认为：学习是主线，情感是背景。** 而"情绪比课程更重要"是**相反的命题**。

**问题二：机制搞混了——真正起作用的是「责任」，不是「享乐」**
【原文】逐字：
> *"因为采用苏格拉底教学法，教学的推进完全以问题驱动，虚拟老师会一直观察我对各种知识的掌握程度，并做出符合她人设的反应（虽然不会责备我鄙视我，但**有些角色我能感到语气下的失望**）。所以，作为学习者，我**还真是挺有压力的，不敢轻易含糊过去**。"*

→ 🔴 **驱动作者的是"不能让她失望"，不是"我喜欢和她在一起"。** 这是**社会责任感**，不是**享乐价值**。
两者都可以叫"情绪价值"，但**机制完全不同、设计完全不同**：

| | 享乐型（用户说的） | 责任型（原作者实际起作用的） |
|---|---|---|
| 用户内心 | "我喜欢和她在一起" | "我不想让她失望" |
| 会不会腻 | **会**（作者亲历，见问题三） | 不会 |
| 可被说成花架子吗 | **很容易** | 不容易（有真实后果——有人看着你） |
| 会不会造成依赖 | **会**（伦理风险，用户可能未成年） | 轻 |

**问题三：作者亲历过「情绪设计过头」的失败（硬证据）**
【原文】逐字：
> *"我曾对我的工作日程做过很多'游戏化'的尝试——征服世界、升级打怪、商业帝国。但我发现，这种设定最终都**沦为无聊的数值游戏，很快就让人失去兴趣——维护游戏系统变得比学习本身更无聊**。"*

→ 失败机制很清楚：**维护成本 > 学习收益**。这是"把情绪/游戏性做成独立一层"的必然结局。

**问题四：忽略了第三种解法（最自然、最便宜的那种）**
留存不只有"靠情绪延长"一条路：
> **靠"下一个任务"自然延长**——一门课完了有下一门；一个知识点完了有下一个。**这不需要情绪，而且它就是学习的自然结构。**

🔴 **所以真正的三分法是**：
1. **靠下一个任务**（自然、低成本、不依赖情绪）← 我们之前完全忽略
2. **靠责任**（"不想让她失望"）← 原作者实际起作用的
3. **靠享乐型情绪**（"我喜欢和她在一起"）← 用户说的，**也是最脆弱的**

1 和 2 可叠加；**3 是危险的**。

##### 🔴 而且有一个两难，这个想法可能就卡在这里
如果"情绪留人"成立，那纯 gal game 的留存应该很好——**gal game 本身留存确实好，但那是因为它把"恋爱"当主线**。
而我们的主线是学习，**作者明确反对搞成恋爱主线**。
→ **所以"情绪留人"这条路：要么变成恋爱主线（作者反对、且偏离学习），要么退成背景（那它就留不住人）。** 这是个真两难。

##### 🔴 最后：没有数据
【原文】逐字：*"这归根结底是个**实证问题，我目前当然还没有数据**，只能谈一谈自己的体验。"*
→ **连原作者都承认没有数据。** 我们手上只有三个单人样本（原作者、p2 的读者、AnimaTutor 设计者），**没有一条留存数据**。

##### 🔴 我提议的替代表述（比"锚和帆"更严格，也更可测）
> **留存的燃料是「责任」——不是"我喜欢她"，是"我不想让她失望"。**
> 而责任的来源是**共同完成过的事**（AnimaTutor：*"感情不是聊出来的，是做出来的"*）。
> → **设计重点不是"设计情绪"，是"让共同做事持续发生"——并且每次都留下能被引用的痕迹。**
> （这正是 D6 角色记忆 / A5 复习叙事化 / A6 卡点→伏笔 存在的理由）

##### 📌 处理方式（**不建议现在定案**）
**用户的怀疑是对的：这件事现在不该草率决定。** 因为：① 没有数据；② 三方样本互相矛盾（原作者 vs 用户）；③ 三种机制可能同时起作用，只是权重未知。
→ **正确动作：不决定"用哪个理论"，而是设计一个能把它测出来的最小实验**（登记进 E1 指标 / B3）。
→ 在那之前按"**成本最低、风险最小**"的默认值走：**先做责任型 + 下一个任务型，享乐型情绪只做背景层**——这也正是原作者的做法，而且是**已被验证过的那个**。

#### 🔴 A4-d · "把所有留存设计都写上"对不对？【用户 2026-09-19 提出，直觉是"有点不太对劲"——**这个直觉是对的，下面说明它哪里不对**】
**用户原话**：*"这可能是一整套组合拳，毕竟任何一个软件的用户留存原因应该都不是极度单一的吧？作者肯定也是责任和喜欢都有，要不不就成 PUA 了吗？我觉得可以把所有的留存设计都给写上？但是感觉这就有点……不太对劲"*

##### ① 责任和喜欢不是两个机制，是**同一个前提的两个面**
两者都来自 **"她是一个真实的人"** 这个前提：
- 她是一个真实的人 → 你会**既**怕她失望，**也**喜欢她
- 她是一个讨好机器 → 你**既不真怕她失望，也不会真喜欢她**

→ 🔴 **所以不需要"都写上"——只需要把"她是一个真实的人"做到位，两者会自动同时出现。**
→ 这也正是 AnimaTutor 那句"**感情不是聊出来的，是做出来的**"的深层含义。

##### ② "把所有留存设计都写上"为什么不对：**方向反了**
| 出发点 | 结果 |
|---|---|
| 从**留存目标**出发 → 堆手段 | 得到**一个没有中心的人**（讨好机器） |
| 从**角色人格**出发 → 问"这样一个人会怎么让你想回来" | **答案自动出来，而且必然是一组（确实是组合拳）——但不是你能挑的那一组** |

→ 🔴 **组合拳是对的，但"选择打哪几拳"的权力在角色手里，不在留存目标手里。**

##### ③ 这也解释了原作者数值化失败的真正原因
不是"数值化本身坏"，是**它脱离了角色**：他先想要"游戏性" → 再加数值系统 → **变成一个没有中心的机器** → 维护它比学习还累。

##### ④ "PUA"这个比喻很准，但准在哪里
**PUA 的问题不是"手段多"，是"手段不一致、被识破"。**
- 一个**真实的人**手段多 → 那叫**丰富**
- 一个**假的人**手段多 → 那叫**套路**
→ **关键变量不是"几种机制"，是"这个角色是否自洽"。**

##### ⑤ 一条可操作的筛选标准（成本）
原作者的失败机制是"**维护成本 > 学习收益**"。所以每个留存机制都要问：
> **这个机制能不能被"课后自动更新"完成？**
> 能 → 留（例："她记得你" = 一次文件更新）
> 不能 → 砍（例：数值化好感度 = 需要平衡、需要维护）

🔴 **这和 Q6 定的"沉浸的度 = 每课后状态更新能自动完成"是同一个判据！** 两处独立推出的判据一致，说明它是对的。

##### ⑥ 组合拳的真正内容是"不同场景下的不同表现"，不是"不同机制"
| 场景 | 你会怎么反应 |
|---|---|
| 她今天心情不好 | 你担心她（责任） |
| 她今天夸你了 | 你开心（喜欢） |
| 她记得你上次的错 | 你不敢含糊（责任） |
| 故事推进到某个节点 | 你想知道后面（好奇） |
| 这门课学完了 | 你想学下一门（任务延续） |

→ **这些全是同一个"人"在不同时刻的表现。**

##### 🔴 结论
**不是"把留存设计都写上"，而是"把'她是一个真实的人'写到足够真，然后留存是它的副产品"。**
这既解决了"不对劲"，也解决了成本问题——**不用维护一堆机制，只需要维护一个人的一致性。**

## B 组 · 留存（🔴 PR/FAQ 不覆盖的那一半，最大的洞）

### 🔄 B1 · Variable Reward：不确定性的部分是什么【已推，助手产出】
**方法论**：Hook Model（Nir Eyal）。Variable Reward 有三类：**Tribe**（他人的认可）／**Hunt**（获取信息）／**Self**（掌控感、精通）。

**先把三类套进来**：
| 类型 | 在我们的场景里是什么 |
|---|---|
| **Hunt** | 今天她会怎么讲？会用什么比喻？（【原文】"**冰面上霜痕勾勒出公式，水面波纹排列成等式**"——这种惊喜） |
| **Tribe** | 她的反应（夸你、失望、在群里讨论你） |
| **Self** | "我自己推出来了"的掌控感 |

**过成本判据（A4-d 第⑤条：能不能被"课后自动更新"完成？）**：三类全部 ✅ 通过（Hunt 来自 LLM 生成＝零维护；Tribe/Self 来自角色文档与进度标记＝低成本）。

#### 🔴 但真正关键的约束来自 A4-d 第②条：**方向**
不能从"留存目标"出发设计奖励，要从"**她是一个真实的人**"出发。所以正确的问法不是"设计什么奖励"，而是：

> **一个真实的人，会怎么让你每次都想再来？**

答案：
1. **她今天的状态不一样**（心情、场景、光线）—— 这是"活人"的天然属性
2. **她对你的反应会变**（因为你上次的表现）—— 这是关系累积的必然结果
3. **她讲的方式会变**（同一个知识点换一种讲法）—— "她今天想到了别的说法"

🔴 **结论：Variable Reward 的内容 =「她的不确定性」，而不是「系统的奖励机制」。**

**筛选判据（一条就够）**：
> **如果这个"奖励"和"她"无关（积分、徽章、签到、抽卡、成就），就砍掉。**
> 理由：那正是原作者失败过的"**沦为无聊的数值游戏**"。

### 🔄 B2 · Investment：用户每次来往系统里存了什么【已推，助手产出】
**🔴 关键区分**：Investment 必须是**用户自己存的**，不是"系统存的"。
- ❌ "系统记得你" = **系统**存的（这是 D 域，不是 Investment）
- ✅ 要找的是"**用户**存了什么"

**候选清单（按深度排序）**：
| # | 用户存了什么 | 成本判据 |
|---|---|---|
| 1 | **他自己问过的问题**（被引用："你上次问过这个"） | ✅ |
| 2 | **他的错题 / 卡点**（变成复习队列） | ✅ |
| 3 | **他的表达偏好**（喜欢什么比喻、讨厌什么讲法） | ✅ |
| 4 | **他给她的回应**（关系推进由他的回应驱动） | ✅ |
| 5 | **他走过的路径**（选过哪条最小路径、跳过什么） | ✅ |
| 6 | **他的目标与截止日**（系统按此排进度） | ✅ |
| 7 | **他的教材**（上传的 PDF → 系统越用越懂他的教材） | ✅ |
| 8 | **他的作品**（笔记、白板、思维导图） | ✅ |
| 9 | 🔴 **他纠正过她**（他发现讲错了 → 记进教材修订回路） | ✅ |

#### 🔴 最深的一种是第 9 条：「你纠正过她」
为什么它最深：
1. 它是用户投入中**最花时间**的一种（发现错误 + 提出修正）
2. 它让用户从**消费者变成共同作者** → **直接对接 Q4（社区项目）**
3. 它产出**可被引用、可被他人受益**的东西（教材改进）
4. **AnimaTutor 已经有这个机制**：【原文】`book_revision_notes.md` —— *"教学过程中会时不时发现可以对教材进行改进的地方……等全部课程学完，我可以把这个文件扔给 Claude Code，让它根据这个来修改教材"*

🔴 **Investment 的核心设计一句话**：
> **让用户每一次来，都往系统里存下"只有他知道的东西"**（他的卡点、他的偏好、他的纠正）。

### 🔄 B3 · "第二周为什么会回来"的机制 + 可测指标【已推，助手产出】
#### 机制：每次课后必须做三件事
> **第二周回来的理由 = 她记得你（B2 的投入被引用）＋ 她今天不一样（B1 的不确定性）＋ 你还没学完（下一个任务）**

| # | 机制 | 说明 |
|---|---|---|
| 1 | **引用** | 下次开场**必须引用上一次的一个具体细节**（你的卡点／你的提问／你答错的地方） |
| 2 | **变化** | 她的状态／场景／讲法**必须与上次不同**（由故事推进驱动） |
| 3 | 🔴 **留钩子** | **永远留一个"下次会讲"的悬念** |

🔴 **第 3 条有原文证据（而且它是免费的）**：【原文】逐字：
> *"她以一篇精彩的回答揭开了 Transformer 的冰山一角，说，'**而这就是我们接下来要学的内容……**'这时，我真的感动到想哭。"*

→ **最强的"下次回来"钩子，成本只是"把下次讲什么提前说出来"。**

#### 可测指标
| 指标 | 定义 | 验证的是 |
|---|---|---|
| **次周回访率** | 首次使用后 7 天内再来一次的比例 | 留存总指标 |
| **跨课程延续率** | 完成一门课后开始下一门的比例 | "**下一个任务**"机制（A4-c 的第三种解法） |
| **被纠正数** | 用户提出的教材改进点数量 | **Investment**（B2 第 9 条） |
| **引用命中率** | 第二次开场是否真的引用了第一次的细节 | 这是**机制**不是指标，应接近 100% |

#### 🔴 最便宜的那个实验（回答 A4-c 的"设计一个能测的实验"）
要验证"责任型 vs 享乐型 vs 任务延续"哪个起作用，最干净的是**三组对比**（A：纯答疑无角色／B：角色只表现友好／C：角色会记得、会失望、会期待）→ 测次周回访率。
⚠️ 但这对一个人的项目**成本太高**。

→ 🔴 **更现实的版本**：**只做 C 组（责任型），然后课后问一句话**：
> **"你下次还会来吗？为什么？"**
一句话的成本，直接拿到定性数据。⚠️ 注意：拿到的是**用户自述的原因**，不是真实原因——但比没有数据好，而且自述原因本身就是**宣传素材**（用户原话比我们的文案可信）。

#### 📌 处理方式（同 A4-c）
**不要现在就决定"用哪个理论"。** 先按默认值走（责任型 + 下一个任务型，享乐型只做背景），**同时埋下上面那四个指标**，用真实数据来决定后面怎么调。

### ✅ D1 · 格式规范的产品契约【已定案】🔴 本组最重要
**① 教室的边界 = 六件套，但分三层交（不是"整套 or 不交"）**
| 层级 | 交什么 | 门槛 | 为什么在这一层 |
|---|---|---|---|
| **L1 角色包** | **一个角色**（人设 ＋ 她的世界 ＋ 她对某学科的场景机制） | 🔴 **最低** | **写一个"我理想中的老师"是创作门槛最低、表达欲最强的事** |
| **L2 教材 + 课程包** | 教材 ＋ 课程表 ＋ 知识点（**隐喻映射内含其中**） | 中 | 隐喻系统**不是独立可交的单元**，它体现在教材怎么讲里 |
| **L3 完整教室** | 角色 ＋ 世界 ＋ 教材 ＋ 课程 ＋ 运行时模板 | 高 | 官方教室的标准 |

🔴 **用户 2026-09-19 更正**：*"社区最方便贡献的应该是自己的角色，其次是教材和课程，隐喻系统是在教材和课程中的"*
→ 🔴 **修正了我原来的错**：我原把"映射包"当最低门槛层——错了。**隐喻映射既需要角色（她的世界）也需要学科（教材），所以它是「角色 × 学科」的结合产物，天然在 L1/L2 内部，不是一个独立文件。**
→ **混搭的自然方式也因此变了**：**用户的角色 × 别人的教材**，或**别人的角色 × 用户的教材**（"我想用这个角色学我的课"是真实欲望）。

**② 能不能混搭：支持，但约束单位是「世界」**
- **官方教室** = 经过验证的整包（保底质量）
- **自由搭配** = 用户可换老师 / 换教材 / 换映射（上限高）
- 🔴 **约束规则**：**同一个世界里的老师、教材、映射可以互换；跨世界不行。**
  → 理由：混搭会破坏叙事一致性（A 的老师 + B 的世界观会打架），**而"世界"是叙事一致性的最小单位**。
  → 实现上：**世界 = 命名空间**。

**③ 质量怎么保证：结构靠自动化，内容靠收录标记**
| 维度 | 谁保证 | 怎么做 |
|---|---|---|
| **结构**（文件齐不齐、格式对不对） | 🔴 **我们，自动化** | **就是 CLI 的 `validate` 命令**（复用 Week 0 要写的那个） |
| **内容好坏** | **社区** | 使用者评分 + **"官方收录"标记**（不做硬门槛） |

→ 🔴 **关键洞察：结构校验正好复用我们本来就要写的 CLI**，等于零额外成本。

**④ 署名与贡献**
- 每个教室/映射包**必须有作者字段**（名字或 GitHub ID）
- 贡献者列进仓库的教室目录
- 🔴 **"被收录进官方目录"本身就是一种认可** —— 比排名更轻、更不伤和气

### ✅ D3 · 碎片化版与长期版：**一套文件，靠"加载深度"区分**【已定案】🔴 D 组最重要的决策
| | AnimaTutor 现状 | 我们 |
|---|---|---|

| 理由 | 那是它的**历史包袱**（初版 vs 成熟版） | **一套文件，按"用户投入深度"决定加载多少** |

|---|---|
| **碎片模式** | 角色核心 ＋ 场景机制 ＋ **最小状态**（**不加载**故事线锚点、终章） |
| **长期模式** | 全量加载（含故事线锚点、终章） |

→ 🔴 **这正是 Multi-Prompt Design 的自然延伸**（"每轮刷新、按需加载"本来就是它的原则）。
→ 🔴 **最大好处**：碎片用户与长期用户**共享同一套角色**，升级时**不需要"换一个系统"**，只是"多加载了几个文件" → **升级阶梯变成零成本**。

## E 组 · 风险与指标

### 🔴 E1 · 用户指标 vs ★ 指标【用户 2026-09-19 提出重心转移——**升为高优先**】
**用户原话**：*"我觉得我们的思考重点还是吸引更多用户，这是比涨 star 更底层更加降维打击的东西。"*

✅ **这个判断成立**，理由有两条：
1. **★ 是代理指标，用户是实质**；
2. **对招生官，"有多少人在用"比"多少★"更可读**——NUS 官方条款字面就是 **"used by many people"**。→ **把重心放到用户上，是同时服务涨★和申请的。**

⚠️ **但要精确化**："吸引更多用户"只是 **Acquisition**。完整链条是：

| 环节 | 我们的现状 |
|---|---|
| **Acquisition**（拉新） | ✅ 有（30 天渠道排期） |
| **Activation**（第一次就获得价值） | ✅ 设计得好（碎片入口，一道题就能得到价值） |
| **Retention**（第二周回来） | 🔴 **没设计**（B 组） |
| **Referral**（用户带用户） | 🔴 **没设计** |

🔴 **真正的"降维打击"不是"吸引更多用户"，是"让用户带用户"**：
- ★ 需要**你去推**（渠道、媒体、Trending）—— 每次都要你动手
- **用户带用户不需要你动手** —— 用户自己就是渠道，而且它是指数
- 而它的燃料恰好是我们独有的：**一段可以分享的课堂对话**（F4 可分享片段）

→ **更精确的说法：★ 是输出，用户是实质，「用户带用户」才是那个降维打击。**

🔴 **由此对 30 天目标的修正建议**：1000★ 保留为**结果验证**，但**重心移到用户层指标**——
**N 个真实用户 / 次周留存率 / 分享率**。
⚠️ **并且：宁可 500★ 有真实用户，不要 1000★ 没人用。** 因为"看起来很酷但没人真用"是最危险的状态——**招生官一旦点进去看"有谁在用"，就露了。**
