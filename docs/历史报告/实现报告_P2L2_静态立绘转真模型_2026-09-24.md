### 1.2 image2live2d —— 我们借的东西（**本轮真的用了**）

**输入要求（`【源码】` `src/image2live2d/core/decompose/sources.py`）**

- 图层目录形态：**文件名必须是 `{order}_{role}.png`**，其中
  - `parse_layer_name()` 逐字要求 `head.isdigit()` 为真，否则 `raise ValueError("layer filename ... must be '{draw_order}_{semantic_role}'")`；
  - `role` 必须**精确等于** `irr/schema.py:SemanticRole` 的某个枚举值（`from_layer_dir()` 逐字 `role = SemanticRole(role_str)`）。
- `SemanticRole` 枚举共 **34 项**（`face_base` / `hair_front` / `hair_side` / `hair_back` / `eye_l` / `eye_r` / `mouth` / `torso` / `neck` / `clothing` …）——**没有"左右侧发"之分，只有 `hair_side`**。
- PSD 形态：走 `from_psd()`，图层名用 `role_from_layer_name()` 的**模糊关键词匹配**（中英日别名、`wear` 前缀优先归类等）。

**输出（`【源码】` `backends/live2d/emitter.py` + `moc3_emit.py`）**

- 无条件写 4 个开放 JSON：`model3` / `physics3` / `motion3`（多组）/ `cdi3`；
- `.moc3` 由**注入的 `moc_writer`** 决定，不注入就**静默跳过**（见 §1.4 的坑）；
- **版本 = v3.00**（`moc3_binary.py:V3_00 = 1`，docstring 逐字 *"Scope: **moc3 v3.00** (version byte 1)"*）。

**它怎么做（带源码路径）**

| 环节 | 源码 | 做法 |
|---|---|---|
| 分层语义 → 角色 | `core/decompose/sources.py:parse_layer_name` / `from_layer_dir` | 文件名即语义 |
| 自动补缺件 | `core/synth/eye.py` / `mouth.py` / `blush.py` | **合成闭眼线**（用眼睛自身的线稿色与粗细画一条浅弧，静止时 opacity=0）与**口腔内部**（由唇线几何与色相推出，静止时隐藏）——docstring 逐字：*"You cannot close an eye that has no closed pose."* / *"You cannot open a mouth that has no interior."* |
| 网格 | `core/mesh/build.py` | 逐部件三角化 |
| 骨架/变形器 | `core/rig/author.py`、`moc3_emit.py:EmitWarp` | **无 deformer 模型**：顶点位置直接由参数 keyform 驱动（IRR 已把动作烘成逐顶点 keyform） |
| `.moc3` 编解码 | `backends/live2d/moc3_binary.py`（读＋写）／`moc3_emit.py:build_moc3` | **从零生成，不需要 Cubism 模板**；docstring 写明关键对齐常数：`DATA_BASE = 0x7C0`、`MOC_ALIGN = 64`、`KEYFORM_ALIGN_PAIRS = 8`（SIMD 对齐，否则在原生 Viewer/VTube Studio 里会散开） |
| 动作 | `core/motion/idle.py` + `drive.py` | 生成 Idle／Blink／Talk／Head_yaw… 多组 motion3 |

**我们借什么**

- ✅ **整个 `.moc3` 生成器**（Apache-2.0，纯 Python，零 GPU，零新依赖）——本轮就是靠它跑通的；
- ✅ **「闭眼线 / 口腔内部自动合成」的思路**——P2L-1 是"新画两张差分图"，它这个做法**不用画师额外出图**，值得回流到 P2L-1；
- ✅ **图层命名规范**（`{order}_{role}`）——我们可以直接拿它当**画师交付规范**。

**明确不借**

- ❌ **不借它的单图分层**：那是外包给 See-through（GPU / Docker / 20 GiB 权重），本机跑不了；
- ❌ **不借 `.inp`（nijilive）那条线**：我们的宿主只吃 `.moc3`；
- ❌ **不借它的 `.cmo3` 导出**（README 自称 "🧪 Experimental — Editor-validation ongoing"）。

### 1.3 psd2live —— 读清楚了，但**本机跑不起来**

🔴 **关键事实（`【源码】` `settings.gradle.kts`）**：

```kotlin
includeBuild("../umamo") {
    dependencySubstitution {
        substitute(module("local.umamo:format")).using(project(":format"))
        ...
    }
}
```

→ **它单独 checkout 编译不了**：依赖的 `format`/`runtime`/`interop`/`render` 四个模块来自
**同级目录 `../umamo`**，而 **`umamo` 不在这个仓库里**（仓库内只有 `docs/`、`src/`、`examples/`、`licenses/`）。
README 里写的 `.\umamo\gradlew.bat -p .\psd2live run` 也印证了"必须先有 umamo"。

**它怎么做（带源码路径）**

- 导出入口 `src/main/kotlin/io/github/psd2live/core/PSD2LivePipeline.kt`（`exportMoc3` 分支）：
  `runtimeBundle` → 取 `.moc3` 字节 → **`Moc3.read()` 重新读回** → `RigIntegrityValidator` 做三道几何自检（中立姿态 / 极端角度 / 变形器镜像对称）。
- **真正的 `.moc3` 写出在 umamo**：`module/interop/src/commonMain/kotlin/org/umamo/interop/moc3/Moc3Sidecars.kt`
  → `Moc3Export.toMocDocument(puppet, version, …)` → `Moc3.write()` → `MocEncoder.bakeFresh()`。
- **版本**：`umamo` 的 `RuntimeTargetMapping.mocVersion()` 逐字给出映射
  （`NoTarget → V53`、`Ayagami → V50`、`Cubism50 → V50`、`Cubism30 → V30`…）；
  仓库示例产物 `examples/ds/moc3-cmo3-output/ds.moc3` 的文件头是 **`4D4F4333 05000000`（v5）**。【实测，已 `xxd`】
- **它不用 Cubism SDK 生成 `.moc3`**：`THIRD_PARTY_NOTICES.md` 逐字 *"it does not embed, include, or redistribute official proprietary Live2D Cubism SDK binaries"*；SDK 只用于"官方渲染一致性对照"（可选）。

**我们借什么**

- ✅ **借它的示例产物当"外部真模型"做交叉验证**——本报告 §四 的 `DS_p2l2` 就是它 `examples/ds` 里那份
  `ds.moc3`（v5），我把它原样装进我们宿主，**渲染 + 嘴驱动都通了**（`changedPixels = 204`）；
- ✅ **借它的 PSD 图层规范当画师交付标准**（31 种语义标签，中日英别名，含"嘴巴必须是最大张口原图""睫毛只画上睫毛"这类可执行条款）；
- ✅ **借它的一条硬约束**：`docs/zh/PSD_LAYER_SPEC.md` 逐字要求 **RGB/8 位通道、背景必须透明、文字/矢量/形状图层必须栅格化、图层样式必须合并**。

**明确不借**

- ❌ **不借它的构建**：要 JDK 21 + Gradle + 一个不在仓库里的 `../umamo`，且 GPL-3.0 ——
  本轮按纪律"先报告再等"，**没有跑**；
- ❌ **不借它的 GUI**（Compose Desktop，只出 Windows Exe/Msi 打包格式）；
- ❌ **不借 `.cmo3`**（我们不需要可编辑工程）。

### 1.4 🔴 一条必须写下来的坑：CLI 不产 `.moc3`，而且**静默吞掉**

`【源码】` 三处连起来看：

1. `__main__.py` 的 `--live2d` 帮助文本逐字：*"JSON-only (model3/physics3/motion3/cdi3) until a .moc3 template is supplied"*；
2. `backends/live2d/moc3.py:write_moc3_from_template()` 在没有 writer 时 `raise NotImplementedError`；
3. `backends/live2d/emitter.py` 的 `build()` 里 `except NotImplementedError: pass` —— **静默跳过**。

→ **直接用 CLI 只会拿到一个"没有 `.moc3` 的 bundle"，不报错、不提示。**
→ 正解：绕开 CLI，注入 `moc3_emit.native_moc_writer`（函数定义在 `backends/live2d/moc3_emit.py` 末尾，docstring 逐字
*"generates a `.moc3` from the IRR **from scratch** — no Cubism template needed"*）。
**这一步是"照着就能写代码"的**，已落在 `scripts/20_convert_moc3.py`。

### 2.1 输入：P2L-1 的分层结果**能用，但必须先改名**

P2L-1 产出 9 层（`torso / hair_back / face / eye_l / eye_r / mouth / side_l / side_r / bangs`）
——**语义对得上 `SemanticRole`，格式过不了 `{order}_{role}` 这一关**。

→ `scripts/10_prepare_layers.py` 只做"改名 + 排序号"，**逐文件 sha256 复核源与目标一致**，
并校验 9 层同尺寸（1024×1024，因为 `from_layer_dir` 用"各层最大宽高"当画布）。【实测】

| P2L-1 层 | → image2live2d role | order |
|---|---|---|
| `hair_back` | `hair_back` | 10 |
| `torso` | `torso` | 20 |
| `face` | `face_base` | 30 |
| `mouth` | `mouth` | 40 |
| `eye_l` | `eye_l` | 50 |
| `eye_r` | `eye_r` | 60 |
| `side_l` | `hair_side` | 70 |
| `side_r` | `hair_side` | 80 |

② P2L-1 为位图路线生成的 `_gen_closed_eye.png` / `_gen_closed_mouth.png` **没有搬**——
image2live2d 有自己合成闭眼/口腔内部的实现（`core/synth/`），搬过去反而会被当成 unknown role 报错。

### 3.4 嘴参数隔离验证（`tools/mouth-iso.cjs`，冻结动画只改参数）

| 模型 | 参数名 | `closedVsOpen.changedPixels` | bbox | **改回后** |

按差异 bbox 外扩裁出、**6 倍最近邻放大**，左右并排（左＝闭合，右＝张开）。
目视结果：**两张都能清楚看到嘴从"闭合"变成"张开"**，且 `DS_p2l2` 张开后能看到**口腔内部的红色**。
**改回后 0 像素差异**＝差异确实只来自嘴参数，不是动画漂移。

### 3.5 文字 → 嘴参数 → 画面（`scripts/40_acceptance.cjs`）

在真浏览器里跑完整链路（选模型 → 点装载 → 冻结基线 → 喂一句 → 按帧采样）：

```
p2l2char: ok=true  pageErrors=[]  lipSync=ok/ParamMouthOpenY
          feed max = 0.344，24 帧里 8 帧非零
          samples = [0.343, 0, 0.304, 0.309, 0.344, 0, 0.263, ...]   ← 标点处的 0 = 停顿闭嘴
DS_p2l2 : ok=true  pageErrors=[]  feed max = 0.344，13 帧非零
```

🔴 **这个脚本我自己踩过一次假阳性，必须记下来**：`#cap` 是**异步**填充的，
`selectOption` 之后立刻读 `textContent` 拿到的是**上一张模型（Haru）**的能力表
——于是第一版报出"p2l2char 有 8 个表情、2 组动作"这种**假结论**。
另外 `#model` 的 change **不触发装载**（演示页源码逐字 `$('load').onclick = () => loadModel(sel.value)`）。
→ 修法已落在脚本里：**显式点装载 + 等日志出现目标模型的 load 行 + 校验下拉框现值 + 日志不含该行就判失败**。

## 四 · 🔴 顺带查出一条**与本次产物无关、但会挡产品**的既有缺陷

### 4.1 现象（三个模型全部复现，含官方 Haru）

演示页点「起 Idle 动作」后，画面**立刻冻住**，日志出现：

```
[frame-error] Cannot read properties of null (reading 'duration')
[frame-stack] TypeError: Cannot read properties of null (reading 'duration')   <- at CubismMotion.doUpdateParameters
```

**实测（6 次连续画布哈希）**：

| 模型 | 装载后（未点任何按钮） | 点「起 Idle 动作」后 | `frame-error` 条数 |
|---|---|---|---|
| `p2l2char` | **在动** | **冻住**（6 帧同哈希） | 1 |
| `Haru` | **在动** | **冻住** | 1 |
| `DS_p2l2` | **在动** | **冻住** | 1 |

→ **不是我们 `.moc3` 的问题**：官方 `Haru` 一模一样。
→ 装载后的呼吸/眨眼**是正常的**（画面在动），坏的只有「起 Idle 动作」这条路径。

### 4.2 定位（源码）

〔H04〕`src/host.js` 的 `update()` 逐字：

```js
const mm = um.getMotionManager();
if (mm.isFinished()) {
  this.startRandomIdleMotion();          // ← 无条件调
} else {
  um.setMotionUpdatedFlag(mm.updateMotion(model, dt));   // ← 下一帧读到 null
}
```

`startRandomIdleMotion()` → `startMotion()` → `getMotionManager().startMotionPriority(g.motions[index], priority)`。
`mm.isFinished()` 与 `startRandomIdleMotion()` 的返回值都**没有被检查**；
一旦 motion 对象为 `null`，下一帧 `updateMotion()` 就抛。

**🔴 这是宿主侧集成问题，不在本任务改动范围内**（任务纪律：不许改 `code/clients/**` 的实现）。
按项目"引用源码位置必须写锚点"的口径，正文只写锚点，行号集中在旁挂锚点表
`开源线/DSH定制/实现报告_P2L2_静态立绘转真模型_2026-09-24.anchors.md`：

- 〔H01〕`src/host.js` `update()` 里 `isFinished()` 为真就**无条件**起 Idle（返回值不检查）；
- 〔H02〕`src/host.js` `startRandomIdleMotion()` —— `idleGroup.count === 0` 时返回 `false`，**调用方不看返回值**；
- 〔H03〕`src/host.js` 真正下发给官方 `startMotionPriority`（`g.motions[index]` 为 `null` 时即埋雷）；
- 〔H04〕`src/host.js` 崩溃所在的 `update()` 方法头；
- 〔H05〕〔H06〕`src/host.js` 渲染循环 `step()` 与其调用点；
- 〔D01〕〔D02〕`demo/demo.html` 的「起 Idle 动作」按钮与其绑定。

### 4.3 对教室的影响（**要说清楚**）

- **装载后的待机（呼吸 + 眨眼）能用** → 教室立绘"静态展示"这一层不受影响；
- **一旦接线去起动作/表情，渲染循环就停** → **所有"会动"的功能都挡在这条后面**；
- 这条**与走哪条路线无关**（位图帧路线 P2L-1 压根不用宿主，所以它没暴露这条）；
- **建议**：把它当成一个独立的修复任务派出去（改 `src/host.js`，加 null 保护 + 检查返回值），
  **不要**在教室侧打补丁绕。

## 五 · 结论：这条路值不值得走

### 5.1 值得 —— 判据是"现有机制复用度"

任务书说得很清楚：**面板与渲染宿主就是按 `.moc3` 建的**。本轮证明了这条路的产物
**能被那套机制原样吃下**，一个改都不用改：

| 现有机制 | 位图帧路线（P2L-1） | **`.moc3` 路线（P2L-2）** |
|---|---|---|
| 能力发现 `parseCapability()` | ❌ 用不上 | ✅ **直接读我们的 model3/cdi3**，判 `ok` |
| 嘴型两条通道（`speak` / `write`） | ❌ 要自己接 | ✅ **`ParamMouthOpenY` 命中 `ok`，喂一句话真的动** |
| 渲染宿主 / WebGL 管线 | ❌ 要换整条 | ✅ **零改动** |
| 物理 / 材质 / 表情 | ❌ 用不上 | ⚠️ **物理已生成（`physics3.json`）、表情为 0**（§六） |
| 换模型不改代码 | —— | ✅ **嘴参数名从模型自声明读，不写死** |
