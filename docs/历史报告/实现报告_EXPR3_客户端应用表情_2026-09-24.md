## §0 一句话结论

引擎那一半（EXPR-1/EXPR-2）早就把「老师这一回合的表情」写成了**三条并列的手段**，但**客户端从来没把它画到脸上**——
所以之前的证据只能证明"工具被调了、状态文件被写了"，**不能证明画面变了**。
本批把缺的那一半补上：**三种手段全部落地 ＋ 每条失败路径都出声 ＋ 画面层有可归因的逐像素证据**。

顺手两处小修都做完并各有对照：① 切深浅色**不再重播**进场动画（对照＝挂载时照常重播）；

## §1 表情指令从哪读（契约）

**唯一通道＝教室的 `runtime/expression.md`**（引擎写、客户端**只读**）。
它是面板读的第 5 个教室文件〔A01〕，格式是「顶部 9 个机器可读键 ＋ HTML 注释 ＋ 给人看的表」，
客户端**按行取值、不解析中文**（与 `runtime/progress.md` 同一手法）〔A02〕。

| 键 | 客户端拿它做什么 |
|---|---|
| `expression_path` | 🔴 **唯一该分支的字段**：`named-expression` / `face-parameters` / `motion` / `-` |
| `current_expression` | 路 A 的取值（命名表情名） |
| `expression_face` | 路 B 的取值（`参数id=值,参数id=值`，引擎按 id 排序；解析口径**照抄引擎自己的 `parseFaceParams`**〔A28〕） |
| `expression_motion` | 路 C 的取值（动作组名） |
| `expression_origin` | `teacher` / `fallback` / `unavailable`——面板显示"谁定的" |
| `expression_emotion` | 兜底依据（老师显式指定时是 `-`） |
| `expression_turn` | **宿主回合号**（见下） |
| `expression_capability` | `ok` / `unavailable` |
| `expression_note` | 只在有问题时出现，一行原因（给人看） |

**三条解析纪律**（都在客户端这一层落地）：

1. **`-` 与"没有这一行"是两件事**〔A03〕〔A40〕：`expression_path: -` 是**引擎的结论**（三条手段都不可用），
   这时**不许再去字段里推断**；只有整行缺失（旧格式）才轮到"按 `named > face > motion` 优先级推断"，
   且面板要**如实标注"推断"**（推断 ≠ 引擎声明的路）。
2. **计划与稳定键分开**〔A04〕〔A05〕：`expressionPlan()` 把文件正文变成"一条可执行的路"，
   `expressionKey()` 给出"只有路/取值真的变了才重设"的判据——**少了它，轮询会把动作/idle 每帧重起一次**。
3. **回合内重读**〔A06〕〔A17〕：引擎现在**每个 pre-step 都重算兜底**，同一个回合里这个文件会被改多次，
   所以面板**不能只在一回合开始时读一次**。做法＝400 ms 轮询该文件（读的是几百字节的小文件），
   按 `expressionKey` 去重后才应用；应用时机接在引擎句柄上〔A18〕。
   🔴 副作用（好的一面）：引擎改成"每 pre-step 重算"之后，老师**在回合中间**改的表情也能在**同一回合**上脸。

**`expression_turn` 的语义（主代理 2026-09-24 定的口径）**：它是**宿主回合号**，
**不是**引擎自己的计数器、**也不是**客户端数出来的回合序号。本批**只原样显示**它（面板写"宿主回合 N"），
**不拿它跟客户端自己数的回合比**——两个来源在"装载后接着上一段会话"的场景里会错开。

## §2 三种手段各自怎么落地

唯一的入口是引擎句柄上的 `applyExpression(plan)`〔A12〕，按 `expression_path` 分支：

| `expression_path` | 客户端做什么 | 失败时 |
|---|---|---|
| `named-expression` | `host.startExpression(名字)`——**先探测再调用**（宿主内建：未命中返回 `false`）〔A32〕 | `false` → **不重试**，面板写"模型 X 没有注册名为 Y 的表情"〔A13〕 |
| `face-parameters` | 逐参数直驱（驱动器每帧在 `onLateUpdate` 段写，见 §3） | 一个参数都没写进去 → 面板写"画面不动（这条路这次等于没生效）"〔A16〕 |
| `motion` | `host.startMotion(组名, 0, 1)`——**取下标 0**（确定性、可复现）〔A33〕 | 组不存在 → 面板写"没有动作组 Y（或该组没有第 0 个动作）"〔A14〕 |
| `-`（三路都没有） | **什么都不做，但必须说清**：把 `expression_note` 常显在讲台区 | 状态 `unavailable` ＋ 原因原样带出 |

**相位那条旧路退位但不删**：引擎给了 `expression_path` 时，表情**由引擎定**（`applyPhase` 只保留"通道"那一半）；
文件不存在时**才**沿用旧的 `PHASE_STATES[phase].expressionIndex`（面板如实写"沿用旧的相位映射"）。

## §3 三条纪律 ＋ 两条新坑：各自的落地位置

### 纪律 ① 先探测再调用
宿主 `startExpression(name)` **未命中返回 `false`**〔A32〕——探测已经内建在宿主里，
客户端**不重试、不猜**，并把失败原因写到面板〔A13〕。

### 纪律 ② 参数直驱前先把本表用到的参数全部清零
落地在逐参数驱动器 `createFaceDriver()` 的 `write()` 里〔A09〕：**每帧两步、顺序不能换**——
① 先把**本表出现过的全部参数**清零（范围＝累计出现过的 id 全集，不是"当前这一条的几个"）；
② 再把每个参数朝目标插值一步。两步在同一帧内完成，所以**渲染看到的永远是插值结果**，
中间那个 0 不会上屏。**写值是绝对值**（`setParameterValueByIndex`），
从根上避开"`addParameterValueById` 是累加的"那个坑。

> 清零范围＝**累计出现过的 id 全集**（客户端能知道的全部）：引擎那张 `faceRoles` 大表在服务端，
> 客户端只看得见写进 `expression_face` 的那些 id——**这一层能做到的上界就是把用过的都清掉**。

### 纪律 ③ 每帧平滑过渡
触发帧**只记目标**，之后每帧 `cur += (target - cur) * 0.25`〔A09〕。
测试用假宿主把这条**钉死**：第一帧写入必须等于 `k` 倍差距（硬切会等于 1）〔A24〕。

### 🆕 新坑一：逐参数那一路必须写在 `onLateUpdate` 那一段
宿主 `update(dt)` 的顺序是 `loadParameters()` → motion → `saveParameters()` → `onLateUpdate()` → `model.update()`〔A31〕。
应用层若在别的时机写参数，**下一帧 `loadParameters()` 会把写入冲掉**（画面永远不动，且不报错）。
落地方式＝挂一个 updater 进 `CubismUpdateScheduler`〔A11〕〔A38〕，执行序取 **650**〔A10〕
（官方枚举里 `Physics = 600`、`LipSync = 700` 之间〔A34〕）。

### 🆕 新坑二：客户端也要过滤 LipSync 参数
引擎侧兜底已排除嘴参数，但**老师显式指定时引擎不排除** → 这一层必须自己兜住：
嘴参数**一个字节都不许写**，被跳过的 id **如实记账并显示**〔A25〕。

### 🆕 参数名形状：驼峰（Haru）与全大写蛇形（官方 Miku）
🔴 **客户端不做任何形状变换**：写值只认**模型自己的 id 原样匹配**（`parameterIndexMap()` 用
`model.getParameterId(i).getString()` 建的全表〔A07〕），匹配不上就**明说不可用**。
另给一条**只用于把话说清**的提示〔A08〕：模型里同形状的参数是谁〔A15〕——
"你要的 `PARAM_EYE_L_OPEN`，模型里叫 `ParamEyeLOpen`，只是命名形状不同"。
测试把这条也钉死：认不出的 id **一个字节都不许写**，且 `shapeHints` 必须报出来〔A26〕。
（引擎侧刚修的那个"正则按全大写写、Haru 驼峰一个都匹配不上、静默落盘成空 `expression_face`"的 bug，
在客户端这一层的对应防线就是上面这两句：**写不进去必须出声**。）

## §5 不支持／非法时面板显示什么

- 常显一行：`表情 · <路>：<取值> · <谁定的> · 宿主回合 N [· 已应用]`，
  行上带 `data-classroom-ui-expression-apply="<status>"`（取值：`absent` / `named-expression` /
  `face-parameters` / `motion` / `named-missing` / `motion-missing` / `unavailable` / `pending`）。
- 有问题时**再加一行说明**（`data-classroom-ui-expression-note="<status>"`）：
  未注册的名字、不存在的动作组、模型里没有的参数（含"同形状提示"）、被跳过的嘴参数、
  "一个参数都没写进去 → 画面不动"、以及"文件里没有 `expression_path` 行 → 按优先级推断"。
- **判据是可断言的 DOM 属性 + 原文**（不是"我看着有提示"）：见 §4.4 的文案表。

## §6 两处小修

### 6.1 切深浅色不再重播进场动画

**病根**：切主题会换掉整份 `state.svg` 字符串（配色变量写进了 SVG），
而重播判据原本挂在 `state.svg` 上 → 用户切主题时**整张图又长一遍**。
**修法**：判据换成**内容键** `drawAnimKey(sessionId, kind, source)`〔A19〕——它只由图本身决定，
**不含任何主题信息**；键没变就**不重播**〔A20〕（并在 `diag` 打开时留一条 `mode:'skipped'` 诊断，
免得"什么都没发生"与"整条链路没接上"看起来一样）。

**对照证据**（真页面、真卡片，判据＝动画自己留下的痕迹，不是"两张截图看起来一样"）：

| 时刻 | `stagger`（真播了几次） | `skipped`（跑了但跳过） | 被藏起来的元素 |
|---|---|---|---|
| 挂载后稳定态 | **1**（对照：**挂载时照常重播/首播**） | 0 | 0 |
| 切深色 | **1**（没有多播） | 1（**确实跑了、确实跳过**） | 0 |
| 切回浅色 | **1** | 2 | 0 |

→ 三个数一起看才成立：`stagger` 不涨＝没重播；`skipped` 在涨＝**这条路径真的被走到了**（不是"没接上"）；
被藏元素恒为 0＝**没有元素被重新藏起来**（重播一定会先藏再长）。
产出：`evidence/expr3/Haru-expression-frozen.json` 的 `drawCard` 段 ＋ `draw-card-light.png` / `draw-card-dark.png`。
单元层另有三条同族断言：内容键**只吃三个参数**（主题不在里面）、换图源/换会话/换图类型都会变〔A39〕。

## §7 ④ 渲染侧那个字段：**没有**，下面是接线说明

**先看现盘**：渲染侧能力发现的产物 `code/clients/live2d-host/evidence/capability_table.json`

**没有参数 id 列表**。→ **字段不存在**，本批**没有改那棵树**（正被另一路改），下面是精确的接线说明。

**要加什么、长什么样、给谁消费**：

1. **加在哪**：`parseCapability()` 的返回值里（`code/clients/live2d-host/src/capability.js`〔A30〕那一段旁边）。
   现成变量就是函数内部已经算好的 `parameterUniverse`（＝ `cdi3.json` 的 `Parameters[].Id`），
   现在只往外回了"个数"。
2. **长什么样**（两种写法都被引擎接受，**任选其一**，推荐第一种）：
   ```jsonc
   {
     // 推荐：带名字，客户端/引擎都能直接显示
     "parameters": [ { "id": "ParamEyeLOpen", "name": "左眼开闭" }, … ],
     // 兼容写法（引擎的兜底分支认它）：
     "parameterUniverse": [ "ParamEyeLOpen", … ]
   }
   ```
3. **给谁消费**：引擎侧 `expressionCapabilityFor()` 的路径 B 分支〔A29〕——
   它先读 `entry.parameters`，读不到再读 `entry.parameterUniverse`；两者都没有 → `paramPath = false`
   → **引擎给不出 `face` 参数**，路 B 在服务端就断了（这正是本批只能用引擎渲染器造状态文件的原因）。
4. **顺带**：`evidence/capability_table.json` 是**构建产物**（由 `scripts/run-capability.mjs` 生成），
   加了字段要**重新生成**它，并把它接到 profile 的 `socratic-engine` 配置 `expression.capabilityFile`
   （**绝对路径**）上——否则引擎的整个表情通道是关的（`capabilityFile` 没配 → `ok:false`）。
   ⚠️ 这两件事**都在本批的树之外**（`live2d-host/**` 与 profile 配置），**本批只写说明、不动手**。
5. **引擎侧的已知修复**（另一路刚做，与本字段独立）：`faceRoles` 的正则按全大写蛇形写、
   匹配不上 Haru 的驼峰参数名 → 已改成"两边做同一形状变换再匹配"，并加了"选了逐参数路却一个参数都写不出 → 明说不可用"的防线。
   客户端这一层的对应防线是 §3 最后一段。
