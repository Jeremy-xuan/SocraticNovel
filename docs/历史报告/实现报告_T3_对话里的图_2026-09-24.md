### 1.5 拿不到的字段（如实写）

| 字段 | 能不能拿到 | 说明 |
|---|---|---|
| 这次调用是**第几讲 / 第几回合** | ❌ 客户端拿不到 | 服务端把它写进了**结果文本**（`第 1 讲 · 第 1 回合`），但那是**给人读的字符串**；客户端没有结构化字段。本插件**不去正则解析它**（解析人读文案＝脆）→ 卡片上不显示讲次/回合 |
| 这张图的**落盘路径**（结构化） | ❌ 同上 | 同上（只在结果文本里） |
| 引擎判过的 `diagramType`（`flowchart-v2`） | ❌ | 同上 |
| **文件是否存在**的独立确认 | ❌ | 本插件**不去读盘验证** `runtime/diagrams/*.mmd` 是否真在（那是引擎的事实，客户端复读一遍只是多一个失败点）；卡片显示的是**入参里的源码**，渲染的也是它 |

> 结论：**卡片上显示的一切都来自入参**（源码 / 图类型 / 标题 / 说明）＋**节点自带的状态**（运行中 / 已完成 / 工具报错）。
> 凡客户端拿不到的，**就不显示**，不去猜、不去解析人读文案。

## 2 · 渲染方案 ＋ mermaid 产物来源通道（★ 核心）

### 2.1 挂载（代码在 `lib/client.js` §8 `apply()` 里）

```js

  name: "tool.call.toolview",
  key: DRAW_TOOL_NAME,                 // = "classroom_draw"，必须与服务端 defineTool({name}) 逐字一致

```

组件同时白拿标准 kit（含 `sessionId`）与 owner props（`block` / `toolName` / `callId` / `cwd` / `inspect`…）——
合并顺序逐字见 `dsh-client-ui-renderer/lib/client.js:637-650`（`{...kit, ...injected, ...slotInjected.props, ...contextual, ...ownerProps}`，**owner 最后＝优先级最高**）。
`inject` 的返回值怎么变成 props：同文件 `:333 runInject` / `:342 bindInjectSources`（非 `hooks`/`keyedHooks` 的键**原样进 props**）。

### 2.2 渲染链路（一句话一条）

1. `block.argsRaw` → `JSON.parse` → `source`（**逐字**，不加工、不截断渲染输入）
2. `workspaceFiles.readAll` 读 vendored mermaid 产物字节 → `Uint8Array` → `Blob("text/javascript")` → `URL.createObjectURL`
3. `<script src=objectURL>` 执行 → 校验 `globalThis.mermaid` 存在（不存在就**抛错**，不静默）
4. `mermaid.initialize({ startOnLoad:false, securityLevel:'strict', theme })` → `mermaid.render(id, source)` → `{svg}`
5. `dangerouslySetInnerHTML: { __html: svg }`（与官方对 Shiki/KaTeX 产物的处理同一口径；`securityLevel:'strict'` 下产物过 DOMPurify）
6. 缓存键＝「主题 ＋ 源码」，**整页级**；**失败不进缓存**（一次抖动不会把这张图永久钉死）
7. 主题跟随官方 `body[data-ds-dark-theme]`（`MutationObserver` 观察该属性）→ `neutral` / `dark`

### 2.3 mermaid 的**浏览器产物**从哪来（本任务的核心难点）

**通道**：与 T5 装载 Cubism Core **同一条腿** —— 全部走宿主已有的 `workspaceFiles` Remote，**不需要服务端开端点、不需要 CDN、不需要打包器**。

| 环节 | 做法 | 依据 |

| 产物放哪 | **随本插件走**：`vendor/mermaid-11.17.2/mermaid.min.js`（写进 `package.json` 的 `files`） | 自包含：换 profile / 换机器 / 断网都能画；不把渲染成败押在网络上 |

### 2.4 🔴 实测踩到的坑：**`mermaid.render` 的第三个参数是「容器元素」，不是「选项对象」**

**这是本轮图一开始画不出来的真正原因**（不是产物的问题、不是通道的问题）。

**症状**（真实会话里，卡片正常出现、降级态正常触发）：

```
这张图在浏览器里没画出来（mermaid 渲染报错）：
Cannot read properties of undefined (reading 'createElementNS')
```

**定位过程**（逐层二分，每步都是可复现的对照）：

1. 先在真实 DSH 页面里把 vendored 产物当经典脚本执行 → `typeof globalThis.mermaid === "object"`，`document.createElementNS` 是 `function` → **产物和文档都没问题**。
2. 再把「用 blob URL 装脚本 ＋ 直接 `render(id, src)`」放进**同一个真实页面**跑 → **画出 11111 字符 SVG** → **通道也没问题**。
3. 于是唯一剩下的变量就是**我给 `render` 传的第三个参数**。做成最小二分脚本 `_t3_mermaid_api_bisect.cjs`，**同一页面、同一份产物、同一段源码，唯一变量＝第三个参数**：

**机理**（读 minified 产物 `dist/mermaid.min.js` 第 3586 行的 `sNt`/`appendDivSvgG` 段可复核）：
`render` 的签名是 `render(id, text, svgContainingElement)` —— 第三个参数被当成**容器**：

```js
let f = ut(document.body), p = i.securityLevel === GMt /* 'sandbox' */, ...;
if (r !== void 0) {                       // r ＝ 我传的那个 {theme:'neutral'}
  if (r && (r.innerHTML = ""), p) { ... } // p=false（securityLevel 是 strict）
  else f = ut(r);                         // d3.select(普通对象) —— 它不是一个 DOM 节点
  pGe(f, e, u, ...)                       // → f.append("div") → this.ownerDocument 是 undefined → 崩
}
```

**修法（两条，都写进代码注释）**：

1. **主题只能走 `initialize({ theme })`**，不能走 `render` 的第三个参数；
2. `initialize` 是**幂等**的配置覆盖 → **每次渲染前按当前主题重设一次**（代价可忽略），`render` 只吃两个参数。

对应代码（`lib/client.js` 的 `renderDiagram`）：

```js
mermaid.initialize({ startOnLoad: false, securityLevel: "strict", theme: mermaidThemeFor(themeName) });
const result = await mermaid.render(id, source);   // ← 只有两个参数
```

**修后实测**：真实会话里 **6.2 秒**画出图（`waitMs: 6244`），卡片读数 `渲染 28–33 ms`，SVG 20 个图形元素、文本节点 `进程A` / `进程B`。

### 2.5 失败怎么降级（**绝不白屏**）

| 情形 | 组件行为 | DOM 标记 |
|---|---|---|
| 入参还没到（`argsRaw` 为空） | 卡片显示标题 ＋ 状态行「运行中」，等源码 | `data-classroom-ui-draw="card"` |
| 入参不是合法 JSON / 没有 `source` | **降级态**：一句原因 ＋「下面是这次调用要画的 mermaid 源码（原样，未截断渲染输入）」＋ 源码块 | `data-classroom-ui-draw="fallback"` |
| 产物没拿到（读盘失败 / 脚本装载失败 / 没挂上 `globalThis.mermaid`） | 同上，原因写「这张图在浏览器里没画出来（…）：<报错原文>」 | 同上 |
| mermaid 渲染抛错（源码非法） | 同上，原因里是 **mermaid 自己的报错原文**（含行号与期望 token） | 同上 |
| 正常 | `<svg>` 画出来；标题 / 图类型 / 行数 / 渲染耗时 / `caption` 都在；源码与工具结果收在 `<details>` 里可查 | `data-classroom-ui-draw="svg"` |

**"渲染输入永不截断"**：`SOURCE_PREVIEW_LIMIT` 只管"要不要折叠显示"，**不管渲染** ——
截断后的图不是老师画的那张图（这是服务端 T3a 的同一口径，客户端照做）。

**为什么 `dangerouslySetInnerHTML` 在这里是合规的**：内容不是用户输入，是 **mermaid 自己渲染出来的产物**，
且 `securityLevel: 'strict'` 下产物过 DOMPurify。官方对 Shiki 高亮产物、KaTeX 产物走的是同一条路
（`dsh-client-ui-primitives/lib/index.js:6937` 逐字 `dangerouslySetInnerHTML: { __html: html }`），
而聊天 Markdown 里的 raw HTML 则被**当纯文本**处理（同文件 `:7215` 逐字 `case "html": return node.value;`）。
—— 这正是 P3 取证件 §2.4 的结论：**要放图不能靠 raw HTML，必须走 keyed 渲染器**，本插件走的正是后者。

### 2.6 界面上的小取舍（写下来免得被当 bug）

- **图按 mermaid 的自然尺寸渲染**：产物 `<svg>` 自带 `width="100%"` ＋ 一个按图形内容算出来的 `max-width`
  （小图只有一两百 px）。这是 mermaid 的默认行为（GitHub / mermaid.live 一样），**没有放大**——
  放大到整列宽会把 12 px 的字放大 6 倍，反而不能看。
- **白底框贴着图**（`alignSelf:flex-start` ＋ `display:inline-block`）：否则 748 px 的列里一张 119 px 的图会缩在左上角、
  白底框空一大片。**图一律白底**（`background:#fff`），因为 mermaid 的浅色主题是给白底设计的；
  深色模式换的是 mermaid 自己的 `dark` 主题，不是给浅色图套滤镜。

内容是 `JSON.stringify({lesson, turn, kind, diagramType, file})`，或者用宿主支持的结构化 content 类型。
客户端侧对应改 `toolResultText` 旁新增一个"取结构化块"的函数即可。**改动点：`index.mjs` 的 `render()` 一处。**

**接法 B（不改服务端）**：客户端**解析结果文本**里的「第 N 讲 · 第 M 回合」。
🔴 **本轮明确不做** —— 解析人读文案＝脆（文案一改就静默失效，正是本项目"静默不生效"的经典坑）。
