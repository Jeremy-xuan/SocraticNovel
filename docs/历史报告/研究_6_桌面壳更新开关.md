# DSH 桌面壳自动更新机制核查（实测清单⑥）

## 0. 结论速览

- 已安装 macOS/Windows 构建使用 `electron-updater`。启动 15–30 秒后首次检查，每 6 小时检查，长休眠后补查。
- 发现更新先提示，不自动下载（`autoDownload=false`）；用户同意后才下载，下载完成后还需明确选择重启安装。
- 当前仓库检索范围内未找到全局禁用自动检查的设置项、配置键、环境变量或定时延后功能。可跳过单一版本，但新版本仍提示；手动检查会再次显示已跳过版本。
- 可一次性安装具体历史版本（含降级），但源码明确恢复 stable `latest` 更新流，说明没有 version pin。不是持续锁定。
- 更新替换完整 desktop 包，包内可同时更新 Harness 依赖；profile 位于 app 外部，架构文档称升级不替换这些数据。但启动阶段仍可能执行 profile/package 维护，不能保证依赖树绝不变。
- 本机 manifest：`dsh-desktop 0.9.1`、Harness `0.1.5-rc.2`、`electron-updater ^6.8.9`。userData 下有 `.updaterId`；未发现 `update-skip.json`、`dev-app-update.yml` 或 Squirrel 命名文件。通用 Electron cache 存在，未证实为 updater 下载缓存。profile 有 package.json 和插件 node_modules 树。
- 建议：归档验证过的 0.9.1 安装包；升级前备份 profile，升级后记录 app/Harness 版本、按规范运行 `dump-config` 并做插件加载/功能回归。真正 pin 需组织级部署控制或派生构建，不依赖 skip。

## 1. 更新机制

[README](https://github.com/dataelement/dsh-desktop/blob/main/README.md) 与[架构文档](https://github.com/dataelement/dsh-desktop/blob/main/docs/architecture.md)说明自动更新面向已安装 macOS/Windows 构建。源码 [update-manager.ts](https://github.com/dataelement/dsh-desktop/blob/main/src/main/update/update-manager.ts) 导入 `electron-updater`，由桌面服务选取更新 feed 和目标版本，使用 generic provider 调用检查。

[update-policy.ts](https://github.com/dataelement/dsh-desktop/blob/main/src/main/update/update-policy.ts)：启动延迟 15 秒 + 0–15 秒随机 jitter；每 6 小时检查；`AUTO_INSTALL_ON_APP_QUIT=false`；只支持已打包的 darwin/win32。系统 resume 后距上次检查满 6 小时则补查。

manager 设置 `autoUpdater.autoDownload=false`。`update-available` 只展示更新；用户接受后才 `downloadUpdate()`；下载完成后明确安装才 `quitAndInstall(false, true)`。`installSpecificVersion()` 临时将 feed 指向所选版本并可允许降级，最后恢复 `STABLE_FEED_URL`；源码注释说明后续恢复 stable `latest` 自动更新，即没有 version pin。跳过版本记录在 `userData/update-skip.json`，只抑制该版本，手动检查会忽略 skip。

## 2. 开关与延后

检查当前 main 的 README、architecture、`src/main/update/*`、`src/preload/index.ts` 和 `update/autoUpdater/autoDownload/checkForUpdates/skip/settings/disable/env/pin/defer` 等词：在这些更新入口未找到全局禁用检查的设置页开关、配置键、环境变量或按日期延后功能。菜单有手动检查，更新卡有接受下载/跳过版本。可延后下载和安装；不可通过现有官方 UI 关闭检查或持续 pin。该“未找到”结论限定于已检查入口。

## 3. 更新粒度与 profile

本机 app manifest 同时列有 `dsh-desktop=0.9.1` 和 `@deepseek-ai/dsh`、`dsh-web` 等 `0.1.5-rc.2` 依赖。因此更新按完整桌面 app 构建发行，包内可随构建带入 Harness 包版本变化；不是 profile 独立 npm 更新。

[架构文档](https://github.com/dataelement/dsh-desktop/blob/main/docs/architecture.md)列出 Electron `userData` 下的 `harness/profiles`、sessions、plugins、workspaces、settings，并称 app upgrades 不替换这些用户数据。按设计替换 `.app` 不会整体覆盖 `profiles/<profile>/node_modules`。但启动阶段可能进行 profile 一致性修复与包状态维护，不代表依赖树绝不变化，应备份和回归。

## 4. 本机核验

读取 `/Applications/DSH Desktop.app/Contents/Resources/app/package.json`：name `dsh-desktop`、version `0.9.1`、`@deepseek-ai/dsh=0.1.5-rc.2`（相关 DSH 包同版）、`electron-updater=^6.8.9`，仓库 URL 指向 GitHub 上游。GitHub Releases API 显示 v0.9.1 发布于 2026-09-20。

只读检查 `~/Library/Application Support/dsh-desktop/`：找到 `.updaterId`；未找到 `update-skip.json`、`dev-app-update.yml` 或名称含 Squirrel 的文件。其他含 `update` 的命中属于 profile 依赖包。`DawnGraphiteCache`、`GPUCache`、`Cache` 等通用 Electron cache 存在，但无证据认定为 updater 下载缓存。profile 下可见 `web/package.json`、`desktop-safe-mode/package.json`、`socratic-dev/package.json`、`web/node_modules` 及 `.generations/live/.../node_modules`。

## 5. Pin 策略

1. 归档验证过的官方 0.9.1 DMG/ZIP，记录来源、校验值、签名/公证状态、desktop 与 Harness 版本；验收窗口内不主动升级。
2. 升级前备份目标 profile 的插件清单、依赖锁定/包清单、node_modules、关键设置；优先在副本或隔离 profile 测。
3. 升级后核对 desktop/Harness 版本，按团队规范运行 `dump-config`，验证插件加载与关键功能；失败时恢复归档 app/profile。
4. 不把单版本 skip 当 pin，不建议删除 updater 文件或改 feed 充当开关；这些不是已证实的稳定控制接口。严格 pin 需组织级部署控制或派生构建/上游正式选项。

## 待确认项

- 本机安装来源及是否存在 MDM/第三方自动替换 app（本次只核查 DSH 自身 updater）。
- 若把 `dump-config` 固化为步骤，命令和导出范围应按插件组现行规范复核。
