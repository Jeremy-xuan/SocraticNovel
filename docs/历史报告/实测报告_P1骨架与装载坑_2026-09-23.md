## §2 🔴 两个装载坑（分发文档必须写，否则第三方插件装不上）

### 坑①：插件不得把宿主核心包装进 profile —— 会造成实例分裂

**现象**：工具调用报 `dsh: UNKNOWN: Cannot read properties of undefined (reading 'prepare')`。
**根因**：`TOOL_RUNTIME_SCHEDULER` 是 `@deepseek-ai/dsh-tools` **模块内定义的 Symbol**（`lib/index.js:2430`），scheduler 挂在 registry 上靠这个 Symbol 查。一旦 profile 里出现**第二份 dsh-tools 副本**，宿主注册的 Symbol 与副本里查的 Symbol 不是同一个 → `registry[SYMBOL]` 为 undefined → 崩。
**触发方式**：为了让插件 import 解析成功，把 `@deepseek-ai/dsh-tools`／`dsh-llm` 装进了 profile（或插件自己的 node_modules）。
**正解**：**宿主核心包一律不装**——宿主有自己的共享解析（实证：用户的 web profile 的 `node_modules/@deepseek-ai/` **只有外围包**：cosmokit、dsh-app-boot、dsh-mcp-client、tool-fs、sandbox 系列、schemastery 等，**没有 dsh-tools/dsh-llm**，而 dsh-memento 照样工作）。
**排查口诀**：`Cannot read properties of undefined` + Symbol 相关机制 → **先怀疑"同一包被装了两份"**。

### 坑②：本地包安装要用 `file:` 或"改完再装"，`link:` 需插件自带依赖

- `dsh plugin add <本地目录>` 默认 **`link:`**（软链）→ 插件从**它自己的真实路径**解析依赖，宿主核心包解析不到 → `ERR_MODULE_NOT_FOUND`。
- 用 **`file:<路径>`** 装成真实包 → 解析走 profile 树／宿主共享解析 → 正常。
- 开发循环建议：`file:` 安装一次，之后**改完把 `index.mjs`／`lib/` 拷进 profile 的安装目录**（`cp -R`）即可，无需每次重装。

### 附：`defineTool` 的最小完整形状（源码实证）

```js
defineTool({
  name, description,
  parameters: {},                    // 参数 spec（每属性 required:true）
  output: {                          // 🔴 必填！缺 output 会报 "reading 'render'"
    schema: { type:'object', additionalProperties:false, properties:{...} },
    render: (args, value) => [{ type:'text', text:'…' }],
  },
  execute: async (args, exec) => ({ ... }),   // 返回须匹配 output.schema（additionalProperties:false 时不能多字段）
})
```

## §4 复现命令

```bash
export DSH_HOME=~/Library/Application\ Support/dsh-desktop/harness
DSH_BIN="/Applications/DSH Desktop.app/Contents/Resources/app/node_modules/@deepseek-ai/dsh/lib/bin.js"

# 单测（纯逻辑，零 LLM）
cd ~/SocraticNovel-wt/plugins/socratic-engine && /opt/homebrew/bin/node --test test/manifest.test.mjs test/injector.test.mjs

# 装进测试 profile（file: 形态）
node "$DSH_BIN" plugin --profile socratic-headless add "file:$HOME/SocraticNovel-wt/plugins/socratic-engine"

# 会话实测（工作区里跑，headless 单发单收）
cd /tmp/snx-probe-ws && /opt/homebrew/bin/node --expose-internals "$DSH_BIN" --profile socratic-headless "请调用 classroom_status 工具并报告返回内容"
```

**环境要点**：PATH 里的 `node` 是桌面版 Electron 垫片，跑单测要用 `/opt/homebrew/bin/node`；headless 启动需 `--expose-internals`（宿主 HMR 插件要求）。
