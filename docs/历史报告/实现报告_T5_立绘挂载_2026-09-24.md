## 1 · 资源通道的取证结论（★ 本任务的核心难点）

**问题**：浏览器半边怎么拿到 Cubism Core 与模型资源？

**结论一句话**：**全部走宿主已提供的 `workspaceFiles` Remote，不需要服务端插件配合、不需要 HTTP 资源端点、没有任何假数据**；**文本走 `read`（按行分页）、二进制走 `readAll`（base64 回字节）**，拿到字节后自己转成 objectURL 喂给只读复用的渲染宿主。

### 1.1 · 两条路（带源码依据）

| 资源 | 通道 | 源码位置 | 关键点 |
|---|---|---|---|
| 教室自己的 `.md` / `.yaml` | `ctx.remote.workspaceFiles.read(sessionId, path, { offset })` | `lib/client.js:259-274`（`readText`） | 返回 `{text, lines, eof}`，**必须循环翻页**直到 `eof`；中途出现"返回 0 行却未到末行"→ **抛错**（不静默截断） |
| Cubism Core `live2dcubismcore.min.js` | `readAll` → `Blob` → objectURL → `<script src>` | `lib/client.js:641-666`（`loadCore`） | 经典脚本；执行后校验 `globalThis.Live2DCubismCore` 存在，否则抛错 |
| 渲染宿主 `live2d-host.bundle.mjs` | `readAll` → `Blob` → objectURL → **动态 `import(url)`** | `lib/client.js:668-676`（`loadFramework`） | 插件 bundle 本身是经典脚本（宿主按 `<script src>` 装载），故动态 import 合法 |
| `model3.json` / `cdi3.json` | `readAll` → `decodeText` → `JSON.parse` | `lib/client.js:532-545`、`:727-779` | **只在确实要当文本用时才解码** |
| `.moc3` / 贴图 / 动作 / 表情 / 物理 / 姿态 / 13 个着色器 | `readAll` → `Uint8Array` → `Blob` → objectURL | `lib/client.js:580-589`（`materializeAssets`） | **保持字节**，绝不经过文本通道 |

### 1.2 · 为什么二进制必须走字节通道（源码级依据）

`lib/client.js:525-529` 逐字：

> 官方框架把多份着色器源码**直接字符串拼接**成一份 GLSL
> （`vendor/CubismWebFramework/src/rendering/cubismshader_webgl.ts:1639-1664`），
> 少一个换行就让下一段的 `#version`／`#define` 落到同一行 → 编译报
> `ERROR: 0:354: '#' : unexpected token after conditional expression`。
> → **凡是要「逐字节忠实」的资源，必须走字节通道。**

**这是"文本通道能不能用"这个问题的判定依据**：不是"看起来能不能读"，而是"下游会不会因为一个换行/编码差异崩掉"。

### 1.3 · 字节怎么喂给只认 URL 的渲染宿主（本任务最刁的一步）

只读复用的渲染宿主（`live2d-host`，**本批不许改**）取资源的**全部出口只有两个**（`lib/client.js:594-596` 逐字）：

- `fetch(url)` —— model3.json / moc3 / 动作 / 表情 / 物理 / 姿态 / 13 个着色器
- `new Image().src = url` —— 贴图（`live2d-host/src/host.js:70-98` 的 `loadTexture`）

做法：**私有 scheme ＋ 装载窗口内临时改写这两个全局**（`installAssetResolver`，`lib/client.js:603-635`）：

1. 所有资源先 `materializeAssets` 成 `Map<虚拟路径, objectURL>`；
2. 装载期间把 `globalThis.fetch` 与 `globalThis.Image` 包一层：**只改写 `dsh-classroom-asset://classroom/` 前缀**，其余 URL **原样透传**；
3. 宿主拿到 `dsh-classroom-asset://classroom/models/Haru/Haru.model3.json` 这样的 URL → 被解析成对应 objectURL；
4. **装载完（含着色器就绪）在 `finally` 里立即还原**两个全局。

`lib/client.js:786-792` 还处理了一个坑：着色器是**异步编译**的（`cubismshader_webgl.ts:1092-1104` 的 `generateShaders` → `registerShader`），在它完成前 `drawModel` 只打一行 warning 且**不画任何东西** → 必须 `waitForShaders(30000)` 等（给 30 s 是因为软件渲染下编译比真机慢得多）。

### 1.4 · 为什么不用别的通道

| 备选 | 为什么没用 |
|---|---|
| 让渲染宿主起一个 HTTP 静态服务 | 要改只读复用的宿主，或另起进程/端口；且要处理 CORS 与生命周期 |
| 服务端插件开资源端点 | 需要服务端配合，超出「客户端半边」的范围（T1 已确立不需要服务端） |
| 把资源拷进插件包 | 一个模型 4–5 MB，包会变成二进制仓库；且换模型要重新打包 |

> 本节的完整展开也在 `README.md` §3 与 §4.5.1–§4.5.2。

**两条实现纪律（写死在代码注释里）**：

- 🔴 **表情只按下标取**：官方样本的表情名是 `F01…` / `exp_01…`，**语义要人工标定后才有意义**。本轮给的是「确定的、可复现的」映射，**不是「对的」映射**；改标定只需改这张表。
- 🔴 **两条通道实现同一个官方接口** `IParameterProvider`（`update(dt) → boolean` / `getParameter() → number`），所以切换通道只是换一个 provider 实例，**渲染代码一行不改**（`live2d-host/scripts/run-rhythm.mjs:253-254` 逐字）。

**🔴 一条容易误读的语义（本轮查清，已写进 README §7）**：
官方 `CubismLipSyncUpdater.onLateUpdate` 走的是 `model.addParameterValueById(...)` —— **叠加**到动作基值上，**不是覆盖**（`vendor/CubismWebFramework/src/motion/cubismlipsyncupdater.ts:76-84` 逐字）。
→ 所以 **`write` 通道 ≠ 嘴闭上**，它只是**不驱动嘴**，嘴停在 idle 动作给的位置。实测该模型（Haru）的 idle 会把 `ParamMouthOpenY` 留在 **1.000**，因此读数里 `write` 的 `区间 [1.000, 1.000]` 是对的，**而画面上的嘴是张着的**。

## 3 · 通道 → 画面的冻结隔离测量（★ 本轮主证据）

### 3.1 · 为什么要冻结（归因陷阱）

面板里的立绘**一直在跑 idle 动画**（呼吸、眨眼、轻微晃动）。于是：

> 「speak 截图」与「write 截图」**必然不同** —— 但那个差异**不能归因给通道**，
> 因为它也可能只是"两张图截在了不同的动画帧"。

**方法**：先冻结动画（`demo.html` 的「冻结动画」开关 = 渲染循环**只 `host.draw()`、不 `host.step(dt)`**），
再**只改一个变量（通道）**，逐像素对比 → 差异只可能来自通道。

脚本：`tools/iso-channel.cjs`（离线、Playwright、起 `live2d-host/out/demo.html` 同一个渲染宿主，**只读复用**）

### 3.2 · 前提验证：取帧层是确定的

脚本：`tools/probe-frame-stability.cjs` → `evidence/frame-stability.json` ＋ `stab_*.png`

| 对照 | 差异像素 | sha256（前 16 位） |
|---|---|---|
| **冻结后连拍两张**（不做任何操作） | **0** | `1c5f9c8d12649e72` 两张相同 |
| 冻结后**隔 1 秒**再拍 | **0** | `1c5f9c8d12649e72` 三张全同 |
| 冻结下改回同一嘴参数 | **0** | 同上 |
| **运行态**连拍两张（对照组） | 15090 | `5785be6def46a2c7` vs `ef620a6aca26c7a5` |

> 主代理独立复核（逐文件 sha256）结论一致：**三次连拍逐字节相同**、`mouth1` 那张不同（67388 B vs 67007 B）。
> → 证明"冻结 ＋ 取帧"这一层是确定的，**后面那个 0 像素对照不是运气**。

### 3.3 · v1 → v2 → v3 的过程（如实保留，不删）

| 版本 | 做了什么 | 结果 | 判据 |
|---|---|---|---|
| **v1** | 冻结后切通道、截帧 | 空白对照 0 像素、通道对比也 0 像素 | 🔴 **空对照**：speak 侧 provider 输出为 **0.000**，与 write 的恒 0 **无从区分** → 0 像素说明不了任何事 |
| **v2** | 加了 provider 数值记录；顺序＝「解冻 → 喂字 → 冻结」 | 空白对照（speak↔speak，**同值 0.344**）竟有 **1 万像素**差异、铺满全身 | 🔴 **对照没过** → B 的差异无法归因给通道。**病根**：解冻期间 idle 动作推进了姿态，"冻结后的画面"取决于解冻了多久 |
| **v3** | ① **全程不解冻**；② 取帧改 `canvas.toDataURL()`（不经截图层/合成器）；③ 用**官方 LipsSync 同一套语义**写参数（`update(0)` → `getParameter()` → `addParameterValueById` → `model.update()` → `draw()`）；④ 每次取帧前**把嘴参数复位到冻结基线**（因为 `addParameterValueById` 是**累加**，不复位会 2×：实测 0.3442 → 0.6885） | ✅ **全部对照通过** | 见下表 |

**v3 修掉的两个具体 bug（都是量级可辨的硬 bug，不是猜测）**：

1. **文本带标点 → 空对照**：`TextRhythmProvider.pushText` 遇标点会把值清零并进入 `punctuationPause`（180 ms）静默窗（`live2d-host/src/text-rhythm-provider.js:180-186`）。若在**同一虚拟时刻**把带标点的整段喂完再 `update(0)`，值**恒为 0** → 又是空对照。改成无标点文本后 `providerValue` 才变成 0.3442。
2. **累加未复位**：第二次取帧 `mouthAfterWrite` 变成 0.6885（= 0.3442 × 2）→ 说明 `addParameterValueById` 在累加。加"复位到冻结基线"后，三次取帧都稳定在 0.3442。
