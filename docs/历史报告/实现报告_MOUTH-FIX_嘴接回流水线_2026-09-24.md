## 〇 · 一句话结论

**闸不是两道，是三道。本轮按任务书只修了前两道；第三道是本轮才发现的，而它恰好决定了「说话时嘴动」在真渲染器里成不成立。**

三句话：

1. **两道点名的闸都修好了**：`mouth` / `nose` 能出层（我方平色立绘 8 层、真立绘 13 层），

## 一 · ① 两道闸改了什么

### 1.1 第一道：出层阈值 —— 改成**按部件给**，不是把全局值调低

**改法**（`33_make_layers.py`，逐处）：

| 处 | 改法 | 锚点 |
|---|---|---|
| 新增表 | `MIN_PX_BY_PART = {'mouth': 8, 'nose': 8}` —— 点名的部件用各自阈值 | 〔A01〕 |
| 取阈值 | `min_px_for(part)` 先查表、查不到才落回 `--min-px` | 〔A02〕 |
| 筛选式 | 部件入选条件由 `>= args.min_px` 改成 `>= min_px_for(p)` | 〔A03〕 |
| 可审计 | `result.json` 新增 `min_px_default` / `min_px_by_part` / `min_px_used` / `dropped_by_min_px` | 〔A04〕〔A29〕 |
| `--min-px` | **默认仍是 200**，只降级成"其余部件"的默认值（help 文案同步改） | 〔A05〕 |

**理由（全部来自本目录的连通域实测〔A37〕〔A38〕，不是感觉）**：

- 同一张图上两端相差最多 **7,000 倍**：最大的部件（上衣）**132,396 px**〔A53〕、脸 48,725 px，
  而 `mouth` 只有 **918 px**（我方平色）〔A31〕或 **19 px**（真手绘）〔A34〕、`nose` **126 px**〔A52〕。
  → **一个全局数字不可能同时服务这两端**：任何能滤掉碎块的值，都会把嘴／鼻一起删掉。
- 而嘴／鼻**不是碎块**：真立绘的 `mouth` 是**单个连通域、距主块 0 span**；
  本目录探针给出的"碎块"实测特征是 **15.92 span 之外**（我方立绘 `ears` 那两块 11 px / 6 px）。
  → 它们是"**一个很小的真部件**"，语义上与噪声不同类。
- 所以阈值差异是**部件属性**，不是噪声判据。**取值 8**：低于实测最小真部件（19 px）留余量，
  同时仍高于已知碎块。
- 顺带说明：i2l 自己的 `denoise` 就是**相对**判据而非绝对下限，理由逐字相同
  （"a real nose layer's entire content is only 84px"）〔A26〕——**我们这条改动与上游同向**。

**结果（真跑，非推演）**：

| 图 | 参与分层部件 | `mouth` 用的阈值 | `mouth` 可见 px | 补全区 px | 出层后 alpha | 出层文件数 |
|---|---|---|---|---|---|---|
| 我方平色立绘 | 7 个（含 `nose`/`mouth`） | **8** | 918〔A31〕 | 612〔A30〕 | **1530**（×1.667） | **8** |
| 真手绘立绘 | 10 个（含 `mouth`；`nose`=0 px） | **8** | **19**〔A34〕 | 0〔A35〕 | **19**（×1.0） | **13** |

（我方那张的 `ears` 116 px 仍被滤掉——**它需要左右拆分**，不是一个"小真部件"问题，见 §1.2 的实测后果。）

### 1.2 🔴 降阈值会带来什么新噪声 —— **真跑了全局 `--min-px 8`，结果造出一个 11 px 的假耳**

任务书要求"要有实测"，所以我把**全局降阈值**这条备选方案也真跑了一遍（`--min-px 8`，其余一字不动）：

```
左右拆分 eyes -> eyes_l (3093 px) / eyes_r (3043 px)
左右拆分 ears -> ears_l (11 px) / ears_r (99 px)      ← 🔴 这就是噪声
参与分层的部件 8 个：['hair', 'face', 'eyes', 'ears', 'nose', 'mouth', 'neck', 'topwear']
```

〔A36〕**机制**：`ears` 掩码在全局阈值 8 下变成"3 个连通域 99 / 11 / 6"，而左右拆分取的是
**面积最大的两块**〔A07〕 ⇒ 99 px 的真耳配 11 px 的碎块，**凭空多出一个 11 px 的"左耳"**。
按部件给阈值就不会：`ears` 不在表里，仍走 200，于是走"连通域不足两块 → 按单块处理 → 接线时跳过"这条**响亮**的路。

**其余新进项的实测（都不致命，但记在案）**：

| 图 | 部件 | 全局降到 8 后新进的东西 | 判定 |
|---|---|---|---|
| 我方平色 | `ears` | 99 px content（真耳）＋ **11 px / 6 px 碎块**（距主块 15.92 span）〔A37〕 | 🔴 会造假耳 |
| 我方平色 | `topwear` | 多 1 块 **73 px**（面积 < 主块 2%，位于主块 bbox **内部**） | 无害但确实是新块 |
| 我方平色 | `nose` | 126 px content | ✅ 正是想放的 |
| 真手绘 | `eyes` | 多两块 **89 px**（距主块 0.00 / 0.11 span，是睫毛，属 content） | 无实际影响（拆分只取最大两块） |
| 真手绘 | `mouth` | **19 px** content | ✅ 正是想放的 |
| 真手绘 | 其它 8 个部件 | **无新增** | ✅ |

→ **结论**：**全局降阈值会把"小真部件"和"碎块"一起放进来，并且能造出假部件；按部件给阈值不会。**
这条实测就是选"按部件"而不是"调低默认值"的依据。

### 1.3 第二道：角色直映表 —— 加两行，名字与序号**逐字对齐 i2l 自己**

**改法**（`50_wire_to_i2l.py`）：

| 处 | 改法 | 锚点 |
|---|---|---|
| `SINGLE` 加 `mouth` | `"mouth": ("mouth", 70)` | 〔A08〕 |
| `SINGLE` 加 `nose` | `"nose": ("nose", 55)` | 〔A09〕 |
| 能力表落盘 | 跑完 rig 就 `rig_capabilities(rig).to_dict()` 写进 wire json | 〔A10〕 |

**为什么名字是这个、序号是这个**（先读现成实现，不自造）：

- 角色名必须**逐字等于** i2l `irr/schema.py:SemanticRole` 的枚举值。上一轮已把逐字原文抄成稳定证据件，
  枚举里**本来就有** `nose` 与 `mouth`〔A26〕——所以不是我起的名字，是它的名字。
- 绘制序号取 i2l **自己的**规范层序（`samples.py` 的 spec：`face_base` → `eyebrow` → `eye_white` → `eye`
  → **`nose` 55** → `pupil` → **`mouth` 70** → `hair_front`）。**不自己发明数字。**
  （上一轮那份自己的映射件把嘴记成 40，落在眼睛 50 之下；本轮按上游规范改成 70。）
- `nose` 要不要加：**要**。i2l 侧 `nose` 角色被多处使用（面部件序、头刚性 0.30、脸部特征定位），
  加进去才与上游同构；本轮实测我方立绘的 `nose` 层 126 px〔A52〕也真的出来了，走的就是 8 这个阈值〔A29〕。
- 加进去之后 i2l 侧会**自动**把 `ParamMouthOpenY` 写进 `.model3.json` 的 `LipSync` 组——
  这是"宿主能不能驱动嘴"的**唯一开关**（§2.2 实测：没有它，宿主 `lipSyncIds` 是空数组）。
  口型同步参数在 i2l 里逐字就是 `ParamMouthOpenY`〔A28〕。

**结果**：我方立绘 8 层全部接线成功（含 `055_nose.png` / `070_mouth.png`），
rig 侧 `parts=13 / params=16`、`mouth_open=True`、`mouth_form=True`、`talk=shipped`〔A49〕；
真立绘 12 层接线成功（`ears` 因拆不开被**响亮跳过**并记进 `skipped`）、`parts=21 / params=27`。

### 2.4 🔴 为什么是 0 px 而不是 330 px —— 第三道闸的定位链

四步，每步都有可核的数字：

1. **`hair` 层在补全后变成一大块**：SAM 的 `hair` 掩码 **136,917 px**〔A32〕，
   补全区 **67,982 px**〔A33〕 ⇒ 层 alpha **204,899 px**。补全区的算式是
   "**其它部件的并集** ∩ 本部件外接框 ∩ 非本部件"〔A06〕——`hair` 的外接框覆盖整个头部，
   于是"画在**下面**的脸"被当成了"盖住头发的东西"，LaMa 把整张脸重画成"头发层的内容"。
2. **它盖住嘴，而且是 100%**：`hair` 层 alpha 盖住嘴层 alpha **1530 / 1530**。
3. **而这不是 SAM 分割的错**：SAM 的 `hair` 掩码本身盖住嘴的可见像素 **0 / 918**。
   ⇒ **是补全造成的，不是分割造成的。**
4. **接线把它放到了最上层**：`hair` → `hair_front`（序号 120，i2l 规范里刘海就在最上）
   ⇒ 嘴被整块盖住 ⇒ 真渲染器 **0 px**。
   最直观的旁证：我方立绘那张**整帧渲染出来根本没有眼睛和嘴**，只有一片被重画成肤色的"头发"。

**消融对照证明这条链是完整且唯一的**：只把 `hair` 层的 alpha 收敛回 SAM 掩码
（`ablate_hairhole_*`，**其余每一层逐字不动**）⇒ 同一份 rig、同一个 `.moc3` 生成流程、
同一个渲染器，**0 px → 359 px**〔A39〕。所以第三道闸就是它。

### 2.5 与上一轮 330 px 的差别，说清（任务书要求"两者都报"）

| | 上一轮那份 330 px | 本轮真渲染器 |
|---|---|---|
| 渲染器 | image2live2d 的 `preview.render_pose`（上游自认 approximate piecewise-affine 软件光栅） | **官方 Cubism 框架 + Core + WebGL** |
| 层集 | 上一轮**自己的**脚本出的层（`hole-mode=above` ＋ `order-mode=fixed` ⇒ **`hair` 层没有补全膨胀**） | auto-layer 原样（`hair` 层带 67,982 px 补全） |
| 数字 | 330 px | **0 px**（消融掉 hair 补全后 **359 px**） |

🔴 **两处差别要分开说，不能混成一句"软件光栅不准"**：

- **渲染器这一层**：两个渲染器**都是真的**，但软件光栅不保证与 Live2D 的绘制序／网格细分逐像素一致，
  所以它**不能当验收判据**（上一轮自己也这么写了）。这一点成立，**但它不是本轮 0 px 的原因**。
- **层集这一层才是主因**：上一轮那 330 px 是在**没有 hair 补全膨胀**的层集上量的。
  换句话说，**330 px 与 0 px 的差不是"近似 vs 精确"，而是"嘴可见 vs 嘴被盖住"**。
  证据是：本轮把 hair 补全关掉之后，真渲染器给的是 **359 px**——**与 330 px 同量级**。
  ⇒ 一旦嘴真的可见，两个渲染器给出的量级是一致的；**0 px 是层的问题，不是渲染器的问题。**

### 2.6 接触表与「该看什么」

接触表：`evidence/70_contact_mouth_gate_x12.png`（6 行 × 4 格：整帧 / 嘴区闭 ×12 / 嘴区开 ×12 / 差异热图；

**🔴 「该看什么」——按这个顺序看，五条**：

1. **别看能力表**。本表前三行全是 `mouth_open ✓ / talk shipped`，其中两行画面**完全不动**。
2. **别只看"嘴层有多少 px"**。918 px 的那张照样可以**一点都看不见**（第 1 行）。
3. **先看整帧（第 1 格）有没有五官**。我方立绘那张整帧**没有眼睛也没有嘴**——
   这是"被最上层盖住"最快的判据，一眼就能判死。
4. **再看嘴区的闭／开两格**（第 2、3 格）。如果那一格是**一片平坦的肤色**，就是被盖住了；
   如果闭档是唇线、开档出现更深的腔体形状，就是真的在动（第 2 行就是对的形状）。
5. **最后看差异热图与蓝框**。红在哪、蓝框落在不在嘴上——红区落在嘴的位置才算数。

## 三 · ③ 产品级闸门（防"能力表绿了画面没动"）

### 3.1 判据与阈值

🔴 **判据（任务书指定，原样实现）**：**在真渲染宿主里驱动 `ParamMouthOpenY` 0 → 1，渲染像素差 < 20 px 就报红。**

🔴 **阈值写在脚本头部，可被报告引用**：

```
GATE_MIN_RENDER_PX = 20
```

〔A12〕阈值取 20 的理由（也写在脚本头部）：**「说话时嘴动」是这个产品的核心特征**；
上一路实测的失准案例是 5 px（真立绘 19 px 嘴层：能力表全绿、`talk` 照常 shipped，画面只动 5 px）；
取 20 是给"确有动作但极小"留一档余量，同时**远高于噪声底**——
宿主自带探针要求"改回闭合后 0 像素差"，本轮六例的可逆性**全是 0 px** ⇒ 噪声底 = 0。
**阈值不当"可随时调低"的软参数**：它是脚本顶部的常量，报告直接引用它。

**过闸的完整判据**（两条同时成立）〔A13〕：

1. 真渲染器 0→1 像素差 **≥ 20 px**；
2. 模型里**确实存在**可驱动的口型参数（宿主 `lipSyncIds` 非空）。

第 2 条是必须的：如果模型里根本没有 `ParamMouthOpenY`，那"像素差 0"与"嘴很小"是**两回事**，
闸门必须能分开报（实测：去掉嘴层的对照组 `lipSyncIds` 是**空数组**）。

> 🔴 **为什么必须另装一道闸**：i2l 那条能力判据本身是"**要有 `ParamMouthOpenY` 且要有腔体**"〔A27〕——
> 它**根本不检查"看不看得见"**。所以能力表可以在画面完全不动时全绿，这不是 i2l 的 bug，是它的判据范围。
> **闸门要抓的正是这个判据之外的东西。**

## 四 · ④ 内存：两条独立通道 + 单位实测标定（上一轮的规矩，本轮照守）

**规矩原文**：凡结论涉及内存，**必须写清用哪个命令**且**至少两条独立通道**；三个口径不许混写；
**单位必须实测标定**；🔴 **不许用 `pgrep -f 脚本名` 取 pid**（`/usr/bin/time -l <py> 脚本.py`
的命令行里也含脚本名，会先匹配到包装进程）。

脚本：`scripts/63_mem_two_channel.sh`〔A23〕〔A24〕〔A25〕。取 pid 一律用 `$!` 直接拿**被测进程自己**。

### 4.1 先标定：分配已知 800 MB 并逐页触碰〔A46〕

| 通道 | 命令 | 读数 | 换算 |
|---|---|---|---|
| A | `ps -o rss= -p <pid>` | 807,376 **KB** | 788 MB |
| B | `footprint -p <pid> -f bytes --noCategories` 里的 `phys_footprint` | 846,776,704 **B** | 808 MB |
| C | `top -l 1 -pid <pid> -stats rsize` | 808 **M** | 808 MB |

**标定结论**：已知 800 MB ⇒ 三条通道都给 ≈800 ⇒ **单位分别是 KB / B / MB**；
且**通道 C 与通道 B 同值 ⇒ macOS `top` 的 MEM/rsize 列量的是 `phys_footprint`，不是 RSS**（上一轮的结论本轮独立复现）。

### 4.2 真实工作负载：`33_make_layers.py --device mps`（真手绘立绘那张）〔A51〕

| 通道 | 命令 | 峰值 |
|---|---|---|
| A | `ps -o rss= -p <pid>`（每 2 s 采样，18 次） | 674,752 KB = **659 MB** |
| A′ | 脚本自报 `resource.getrusage(RUSAGE_SELF).ru_maxrss`（**也是 RSS**，独立读数） | **719.1 MB** |
| B | `footprint` 的 `phys_footprint` | **2951 MB** |

⇒ **两个口径相差约 4.5 倍**；**这台机器上这一步的真实占用约 2.9 GB**（不是 1 GB）。
🔴 **口径必须连命令一起写**：RSS 不含被压缩页（内存压力大时系统性偏小），
`phys_footprint` 含被压缩页。**两者都不是"错"**，是两个不同的量。
📌 范围声明：这是**只含 LaMa 补全那一步**（`33_make_layers.py`）的数字；
SAM 分割是**另一个进程**，本轮**没有量**，所以**不要把 2.9 GB 当"整条轻量路线的占用"**。
（上一轮报的 5.2–5.3 GB 是另一套工作负载/进程边界下的数，与本轮的 2.9 GB 不可直接比。）
