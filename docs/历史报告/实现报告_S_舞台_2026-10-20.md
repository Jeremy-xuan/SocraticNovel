## 一 · 先说那条"发现既有缺陷"

主代理在隔离 profile + Playwright 里测到：舞台上 `#stage-warm-root canvas` 只有 1 个、backing store
`300×150`（PIXI 默认）、CSS 盒 399×546、画面上那块是空书架、且页面没有"我们插件的报错"。
要求先定性：**「模型没加载」还是「加载了但尺寸/位置不对」**。

### 1.1 定性结论：都不是 —— 是「headless 没有 WebGL」＋「降级路径被一个 ReferenceError 吃掉」

判据（真机，隔离 profile `stageverify` 的副本，端口 4510）：

| 场景 | 读数 | 结论 |
|---|---|---|
| 默认 headless Chromium | `webgl = false`；控制台一条 `WebGL unsupported in this browser, use "pixi.js-legacy"…`；`data-l2d="on"`、`<img>` 不存在、canvas `300×150`、`canvas.getContext('webgl')` 拿不到上下文 | PIXI 6 建渲染器就抛了 |
| 加 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` | `webgl = "WebGL 2.0 (OpenGL ES 3.0 Chromium) \| WebKit WebGL"`；canvas backing store **399×546**（与 CSS 一致）；模型**真的画出来**（鲸·女仆装立绘） | 模型能加载、也能画 |

也就是说：
1. **主代理看到的现象本身是 headless 环境的**（Playwright 默认无 WebGL）；真机 Electron 窗口有 WebGL。
   因此 **C 的验收不需要降级成"驱动值正确但渲染未验"**。
2. 但**底下压着一个我们自己的真 bug**（见 1.2），它把"没有立绘"变成了"没有立绘也不回落静态图"，
   而且**一条报错都不留**。修完再看，才是干净的定性。

### 1.2 真 bug（已修，`fix(stage):`）：降级路径里的 `warnings is not defined`

`StageRoot` 的 Live2D effect 的 catch 里写了 `warnings.push(...)`，而 `warnings` 当时只存在于
`apply()` 的函数作用域 —— 那个 catch 里根本没有这个变量。于是：

```
Live2D 任意一步失败 → catch → ReferenceError: warnings is not defined
  → setL2dFailed(true) 永不执行 → 不回落静态 PNG、data-l2d 仍 "on" → 只剩一个空 canvas
```

主代理测到的 3 条 `ReferenceError: warnings is not defined` **至少有一条是我们的**（不是全部来自 web 模板）。

修法：模块级 `const warnings = []` + `pushWarning(msg)`（顺带 `console.info` 留痕，真机归因时比"什么都没有"强）；
`apply()` 里删掉同名局部变量，避免 shadowing 后同族 bug 复发。

修后实测（同端口）：
- 无 WebGL：`data-l2d="off"` + `teacher_gen.png` 上屏（1024×1536 真加载）、`pageerror` **0**（修前 3 条）。
- 有 WebGL：`data-l2d="on"`、canvas 399×546、模型绘制成功。

### 1.3 顺手核实的另一条老注释

代码里那条「构造参数里的 width/height 实测不生效（canvas 内部仍是 300×150），必须再显式 resize」，
在 PIXI 6.5.2 上**本场景已经不成立**（构造参数 + `renderer.resize` 都生效：399×546）。
注释保留但未改行为（`resize` 调用无害且兼容旧版），在报告里如实记一笔。

## 二 · 任务 1 · K0 挂载点

### 2.1 做了什么

`lib/client.js`：

- **纯函数区**（`[STAGE-PURE-BEGIN] … [STAGE-PURE-END]`）：`createStageBridge(deps)` —— 只依赖入参与
  `globalThis`，不碰 React/DOM/PIXI。`check.sh` 把这一段**逐字抽出**到 `/tmp` 变 ESM 跑单测
  （`test/20-stage-pure.mjs`），测的是产品源码本身，不是另写一份实现。
- 字段逐条照 K0：`version / React / subscribe / getSnapshot / screen / app(getter) / model() /
  setExpressionDriver / dispose`，外加两个**加法字段** `driver()` 与 `mouthSource()`（见 §五）。
- `getSnapshot()` 的 `phase` **恒 `null`**：相位在引擎侧，舞台看不到 —— 如实留空，不编值。
- `setExpressionDriver` 语义：非法对象/`null` → 交还静态待机；换驱动时**先 dispose 旧的**；
  同一个对象重复注册不 dispose 自己；变化时回调 `onDriverChange`（舞台据此决定表情层归属）。
- `dispose()` 顺序写死：① `driver.dispose()` ② 清引用 ③ 摘全局键；**不删除别人的同名全局**。
- 挂载在舞台根 `useEffect(..., [enabled, killed])`：mount 建、`killed` 或卸载时销毁。
  🔴 这条 effect **写在 Live2D effect 之前** —— React 的 cleanup 按声明顺序执行，
  于是"驱动先清理、PIXI 应用后销毁"是结构保证的，不靠运气。
- `ensureStageModule(file, subdir='l2d')`：复用 `loadOneScript`，按 URL 缓存 promise、失败不缓存。
  **没有**塞进 `listLibs()` 的 phases（`check.sh` 第 7d 组会挡这条）。

## 三 · 任务 2 · S1–S4

### 3.1 S1 · 节拍与过冲：**定案值到底是什么**

**核对结果**（`docs/架构/规格_舞台样式令牌_2026-09-30.md` §5.2/§5.3/§5.4 是这一项的权威源）：

| 项 | 对比件（`pull-out.html`） | 原舞台代码 | 现在 |
|---|---|---|---|
| 三段时长 | `--T1:170ms` / `--T2:390ms` / `--T3:220ms` | 170/390/220（CSS）＋ 切换点 170/560 | 不变（切换点 170/560 = 串行口径，已由 09-30 的复验定过） |
| 面板过冲位移 | `translateX(-24px)`，面板宽 **1180px** → **2.03% 板宽** | `translateX(-2.2vh)`（注释却写「定案值 −24px」） | **`translateX(-2.03%)`** |
| 旋转/缩放过冲 | `rotate(.5deg)` / `scale(1.012)` | 同 | 同 |
| 角色侧身 | `rotate(-1.6deg) translateX(-30px) scaleX(.965) scaleY(.995)` | `rotate(-1.6deg) translateX(-3vh) scale(.965)` | 加 `.995` 的 Y 轴缩放：`scale(.965,.995)`；`-3vh` 保留（−30px 在 1080 画布上 = 2.78vh） |
| 正文退后 | `opacity .42 / scale(.975) / blur(1.2px)` | `.45 / .985 / 无 blur` | `.42 / .975 / blur(1.2px)`，并补上反向时的过渡 |

**单位选择：百分比（面板自身宽度），不是 px、也不是 vh。** 理由三条：

1. **与对比件同源**：对比件的过冲本来就是"板宽的百分之几"（规格 §5.3 自己就换算过 `24/1180 = 2.03%`）。
   抄它的比值，比抄它的像素更忠实。
2. **换分辨率/换屏不漂**：`translateX(%)` 在 CSS 里按**元素自身宽**解析。舞台有两个面板宽度
   （live 屏 62vh、板书屏 80vh），百分比让两种屏的过冲比例一致；原来写 `-2.2vh` ≈ **3.5%** 板宽
   （在 80vh 面板上约 29px），比对比件冲过头约 1.7 倍。像素值换分辨率必漂，这是没选 px 的直接原因。
3. **可机核**：定帧量 `transform` 的 translateX 即可，不必依赖采样时延。

**定帧实测**（真机 1680×1050，强制 `data-board=pull` / `settle`，关掉过渡后量）：

```
settle: left=420  width=840  transform=matrix(1,0,0,1,0,0)
pull:   left=390  width=855  transform=matrix(1.01196, 0.00883125, -0.00883125, 1.01196, -17.052, 0)
                                                                    ↑ translateX = -17.052px
-17.052 / 840 = 2.03%  ✓（对比件 24/1180 = 2.034%）
角色侧身位移 castShiftPx = 32（对比件 -30px）
```

> 说明：`left` 差 30px = translate（17px）＋ scale 1.012 在 `transform-origin:right center` 下把左边缘又推出去约 10px，
> 两个量都会出现在对比件里，所以"过冲"应当看 **translateX 本身**，这也正是对比件的 `-24px` 的含义。

`test/14` 也跑了（逐帧相位 `turn→pull→settle` 齐全、`overshootPx` 12–30 随采样漂移），
但因为每次 `page.evaluate` 有 10–30ms 时延，逐帧采样的时间标签会漂，**不适合作过冲量判据** —— 记在这里以免下次又拿它当证据。

### 3.2 S2 · 动画整屏放完自动回：**规则与实测**

规则（写进 README §四）：

1. `<video>` 的 `ended` → 自动回 live 屏。
2. **放映中学生发言不打断**：放映时 `.animscr` 是 `position:absolute;inset:0;z-index:60;pointer-events:auto`
   的整屏层，输入条在其下**不可达** —— 所以"发言打断"这一路径本来就不存在；若消息从别的入口到达，
   `anim` 状态不受消息流影响（不在任何消息依赖里），也不打断。
3. 提前收：点画面 / `Esc`（保留原行为）。
4. 视频出错 → `as-fallback` 显示不可用原因，不白屏，点画面/Esc 仍可收。
5. 本包视频 `scene.mp4` **无音轨**（`ffprobe`: 只有 h264 视频流），所以 `autoPlay` 不受"有声自动播放"策略限制。

## 四 · 任务 3 · W-s 板书闭环

### 4.1 宿主半边（契约 K2.2）

四条路由，全部 loopback-only、每条 handler 各自 try/catch：

| 路由 | 返回 |
|---|---|
| `GET /stage-board/diagrams/<id>` | `text/plain; charset=utf-8`（mermaid 源码） |
| `GET /stage-board/diagrams` | `{ items:[{id,lesson,turn,kind,title,time,file,session}], root, classroom }`，时间倒序 |
| `GET /stage-board/emotions?after=<seq>` | `{ events, nextSeq }` |
| `GET /stage-board/health` | 归因：教室目录、`source`、`tried`、图/情绪条数 |

**根目录解析**（新增两个设置项 `classroom`（默认 `cs-os`）、`workspaceRoot`（默认空））：
候选顺序 = `settings.workspaceRoot` → `workspaceRegistry.list()` 每个 path → `process.cwd()`，
每条都要求磁盘上真有 `<候选>/classrooms/<教室>/`（或候选本身就是教室目录）。
找不到就 404 并返回 `tried`，**不静默编路径**。

**拒绝规则**（`resolveDiagramFile`，逐条独立）：原文匹配 `^[A-Za-z0-9_-]+$` →
`decodeURIComponent` 后仍须匹配 → `path.resolve` 后父目录必须就是根 → `realpathSync` 后仍须在根内。
任一不满足 **400**；缺文件 404；非 GET 405。

真机 curl 实测（对真实教室根）：

```
%2e%2e%2f%2e%2e%2fetc%2fpasswd -> 400 bad-chars
..%2Fclassroom.yaml            -> 400 bad-chars
a%2Fb                          -> 400 bad-chars
a.b                            -> 400 bad-chars
L03%20x                        -> 400 bad-chars
L99-T01-20260101-000000-missing -> 404 file-missing
POST /stage-board/diagrams     -> 405
GET /stage-board/emotions?after=0 -> {"events":[],"nextSeq":0}   ← 文件不存在也 200（主代理点名要的）
```

**索引解析按表头名取列**（主代理 2026-10-20 通知：引擎侧表格末尾新增「会话」列）：
`items` 补 `session`（老索引没有该列 → 空串，不把整条判坏）；列序被打乱也认（`test/21` 有乱序表头用例）。

### 4.2 浏览器半边（K2.3 判据 / K2.4 行为）

- `boardEventOf(node)`（纯函数）：`kind==='tool-result'` + `name==='classroom_draw'` + `isError!==true`；
  id 先 `meta.board.id`，否则 `/\n\[board\] id=(\S+) lesson=(\d+) turn=(\d+) kind=(\S+)/`；都没有 → `{id:null}`。
  `readMessages` 里为命中项推一条 `role:'board'` 的条目（**只作切屏信号，不进纸带正文**），
  没有 id 时 `pushWarning` 一条 warn（会进 `/stage-static/health` 的 warnings）。
- `openDiagram(req)`：拉源码 → 归一化 → mermaid 渲染 → 上屏；**只认最后一次请求**（老师连画两张时旧请求不许覆盖新图）。
- 拉出节拍复用 `pullOut()`：已在板上时 `board` 已非空 → **不重播**；收起走反向节拍（面板沿原路滑出 390ms，420ms 整块离场）。
- 学生发下一句 → `closeBoard()`（用 `screenRef` 读当前屏，避免把 `boardScreen` 塞进依赖）；
  舞台 `killed` → effect 直接 return（**不自动打开**）；挂载时已存在的板书不算新事件（刷新后先看 live）。
- 渲染失败 → `.bp-fail`：「这张图渲染失败」＋ 错误行 ＋ `<pre>` 源码。
- 手动「板书」按钮保留：有图看最新那张，没图退回老的静态场景 L03。

### 4.3 mermaid 来源取舍（**决定与理由**）

**决定：逐字节复制进本包 `assets/l2d/mermaid.min.js`**（源：`clients/classroom-ui/vendor/mermaid-11.17.2/`，
sha256 两处相同 `581ed7d7…90eb8`，`check.sh` 第五组会核；版本纪律照抄 BUILD-INFO：换版本＝重新验证）。

否决「跨插件引用」：舞台不能依赖"面板恰好装着"——没装/换版本/vendor 改名就白屏，而且依赖不在

否决「启动就装」：3.5 MB，只有真画了图才需要 → `ensureMermaid()` 按需装一次。

### 4.4 **踩到的坑（写下来免得下次再踩）**：mermaid 的内联 `max-width`

mermaid 11 的产物是 `<svg width="100%" style="max-width: 343px;" viewBox="0 0 343 454">`。
直接塞进 840px 的画布 → **只画出 343px 宽**（内联样式钉死）。

## 五 · 任务 4 · C-s + K1 舞台侧

### 5.1 防御性剥离（K1.3 / K1.4）

`stripEmotionMarkers(text, {final})`（纯函数，14 例单测）：合法 `〔emo:<label>:<0.00–1.00>〕` 剥掉并发事件；
非法标签/强度越界/缺两位小数整段剥掉、不发事件、不报错；一句（到 `。？！…` 或换行）多个只认第一个；
**半截标记**：`final=false` 先不下传、`final=true` 原样交回（宁可显示半截，不吞正文）。

**一处刻意的偏离（要记账）**：K1.3 的引擎解析器把"任何 `〔…〕`"都当标记候选（非法也整段剥掉）。
舞台这一遍是**防御性剥离**，如果照抄，老师真的用 `〔〕` 强调的正文（如「我把〔阻塞队列〕画在板上」）
会被吃掉 —— 那比"漏剥一个标记"严重。所以舞台只把 **`〔emo:`** 开头当标记候选，其它全角方括号原样保留。
这一条单测覆盖（「非标记的〔〕原样保留」「孤立〔原样保留」）。引擎侧仍是 K1.3 的原语义，两处不冲突。

纸带渲染顺序：先剥标记（`final = !m.running`）→ 再 `stripMarkdown`。`role:'board'` 条目跳过不画。

### 5.2 情绪通道

宿主：`GET /stage-board/emotions?after=<seq>` 读 `<教室>/runtime/emotions.jsonl`，只回 `seq > after`，
坏行跳过（进程被杀时末行可能是半截），单次上限 200 条；文件不存在 → `{events:[],nextSeq:0}`（**不 500**，主代理点名要测，已测）。

浏览器：仅当「`enabled` 且未 `killed` 且 `running===true` 且 `document.hidden===false`」时 `setInterval` 250ms 拉一次；
`inFlight` 防重入；失败只等下一拍（不重试、不排队、不堆积）；`nextSeq` 更新本地游标；
拿到合法事件 → `active = {label, intensity, at:now}`；4 秒无新事件 → `active=null`（回到平静的舞台侧兜底）。

### 5.3 口型源（可替换接口）

`createTextCadenceMouth()`：`{ kind, note, feed(text, done), advance(dtMs), current(), reset() }`。
本阶段实现「纸带逐字显现的节奏」：14 字/秒推进"已显现字数"，还有字要出就按 5.2 音节/秒摆开合；
**一句显示完 `open` 归 0（闭嘴）**；单帧推进上限 250ms（切后台回来不会一帧跳完）。
**没有写死在混合层**：舞台每帧只做 `feed/advance`，把结果通过 K0 的 `mouthSource()` 交出去；
驱动读 `mouthSource().current()` 拿 `{open, speaking}` 写嘴部参数。将来接音频：写 `createAudioMouth()`
实现同样三件套、换掉 `mouthRef.current`，驱动与混合层都不用动（单测 8 例）。

### 5.4 动作层保留 / 表情层让位

- 动作层原逻辑不变：`running→Anima2+thinking`、最后一个开口是 teacher→`Anima0`、you→`Anima1`、否则 `Idle0`。
- 表情层：`driverOn`（由 `onDriverChange` 驱动）为真时**完全不调** `model.expression()`；为假时沿用原静态表情。

### 5.5 ticker 管理

- 舞台在 PIXI 应用创建时 `app.ticker.add(...)` 挂一条帧循环，**app 销毁 ⇒ ticker 一起死**。
- 驱动的 `dispose()` 由 K0 的销毁顺序保证**在 app 销毁之前**被调用（effect 声明顺序）。
- 真机实证「关掉再打开」：`Ctrl+Shift+M` → `bridge="undefined"`；`Ctrl+Shift+U` → `bridge="object"`、
  `canvas=1`（没有第二个 canvas，也没有 Ticker 回调残留 —— 帧循环是挂在 app 上的那一条）。

### 5.6 顺手修掉：依赖数组里的整个 `data` 快照

原 Live2D effect 依赖 `[enabled, data, props.l2d, props.models, props.killed]` —— `data` 是 store 快照，
流式期间**每来一块文本换一次引用** → PIXI 应用被反复销毁重建（还会重复下载模型）。
现在依赖 `[enabled, props.l2d, props.models, props.killed, stageFrame]`（`stageFrame` 是 `useCallback([])`，恒定）。
动作 effect 也从 `[l2dReady, data.running, data.messages]` 收窄成 `[l2dReady, data.running, lastSpokenRole, driverOn]`
（`lastSpokenRole` 只取"最后一个开口的角色"，与文本长度无关）—— 顺带治好了"流式期间动作每块文本都重新起播"。
