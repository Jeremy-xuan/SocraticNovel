### 1.4 目录结构与必需文件

**结论（四条，都从上面这段直接读出）：**

1. **两种形态**：目录包 `<技能名>/SKILL.md`，或扁平文件 `<技能名>.md`（只能放在**扫描根的顶层**）。
2. **只扫两层**：根的**直接子项**。目录包里的其他文件（`references/`、`classroom/`……）
   **不会被当成技能**，但会被记进 `resourceBase.directory` 交给模型按需读。
   → **嵌套的 `**/SKILL.md` 是故意不发现的**（master README 原话：*"nested `**/SKILL.md` files are deliberately not discovered"*）。
3. **必需文件只有 `SKILL.md`**；`references/`、`templates/` 这类目录不是必需的，是本仓库既有技能
   自己的组织习惯（对照 `tmp/dsh-src-0923/.agents/skills/dsh-doc/`：`SKILL.md` + `references/` + `templates/`）。
4. 目录包必须叫 `SKILL.md`，**大小写敏感**（`segments[1] === "SKILL.md"`，`:550`、`:556`）。

**frontmatter 字段** —— `dsh-skill-filesystem/lib/index.js:664-703`（逐字，节选）：

- **必需**：`name`、`description`（都必须是非空字符串）。
- `name` 必须匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`（`dsh-skill/lib/index.js:17`）——纯小写 kebab-case。
- **可选**：`whenToUse`、`metadata`、`disable-model-invocation`、`user-invocable`（`:699-701`、`:841-854`）。
- 布尔写法宽容：`true/false`、`yes/no`、`on/off`、`1/0`（大小写不敏感，`:855-869`）。
- 🔴 **旧字段名会直接报错**（不是忽略）：`disableModelInvocation` / `modelInvocable` / `userInvocable`

- frontmatter 必须是**文件第一行的 `---`** 开始（`:772-780`），YAML 根节点必须是映射。

**回答「一个 skill 还是 skill + 教室文件」**：
**一个目录包**，教室里所有文件都放进这个包里（`classroom/`）。理由：
- 发现机制**只看 `SKILL.md`**，包内其他文件不会被误认成技能；
- `resourceBase.directory` 正好就是包目录，模型拿得到绝对路径；
- 分发形态是「一个文件夹复制过去」，符合 M3 的目标（别人装上就能用）。

### 1.6 校验/加载报错机制（会不会静默？）

**会静默 —— 这是本次最重要的负面发现。** `dsh-skill-filesystem/lib/index.js:664-703` 的每一种失败都是
`ctx.logger.warn(...)` 然后 `return undefined`（跳过该文件）：

```js
		ctx.logger.warn(`skill file ${path} ignored: invalid YAML frontmatter: ${errorMessage(error)}`);
		...
		ctx.logger.warn(`skill file ${path} ignored: missing YAML frontmatter`);
		...
		ctx.logger.warn(`skill file ${path} ignored: frontmatter requires name and description`);
		...
		ctx.logger.warn(`skill file ${path} ignored: invalid skill name "${name}"`);
		...
		ctx.logger.warn(`skill file ${path} ignored: invalid invocation frontmatter: ${errorMessage(error)}`);
```

master README 把后果写得最直白（`tmp/dsh-src-0923/packages/skill/skill-filesystem/README.md:85`，逐字）：

> A valid skill under any scanned root appears in the session catalog sorted by name, and loading it returns the current file body. A file without valid frontmatter, an invalid name, or an invalid invocation value is skipped with a warning, **so the model catalog receives no per-skill diagnostic and cannot distinguish an absent skill from an invalid one.**

→ **「没装上」和「装上了但写坏了」对模型完全一样：目录里就是不出现。**
**这就是为什么必须自带 `validate`**：DSH 自己不会告诉你哪一行写错了。

**为什么 `classroom/` 是副本而不是引用路径**（理由与代价）：

- **理由**：分发形态要求「一个文件夹复制过去就能用」。引用外部路径 = 用户还得先有那份教室，
  等于没打包。且 `resourceBase.directory` 天然支持包内资源。
- **代价（写清楚）**：① 包体积翻倍（教室 300 KB ×2）；② **两边不自动联动** ——
  源教室改了必须手动跑 `sync-classroom.sh`，否则副本会旧。
- **为什么可以接受**：教室正文正由另一条工作线持续补写（本次执行期间 `materials/` 从
  ch01–ch03 一路长到 ch01–ch08）。副本陈旧是**可检测的**：`validate` 会报出正文缺口，
  同步命令是一行。

### 2.3 自检命令 `validate`

- **运行**：`/opt/homebrew/bin/node validate [教室目录]`（不给参数则检查包内 `classroom/`）。
- **依赖**：只用 Node 内置模块 + 包内 `yaml`。**没有新增任何依赖，没有联网安装。**
- **退出码**：`0` = 全部通过；`1` = 查出问题；`2` = 连检查都做不了（目录不存在／解析器缺失）。
- **绝不静默**：任何一项查不出来都打印原因；解析器缺失直接 `exit 2`，不会"跳过检查当作通过"。

四项检查与判据：

| 检查 | 内容 |
|---|---|
| ① 必需文件 | 17 个固定文件（入口/教学法/纪律便条/课程表/知识点/世界观×2/清单/故事总览/运行记录×8）＋ `characters/` 至少 1 份人格 ＋ `story/`、`materials/` 目录存在 |
| ② 声明材料 | 逐块检查 `classroom.yaml` 的 `blocks[].path` 与 `runtime_store.progress` 是否真的在磁盘上；顺带按引擎同款规则检查 `section:` 声明的段标题是否存在（**section 不存在会让该块静默失效**）；检查块 `id` 不重复 |
| ③ 讲次序号 | 每个讲次门（`lesson.of` / `lesson.list` / `lesson.range`）的**上界是否超过 `classroom.lessons`**；并交叉核对「声明讲数」与 `story/` 实际节点数是否一致 |
| ④ 教材正文 | `materials/ch{NN}.md` 按声明讲数逐个查，报出缺哪几讲 |

**③ 的判据与插件同源**：`code/plugins/socratic-engine/lib/manifest.mjs:221-233` 的
`assertLessonGateWithinBounds`，报错理由逐字是
*「这个门永远不会命中，块会静默不注入，故报错」*。`validate` 照这条规则重写（只读该文件，未改动）。

### 2.4 依赖来源（`yaml` 从哪来）

- **来源**：`code/plugins/socratic-engine/node_modules/yaml`（**v2.6.1**）。
  它是教学插件自己 `package.json` 里就声明的依赖（`"yaml": "^2.6.1"`）。
- **怎么来的**：`cp -R` 复制进包内（`node_modules/yaml`），**不是 `npm install`，没有联网，没有改动文件内容**，`LICENSE` 一并复制。
- **为什么必须自带**：技能包要能离开本仓库独立运行。若不自带，就只能去猜 DSH 的安装路径
  （macOS 上是 `/Applications/DSH Desktop.app/...`，换平台就断），那是不可移植的硬编码。
- **为什么不用手写解析器**：`classroom.yaml` 的解析结果**决定自检报不报得出问题**。
  手写一个"够用"的子集解析器，会在它不认识的结构上**少报** —— 那正是自检最不该犯的错。
  用真解析器 + 「解析失败就 `exit 2` 不跳过」是唯一诚实的做法。
- **`package.json` 里为什么只有 `"type": "commonjs"`**：`validate` 是无扩展名文件，
  Node 靠**最近的 `package.json` 的 `type`** 决定按 CJS 还是 ESM 跑。不写这一行，
  行为就取决于上层目录里恰好有什么 `package.json`（本工作区根目录正好有一个），不可移植。
