### 2.1 `index.mjs`（原 75–81 行 → 现 75–89 行）

**改前：**

```js
  const log = (...args) => {
    try {
      ctx.logger?.('[socratic-engine]', ...args)
    } catch {
      /* logger 不可用不致命 */
    }

```

**改后：**

```js
  // 🔴 FIX-6（2026-09-24）：原来的形状是 `ctx.logger?.('[socratic-engine]', ...args)`——
  //    cordis 的 `ctx.logger(name)` **只接受 name 一个参数**（`@deepseek-ai/cordis/lib/index.js`
  //    的 `LoggerService[symbols.invoke](name)`），其余参数被丢弃、返回的 Logger 被抛弃
  //    → 插件所有日志一条都不落任何地方（真 cordis 4.0.2 运行时段实测：旧形状收 0 条、
  //    同级别同出口的新形状收 1 条）。正确形状是**先取 logger、再调级别方法**。
  //    级别选 `info`：本函数记的是装载/发现/注入/相位/落盘等**正常运行轨迹**，
  //    非异常；`info`(level 1) 是这些消息的语义档，也是默认 exporter 门限下可见的档。
  const LOGGER_NAME = '[socratic-engine]'
  const log = (...args) => {
    try {
      ctx.logger?.(LOGGER_NAME).info(...args)
    } catch {
      /* logger 不可用不致命 */
    }
  }
```

**逐项说明（对任务书的四条硬要求）：**

| 要求 | 落实 |
|---|---|
| 正确形状＝先取 logger、再调级别方法 | `ctx.logger?.(LOGGER_NAME).info(...args)` |
| `name` 固定且可辨识；**不再把前缀塞进参数里** | 提成常量 `LOGGER_NAME = '[socratic-engine]'`；`args` 里现在**只有消息本身**，没有前缀 |
| **级别按原语义选** | 选 **`info`**，理由见下 |
| **宿主没 logger 时什么都不炸** | `?.` 保留 ＋ `try/catch` 保留；实测 C 组（`logger: undefined`）**不炸** |

**为什么定级 `info`（任务书要求说明）**

1. **按原用途**：这个 `log()` 记的是「教室已装载／相位值域／系统段注册 N 块／turn N 注入 M 块／相位切换／课后写入结果」——**正常运行轨迹**，不是异常。`info`（level 1）是它的语义档。
2. **不是 `warn`/`error`**：定成 `warn` 会把"装载成功"这种正常事件说成告警，污染日志级别语义；而真正的失败消息**本来就自带 🔴 前缀**（见 ③），靠文本可辨，不需要靠级别抬升。
3. **可观测性**：cordis 的 level 门是 `(exporter.levels?.default ?? this.level ?? 1) < level` 才跳过。`info`=1，**在默认门限（1）下就可见**；`warn`=2／`debug`=3 在默认门限下会被静默过滤——**那等于换一个地方继续静默**。选 `info` 是"这条日志真能被看见"的必要条件。

**为什么保留 `try/catch`（这是有实证的，不是习惯）**

证据 B 的 **D 组**：单测 harness 用的是 `logger: () => {}`（`test/discovery.test.mjs:516`），**它存在、可调用、但返回 `undefined`** → `?.` 拦不住后续的 `.info`，会抛 `Cannot read properties of undefined (reading 'info')`。原代码正是靠这个 `try/catch` 兜住它。**去掉 `try/catch` 会让 3 个既有单测变红**，所以它是承重结构，不是冗余。

```js
    }
  }
```

**为什么把名字从 `'[socratic-engine:discovery]'` 并成 `'[socratic-engine]'`（【推断／待确认】已列末尾）**

- 任务书要求「`name` 用**固定且可辨识的一个**」——一个插件一个 logger 名，是这个要求的直读。
- 现实理由：**按名过滤日志时，分叉的名字会让发现层被漏掉**。本次验收的 A6 6.2 就是按 `name === '[socratic-engine]'` 过滤的——名字若保持分叉，**发现层那 5 条日志（含"问题：…"这条失败播报）不会被算作"被测插件的日志"**，等于留了一个盲区。
- 代价：失去了"哪条来自发现层"的直接区分。**缓解**：发现层每条消息文本本身自带上下文（"发现 N 个候选（状态 X），工作区根 …"），信息没丢。
- **这条我标【推断】——理由已写明，但"是否该保留分叉名"属可被用户推翻的口径选择。**
