## 1. 判据与阈值来源（浓缩版）

### 1.1 共同底座：怎么从一帧里认出"文字"

| 环节 | 做法 | 阈值来源 |
|---|---|---|
| 墨迹 | 与背景色 L∞ 距离 > **48** | 文字核心像素距黑底 ≥ 120、抗锯齿边 20–80，48 取在两者之间 |
| 色相族 | 12 族（30°/族）+ 灰阶；**分界平移 15°** | 不平移时 Manim `RED`（h≈4.7°）被 0/360 环绕切成两族 → 同一个红字被判成两个对象 |
| 去色噪 | 5×5 邻域多数投票 | 不做时一个字被拆成多个"对象"，第一版实测一次报出 986 处误报 |
| 连通域分类 | 单字 / 实心块 / 文字条 / **线状结构** / 其余（仍算文字墨迹） | "线状结构"用**每列墨迹纵向跨度中位数 ≤ 8 px** 判定：箭头与文字行在 bbox、填充率上几乎一样（A_P2 红箭头 209×28、填充率 0.191），只有"每列多厚"分得开（箭头 4 px，文字 ≥ 8 px）。"其余"必须保留——`r1_A_P1` 的「已完成/接着跑」与框线下边粘成 260×158 一个大域，只认"单字+文字条"会让它们整块消失 |
| 文字行 | **按色相族各自**做行投影（不跨族合并行带）→ x 方向空隙 > 30 px 再切 | 跨族合并行带是第二版最大误报源：相邻两行（灰「执行到一半」+ 黄「存的是…」）被并成一行，x 相交 0.80 → 误报 |
| 行的颜色 | 饱和像素的圆均值；饱和像素占比 < **0.30** 按灰阶处理 | 不设这条时，白字压在彩色条边上会从几个彩色像素里算出假色相（C_P3 的「完成时刻」行被判成 hue 86），D2 认错颜色 |

### 1.2 D1 文字重叠

**行对判据**：两条**不同色相族**的文字行，同时满足
① 色相差 ≥ **45°**（灰阶参与的配对，要求灰阶那侧平均饱和度 ≤ **0.10**）；
② x 支撑相交 / 较短者 ≥ **0.30**；③ y 区间相交 / 较矮者 ≥ **0.25**；
④ **相交区里双方都必须有墨迹**。

**同域双峰**（两字笔画粘成一个连通域时）：一域内两个色相峰差 ≥ 45°、各自 ±15° 质量 ≥ **0.30**、
且**两簇 x 质心相距 ≥ 25 px**。

**持久性**：同一处命中出现在 ≥ **2** 个抽样帧才算"持久"→ 阻断；只 1 帧 → warn。

> **阈值来源**（24 例 × 全帧实测）：单字内压缩色噪产生的假双峰 **gap 全部 ≤ 50°**，
> 而真重叠实测 52.2°（r1_A_P1）、140°（C_P1）、180°（r1_C_P3）→ 45° 取在中间，
> 并用"空间分离 ≥ 25 px"和"真灰阶 ≤ 0.10"兜住 45–52° 那一段（这两条一加，
> 8 例假双峰全部消失）。x/y 相交比 0.30 / 0.25 是**直觉值**，实测 24 例无误报。
> 持久性判据是照抄上一轮"9.6s 与 10.3s 两帧像素一致"的做法固化的。

### 1.3 D2 元素整段消失（脚本预期 ↔ 画面实测）

- **脚本侧**：静态抽 `Text/MarkupText/MathTex/Tex`（含返回 Text 的本地辅助函数），
  记录颜色（调色板常量名与 `#RRGGBB`）；`FadeOut/Remove/Uncreate` 视为移除；
  被 `Transform` 改写过的**不计入预期**并记入"未核对"。
- **画面侧**：末帧每条文字行**就近归属**到脚本声明的色系（色相最近且差 ≤ **40°**），
  再按 y 合并成"文字块"（相邻 ≤ 10 px 算同一块的多行），数块数。
- **判定**：实测 **0 块**且该色系在全片别的帧出现过 → **阻断**；实测 < 预期但未归零 → **warn**；
  该色系全片都没出现 → **warn**（色相对不上，不当作缺失）。

> **阈值来源**：`HUE_MATCH_TOL = 40°` 因为 **h264 实测色相漂移可达 25°**（A_P2 脚本写 `ORANGE`
> h≈25°，画面实测 h≈50°）。必须"就近归属"：一个 84° 的浅绿块会同时落进 60° 与 90° 两个容差圈，
> 按容差圈各自计数会把两边都算错（实测 60° 记成 3 块、90° 记成 0 块）。

### 1.4 D3 箭头/连线缺失

- **D3a（纯静态）**：创建了 `Arrow/Line/…` 但该名字**在整份脚本里只出现在它自己那次赋值上**
  → 必然没画出来 → 阻断。宁漏不误报（认不全的用法一律按"用过"处理）。
- **D3b（画面）**：脚本声明并 play 了某色系的箭头，而全片抽样帧里该色系的**非字形墨迹总量 ≈ 0**
  （< 150 px）→ 阻断。只在"连框线都没有"时才响。

### 1.5 D4 元素被压住

与 D1 共用行对遍历，用"谁被吃掉了"区分：一方落在相交区内的墨迹占比 < **0.10**、
另一方 ≥ **0.20** → **D4**（前者被压住）；否则 **D1**（并置相压）。
> 真重叠实测 frac 组合为 (0.948, 0.004) 与 (0.993, 0.412)；0.10 / 0.20 是**直觉值**，实测 24 例无误报。

### 1.6 🔴 被删掉的判据（留档，防止有人再加回来）

**「行带填充率异常」（原 D1b）已删除。** 实测 24 例里宽度 ≥ 60 px 的文字行填充率
**p95 = 0.367、p99 = 0.447、最大 0.501**，而 C_P1 那处真缺陷行的填充率是 **0.42**——
落在正常分布里。**没有区分度，删掉，不留假判据。**

同样删掉的还有 **「同族行高异常」**（想抓同色文字重叠）：合法堆叠标签与同色重叠在数据上分不开——
A_P2 的「时钟中断！」/「硬件打断」两个标签正常堆叠，行高 52–59 px、本帧行高中位数 18–19 px，
与 r1_B_P2 真重叠的 39 px / 中位数 18 px 落在同一区间。**删除，不留在代码里当摆设。**

## 2. 实现与用法

### 2.1 一条命令

```bash
python3 开源线/DSH定制/code/tools/animation-gate/animation_gate.py <视频.mp4> \
        [--script <场景.py>] [--out <证据目录>]
```

例（本轮验收实际用的）：

```bash
cd 开源线/DSH定制/code/tools/animation-gate
python3 animation_gate.py \
  "/Users/wujunjie/Documents/ChatGPT/大学申请/开源线/DSH定制/poc_动画可写性/media2/videos/C_P1/480p15/C_P1.mp4" \
  --script "/Users/wujunjie/Documents/ChatGPT/大学申请/开源线/DSH定制/poc_动画可写性/raw2/C_P1.py" \
  --out runs/C_P1
```

**退出码**：`0` = 机器层无阻断（可进入人工目视）；`1` = 有阻断级问题（**不能播**）；`2` = 输入/工具错误。

### 2.2 输出（一次运行的四样东西）

| 文件 | 是什么 |
|---|---|
| `contact_sheet.png` | **人看的那一半**：全部抽帧拼一张图（每格标帧名与时间），有命中的帧画**红框** |
| `zoom/` | 每处命中的 3–6× 放大图（D2/D3 没有 bbox 时给整帧） |
| `verdict.md` | 判定 + **每处命中的原始数字与帧号** + D2/D3 的"脚本预期 vs 画面实测"对照表 + 「待你目视确认」 |
| `verdict.json` | 机器可读全量：逐帧文字行统计、全部阈值、findings、D2/D3 明细 |
| `frames/` | 抽帧 PNG（2.5 fps + 末帧）与 `frames.json` 清单 |

### 2.3 幂等、可重跑

抽帧清单带 `视频 sha256 + 抽帧频率` 的 key；同一份视频重跑**不重新抽帧**，`verdict.json` 字节级一致
（实测：同一输入两次运行 sha256 相同）。抽样帧数固定（2.5 fps + 末帧），不含时间戳。

### 2.4 失败文案

判"不能播"时逐条打印类别、帧号、原始数字，例如：

```
[闸门] C_P1.mp4 → BLOCK（阻断 1）
   - D1 block ×1
```
`verdict.md` 里对应的一行：
`D1 | block | 1 | f_0014.png @ 5.2s | 行对；色相差 142.2°（阈值 45.0）；「红」1509px ×「蓝」450px；
x 相交 0.317（阈值 0.3）／y 相交 0.867（阈值 0.25）；落在相交区的墨迹占比 0.871 / 0.071；
交点 x164–183 y269–282`

—— 类别、帧号、每一类判据的数值与阈值都在一行里，能照着去改脚本。

### 4.2 B_P2「缺箭头」——不成立

- `r1_B_P2` 的画面里，红色箭头（`到点！硬件打断` → `内核决定`）**在**：
  D3 核对表实测该色系**非字形墨迹 3119 px**、紫色 3193 px。
- `raw2/B_P2.py`（对照轮）同样两条箭头都在（`irq`、`ctl`）。
- 第一轮报告自己的原话是"**绿色箭头方向可读**，但因果链是『定时器→CPU』再『CPU→内核』两段"——
  那是**语义**层面的表述问题，**不是缺箭头**。任务书里那句"没有箭头"与报告正文不一致。

**结论**：24 个真样本里**没有一个真的缺箭头**。D3 的阳性只能靠人为突变造（§3.4 #3/#4）。

### 4.3 唯一一处真漏报：`r1_B_P2` 末帧标题被结论句压住（同色文字重叠）

🔴 **漏报**。`r1_B_P2` 末帧最上方，白色结论句「中断≠每次换进程：切或不切，由内核决定」
**压在白色标题「第1讲 · 时钟中断：内核怎样重新介入」上面**，两行都是白色。

- **为什么抓不到**：D1 的前提是"两个**不同色**的文字行"，同色文字压在一起色相差为 0，判据不触发。
- **闸门给了什么**：只给了 **warn** 级信号——D2 表里 `灰阶 脚本预期 3 块 / 末帧实测 2 块`
  （两行白色文字并成一块，块数少 1）。这个 warn 会把该帧画红框送进 contact sheet，**但不会阻断**。
- **要抓它需要什么**：需要对象级跟踪（把"哪几笔画属于同一个 Text 对象"还原出来），
  或者 OCR／模板匹配。本轮**试过并放弃**的替代判据：「同族行高异常」（同族相邻两行若中间还有全空行
  会被切开，切不开且行高近两倍 → 疑似同色重叠）——**数据不支持**：合法堆叠标签（A_P2 的
  「时钟中断！」/「硬件打断」，行高 52–59 px）与真重叠（r1_B_P2，39 px）在"行高 / 本帧行高中位数"
  这个统计量上完全重叠。**判据已从代码里删除，没有留在代码里凑数。**
