## 一句话结论

**老师最后问了问题但未出现选项卡片，根本原因在于「契约断裂」：舞台前端 `client.js` 严格要求老师正文以行首编号清单（`1. xxx` / `2. xxx`）格式输出选项才渲染卡片，而教室纪律层（`_anchor.md`）与教学引擎（`socratic-engine`）侧从未对模型注入「提问必须用编号清单给出选项」的渠道纪律，甚至在 `_anchor.md` 中禁止了类似回答指南的界面说明，导致模型按纯文学叙事自然输出开放式问句，前端解析为空，优雅退化为 0 个卡片。**

## 三、是设计如此，还是遗漏？

### 3.1 历史事实还原
在 `开源线/DSH定制/排产计划_技术线_2026-09-24.md` 第 2254–2260 行（2026-09-30 第九段记录）：
> *“先查了教室与引擎有没有选项字段：grep options|choices|选项 在 classrooms/cs-os/classroom.yaml 与 plugins/socratic-engine/index.mjs 全部零命中 → 没有这个字段。→ 处置：显式认一种形状（行首编号清单），而不是编一个字段、更不是让模型凭空产出……抽不到 → 不显示选项（优雅退化，绝不产生幻觉选项）……”*  
> 并在第 2283 行明确留下尾巴：  
> *“**仍未做**：真实选项在真会话里上屏（需要模型回一段编号清单 —— 属 goal 第 4 条，等凭据授权）。”*

### 3.2 性质判定：教室纪律层遗漏了「渠道纪律」
1. **舞台侧的设计是自觉的**：舞台前端在设计之初就预料到大模型可能不输出选项，因而采用了“认编号清单这一硬形状，匹配不到则优雅退化为 0 个卡片”的防御性实现，避免捏造虚假选项。
2. **链路整体是断裂的**：舞台单方面指望大模型输出行首编号清单，但**上游的提示词和纪律层没有任何一处告知大模型这项契约**。
3. **符合核心实测铁律**：`开源线/AGENTS.md` 第 25 行明确载有核心经验：
   > `🔴 "引擎挂上工具 ≠ 老师会用"——工具必须有"渠道纪律"，已连续第三次实证（2026-09-24）`  
   > `规则：每新增一个"给模型用的能力"，必须同时在教室的纪律层（_anchor.md 的"本课不许违反项"）写一条"渠道纪律"，写明什么时候用它、和已有渠道的分工与优先级；只把工具注册上去＝它不会存在。`
4. **结论**：选项卡片虽然不是工具，而是舞台消费的「文本交互契约」，但其逻辑完全等价——**缺少渠道纪律，模型必然按默认文学对白输出开放问答，选项卡片永远无法出现**。因此，这是**教室内容侧（`_anchor.md`）缺了一条关于交互选项的渠道纪律**。

## 四、方案对比与修改建议

| 维度 | 方案 A：改教室内容（`_anchor.md` 补渠道纪律） | 方案 B：改舞台解析（`client.js` 的 `parseOptions` 放宽） |
|---|---|---|
| **改动位置** | `classrooms/cs-os/_anchor.md` 的「本课不许违反项」 | `code/clients/classroom-stage-warm/lib/client.js` 的 `parseOptions` |
| **修改性质** | 纯 Markdown 文本规则，增加 1~2 条纪律约束 | 修改客户端前端 JavaScript 语法树与正则匹配逻辑 |
| **生效代价** | **极低**：保存文件即生效（下一回合注入生效）；无需重装插件，无需重启 DSH 服务 | **高**：需修改源码、重新通过 9 项单测、重新跑 profile 重装与客户端刷新 |
| **对模型表现影响** | 引导模型在提出推进问题时，明确列出 2~4 个编号候选，符合交互预期 | 无法引导模型行为，模型仍输出长段开放式叙述 |
| **假阳性/幻觉风险** | **零**：格式由模型严格按规范生成 | **极高**：若放宽至“一行一个问句”或分段拆分，极易把角色普通台词或心理活动错判为卡片，产生幻觉选项 |

### 推荐结论
**强烈推荐方案 A**。

#### 方案 A 实施要点（供后续排产参考）
在 `_anchor.md` 的「本课不许违反项」中追加一条**选项渠道纪律**，示例建议：
> - 🔴 **选项渠道（驱动舞台交互卡片）**：在阶段性向学生提问、需要学生做选择或继续推理时，**在发言末尾用明确的编号清单（`1. xxx` / `2. xxx`，2–4 项）列出直觉方向或推导选项**。选项文字保持简短（≤20字），符合场景内小鞠的语气；不要输出开放式无选项的空提问，也不要用非数字符号（如破折号、圆点）。
