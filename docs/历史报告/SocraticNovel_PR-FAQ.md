# SocraticNovel · PR/FAQ（2026-09-19 起草）

> **这是什么**：Amazon **Working Backwards** 的核心工具。**在建之前先写"假装已经发布了"的发布稿 + FAQ**。
> **它的用途不是营销，是决策**——官方判据逐字：*"If the press release doesn't describe a product that is meaningfully better (faster, easier, cheaper) than what is already out there, or results in some stepwise change in customer experience, then it isn't worth building."*
> **格式硬约束**（官方）：发布稿 **"a few paragraphs, always less than one page"**；FAQ **"five pages or less"**。
> ⚠️ **本件是虚构的练习稿**（这正是该方法的设计：假装已发布）。**里面那句用户引语是占位符，不是真实用户的话**——在没有真实用户之前不得对外使用。
> 上游：`SocraticNovel_宣传素材与待办.md`（素材库）｜`SocraticNovel_上层设计待办清单.md`（A–E 组）

---

## §0 C1 定案：发布稿**写给「用户」**，不写给「受众」

**理由（不是偏好，是方法的定义）**：
- Amazon 的 PR 是**决策工具**，不是营销文案。它的判据要求回答"**比用户现在用的好在哪里**"。
- 而"用户现在用的"是**替代方案**：GPT、机构、网课、生啃课本。**只有对着"用户"才能回答这个问题。**
- 若把 PR 写给**受众**（觉得有意思的人），它就退化成营销文案，**失去"判断该不该建"的功能**。

🔴 **所以两条线分工**：
| | 对象 | 载体 | 目的 |
|---|---|---|---|
| **PR/FAQ** | **用户**（被某门死板课程卡住的大学生） | 本文档 | **决策**：该不该建、比替代方案好在哪 |
| **传播素材** | **受众**（觉得有意思的人） | `宣传素材与待办.md` §1/§2 | **涨★**：让人点进来 |

→ 两者不矛盾：**PR 回答"它值得存在吗"，传播素材回答"怎么让人知道它存在"。**

## §1 发布稿（PR）——**硬上限：1 页以内，不许出现技术词**

> ### 大学给了你一门课，但没给你一个老师
>
> **SocraticNovel 今天开源：把任何一门教材，变成按你能懂的方式讲给你听的课**
>
> 2026 年 X 月 X 日 —— 今天，SocraticNovel 在 GitHub 上开源。
>
> 每个大学生都有一本必须读、但读不懂的书。
>
> 大学的结构是：一位教授，两百个学生，一本权威但难读的教材。老师讲一遍，剩下的时间你自己回去啃。于是真实的解法变成了**拼装**——B 站的公开课、国外教材的翻译版、学长的笔记，再加一个通用 AI 助手。拼得出来的人靠自学能力和运气；拼不出来的人，就卡在某一章，然后这门课就这么过去了。
>
> SocraticNovel 做的是另一件事：**你把那门课的教材交给它，它按你能懂的方式重新讲一遍。**
>
> 它不直接给答案。它一个问题一个问题地问你，直到你自己把那个结论推出来——因为自己推出来的东西才记得住。它记得你上周卡在哪，所以知道这次该从哪一层讲起。你卡住的时候，它会用你熟悉的东西打比方；你答错的时候，它不会不耐烦，下次还会回头问你。
>
> 它和网课的区别是：**网课听不懂不会停，你也没法问。**
>
> 它和一个通用 AI 助手的区别是：**通用助手不知道你的水平在哪，只能说给所有人听。**
>
> > "我以前的解法是把能找到的课都看一遍，然后自己拼。拼完还是散的。"
> > —— 一位计算机系学生（⚠️ **占位符，非真实用户**）
>
> SocraticNovel 完全免费、完全开源，教材和你的学习记录都留在你自己的电脑上。
>
> 今天就可以开始：把你手上那门最难的课的教材交给它。

### 逐条过 Amazon 的判据
| 判据 | 我们的答案 | 通过吗 |
|---|---|---|
| **更快** | "不用再自己拼课了" | ⚠️ **半通过**——学习本身不会变快，**变快的是"从看不懂到看懂"这一段** |
| **更容易** | **按你能懂的方式讲**（记住你的卡点 → 知道从哪一层讲起） | ✅ **通过** |
| **更便宜** | **完全免费 + 开源** | ✅ **通过** |
| **台阶式变化（stepwise change）** | 🔴 **从"你自己去啃"变成"有人按你能懂的方式讲"** | ✅ **通过**——这是真实的台阶，而且**大学里本来没有这一级**（一个教授对 200 人＝你实际上没有老师） |

🔴 **写出来才发现的**：**我们真正的差异是"讲得懂"，不是"学得快"。**
原文作者主张"效率提升三倍"——【原文】逐字：*"10 个小时能顶过去 30 个小时"*，但他**紧接着自己承认**：*"这归根结底是个**实证问题，我目前当然还没有数据**"*。
→ **所以我们对外只说"讲得懂"，不说"快三倍"。** 前者可证，后者不可证。

## §2 外部 FAQ（客户会问的硬问题）

| # | 问题 | 答案（或状态） |
|---|---|---|
| 1 | **和 ChatGPT 有什么区别？** | 三条：① **它不知道你的水平在哪，只能说给所有人听**；我们记得你的卡点，知道从哪一层讲起 ② 它是"展示"（甩给你一整面推导），我们是"引导"（问到你推出来）③ 它没有"人"，问完就走 |
| 2 | **要花钱吗？** | **不要**。完全开源免费。⚠️ **但见 §3 内部 FAQ 第 2 条（API 费用谁出）——这是本文档暴露出的最大未解决问题** |
| 3 | **我的教材能用吗？** | 能。PDF / EPUB / Word / Markdown 都行（复用现成开源工具，见能力清单 E2）。⚠️ **扫描版 PDF（纯图片）需要额外处理，暂不保证** |
| 4 | **英语不好行不行？** | **行，而且这是我们的强项之一**。【p2】原话：*"这个系统可以扔进去英文教材但用中文授课"* |
| 5 | **要装什么？** | ⚠️ **未定**（取决于最终形态：Claude Code skill / CLI / 网页版）。**这一条的答案直接决定门槛高低** |
| 6 | **要多久见效？** | 一节课。第一节课结束时你应该能感到"这一章我懂了"。⚠️ **不承诺"效率提升几倍"**（见 §1） |
| 7 | **和我学校教的不一样怎么办？** | 那正是它存在的理由。它不替代你的课，**它让你能跟上你的课** |
| 8 | 🔴 **如果它讲错了怎么办？** | ① 你发现错了可以直接告诉它 ② **你的纠正会被记下来，用来改教材**（这是 B2 里最深的那项投入）。⚠️ **但不能保证零错误——这是一个真实局限，要如实说** |
| 9 | 🔴 **我快考试了，现在开始来得及吗？** | **来得及，而且这正是它的用法**：不用从头学，**把你不懂的那几章挑出来**。→ ⚠️ **这是最高意图的时刻，应该单独做一版文案** |
| 10 | **我的数据会被拿走吗？** | 不会。所有数据在你自己电脑上（教材、学习记录、对话）。⚠️ **但会调用大模型 API——这一点必须说清楚，不能说"完全不上网"** |
| 11 | **它能讲我的专业课吗？**（有机化学 / 法律 / 会计…） | ⚠️ **部分能**。隐喻映射系统目前只做好了几个学科（【AT】物理／统计学／Java…），**计算机系的硬课（组成原理／操作系统／编译原理）还没做** → **这是待补的** |
| 12 | **会不会让我变懒、变成代写作业？** | 不会——**它不给答案**。这是苏格拉底教学法的定义。⚠️ 但要如实说：**你确实可以逼它直接给答案，我们不做技术拦截** |
| 13 | **不用 Windows 行不行？** | 待定（取决于形态）。⚠️ 见 §3 第 6 条 |
| 14 | **要我付 API 费用吗？** | ⚠️ **见 §3 第 2 条** |

## §3 内部 FAQ（硬问题，这才是 PR/FAQ 的用处）

| # | 问题 | 状态 |

| 4 | **为什么不做成 App / 不做账号系统 / 不做论坛？** | App：**不带来任何一个★**，且吃掉两周（★ 来自网页与 README）。账号系统：**它是网页版的前置，不是★的来源**。论坛：**冷启动死路**——我们现在 0 issue、0 PR、停更半年，**先用 GitHub Issues**（issue 数量本身就是招生官能读懂的采用证据，现在那个数字是 0）。 |
| 5 | **为什么开源？** | ① 【原文】作者已经公开了完整方案并主动放弃独占（*"以一种开源精神来拥抱竞争与合作吧"*）→ **独占不可能** ② 开源是我们"外部认可"的唯一来源（Q4 定案做社区项目）③ 开源让"用户纠正她"这件事有地方去（B2） |
| 6 | **不用 Windows / 用手机行不行？** | ⚠️ 未定。**【AT】`airi` 49,300★ 已支持 Web/macOS/Windows**，可参考其覆盖面。**优先级：Web > macOS > 手机**（手机不在 30 天内） |

| 9 | **如果没人用怎么办？** | **kill criteria 未定**（F2，已推到下一阶段）。 |

### 4.3 README 第一屏信息架构（按顺序）
1. **一句英文 hook** + 一句中文（英文在上——国际流量是 GitHub 发现的主体）
2. 🔴 **一段 30 秒真实课堂录屏（GIF）**——现在 README 里 **0 张图**
3. **三行"它做什么"**（不给答案／按你能懂的方式讲／记得你卡在哪）
4. 🔴 **一个"立刻试试"的入口**（Live Demo 链接）——现在没有在线站点
5. **一行安装命令**（自动写好 `CLAUDE.md`；现在 fork 的人第一件事就是自己补这个文件）

### 🔴 三条立刻可用的结论
1. **对外口径改掉"效率三倍"** → 改成 **"讲得懂"**（可证、诚实、且就是我们的差异）。
