## 1. ① schema：字段集与「每个字段为什么必须存在」

### 1.1 定 schema 时用的唯一判据

> **白名单只收「有明确消费者，且该消费者在本轮或下一批已定案」的字段。** 每个字段在 §1.4 点名它的消费者（哪个函数／哪一步读它）。凡消费者不存在或未定案的一律**不收**——包括研究 §10.2／§10.3 里列过、但本批没有落点的字段（§1.5 逐个列出并给理由）。

另一条同样重要：**引擎不藏默认值**。凡影响教学行为的数值（额度、开场保护、僵局阈值）**一律必填**，写在教室里；引擎侧没有一份"默认值"可与教室声明分叉。

### 1.2 `cast:` 段（角色表）

```yaml
cast:
  # 教室级出场规则（有启用中的同学 → 必填；段内三字段全必填）
  policy:
    lessonQuota: 4                        # 每讲最多出场几次（用户口径 3–5）
    minTurnGap: 5                         # 开场保护：前几回合不出场
    allowedPhases: [probe, check, review] # 同学可出场的相位（open/close 不出场）

  roles:
    - id: komari                          # 引用键
      file: characters/komari.md          # 人格文件在哪
      name: 小鞠知花                       # 名牌上显示的名字
      role: teacher                       # teacher | buddy | guest
      enabled: true                       # 本讲开关
    - id: chengji
      file: characters/chengji.md
      name: 程霁
      role: buddy
      enabled: true
      style: precise                      # 认知风格（四选一，闭合值域）
      styleLabel: 精确型                   # 给学生看的中文标签
```

**逐字段依据（没有一个字段是随手加的）**

| 字段 | 必填？ | 为什么必须存在（消费者） |
|---|---|---|
| `cast` | 段可选 | 顶层段本身可选；**不写 ⇒ 引擎行为与今天完全一致**（§4） |
| `policy.lessonQuota` | ✅（有启用同学时） | 约束④「发言是稀疏事件（每讲 3–5 次）」的**唯一落点**；下一批的额度门第一句读它（研究 §9.2） |
| `policy.minTurnGap` | ✅（同上） | 约束④／研究 §9.3「开场保护」的阈值。**不能由引擎拍**：研究 §9.3 的依据是教室 `world/setting.md` 的过渡场景长度 |
| `policy.allowedPhases` | ✅（同上） | 研究 §6.4 门 2：同学只在 probe／check／review 出场，open（老师建场景）／close（老师收束）不出场。**必须显式列**，因为"哪些相位是开场/收尾"是**内容**（各教室相位不同），引擎不许硬编码 |
| `roles[].id` | ✅ | **引用键**：`cue.triggers[].roles` 要引用它、`cue_log` 要记它、下一批的"防连说两次"要按它比（研究 §6.4 门 3） |
| `roles[].file` | ✅ | 约束⑧「格式照 `characters/komari.md`」⇒ **人格文件在哪**是角色声明的一部分；**校验其存在性**（有 `baseDir` 时） |
| `roles[].name` | ✅ | 名牌。研究 §4.1／§4.5：名牌是**角色声明的一部分**，不运行时算；也是 §5.1.5「注入行自带名字」那条通道要写进台词的那两个字 |
| `roles[].role` | ✅ | ① 硬约束的判定键（**只有 teacher ⇒ 行为不变**，§4.4）；② 下一批的选人池（`buddy`／`guest` 才是同学）；③ 客串位轮换（约束⑤"每讲客串 1 位"） |
| `roles[].enabled` | ✅ | 约束⑤／研究 §10.2 的 MVP 开关（示例位默认关闭，**不删掉**）。同时是"先跑没有同学的课"的另一条开关 |
| `roles[].style` | ✅（仅同学） | 约束⑤「玩法多样＝**认知风格差异 × 知识点错法**」⇒ 选人匹配的**机器键**（研究 §9.4 是查表、不是算分）。闭合值域四选一：写错即报错，不静默降级成"没有风格" |
| `roles[].styleLabel` | ✅（仅同学） | 研究 §7.3 的台词骨架里 `{name}（{styleLabel}）` 是**给学生看的中文标签**。机器键 `precise` 不能直接给学生看，而这张"英文键→中文标签"的表属**内容**，不许硬编码进引擎 |

### 1.3 `cue:` 段（出场提示）

```yaml
cue:
  # 僵局判据参数（triggers 里有 when: stall → 必填；段内字段全必填）
  stall:
    nTurns: 3                            # 连续 N 回合无新知识点
    shortWindow: 5                       # 取最近 N 条学生消息算长度中位数
    shortRatio: 0.4                      # 本回合长度 < 中位数 × 0.4 → 计"变短"
    shortFloor: 8                        # 中位数 < 8 字时不判"变短"（防误伤习惯短答的学生）
    dontKnowPatterns:
      high: ["不知道", "不会", "想不出来"]  # 命中 1 次即计僵局
      mid: ["大概", "我不确定"]            # 须与 nTurns / shortRatio 共现才计
    dontKnowExempt: ["不会影响", "不会导致"] # 误伤白名单（"不会影响"是正确技术表述）

  triggers:                              # 数组顺序即优先级
    - when: stall
      roles: [chengji]                   # 可选：限定可出场的角色子集
    - when: student-hit-known-wrong-step
      source: runtime/wrong_step_library.md
    - when: teacher-invite
```

**逐字段依据**

| 字段 | 必填？ | 为什么必须存在（消费者） |
|---|---|---|
| `cue` | 段可选 | 不写 ⇒ 不出场；**写 `triggers: []` ⇒ 显式不出场**（"先跑一讲没有同学的真实课"的开关） |
| `triggers` | ✅（段存在时） | 三条出场路的声明（研究 §6.4 门 4）。**数组顺序即优先级**——沿用教室既有约定「顺序即推进顺序」（顶层 `phases:` 就是这么写的），所以**不另设 `priority` 字段** |
| `triggers[].when` | ✅ | 闭合值域 `stall`／`student-hit-known-wrong-step`／`teacher-invite`；写错即报错（研究 §6.4 三条路，路 A 僵局／路 B 错法命中／路 C 老师邀请） |
| `triggers[].roles` | 可选 | 🔴 **任务书明确要求的校验项**："`cue` 引用了不存在的角色 → 报错"。它同时有真实用途：把某条出场路**限定**给某位角色（不给就整个键不写） |
| `triggers[].source` | ✅（仅错法路） | 约束③「错法必须来自错题本或判据的反面，不能是模型即兴编的稻草人」⇒ **来源文件必须写明**（且校验存在性）。别的路写了它报错（防"配了不生效"） |
| `stall.nTurns` | ✅（有 stall 路时） | 研究 §8.2 规则一的阈值；§8.5 明确"给方法不给拍脑袋的数字" ⇒ 逐教室校准，**引擎不藏默认值** |
| `stall.shortWindow` / `shortRatio` / `shortFloor` | ✅（同上） | 研究 §8.2 规则三"变短"的**三个不同角色**：窗口（样本量）／比例（阈值）／下限（防误判习惯短答的学生）。少任一个该规则就不成立 |
| `stall.dontKnowPatterns.high` | ✅（同上） | 研究 §8.2 规则二的高置信词表（命中 1 次即计）。**属内容**（中文表述），不许硬编码进引擎 |
| `stall.dontKnowPatterns.mid` | ✅（可为空数组） | 研究 §8.3 合成规则要求"中置信须与 nTurns／shortRatio 共现才计"⇒ **必须与 high 分开**，否则合成规则无法表达 |
| `stall.dontKnowExempt` | ✅（可为空数组） | 研究 §8.2 规则三③的误伤白名单（C6 定案："不会影响／不会导致"这类**正确技术表述**）。没有它，`"不会"` 会系统性误判 |

### 1.4 三条贯穿全段的纪律（写进代码，不是写在文档里）

| # | 纪律 | 落地 |
|---|---|---|
| 1 | **未实现的键一律报错，不静默忽略**（C2 的原话："避免新文件与'写错静默失效'"） | 每层都有 `assertKnownKeys()` 白名单：`cast`／`cast.policy`／`cast.roles[]`／`cue`／`cue.triggers[]`／`cue.stall`／`cue.stall.dontKnowPatterns` |
| 2 | **声明了就必须被读到**（反向的静默失效） | 交叉校验：`cue.stall` 有而 `triggers` 无 `stall` → 报错；`triggers` 有 `stall` 而 `cue.stall` 缺 → 报错；`source` 只准出现在错法路；`cue` 出现而 `cast` 缺席 → 报错；`cast` 只有老师而 `triggers` 非空 → 报错 |
| 3 | **报错要能让作者自己改** | 每条报错 = `classroom.yaml: <YAML 路径>（第 N 行）<问题>（期望值／可用值）`。行号由 `parseDocument` 的节点 `range` 偏移二分求出（键缺失时退到最近的已存在祖先节点） |

### 1.5 明确**不收**的字段（研究 §10.2／§10.3 列过，本批砍掉）

> 砍掉的理由分三类：**(甲) 消费者不存在**（本批与下一批都不读）；**(乙) 是人格内容，应放角色文件**（避免同一事实两个维护点）；**(丙) 未实现**（收了就会"配了不生效"）。**加字段＝扩白名单，不破坏现有教室**——所以"现在不收"是安全方向。

| 字段 | 类别 | 理由 | 什么时候该加回来 |
|---|---|---|---|
| `cast.roles[].name_color` | 甲 | 当前通道（`user/message` ＋ 自有 `source.kind` → **宿主渲染成带名字的注入行**）**颜色不可控**，这个字段**没有任何消费者**。研究 §4.1 的配色依据服务的是**自绘 UI**（立绘／名牌），属客户端插件（T5）的声明 | 做"自绘消息节点"或客户端面板时（**这是最可能第一个被加回来的**） |
| `cast.roles[].cue_description` | 丙 | 只有 B 形态（`judge: model` 两级过滤）才读它。MVP 默认 `rule`、本批不做 model 判断 | 实现"规则粗筛＋模型细判"时，与 `policy.defaultJudge` 一起加 |
| `cast.policy.defaultJudge` | 丙 | 同上 | 同上 |
| `cast.policy.density`／`denseQuota`／`denseMaxPerTurn` | 丙 | 约束⑥的"密集模式"是**可选功能，本批未实现**。收了它 = 作者写 `density: dense` 而引擎按稀疏跑 = **正是 C2 要防的"配了不生效"** | 与密集模式的行为**同批**加 |
| `cast.policy.speakFormat` | 乙 | 三个独立 prior art 一致收敛为 `名字: 台词`（SillyTavern `openai.js:594-611`／AutoGen `_selector_group_chat.py:216-228`／generative_agents `converse.py:148`）⇒ **它不是"选择"，是格式**。做成可配置＝"以后可能有用" | 不加（真要加，先拿反例来推翻三家一致） |
| `cast.roles[].voice`／`stance` | 乙 | 是**人格内容**，放 `characters/*.md`（约束⑧ 的格式）——放两处＝同一事实两个维护点（项目规矩："一条内容只能有一个维护点"） | 不加；下一批的台词语言化（研究 §7.4）从**角色文件**取 |

| `cast.roles[].styles`（复数） | 乙 | 与单数 `style` 高度重叠。约束⑤的"玩法多样"用**固定搭子 1 ＋ 每讲客串 1** 已能表达（一个角色一个主风格） | 若真出现"一个角色要胜任多种风格"，再加（会引入"匹配时怎么选"的新问题） |

### 2.4 行号是怎么来的（一个通用算法，不是补丁）

```
parseDocument(text)                    → 保留 Document（不只要 toJS 结果）
  doc.getIn(path, true)                → 该 YAML 路径对应的 Node，带 range = [start, valueEnd, nodeEnd]
  starts[]（全文换行偏移索引）           → 二分求 offset 所在行
  键不存在时逐级回退到最近的已存在祖先   → 缺失键指向"它所在的映射"，那才是作者该看的那一行
```

实测语义（与直觉一致）：**映射节点**指向它的**第一个键**那一行；**块序列元素**指向 `-` 那一行；**标量**指向自身；**缺失键**指向最近的祖先映射。

### 6.1 C13 —— `apply()` 的 `ctx` 是**挂载点**的 scope，不是"父 agent 的 scope"

**机制（源码逐字）**：

- `dsh-scope` 的 `ScopedLayers.effect(ctx, …)`：`const scope = scopeOf(ctx)`；**`scope === undefined` ⇒ 注册落到「全局层」**（`dsh-scope/lib/index.js:189`，类定义在 `:132`）。
- `dsh-system-prompt` 的 `section(section)`：`return this.layers.effect(this.ctx, …)`（`dsh-system-prompt/lib/index.js:238-241`），JSDoc 逐字：*"Register an ordered prompt section in the calling context's scope."*
- `Service` 构造器把 `this.ctx` 存成**它被构造时所在的 ctx**（`cordis/lib/index.js:1769-1783`），但 cordis 在**按调用者上下文取服务**时返回**按调用者 scope 重绑定的实例**——实测 `ctx.systemPrompt !== 根实例`，且 `scopeOf(ctx.systemPrompt.ctx)` ＝ 调用者的 scope 标签。

**实测（探针逐字输出）**：

```
C13-1 scopeOf(服务自身的 ctx) = undefined                      ← 根上构造的服务实例无 scope
C13-2 root 注册后：global = [harness:identity, deployment:persona-prefix, deployment:persona-suffix, probe:from-root] | scoped.size = 0
C13-3 插件 apply() 收到的 ctx：scopeOf(ctx) = {"probe":"agentA"}  ← 挂在 scope 里的插件，ctx 带该 scope 标签
C13-3b ctx.systemPrompt.ctx 的 scopeOf = {"probe":"agentA"} | 是同一个实例 = false   ← 服务实例按调用者重绑定
C13-4b scoped 层的 key = []                                      ← 从 root 注册 → 全局层，scoped 为空
C13-10b scoped 层的 key = [ '{"agentLoop":"L1"}' ]
C13-10c 层 {"agentLoop":"L1"} 内容 = [ 'probe:from-loop' ]        ← 从 loop scope 注册 → 落到该 scope 的层
```

**链式可见性实测**（`probe_c13_chain.mjs`，键对象**复用同一实例**——scope key 是**对象身份**，不是结构值）：

```

preset  读到 = [ 'probe:at-preset' ]

loopB   读到 = [ 'probe:at-preset' ]                          ← 子代理：**看不到** probe:at-loopA
root    读到 = []
无关 scope 读到 = []
```

**结论（可照写）**：

| 情形 | `apply()` 的 ctx | 注册落到 | 谁看得见 |
|---|---|---|---|
| **`socratic-engine` 现在的挂法**：profile patch（`cordis.patch.yml` 顶层 `insert`） | **无 scope** | **全局层** | 🔴 **每一个 agent，含子代理** |
| 挂进 agent preset 的 composition 文件 | `{agentPreset: <id>}` | 该 preset 的 standing scope 层 | 只有 join 了该 preset 的 agent（＋ 通过 `composeFrom` 加入的子代理） |
| 用 `payload.agent.ctx`（`agent/pre-step` 的 payload 由 `agentEvents()` 融合 `agent`，见 `dsh-agent/lib/index.js:209-213`）在**某个 agent 的 loop scope** 上注册 | 该 loop 的 scope（key ＝ `ReActLoop` 实例，`dsh-agent-loop/lib/index.js:761-762`） | 该 agent 自己的层 | **只有这一个 agent**——子代理的链是 `childLoop → preset`，**不含父 agent 的 loop 层** |

🔴 **这同时给了研究 §5.4.1 那条"修补方向"一个明确答案**：**"让老师人格只在父 agent 的 scope 里注册"在机制上可行**（读 `payload.agent.ctx` → `systemPrompt.section(...)`），且效果正是它要的（子代理不再继承教师人格）。两个必须注意的点（**标【推断／待确认】**，本轮未实现、未端到端验证）：
① 每个 agent 都要注册一次，且**同一层同名 section 会抛错**（`dsh-system-prompt` 逐字："duplicates within one layer and non-finite orders throw"）→ 需要幂等；
② 注册是 `ctx.effect`，随该 agent 的 fiber 释放——这一点与"会话结束即回收"正好吻合。

### 6.2 C14 —— `sessionProjections.register` 的签名与硬约束

**签名（`dsh-session-projection/lib/index.js:68-105` 逐字结构）**：

```js
const dispose = ctx.sessionProjections.register({
  key,                       // 投影键（字符串）
  stateVersion,              // 非负安全整数
  stateSchema,               // 状态的 wire 校验（zod 形状）
  init(header, inheritedEventCount) → state,
  apply(state, event) → state,          // 纯折叠，对**每一条已提交事件**急切执行
  wire: { viewSchema, view(state) } | undefined,   // 可选：给客户端看的视图
})
// 返回 () => void（disposer）
```

**实测（探针逐字输出）**：

```
C14-1 register 返回值类型 = function
C14-2 已注册 key = [ 't8a-probe' ]
C14-3 记录字段 = [ 'key', 'stateSchema', 'init', 'apply', 'wire', 'stateVersion' ]
C14-4 同 key 同 stateVersion 再注册 → refs = 2
C14-5 同 key 不同 stateVersion → session projection key "t8a-probe" is already registered at stateVersion 0; refusing to share it with stateVersion 1
C14-6 stateVersion 负数 → session projection "t8a-bad" stateVersion must be a non-negative integer, got -1
C14-7 stateVersion 非整数 → session projection "t8a-bad2" stateVersion must be a non-negative integer, got 0.5
C14-8 无 wire 也能注册（key 集合） = [ 't8a-probe' ]
C14-9 dispose 后 refs = 1 | 仍在册 = true
```

**四条硬约束（做右栏状态时必须照做）**：

1. **`wire` 可选**；`key`／`stateVersion`／`stateSchema`／`init`／`apply` 五件必需。
2. **`stateVersion` 必须是非负安全整数**，否则抛错（连 0.5 都拒）。
3. **同 key 可注册 N 次（ref 计数）**，但**同 key 不同 `stateVersion` 直接抛错**（"refusing to share it"）→ 版本号一旦发布就不能在同一进程里共存。
4. **注册是 effect，骑在调用者的 fiber 上**（`this.ctx.effect(..., "sessionProjections.register()")`）；`dispose()` 只减 ref，**ref 归零才真正注销**（`C14-9`：两处注册、只 dispose 一处 → `refs = 1`、仍在册）。
   另有一条**载荷纪律**（模块头逐字）：*"a state-carrying log event MUST carry the complete post-change state, never a bare delta"*——**事件带全量状态，不许带 delta**。

```yaml
    - when: student-hit-known-wrong-step
      source: runtime/wrong_step_library.md
    - when: teacher-invite
```

**两条与"先跑没有同学的课"配套的写法（两种都合法）**：

```yaml
# 写法一（最省）：整段不写 cast／cue —— 引擎行为与今天完全一致（本批已实测）
# 写法二（显式）：保留 cast 与 policy，但把开关关上
cue:
  triggers: []          # ＝本教室不安排同学出场
```

🔴 **不要**写成"只有老师的 `cast` ＋ 非空 `triggers`"——那是**死配置**，校验器会报错（§3 倒数第二条）。

## 9. C4 方案（错题本加稳定 id 列）——**本轮只出方案，未改教室文件**

> C4 定案逐字：*"错题本加稳定 id 列 ✅ 加（否则错法无法被引用）——随多角色实现批次做"*。本轮按任务书只出方案。

### 9.1 现状（只读核对）

`code/classrooms/cs-os/runtime/mistake_log.md` 现表头：`日期 | 讲次 | 题目 | 他的答案 | 正确答案 | **错在哪一步**`，正文只有一行占位（"待第 1 讲后填写"）。`runtime/wrong_step_library.md` **不存在**。

### 9.2 方案（三张表，各司其职）

**① `mistake_log.md` 加两列：`id` ＋ `kpId`**

```markdown
| id | 日期 | 讲次 | kpId | 题目 | 他的答案 | 正确答案 | **错在哪一步** |
|---|---|---|---|---|---|---|---|
| M-01-01 | 2026-09-25 | 1 | KP-1.3 | 受限直接执行的前提 | …… | …… | 把"受限"当成"受限的指令集"而不是"受限的特权" |
```

- **`id` 格式 `M-<讲次两位>-<序号两位>`**（如 `M-01-01`）。选讲次而非日期：日期会因补记／跨天而变，**讲次在本教室是稳定编号**（`classroom.lessons: 14` 已声明、`progress.md` 有机器可读行）。人可读、可核对、可手写。
- 🔴 **必须同时加 `kpId`**：约束① 要求"问题的本体绑定知识点清单条目"，而"这条错题属于哪个 KP"**只有人能填**——不加这一列，引擎就只能靠题目文本模糊匹配（＝静默猜）。`kpId` 的合法值域 = `knowledge_points.md` 里的 `KP-x.y`。

**② 新建 `runtime/wrong_step_library.md`（引擎面向的机器可读表）**

```markdown
| id | kpId | 错法（判据的反面） | style | 状态 | 来源 |
|---|---|---|---|---|---|
| W-KP-1.3-01 | KP-1.3 | 把"受限"理解成指令集受限，而不是特权受限 | precise | active | M-01-01 |
| W-KP-3.1-01 | KP-3.1 | 把周转时间与响应时间当成同一个东西 | precise | active | derived:KP-3.1 |
```

- `id` 格式 `W-<kpId>-<序号两位>`（**与 kpId 同构**，看 id 就知道它绑哪个知识点）。
- `状态 ∈ {active, retired}`：`retired` = 学生已改对，**不再演示**（否则同一错法反复出现＝刷屏）。
- 🔴 **`来源` 列强制**：`M-xx-nn` ＝ 真实错题；`derived:KP-x.y` ＝ 从判据反面推导。**C5 定案要求"必须标注来源＝推导值，不许冒充学生真实错法"**——这一列就是那条要求的落点。
- `style` 列取值 = `CAST_STYLES` 四值之一（与 `cast.roles[].style` **同一值域**，选人才是查表）。

**③ `cue.triggers[].source` 指向它**（已在 §8 的示例里写成 `runtime/wrong_step_library.md`；本批的校验器会检查该文件存在）。

### 9.3 迁移顺序（下一批照做）

1. 先跑一讲真实课 → 填 `mistake_log.md` 的**第一行**（含 `id`／`kpId`）。
2. 从这一行抽出 `wrong_step_library.md` 的第一条（`来源 = M-01-01`）；**同时**给本讲相关 KP 补 `derived:` 条目（C5 允许，但必须标来源）。
3. 打开 `cue.triggers` 的错法路，`enabled: true` 开搭子 → 观察 `cue_log.md`。
