## 三 · 🔴 0.1.5 → 0.2.1 的真实不兼容清单（本次实测得到，文档没写全）

### 3.1 文档已列的三条：核对结果全部「本仓库没中招」

| 文档里的坑 | 核对结果 |
|---|---|
| ① `@deepseek-ai/dsh-workflow-worker-thread` 已删除 | 本仓库三个插件的 `cordis.patch.yml` 都不用工作流引擎；全仓只有 `docs/证据图/…/prior-art` 那份第三方快照提到它。**没中招** |
| ② prompt 变量没有 `{{cwd}}` | 本仓库的教室提示词里 `grep "{{cwd}}"` **零命中**。**没中招** |
| ③ 相对路径插件（`./tools/...`）基准目录变成 `$DSH_HOME` | 三个插件的 bundle patch 都是 `name: <包名>` 形式，没有 `./` 相对路径。**没中招** |

### 3.2 文档没列、但确实把插件打挂的两条（**这才是本次真活**）

**① 宿主包解析兜底没了 → `ERR_MODULE_NOT_FOUND`**

`socratic-engine/index.mjs` 直接 `import '@deepseek-ai/dsh-tools'` / `'@deepseek-ai/dsh-llm'`，
`classroom-ui/lib/whiteboard-host.mjs` 直接 `import '@deepseek-ai/dsh-typert-protocol'` / `'@deepseek-ai/dsh-atomic-write'`。
0.1.5 上这些能解析到（服务器 0.1.5 的日志证明引擎跑到了 `index.mjs:332`，早过了 import），
0.2.1 上不行：

```
socratic-engine (socratic-engine): failed to import: Error [ERR_MODULE_NOT_FOUND]:
  Cannot find package '@deepseek-ai/dsh-tools' imported from …/plugins/socratic-engine/index.mjs
classroom-ui (classroom-ui): failed to import: Error [ERR_MODULE_NOT_FOUND]:
  Cannot find package '@deepseek-ai/dsh-typert-protocol' imported from …/lib/whiteboard-host.mjs
```

`classroom-stage-warm` 没炸，因为它的头注释里写明了「**不 import 任何外部包 ⇒ 少一个模块解析点**」——
那是一次有先见之明的设计，这次救了自己。

**修法（已做）**：把四个包提成插件自己的**显式依赖并锁 `0.2.1-rc.2`**（这四个版本号在 npm 上都存在：
`dsh-tools` / `dsh-llm` / `dsh-typert-protocol` / `dsh-atomic-write`）。
⚠️ **副作用要知道**：这样做等于在进程里放了一份插件自己的 `dsh-tools` 副本。实测工具注册与 typert 注册都正常
（`classroom_status` 等工具能注册、白板 Remote 能注册进 `ctx.typert`），但这是「靠实测通过」而不是「设计上干净」。

**② typert codec 从 `schema` 改成要 `create()` 工厂**

`classroom-ui` 的 typert 清单过了 import 这一关，又被 loader 挡下：

```
typert-loader: 1 typert contributor(s) failed to register:
  - typert-loader: classroom-ui invocation "classroom-ui#whiteboardStore/save" parameter codec has no create() factory
```

0.1.5 的 loader 校验 `"_zod" in schema.schema`；0.2.1 的 `requireSchemaProjection` 逐字是
`if (typeof value.create !== "function") throw … has no create() factory`。**两份契约互斥**——
这也是「只回滚 release 不还原插件树，`classroom-ui` 一定炸」的原因。

**修法（已做）**：`clients/classroom-ui/lib/typert.host.js` 统一改成
`_codec(typeSymbol, create, jsonSchema)`，`create` 是返回 zod schema 的惰性工厂，与 0.2.1 官方清单同构。

### 3.3 还有一条 API 变更（面板的立绘直接坏掉）

**③ `workspaceFiles.readAll` 在 0.2.1 里没有了**

真浏览器里点开右栏「教室」tab 后，DOM 上直接出现：

```
[data-classroom-ui-live2d="failed"]
[data-cui-live2d-failure] 内文 = "立绘装载失败：remote.workspaceFiles.readAll is not a function"
```

0.2.1 的 `workspaceFiles` Remote 只注册了 `read` / `readBytes` / `list` / `stat` / `changes`
（读自宿主 `@deepseek-ai/dsh-api-workspace-files/lib/typert.host.js`）。`readAll` 被 `readBytes` 取代，
且 `readBytes` 走的是**二进制通道**（`WorkspaceFileBytes`，schema 里提到 `Uint8Array`），不是 base64 字符串。

这条**不是**「资产缺失」——资产缺失是第二因。已转给车道 P（D4 的修法必须先从 `readAll` → `readBytes` 起）。

### 3.4 一条**形态**变更（预设机制整体换掉）

**④ `@deepseek-ai/dsh-agent-presets` 包被删除**

`--dump-config` 在两个 release 上的对照：

| | 0.1.5 | 0.2.1 |
|---|---|---|
| patch 告警 | 无 | `patch: entry "agent-presets" not found` |
| 预设来源 | `agent-presets` 扫目录（`preset.yml` + `agent.cordis.yml`） | `agent-preset-registry` + 每份预设一条 `@deepseek-ai/dsh-agent-preset` 插件行，**插件清单内联在 config 里** |
| `presets-private` | 出现在 dump 里 | **0 次出现**（死文件） |
| 失败方式 | — | **静默**：默认回落到内置 `standard`，教室预设从选择器里消失，不报错 |

班级服务器上已有 battle-tested 的转换脚本 `/opt/dsh-class/dsh-convert-presets-021.py`，
它顺手处理了另外三处坑（`{{cwd}}` → 字面量、`workflow-worker-thread` → `dsh-workflow`、
技能目录从 `baseUrl` 相对路径改成绝对路径，且字段名是 `customSkillDirs` 不是 `roots`）。

**修法（已做，在 stage 上）**：

```bash
python3 /opt/dsh-class/dsh-convert-presets-021.py \
  --presets-root /srv/dsh-users/stage/home/presets-private \
  --default cs-os-classroom \
  --apply /srv/dsh-users/stage/home/cordis.patch.yml
```

结果：旧块（9 行）→ 新块（290 行），替换后文件 453 行；`--dump-config` 退出码 0，
树里出现 `- id: preset-cs-os-classroom`、`agent-preset-registry.config.default = cs-os-classroom`；
真启动后 `NRestarts=0`、端口 10 秒 listen、装载零告警；真浏览器里工作区标题显示「计算机系教室 · 操作系统」。
备份：`/srv/dsh-users/stage/home/cordis.patch.yml.bak-presets-021-20261021-033006`。
